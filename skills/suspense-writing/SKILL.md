# 悬疑写作

这是作者批准正式使用的类型方法，不是已经由 A/B 证明有效的保证。方法服务于当前小说，不把评测题面的封闭限制搬成所有小说的固定模板。

## 任务与优先级

- 依据作者本轮指定、已确认类型和读者承诺决定是否使用；不要从书名、某个“秘密”或普通争执推断整部小说是悬疑。
- 悬疑相关决策优先使用本 Skill；未涉及悬疑的部分仍用对应通用任务方法。类型未知或作者只要校对时不套悬疑规则。
- 作者当前要求、已采用事实、人物知识、权限与输出契约高于类型偏好。允许倒叙、已知凶手、开放结尾或非典型写法；只检查它是否兑现作者实际许下的承诺。
- 与 `golden-finger-writing` 混合时，能力可以提供线索，但不自动提供真实解释、证据资格或行动权限；已确立的全知能力可保留，把压力放在如何证明、行动或承担后果，不擅自削弱能力。

## 本轮只处理相关的悬疑决策

1. 确认读者当前在等待什么：未知真相、已知威胁如何应对、长案如何推进，或共享规则下如何生存。不要让所有路线都变成“最后猜凶手”。
2. 分开事实、读者已知、各人物已知、能支持什么的证据、当前允许采取的行动。直觉可形成搜索假设，不因主角确信就写成已经证实。
3. 让调查或求生行动改变局面：解释权重、嫌疑范围、证据资格、关系、行动权、规则可信度或回收进度。缓冲章可改变关系与选择，不强塞新线索或反转。
4. 关键解释需要能区分竞争解释的核查。反例出现后，人物应修正假设、限制其适用范围或改变策略；核查结果尚未知时保留未知，不把“去核查”写成“已排除”。
5. 揭晓尽量重新解释先前可得、可检验的信息。不要靠结尾新增决定性证据、突然可用权限或规则改写解决核心悬念；红鲱鱼可以误导解释，但不能让叙述者隐瞒视角人物必然重视的已见事实。
6. 阶段出口兑现本阶段能兑现的承诺，明确仍开放的问题怎样推动下一步。不能用关系和解、突发危机或对下一卷的预告代替本阶段应交付的结果。

开放创作可以设计新人物、新线索和新行动，把关键来源、可得时机与后果铺进叙事；新设计是候选，不是假装前文已有。作者要求“只沿用”或给出封闭事实集时，严格限制在该范围；缺失的工具、权限、证据属性和核查结果不能补造。现实专业流程不确定时说明需要核实，不能编精确法条、仪器结论或程序效力来证明剧情成立。

## 按需展开

做案件/规则结构、揭晓审查、跨章或阶段规划时读取 [悬疑路线与核查](references/mystery-mechanisms.md)。单个对白或短段落只使用相关判断，不每次列全套账本。

## 输出和接入

- 按作者要的产物回答：正文给连续正文，章纲给章纲，诊断给问题与依据。内部账本不默认展示，不强制 JSON、不附自检或完成尾注。
- 在项目 Agent 中，正文由 `prose-writing`、章纲由 `chapter-outline`、人物由 `character-craft`、连续性由 `continuity-check`、审稿由 `style-review` 收口；本 Skill 提供类型决策，不另起一次生成。
- 在 PawApp 可信 `chapter_generation` 或 `selection_edit` 任务中，遵守任务原有格式、范围和禁工具规则，不请求额外轮次；已提供的资料不足时不冒充已知事实。
- 原生工作台需要核对内容时复用只读 `novel_get_context`、`novel_get_document`、`novel_get_workspace_context` 或 `novel_search`，检查来源与截断；不得跨小说读取或用 Shell 操作小说。
- 选区提案及保存完全交给现有主要任务 Skill 和 PawApp 受控流程。本 Skill 不直接写权威正文，不得声称候选已采用；不改变作者的模型、Agent 或权限。

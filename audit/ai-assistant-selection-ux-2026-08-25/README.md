# 选区 AI 改写与审阅体验审计

日期：2026-08-25

范围：桌面端章节正文“选区 → 润色 → 原生助手 → 候选审阅”路径。

证据视口：1819×1229。

数据影响：只框选文字、复制并粘贴 slash 命令；没有发送新请求，没有应用或保存候选，没有修改正文。

## 总体结论

当前方案能保持 QwenPaw 原生聊天与显式采用边界，但不应作为最终产品体验：选区动作没有直接启动 AI，作者必须跨栏粘贴并再次发送；候选又被放进右侧聊天消息中的独立审阅区，正文与候选无法在同一阅读面完成比较。

建议把选区改写定位为“编辑器命令”：AI 助手只负责对话、进度和简短结果摘要；真正的候选比较与采用进入中央编辑区的 IDE 式统一审阅模式。

## 流程步骤

### 1. 框选正文并出现操作条 — 健康度：较好

证据：`01-selection-toolbar.png`

- 优点：润色、改写、扩写、缩写、增强对白、检查问题和自定义均在选区附近直接出现；动作名称明确。
- 问题：工具条覆盖正文上方内容；当选区很长时仍显示同一平面，缺少“本次将处理多少内容/是否超过建议长度”的醒目提示。
- 无障碍：当前 DOM 有 toolbar、按钮名称和收起按钮；仍需实际验证键盘进入/退出工具条后焦点是否回到原选区。

### 2. 点击“润色”后只复制命令 — 健康度：差

证据：`02-polish-clipboard-handoff.png`

- 点击主动作后 AI 并未开始工作，只出现“已复制 `/polish-selection`；按 ⌘V，再点击发送”的说明。
- 这违背“点击润色即开始润色”的直接预期，也让用户难以判断系统是处理中还是没有响应。
- 操作会覆盖作者剪贴板；对不熟悉快捷键、使用辅助技术或剪贴板受限的用户不友好。

### 3. 转到右栏、手动粘贴、等待再次发送 — 健康度：差

证据：`03-manual-paste-before-send.png`

- 作者从正文跳到右侧输入框，选区工具条随焦点变化消失；输入框只显示 slash 命令，真正的选区与操作结果不可见。
- 整条路径至少包含：框选、点润色、切换焦点、粘贴、点发送五个动作。任何会话、选区或上下文过期都会让结果失效。
- 这是一条可解释的公开接口兼容降级路径，但不适合作为默认主流程。

### 4. 候选显示在聊天内的独立审阅区 — 健康度：勉强可用

证据：`04-current-nested-review-card.png`

- 优点：候选不会静默覆盖正文；替换、插入、复制、撤销和放弃都要求作者显式操作；冲突/过期时按钮会禁用。
- 结构问题：候选位于“右侧助手 → 消息流 → 工具审阅区 → 候选文本”多层容器中，和中央原文分离；窄栏里还形成消息流与候选正文的多重滚动。
- 当前可见卡片已经提示“选区不存在或已经过期”，大量按钮不可用，却仍占据明显空间。过期结果更适合折叠为一条历史记录，而不是持续充当主审阅面。
- A7 证据把这一样式称作“IDE 单窗口审阅器”，但现状只是把卡片边框压平后嵌入聊天，并没有实现 IDE 的同文档差异比较、分块接受/拒绝和单一滚动审阅语义。

## 建议的目标流程

1. 作者框选正文并点击润色/改写。
2. 系统直接创建一次“编辑器 AI 任务”，原位显示生成状态；不要求复制、粘贴或再次发送。
3. 生成完成后，中央编辑区切换到统一审阅模式：原文与候选在同一文档面显示差异。
4. 1920 宽度优先统一 diff；2560 宽度可选左右对照。支持逐块接受/拒绝、全部接受、重新生成、手动编辑候选和退出审阅。
5. QwenPaw 助手只保留简短状态与追问入口，例如“润色候选已生成 · 打开审阅”，不重复放置完整候选正文。
6. 应用仍走现有字段 Adapter、全文哈希/CAS、显式保存或正文自动保存；失败不改正文。

要实现真正一键开始，需要先核实 QwenPaw 是否提供公开的 Agent 调用或编辑器动作接口；若没有，应新增经过 ADR 批准、仍复用“AI 小说作家”有效模型的 PawApp 编辑任务通道，不能通过私有 DOM/store 模拟发送。当前剪贴板方案仅保留为“兼容模式”降级。

## 无障碍风险与证据边界

- 统一 diff 不能只依赖红/绿色，需同时提供“删除/新增”标签、符号和文本说明。
- 审阅模式需要明确焦点入口、Esc 放弃、快捷键提示、生成/失败的 `aria-live` 状态，以及退出后返回原选区。
- 截图与 DOM 快照只能证明当前可见层级和部分名称/角色；尚不能证明屏幕阅读器朗读顺序、焦点陷阱、中文输入法、缩放重排和真实模型等待期间的完整行为。

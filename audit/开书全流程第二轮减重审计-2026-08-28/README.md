## 1. 审计范围与方法

本轮从作者真实路径复查：创作中心 → 建书 → 大纲 → 新建章节 → 章纲 → 正文生成 → 同步进展，并同时核对当前源代码与计划 28。

- 页面证据来自本轮应用内浏览器的只读检查。
- 没有点击“新建小说”或“新建章节”：这两个入口会立即 `POST` 创建可持久化草稿，继续操作会改变本地运行态，不属于只读审计。对应步骤改用当前源代码核验，并在结论中明确标注。
- 没有发起模型调用，没有保存表单，没有修改小说正文、revision、故事账本或 Agent 模型。

## 2. 结论

当前最重的地方不是 Agent 数量，而是同一个作者动作被拆成过多页面、确认和模型调用：

1. 建书保持六个可见进度节点，唯一支持的“长篇”仍占一屏，模板又是完成建书的硬前置；默认路径可能调用模板、取名和伪 AI 封面三次模型。
2. 大纲编辑仍是章节数、背景、角色、情节、亮点五步串行流程。作者只想改一个模块，也要重新进入完整向导。
3. 新建章节是线索、角色、伏笔、期望、章纲、完成六步；章节故事线推荐与章纲各可再发起模型任务，章纲内部最多自动重试三次。
4. 空正文页同时出现“生成章节内容”和“生成正文”两个同义主动作。
5. 点击生成正文后，必须先经过素材选择弹窗，再经过通用模型确认；正文任务内部最多自动调用三次，成功后又自动弹出“同步进展”，可能继续触发另一类模型任务。
6. 同屏同时显示作品任务模型 `deepseek-v4-pro` 与右侧原生聊天模型 `glm-5.3-flash`，但没有足够强的语义隔离，容易误判实际生成模型。
7. 创作中心返回后显示 `0章`，工作台同时存在 1 个章节；章节列表又在已分卷章节下方显示无归属说明的“暂无章节”。这是统计刷新和空态表达问题，不应被纳入模型诊断。

## 4. 建议的最短作者路径

```text
建书（默认 0 次模型调用）
  作品定位：受众 + 题材 + 思路 + 可选模板
  → 作品信息：书名 + 作者 + 默认文字封面
  → 创建

作品准备（可选、模块化）
  背景 / 角色 / 主情节 / 亮点
  每块独立手填或 AI 生成，不再强迫走五步

写章
  单页章前卡：标题 + 目标字数 + 章纲
  高级约束折叠：线路 / 角色 / 伏笔 / 禁项
  → 创建章节
  → 直接写作 或 AI 生成正文（一次调用）
  → 作者需要时再手动“同步进展”
```

## 5. 必删、必改与保留

### 必删

- 唯一可用的长篇类型单独一屏。
- 建书完成确认屏、章节创建最终确认屏。
- 新建章节的独立“AI 推荐线路”模型任务。
- 章纲和正文的三次隐藏自动重试。
- 空正文页重复的第二个生成主按钮。
- 生成正文前强制素材弹窗、空正文的通用二次确认。
- 正文成功后自动弹出同步进展。
- 新建 AI 封面任务。

### 必改

- 建书由六个可见节点压缩为两页；模板改为可选，默认自由创作。
- 大纲改为单页模块编辑；各模块独立生成、独立失败，不自动连锁重做。
- 新建章节改为单页章前卡；高级约束默认折叠。
- 私有库资料改为生成按钮旁的可选设置，不阻塞默认路径。
- AI 按钮直接显示本次任务模型和最长等待；点击即为明确授权。只有现有正文会被换成新 working copy 时保留一次确认。
- 作品模型区改称“AI 生成任务模型”；右侧状态明确“聊天模型仅影响右侧会话”。
- 返回创作中心或完成章节后重取作品摘要；无未分卷章节时隐藏空态，或明确标注“未分卷章节”。

### 保留

- 唯一 `ai-novel-writer` Agent 和 `follow-agent-effective` 模型权威。
- 现有 draft、job、候选、working copy、不可变 revision 和 CAS。
- 模型失败零正式正文／故事账本写入；不自动换模型。
- 大纲按钮点击后经 job、归属、版本与 CAS 校验自动采用到大纲草稿，不增加第二层确认。
- 正文候选成功后进入 working copy；正式 revision 仍由现有显式保存／检查点规则控制。

## 6. 对计划 28 的影响

计划 28 第一次复查只解决了部分真实性和调用问题，但仍保留七屏建书、五步大纲、六步建章、强制素材弹窗、通用确认、自动同步提示和四次跨模型验收。本轮建议把计划改为：

- 产品结构从“修三个向导”改为“建书、作品准备、写章”三段；
- 默认建书 0 次模型调用；
- 每个 AI 按钮最多一次模型调用，所有重试由作者显式发起；
- 发布验收只用当前有效模型做一次结构化任务和一次正文任务；三模型比较保留为独立诊断，不再重复切换全局 Agent 状态；
- QwenPaw 卸载 hook 缺陷作为独立发布阻断热修，不继续绑在作者流程施工的关键路径上。

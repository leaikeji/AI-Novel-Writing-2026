# MOSS 模型与可重建制品清理记录

状态：**已执行并复核**
日期：2026-09-08（Asia/Shanghai）

## 授权与边界

作者在听检 Qwen3-TTS CustomVoice、Base 克隆和 VoiceDesign 样音通过后，明确要求先删除 MOSS 模型及清理文件释放空间。

首次清理只删除 MOSS 运行制品和可重建依赖；作者随后明确不再回退 MOSS，因此又删除了当前 Compose 拓扑与 sidecar 镜像源码。全程不删除小说正文、revision、故事账本、PostgreSQL/QwenPaw 数据卷、小说媒体、Qwen 模型或历史验收证据。

## 已删除

- Docker 容器：
  - `ai-novel-2026-moss-tts-sidecar`
  - `ai-novel-tts56-sidecar`
  - `ai-novel-2026-moss-tts-model-installer`
  - `ai-novel-2026-moss-tts-runtime-init`
- Docker 卷：`ai-novel-2026-moss-models`，删除前占用约 763.4 MiB。
- Docker 镜像标签：
  - `ai-novel-world/moss-tts-sidecar:t1-b-linux-arm64`
  - `ai-novel-world/moss-tts-sidecar:tts56-lease-guard`
  - `ai-novel-world/moss-tts-sidecar:tts56-reference-bound`
  - `ai-novel-world/moss-tts-sidecar:tts56-before-reference-bound`
- 可重建原型依赖：
  - `prototypes/moss-tts-nano/.venv`，约 589 MiB；
  - `prototypes/moss-tts-nano/node_modules`，约 316 MiB。

删除后 `prototypes/moss-tts-nano` 仅剩约 964 KiB 的源代码、锁文件与测试材料。磁盘可用空间由约 15 GiB 增至约 24 GiB；Docker Desktop 的稀疏磁盘回收会使该变化大于简单文件标称大小之和。

## 有意保留

- `ai-novel-2026-moss-tts-secrets`：仅 64 B，但仍由当前 QwenPaw lab 容器挂载；不为清理 64 B 强拆主应用容器。后续移除 Compose 挂载并正常重建时再删。
- `ai-novel-tts56-qwenpaw-data` 与 `ai-novel-tts56-qwenpaw-secrets`：属于 QwenPaw 数据/密钥卷，不因“MOSS 模型清理”推断为可删除。
- 11.44 GiB Docker build cache：包含多个项目且无可可靠归属到 MOSS 的标签，不执行跨项目 `builder prune`。

## 后续部署收口

- `compose.yaml` 已删除三个 MOSS 服务、MOSS 模型/令牌卷声明、两个专用网络、QwenPaw 对旧 sidecar 的依赖及全部 `MOSS_TTS_*` 环境变量；以后执行 Compose 不会重新下载或启动 MOSS。
- 已删除无调用者的 `docker/tts-sidecar/**`，并从 `.dockerignore` 移除旧构建上下文放行项。
- 通用 FFmpeg 工具链继续保留，仅将构建身份变量从 `MOSS_FFMPEG_BUILD_ID` 改为 `NARRATION_FFMPEG_BUILD_ID`。
- 正在运行的 QwenPaw lab 容器尚未为此强制重建，因此仍暂时挂载 64 B 旧令牌卷；下次正常重建后即可删除。

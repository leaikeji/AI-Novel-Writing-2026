# 计划 61：语音模型接入页面产品审计

- 日期：2026-09-08
- 方式：当前长期运行环境、内置浏览器桌面视口、当前源代码与相关测试交叉复核
- 结论：**成立，可作为首版投入使用；可靠性强于易用性，建议先做少量减法式修正。**

## 审计范围

1. 创作中心入口：确认“语音模型接入”与现有入口并列，入口可发现。
2. 接入页空态：确认本地状态、隐私/计费提示、云端渠道空态及新增入口。
3. 新增渠道表单：确认渠道名称、只读协议、Base URL、质量/速度模型 ID、API Key 和“保存但不测试”的交互。
4. 可靠性复核：结合服务端实现与测试，核对密钥脱敏、计费确认、模型验证、启用门禁、并发版本校验和 URL 安全边界。

本次没有保存虚假渠道，也没有触发真实云端计费测试；“测试—启用—停用—删除”的真实页面状态待用户填写有效渠道后复核。

## 总体判断

| 维度 | 判断 | 说明 |
| --- | --- | --- |
| 方案是否成立 | 成立 | 本地与云端职责分开，云端可配置多个渠道但只启用一个，符合当前产品范围。 |
| 合理性 | 较好 | 入口位置正确，配置字段完整，保存、测试、启用分离。 |
| 可靠性 | 较强 | 服务端具备密钥隔离、显式计费确认、实测后启用、CAS/幂等、单活和 URL 安全校验。 |
| 易用性 | 中等 | 能用，但首次配置仍容易在 Base URL、协议兼容性和 API Key 是否必填上产生疑问。 |
| 无障碍 | 基础较好，仍有风险 | 使用原生标签、按钮、状态提示；自制确认对话框尚未证明具备完整焦点圈、Esc 关闭和焦点恢复。 |

## 做得好的地方

- “保存配置”不会联网或计费，测试前再次确认，默认行为安全。
- 云端渠道不会静默替代本地模型；启用只影响之后新建的朗读任务。
- API Key 只写入、不回显，列表只展示脱敏结果。
- 启用前必须验证所有已配置的模型槽位，页面和服务端均有门禁。
- 使用可编辑 Base URL，支持多会员渠道，没有把域名写死。
- 桌面信息层级清楚，表单两列布局简洁；窄屏已有单列响应式处理。

## 主要缺口

### P0：应在用户正式配置前修正

1. **“可改域名”不等于“任意渠道都兼容”。** 当前只支持 `Qwen-Audio 原生 HTTP v1`。页面虽然显示了协议，但没有直接告诉普通用户：第三方渠道必须实现相同请求/响应契约。
2. **Base URL 容易填错。** 目前只有占位示例，用户无法确定应填写根域名、路径前缀还是完整接口地址。
3. **API Key 的“可选”表述不够准确。** 它仅对保存草稿可选，测试和启用前实际必填。
4. **本地“运行正常”容易被理解为刚完成了一次真实合成。** 当前状态来自整体朗读能力健康检查，不等同于本轮真实音频试听验证。

### P1：可在首版运行后轻量改进

1. 云端渠道空态留白较大，空态内部缺少“新增第一个渠道”按钮。
2. 黄色隐私警告视觉权重过高，压过了首要配置任务；可以缩成短提示，把完整说明放到测试确认处。
3. 只读“接口协议”占据主要表单位置且术语偏技术，可降为兼容说明或高级信息。
4. 最近测试失败直接显示内部错误码，建议先给中文行动建议，再把错误码作为辅助信息保留。
5. 自制 `alertdialog` 需要补足或验证焦点限制、Esc 关闭和关闭后的焦点恢复；优先复用宿主 Ant Design Modal。

## 最小改造建议

不增加新的管理体系，只做以下四项：

1. 增加“阿里云官方 / 自定义兼容渠道”轻量选择；选择只负责填充说明或默认值，Base URL 仍可自由编辑。
2. 在 Base URL 下方写清允许的格式，并显示最终请求地址预览或最小示例。
3. 将字段改名为“API Key（启用前必填，可暂存草稿）”。
4. 将本地状态改成“本地朗读服务已就绪”，同时展示实际模型标识与上次健康检查时间；不自动执行计费或耗时试听。

## 证据边界

- 当前入口、空态和新增表单已在长期运行环境中逐屏检查；截图在本次审计会话中以内置浏览器原始画面呈现。
- 当前没有用户提供的有效云端域名、模型 ID 和 API Key，因此没有执行真实云端测试，也不能把渠道可用性写成已验收。
- 配色对比度未做数值测量；绿色状态标签、黄色提示和浅色占位文本仍需专项测量后才能声明符合 WCAG。

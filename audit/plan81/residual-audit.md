## 3. 当前源码确认、应进入新尾项计划

### 3.1 数据安全、真实语义与写作流程

| 原编号 | 当前源码证据 | 建议去向 |
| --- | --- | --- |
| `F70-UI-01` | `creative-center.ts` 在列表请求失败后设置错误，同时 `activeNovel` 为空仍渲染“开始您的第一部长篇小说”，没有独立错误态和重试动作。 | 计划 82 必修：错误、空列表、加载中三态互斥；失败不得暗示作品不存在。 |
| `F70-UI-02` | 建书 `startDraft` 读取既有 `draft_key` 后直接 `setStep(next.step)`，没有恢复来源、时间或“继续／重新开始”说明。 | 计划 82 必修：显式恢复提示，不读取或展示敏感存储内容。 |
| `F70-UI-03` | 纯手写入口仍为“已有作品点击直接填写模板”，正文空态仍为“我已有正文，点击直接填写”。 | 计划 82 必修：改为同时适用于从零手写的准确文案。 |
| `F70-UI-04` | 手选模板后仍由 `data.template_key` 触发“智能模板生成／AI根据…”，手填书名出现“重新生成名称”，文字封面完成页仍称“封面生成完成”。 | 计划 82 必修：保存明确的来源状态并据此显示文案，不猜测是否调用 AI。 |
| `F70-UI-09` | `latestChapterTitle()` 只按 `chapter_count > 0` 显示“已完成 N 章”，没有检查正文或正式 revision。 | 计划 82 必修：改为中性“已有 N 章”或使用可证明的完成定义。 |
| `F70-UI-10` | 作品设定仍以 `Object.entries(settingsForm.template_data)` 直接把 `core_hook` 等内部 key 当标签。 | 计划 82 必修：复用模板字段中文元数据，未知字段使用安全的人类可读降级。 |
| `U019` | 正文候选采用后 `generateBody()` 仍直接 `await confirmSyncProgress(result.document)`，生成完成即抢占式弹出下一次模型操作确认。 | 计划 82 必修：正文完成先稳定落位；把同步进展改为明确的后续动作，不自动抢占。 |

### 3.2 朗读 Edition、投影与恢复

| 原编号 | 当前源码证据 | 建议去向 |
| --- | --- | --- |
| `F70-AUDIO-04` | `refreshManifestInPlace()` 只替换 Manifest；`editionOptionLabel()` 仍读取初次 context 的 `ready_segment_count/total_segment_count`，因此制作计数可与最新 Manifest 分离。 | 计划 82 必修：给活动 Edition 使用最新 Manifest 派生计数，或窄刷新历史投影；不得重建正在播放的 session。 |
| `F70-AUDIO-06` | `afterAccepted` 超时固定抛“可以稍后再次重试”；控制器随后虽刷新出 `retryable=false`，仍优先显示该旧错误。 | 计划 82 必修：终态投影优先于过期动作建议；不可重试时显示权威 `retry_reason_code` 对应动作。 |
| `F70-AUDIO-07` | 更新工作流载入并可自动播放新 Edition，但后端按安全设计不会替换已有 current pointer；前端只在另一次版本选择确认中调用 `switchNarrationEdition()`。刷新会回到旧 current Edition。 | 计划 82 必修：冻结“更新并设为当前”的显式确认时点；不能后台静默切换，也不能自动播放一个未持久选中的版本后假装完成。 |
| `F70-AUDIO-08` | `ACTIVE_PLAYER_PHASES` 包含 `paused`，版本选择器在暂停时仍 disabled；页面也没有单章“停止并退出当前播放会话”的直接入口。 | 计划 82 必修：增加明确停止／退出动作；停止后才允许切版，或证明暂停切版能安全原子停止旧播放。 |

## 5. 裁决

计划 70 不应继续作为活动总计划：其专属 Skill 限定范围、失败质量结论和历史运行证据已经完整，继续追加会混合写作质量、创作中心、章节向导与 TTS 状态机。建议把计划 70 标记为 `CLOSED_WITH_LIMITS`，把第 3 节确认的现行产品缺口转移到新建的[计划 82](../../docs/开发文档/82-计划70现行界面与朗读状态尾项收敛计划.md)。

计划 82 当前只是 `PROPOSED`，不自动授权代码、正式环境、模型调用或 Git 操作。第 4 节的可选项不作为计划 82 的强制完成门禁；只有在同文件改动或真实桌面复核中确认仍有价值时才一并收口。

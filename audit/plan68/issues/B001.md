# B001 手动模板路径在最终创建时要求缺失的创作思路

- 严重度：P1（建书阻断）
- 首次步骤：S0023
- 前置：长篇、男频；在“创作思路”页选择“已有作品点击直接填写模板”，手动选择“都市成长”，填写4个模板字段、作者与书名，选择文字封面。
- 预期：明确提供的“直接填写模板”路径可以不调用AI并完成建书；或在离开创作思路步骤前提示仍必须填写思路。
- 实际：最终“完成创建”才报错“请填写或生成创作思路”。此前步骤均显示已完成，用户到最后一步才被退回。
- 用户代价：至少需要回退多步；不清楚能否在填写思路后仍不触发“生成模板”，且存在误点AI的风险。
- 初始证据：[S0023](../screenshots/S0023-完成创建被创作思路校验阻断.png)。原图已检查，错误条与最终确认页同时可见。
- 数据状态：小说尚未创建；向导草稿中已填标题、作者、模板字段与文字封面。未关闭页面，未调用AI，未后台补数据。
- 根因：界面允许跳过创作思路进入手动模板，但完成服务无条件执行思路非空校验；UI 与服务端合同不一致。
- 恢复方案：使用“返回修改/上一步”回到创作思路，填写完整原创思路；再次点击“已有作品点击直接填写模板”，确认现有模板字段是否保留，再原路创建。
- 恢复结果：本次作品通过可见 UI 回退、手填思路后成功创建，原有模板/标题/封面均未丢失。
- 代码修复候选：直接模板入口写入显式 `manual_template_entry=true`；作者手填思路时清除此标记；完成服务只在非手工模板路径要求思路非空，手工路径可以如实保存空字符串，不生成替代文案。
- 自动验证：前端静态合同测试通过；数据库集成用例已新增，但当前测试库未配置而跳过。
- 修复状态：自动化候选通过；因本轮明确只创建一本小说，不能再建第二本取得修复后UI截图，故原路UI复验未执行。

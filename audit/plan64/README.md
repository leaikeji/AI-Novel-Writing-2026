# 账本前端移除与系统自动维护收口：实施与运行证据

日期：2026-09-10。状态：代码、自动化、长期安装及本轮桌面/窄屏运行验收完成。范围依据为作者本轮两项明确指令和随后对 Docker 安装的明确授权，见[计划 64](../../docs/开发文档/64-账本前端移除与系统自动维护收口.md)。计划 60 整体停止，历史材料保留，不作为本次设计依据。

## 删除内容与保留理由

- 删除 `story-ledger/workspace`、`fact-list`、`fact-detail`、`filters`、`styles` 及其页面专用测试；生产调用者仅为已移除的账本工作台接线，类型检查与构建验证无悬空导入。
- 删除一级账本入口、时间线跳转、账本筛选路由及缓存字段。旧链接和旧缓存回到本书章节；路由所有权、会话隔离、无效输入的负向测试仍保留。
- 删除无人使用的页面 API 列表/详情封装、专用 DTO、助手上下文生成器、原因标签。共享事实摘要、来源核验、纠错、撤销及快照 API 继续服务人物/时间线。旧助手协议类型和验证器保留兼容，测试静态 fixture 仅由测试导入；跨页、预算、正文泄漏与事实错配负向测试保留。
- 去掉大纲人物引用技术说明、创建人物的自动建档提示、人物状态页的账本说明、额外保存确认。原有保存动作、恢复、CAS、人物同名冲突提示继续存在。
- 去掉“本次写作方法”选择器，正文请求统一采用现有 `auto`；删除正常方法回执、技术历史展开、无调用的展示解析函数和显示名称状态。失败/未知结果仍可恢复查询，成功后不常驻“查询原任务”。后台方法历史审计 API 和其独立负向测试保留。
- 正常索引状态、本地检索降级与无额外命中不打断作者，不再从流程提示引导索引管理。真实失败或最新资料尚未跟上时保留简短反馈。没有改动云端数据授权或已有向量接入配置。

本次没有重排建书、大纲、章节、人物、线索、设定、朗读布局，没有新增页面、配置项或依赖。没有删除账本数据库、迁移或用户故事数据。

## 系统处理核查与实际修复

1. **事实去重修复**：旧指纹未纳入 subject/predicate/details/visibility 等完整含义，同一引文范围内不同事实可能被误合并。新指纹从验证后的事实含义和来源生成，排除随机 ID、创建时间等元数据；先走指纹索引，再以完整身份匹配旧指纹事实，历史行不重写。兼容 SQL NULL/JSON null，不因展示标签变化重复写入。新增测试覆盖含义不同、重复请求、旧指纹、标签变化和空值。
2. **冲突边界修复**：512 候选与 160 最终事实预算可能截断同位置冲突组。SQL 选择仅接受预算内完整组；显式矛盾的另一端即使被预算排除，也需按同小说、时间线、叙事截止与来源有效性核验，必要时排除保留侧。SQLite 窗口 SQL 反例和有界模拟验证覆盖完整组、跨界/交错组、有效及失效外端点。没有真实 PostgreSQL 性能证据。
3. **来源与增量索引保留**：`services.py` 的正式正文采用、检查点与恢复路径调用 `_reconcile_story_facts_for_revision`，按来源内容哈希更新有效性，不改写旧 revision。相应路径向 `embedding/indexing.py` 传递 `SourceRefreshHint`，针对已有有效索引请求增量刷新；失败保留过期标记和恢复路径。working copy 与正式版本边界保留，不能把未采用草稿当权威事实。已有测试通过，本次没有重造维护系统。
4. **Skill 自动装载核查**：当前按钮确定性主 Skill 路由已启用，分别覆盖创意方向、故事基础、人物、章纲、正文与审稿；服务端通过公开 Skills 能力与专用 Agent 范围装载。可信题材/子题材可补充分类方法，不要求作者逐次选择。自由文本机制语义补选仍未发布，不启用计划 58。安装保留了此前全部禁用的状态；作者本轮要求 Skill 正确调用后，该指令取代旧状态，通过 QwenPaw 公开 API 启用专用 Agent 的 11 个项目 Skills。默认和 QA Agent 仍为零项目 Skills，没有扩大作用域。本次未修改 Skill 文本或安装逻辑。

作者仍决定是否采用新生成的正文和故事事实候选；自动去重、来源维护和索引刷新不需要新增作者操作。没有真实模型对照样本，因此不能声称文学质量已提升。

首次运行检查遇到 `18088` 拒绝连接和 Docker API 500。获作者授权安装后，安装脚本先完成全量测试和打包，但因长期环境四个 TTS 开关与安装前置不一致而在写入前停止。只读确认后台任务为 0 后，以四个 TTS 开关关闭的安全状态重建 QwenPaw；Docker Desktop 在停止阶段卡住，使用官方 `docker desktop stop --force --timeout 30` 和 restart 恢复引擎，没有删除卷。随后按长期环境实际 TTS 目标重新安装，脚本完成迁移检查、插件安装、热加载、容器重建和运行校验，并恢复本地 TTS 为 `ready`。

运行页面使用实际长期数据中的《雾宅来信》检查。桌面工作台显示章节、大纲、角色、线索、设定、朗读六项，逐页均能加载；打开《第1章 门廊来信》后正文、审稿、情报、同步、历史和朗读控件均能显示。另打开建书向导至“创作思路”、新建章节向导首步和大纲编辑首步但没有提交，页面未出现账本、索引、指纹、dispatch 或 Skill 选择等技术提示。保留的“描述越详细”等内容属于直接帮助作者完成当前表单的写作提示。

390×844 下折叠宿主助手后，创作中心和书内工作台正常显示，章节列表与正文编辑器可进入，设定页可滚动访问；根页面无横向溢出。窄屏章节页同时如实显示已有 4 个 TTS 质量失败段的“查看失败”恢复提示，该历史内容未被本次操作改写。

设定页仍保留“语义索引”标签，因为其中包含云端数据授权、撤销和异常处置，不属于已移除的账本页面。正常增量索引、来源更新和本地降级不要求作者操作；本轮没有擅自改变既有云端授权。

## 数据与恢复

安装脚本执行了迁移检查和插件替换；本次代码没有新 schema revision，不需要批量改写历史事实。没有删除卷、小说、revision、媒体或备份，也没有提交或推送 Git。共享运行状态的唯一额外变更是按作者当前指令启用专用 Agent 的 11 个项目 Skills；可通过 QwenPaw 公开 Skills API 逐项禁用恢复。插件失败时仍可按既有安装脚本回退此前包；新旧事实指纹兼容，不依赖历史数据重写。

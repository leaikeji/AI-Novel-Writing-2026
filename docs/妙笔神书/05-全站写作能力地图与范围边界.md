# 妙笔神书全站写作能力地图与范围边界

实测日期：2026-08-22  
入口：https://www.miaobishenshu.cn/index.html

## 一、这轮只研究什么

这轮把研究范围重新收紧为“直接帮助个人完成小说创作的能力”。纳入范围：

- 灵感进入建书流程。
- 长篇、短篇建书。
- 作者自定义模板。
- 私有创作资产及其在生成时的注入。
- 大纲、卷章、正文、角色、关系、线索、设定、伏笔。
- 正文生成、手写、保存、版本、恢复、审稿、情报提取。
- 基于作者自有或获授权文本的拆解学习。
- 作品封面与正文导出，但只记录创作流程，不研究商业权益。

明确排除：

- 不研究计费、额度、字包、套餐、会员、VIP 和任何价格规则。
- 新闻、公告、网文早报、教程资讯流和活动推广。
- 不研究发现中心、会员中心、个人中心、邀请、任务和签到。
- 投稿、签约、收益、平台运营和社交增长。

本项目是个人自用软件，以上商业和运营模块没有开发价值，不进入信息架构、数据模型、接口或验收用例。

## 三、入口之间的真实数据流

```text
每日灵感
  -> 复制文本
  -x- 建书思路没有自动带入

作者模板
  -> 建书时按分类选择模板
  -x- 自定义字段没有出现可填写实例

私有库资产
  -> 生成正文前选择桥段/文风/词汇/热梗
  -> 模型生成正文

自有文本
  -> 智能拆书
  -> 写作风格建议
  -> 保存为私有库写作风格
  -> 后续正文生成可再次选择

章纲与正文
  -> AI 提取角色状态/关系/线路/伏笔
  -> 保存正文时同步全局故事数据
```

这里最值得借鉴的不是页面数量，而是“研究材料 → 私有资产 → 生成约束 → 正文 → 故事账本”的闭环。最需要修复的是每个箭头目前都缺少明确来源、实体匹配、变更预览或撤销能力。

## 四、首页每日灵感的实测结论

1. 点击“开书试试”后，页面提示思路已经复制。
2. 打开长篇建书并进入思路步骤，文本框仍为空。
3. 因此它只是剪贴板动作，不是建书草稿之间的数据传递。
4. 用户必须手动粘贴，且无法追溯该灵感来自哪张卡片。

项目实现应使用显式命令 `start_novel_from_inspiration(inspiration_id)`：

- 创建建书草稿。
- 把灵感写入 `idea_text`。
- 保留来源卡片和原始版本。
- 进入思路确认页，而不是直接调用模型。

复制仍可保留为次要操作，但不能把“已复制”包装成已经进入创作流程。

## 五、优先级重排

### P0：必须先做稳

1. 作品、卷、章、章纲、正文的稳定身份和自动保存。
2. AI 正文只生成候选，作者接受后再进入工作稿。
3. 正文版本、手动修改版本和恢复。
4. 角色、关系、线路、伏笔的带来源候选与人工采用。
5. 保存正文不隐式移动分卷、不隐式删除记忆、不静默落库 AI 情报。
6. 删除或恢复章节时，派生情报有明确的失效、回滚和重新采用策略。

### P1：形成创作闭环

1. 分阶段大纲和一致性扫描。
2. 私有库资产及生成时的可见注入。
3. 短篇九步建书、整篇候选生成和编辑。
4. 章节/短篇审稿，但只提供可解释建议。
5. 自有文本场景拆书与资产沉淀。

### P2：增强但不阻塞

1. 自定义模板市场或分享。
2. 多维拆书组合报告和跨作品研究库。
3. 关系图多视图、复杂筛选和自动布局。
4. AI 封面多候选与风格控制。

## 六、这轮新增的关键反例

| 反例 | 实测表现 | 项目约束 |
| --- | --- | --- |
| 灵感传递断点 | “开书试试”只复制，建书思路为空 | 入口必须创建带来源的草稿 |
| 自定义模板字段疑似无效 | 定义了字段名和必填，建书时没有填写字段值的页面 | schema 必须实例化为 values，必填由服务端验证 |
| 目标字数失真 | 短篇最低目标仍只生成约三成内容 | 用目标范围、完成状态和续写任务管理 |
| 角色约束漂移 | 设定 28 岁，正文写成 32 岁 | 生成前做约束清单，生成后做实体事实校验 |
| AI 检测不可信 | 纯 AI 正文被显示为多数人工特征 | 不建设伪精确 AI 检测百分比 |
| 情报近义重复 | 已有追查线又新增近义追查线 | 写回前实体消歧、合并候选和人工确认 |
| 线路类型错分 | 兄妹线被新增到支线 | 线路类型可重分类，关系线与恋爱线分开 |
| 删除不级联 | 删除章节明确不删除角色记忆和线路事件 | 删除章节必须使派生数据失效或提供事务化回滚 |

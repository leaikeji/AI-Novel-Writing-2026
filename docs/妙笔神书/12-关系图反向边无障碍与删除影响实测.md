# 关系图反向边、布局、无障碍与删除影响实测

实测日期：2026-08-22  
研究作品：《封存区没有明天》  
角色基线：主角林默、张子涵；配角王建国、陈晓峰、郭晓霞。  
当前状态：R5 非破坏性部分已完成；画布保留两条反向有向边和一条真实无向边。角色删除只检查确认提示并取消，没有实际删除云端角色。

> **方法修正（2026-08-22）**：方向、布局、可访问性和删除预览是结构事实；关系名称和描述必须同时承担故事语义。早期协议化标签已在原关系上直接改写，未删除或重建边。

## 一、测试问题

本轮只验证关系图的数据和操作边界：

1. 同一对角色建立相反方向关系时，是覆盖、去重还是两条有向边。
2. 节点位置、自动布局和关系语义的持久化是否分离。
3. 不使用鼠标或触控板时，能否通过列表完成相同关系编辑。
4. 角色较多时是否有查找、聚焦、适应画布和重叠处理。
5. 删除有关联角色前，页面是否展示精确级联影响。

## 二、关系编辑数据结构

点击 Canvas 节点后打开“编辑关系”，标题为“某角色的关系”。关系表单包含：

- 目标角色下拉。
- 关系名称。
- 关系描述。
- “单向关系”复选框。
- 添加关系。
- 已有关系列表；每项可以修改名称、描述、方向或删除。
- “保存所有修改”。

关系先加入弹窗内的本地列表，点击“保存所有修改”后才整体提交。保存成功关闭关系弹窗并显示一次性提示。

打开王建国节点时，会看到林默指向王建国的入边；因此“某角色的关系”不是只列该角色作为 source 的关系，而是列出所有与它相连的边，并用箭头标明方向。

## 三、反向关系实测

### 3.1 第一条边

从林默节点添加：

- source：林默。
- target：王建国。
- 名称：`隐瞒调查`。
- 描述：`林默表面服从主任安排，暗中核对封存区的出入记录，并隐瞒未来磁带仍在自己手中。`。
- 单向关系：勾选。

保存后画布显示指向王建国的箭头和关系标签。

### 3.2 反向边

再从王建国节点添加：

- source：王建国。
- target：林默。
- 名称：`监视与试探`。
- 描述：`王建国察觉林默接触了未来录音，以值班复盘为名持续试探，试图夺回磁带和坐标纸。`。
- 单向关系：勾选。

保存结果：

- 第一条边没有被覆盖。
- 第二条边没有被判重。
- 画布同时显示两个相反箭头。
- 两条关系各自保留名称和描述。
- 刷新后两条语义关系仍存在。

结论：**有向关系按 source/target 区分，A→B 和 B→A 是两个独立实体。** 这对“隐瞒调查/监视试探”“追捕/逃避”等非对称叙事是正确的基本能力。改名和改描述后两条边仍保持原方向，也说明文本编辑不会重建或反转端点。

### 3.3 显示问题

同一对节点的两条反向边距离很近，标签沿线旋转并相互挤压。随着名称变长或同一端点再增加多条关系，难以区分点击目标。

页面没有：

- 同角色对关系分组。
- 平行边曲率或 lane 调节。
- 展开同一角色对的关系清单。
- 标签避让、截断提示或悬停完整内容。
- “合并为双向关系”或“拆成两条单向关系”的显式命令。

因此数据语义允许反向双边，但画布并没有为多重边提供稳定可读布局。

### 3.4 无向关系与箭头文案不一致

为真实剧情新增张子涵与林默的关系：

- 操作入口：点击张子涵节点 → 添加关系。
- 目标角色：林默。
- 关系名称：`共同记忆锚点`。
- 描述：`二人共同接触原始坐标纸，能交叉验证被改写前的记忆；约定若一方从记录中消失，另一方用纸质目录和原始录音保留其存在证据。`
- “单向关系”：未勾选。

保存后的可见结果：

- Canvas 使用无箭头的普通线段连接张子涵和林默，与两条有向边的箭头外观可区分。
- 刷新并重新进入关系网后，该无向线仍存在，说明方向语义已经持久化。
- 同一弹窗的关系摘要仍显示 `张子涵 → 林默：共同记忆锚点`，没有使用 `—`、`↔` 或“无向”标记。
- 后续章节情报提取又把同名“共同记忆锚点”建议为 `林默 → 张子涵（单向）`，说明提取器没有可靠复用已有无向实体；本轮取消了全局写入，画布未被污染。

结论：未勾选“单向关系”在画布层确实产生无向边，但弹窗摘要和 AI 提取建议仍默认使用有向表达。产品不能只靠“是否画箭头”传达方向，列表、摘要、编辑器和数据层必须同时明确 `directed/undirected`。

## 四、Canvas、布局和刷新

关系图使用 `vis-network`：

- 一个 1692×1196 的 Canvas 承载全部节点、边和标签。
- Canvas 本身没有 role、aria-label 或 tabindex。
- 外层 `.vis-network` 只有 `tabindex=0`，没有 role 或 aria-label。
- 聚焦外层后按 Enter 不会选中角色或打开关系编辑器。

节点可拖动，边会实时跟随。本轮把林默从关系簇拖到画布右下，页面没有“布局已修改”“保存布局”或撤销状态。刷新后：

- 页面先回到“角色列表”，关系网子标签状态不保留。
- 再打开关系网时，节点重新自动排布，拖动坐标消失。
- 两条反向关系语义继续存在。

这再次确认：语义关系已持久化，节点坐标和缩放是临时视图状态。当前自动布局每次进入可能明显变化，不适合作者依赖空间位置记忆人物群组。

## 五、列表替代与无障碍

### 5.1 角色列表不是关系列表

“角色列表”只按主角/配角显示卡片。点击林默打开“编辑角色”，字段是：名称、性别、年龄、身份、性格、人物小传和删除最新记忆。

角色编辑弹窗没有：

- 该角色关系清单。
- 新增/编辑/删除关系。
- 入边与出边筛选。
- 跳到关系图并聚焦该角色。

因此关系表单虽然是普通可访问控件，但其入口只能先在 Canvas 中命中一个节点。没有鼠标、触控板或精确点按能力时，无法从角色列表完成同一任务。

### 5.2 查找和大图操作

五个角色时页面已没有角色搜索、关系筛选或节点聚焦。关系图工具栏还缺少：

- 搜索角色并居中。
- 适应全部节点。
- 放大/缩小按钮和比例显示。
- 自动排布和布局算法选择。
- 保存/重置布局。
- 按角色层级、关系类型或线路过滤。
- 重叠节点/标签检测。

本轮没有为制造规模而批量创建大量无意义角色；现有五节点结构已经足以确认这些入口缺失。不能据此推断具体性能上限，只能确认规模化操作设计尚未提供。

## 六、有关联角色的删除提示

在王建国已拥有两条关系时，点击角色卡右上角 `×`，页面显示：

> 确定要删除角色“王建国”吗？删除角色是不可逆操作；与该角色相关的所有关系将被删除，已生成章节可能不一致，剧情线索可能断裂，大纲设定将失效。

确认框的问题：

- 没有列出关系数量和名称。
- 没有列出引用它的章节、线路、事件、大纲 section 或伏笔。
- 没有区分会级联删除、保留为历史、变成失效引用或只产生警告。
- 没有归档、合并到另一角色、替换引用或导出备份选项。
- 只给“取消/确定”，并明确不可逆。

本轮点击“取消”，王建国及两条关系都保留。因此只能记录页面声称会删除关系，不能把“实际数据库一定正确级联、不会留下孤儿引用”写成已验证事实。

真正点击确定属于删除云端角色及关系的破坏性操作，必须在操作当时获得明确确认；当前没有执行。

## 七、结论

| 问题 | 实测结论 |
| --- | --- |
| A→B 后再建 B→A | 保存为两条独立单向关系 |
| 未勾选“单向关系” | 保存为无箭头的无向连线 |
| 无向关系的弹窗摘要 | 仍使用 `A → B`，与画布语义不一致 |
| 第一条是否覆盖/去重 | 否 |
| 反向双边刷新后是否保留 | 是 |
| 平行边是否易读 | 否；边和旋转标签容易重叠 |
| 节点拖动是否保存 | 否；刷新后重新自动布局 |
| 关系语义是否随布局重置 | 否；语义保留 |
| 角色列表能否编辑关系 | 不能 |
| Canvas 是否有节点级无障碍语义 | 没有 |
| 搜索/聚焦/适应画布/保存布局 | 无入口 |
| 删除是否展示精确影响清单 | 否；只有笼统不可逆警告 |
| 真实删除级联是否验证 | 未执行，不能下结论 |

## 八、对本项目的强制约束

1. 有向关系用稳定 source/target；A→B 与 B→A 可以并存。完全相同 source、target、类型和活跃 revision 的重复项应提示合并，不静默新建。
2. 无向关系用规范化端点唯一键；A—B 与 B—A 不得重复。
3. 同一角色对的多条边在画布上分配不同曲率/lane，并提供角色对关系抽屉；标签避让、截断和完整内容提示必须可用。
4. 关系编辑器显式提供“有向/无向”“反转方向”“拆分双向”“合并为无向”，变更前预览箭头。
5. 角色列表展开后直接显示全部入边/出边，并能新增、编辑、归档、反转和合并；Canvas 不是唯一入口。
6. Canvas 节点和边有可访问镜像树，支持 Tab、方向键、Enter 和屏幕阅读器；关系表格覆盖全部语义操作。
7. 提供角色搜索、节点聚焦、适应画布、缩放比例、过滤、自动排布、重叠检测和键盘操作。
8. 语义关系、个人布局和临时视图分层；拖动显示 dirty 状态，只有“保存布局”才持久化，刷新前可恢复或丢弃。
9. 关系网子视图进入 URL 或可恢复导航状态；刷新后不应无提示跳回角色列表。
10. 删除角色默认软归档。影响预览必须列出关系、章节引用、线路事件、大纲、伏笔和记忆的精确数量与链接。
11. 已被正文或故事账本引用的角色禁止直接硬删除；提供合并、替换引用、inactive 和归档。
12. 归档角色时关系进入明确的 inactive/source_archived 状态，历史 revision 仍可审计；不能把关系硬删后让旧正文失去解释。
13. 情报提取匹配已有关系时必须同时比较规范化端点和 `directionality`；不能把已有 A—B 再建议为 A→B，也不能只因名称相同就覆盖方向。

## 九、现场保留

为继续创作，当前保留三条剧情关系：

- 林默 → 王建国：`隐瞒调查`。
- 王建国 → 林默：`监视与试探`。
- 张子涵 — 林默：`共同记忆锚点`。

王建国删除操作已取消。没有删除角色、关系或任何其他云端数据。

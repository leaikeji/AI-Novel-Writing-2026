# 真实章节生成、保存、情报与伏笔闭环

实测日期：2026-08-22  
研究作品：《封存区没有明天》  
正式结果：第 4 章《复写纸底层》，编辑器显示 1853 字，已保存到“第一卷 未来回声”。

本文只记录小说创作本身。页面中的商业规则、会员、运营和资讯均不在范围内。

## 一、这次采用的真实剧情任务

第 3 章《纸上坐标》结尾已经给出明日照片：林默、张子涵、王建国身后站着一个穿林默值班外套的第四人。第 4 章必须继续这个承诺，而不是另起一段功能占位内容。

本章剧情目标为：

- 林默与张子涵带照片去找纸质目录保管员郭晓霞。
- 郭晓霞说明电子记录会随现实改写，复写纸底层可能保留上一版世界的压痕。
- B2-17 目录出现互相覆盖的“林启年”和未知“林”姓记录。
- 第四人的外套留下二十七年前的旧式工牌夹证据。
- 章末张子涵收到“从未出生”的注销单，生效时间为明天 4:12。

这组目标同时检验连续性、角色约束、世界规则、私有文风、伏笔推进和章末新异常，所有内容都可以直接用于后续创作。

## 二、创建新章节六步流程

### 2.1 线路

选择“主线剧情推进”。当时主线、支线、感情线和势力线的全局账本均没有正式线路数据；向导仍允许继续，不强迫先创建线路实体。

### 2.2 角色

选中：林默、张子涵、郭晓霞。

关闭：

- 允许 AI 新增角色。
- 允许 AI 安排角色退场。

完成页明确显示“实际选择 3 人 / 不允许 AI 新增角色 / 不允许 AI 退场角色”。后续正文候选仍让既有角色王建国在开头短暂出场。结合上下文可知，这两个开关只限制“创造全新角色”和“安排退场”，并不把已选角色解释为正文出场白名单。产品若需要严格白名单，必须另设 `required / allowed / context-only / forbidden`，不能用“已选角色”让作者自行猜测。

### 2.3 伏笔

向导提供两个入口：

- “让 AI 自动选择伏笔”。
- “+ 添加伏笔”。

本次关闭 AI 自动选择，手工新建并勾选：

| 字段 | 内容 |
| --- | --- |
| 名称 | 照片中的第四个人 |
| 内容 | 明日归档的黑白照片里，林默、张子涵和王建国身后站着一个穿林默值班外套的人。其脸被闪光照白，无法确认是未来林默、被替换的版本，还是本应消失的林启年。 |
| 状态 | 进行中 |

卡片右上角圆形选择器被勾选后，外框和勾选标记变为橙色；只点击标题文字不会产生足够明确的选中反馈。

### 2.4 期望剧情

输入了 223 字的完整剧情走向，包含人物目标、调查方法、两层目录信息、章末注销单和精确生效时间。字段可选、上限 5000 字，实时显示字数。

### 2.5 章节大纲

目标字数由默认 2500 改为 2200，可填范围为 2000—5000。

AI 首次输出：

- 标题：`第四章 底层的压痕`。
- 大纲：完整覆盖郭晓霞、复写目录、B2-17 两层记录、未知“林”和张子涵注销单。
- 配置摘要：3 名角色、禁止新增/退场、手工选择 1 个伏笔。

生成结果页允许直接编辑标题和大纲，也提供“返回修改 / 下一步 / 重新生成”。本次把标题改为 `复写纸底层`，并收紧大纲：照片只是归档索引，原件是 B2-17 原始归档袋；不让郭晓霞提前猜出第四人身份。

### 2.6 确认并创建

最后一步再次展示标题、目标字数、角色数、伏笔数和完整章纲。点击“确认创建章节”后得到稳定章节地址和 0 字章节壳，章节 ID 为 573768。

创建完成时章节没有自动进入任何分卷，列表把它显示在分卷之外并提供“+ 添加到分卷”。即使后来已经手工加入第一卷，正文保存时仍会再次要求选择分卷。

## 三、私有文风正文候选

正文生成器会先打开“选择私有库配置”。切到“写作风格”后，能看到并勾选私有资产“冷峻声景悬疑”；选中卡片出现橙色边框和勾选标记。

AI 候选显示 1969 字。优点：

- 能从第 3 章的照片直接续写，没有另开场景。
- 使用扫描仪、打印机、纸张摩擦和脚步回声承担线索，私有文风有可见影响。
- 郭晓霞、复写纸、B2-17、未知“林”和注销单都被覆盖。
- 章末确实给出下一章可验证的新异常。

需要人工修订的问题：

1. 正文开头多出一个无意义的 `=`。
2. 写“明天四点十二分”，却让林默说“还有四个小时”；当前时间是 4:23，正确时限应接近二十四小时。
3. “照片今晚才拍出来”“闪光灯刚灭”等表述与第 3 章的“照片不知何时出现”不完全一致。
4. 复写纸示范和“改过两次”的因果解释不够清楚。
5. 语言能模仿短句和设备声，但部分段落仍是通用悬疑口吻，私有风格不是严格约束器。

本次没有把候选原样保存。正式稿改为“广播里的低语戛然而止”承接上章，重写复写纸规则，补上旧式工牌夹，并把时限修正为“不到二十四小时”。

## 四、候选、工作稿与正式正文不是同一状态

AI 候选在原标签显示 1969 字，同时出现“章节情报已更新”。但从另一个新页面打开同一章节时，仍显示 0 字和“暂无章节内容”。因此：

```text
正文流式生成完成
  != 新标签可见的章节正文
  != 已保存到分卷
  != 正式章节情报已采用
```

候选可以停留在生成标签中，未完成保存流程前不会成为云端正式正文。这是正确的安全边界，但页面没有把“候选未采用”讲清楚，容易让作者把可见字数误认为已经落库。

正式保存后再打开“历史”，页面显示“生成历史（共 2 次）”：

- 第 1 次是原始 AI 候选，历史显示 2011 字、伏笔 1；生成页当时显示 1969 字。
- 第 2 次是人工修订后的正式稿，历史显示 1880 字、伏笔 4；编辑器显示 1853 字。
- 两项都提供“恢复此版本”。本轮没有执行恢复，以免覆盖当前正式正文和再次触发故事账本副作用。

这说明人工修订保存也进入同一个历史序列，但仍被统一叫作“生成历史”，没有标明 `AI 生成 / 人工修订 / 正式保存` 来源。历史中的“伏笔 4”反映章内情报候选，不等于四条伏笔已经写入全局；本轮取消采用后，全局仍只有手工伏笔 1 条。两个历史字数又分别与编辑器可见字数不一致，进一步证明页面同时存在多套计数口径。

## 五、正文保存的实际三段式提交

正式保存不是一次点击：

1. 点击页面顶部“保存”。
2. 在“选择分卷”弹窗中选择“第一卷 未来回声”或“不选分卷”。
3. 再确认“保存后将同步最新进展”的不可撤销提示。

只做第 1 步，或做到第 2 步但没有完成第 3 步，新页面仍是 0 字。完成三步后，再从全新页面打开章节，才稳定显示：

- 开头：`广播里的低语戛然而止，复制室只剩扫描仪风扇的低响。`
- 结尾：`上一次，被注销的人叫林启年。`
- 章节字数：1853 字。

保存把“正文提交、分卷选择、角色记忆与最新进展同步”绑在同一流程里。作者已经把章节放入第一卷后仍需再次选择分卷，且普通正文保存带有跨模块不可撤销副作用。这会放大误操作和失败恢复成本；本项目必须把 working copy、分卷移动、revision 发布和情报采用拆成独立命令。

## 六、修改稿与章节情报的边界

人工修订并保存后，“情报”弹窗最初为空。点击“同步进展”后，系统才针对 1853 字正式稿重新提取。

提取结果包括：

| 类别 | 数量 | 关键结果 |
| --- | ---: | --- |
| 角色状态 | 4 | 林默、张子涵、王建国、郭晓霞 |
| 关系变化 | 4 | 全部被建议为单向关系 |
| 下一章必现角色 | 2 | 张子涵、郭晓霞，反而没有林默 |
| 推进中伏笔 | 1 | 照片中的第四个人 |
| 新增伏笔 | 4 | 注销单、原始归档袋、林启年双重身份、旧式工牌夹 |
| 新增剧情线 | 4 | 同盟、调查、线索交换、长期对立 |

最严重的分类结果是：四条新增剧情线全部被标成“感情线”，包括“林默与郭晓霞的调查线”“张子涵与郭晓霞的线索交换线”和“王建国与郭晓霞的对立线”。此外，已有无向关系“共同记忆锚点”被再次建议成 `林默 → 张子涵（单向）`。

结果弹窗只有整包“保存 / 取消”，没有逐项勾选、编辑名称、改类型、匹配既有实体或合并重复项。为避免污染正式账本，本次选择“取消”。

取消后的状态非常关键：

- 本章“情报”仍能重新打开并看到完整提取结果，说明章节级候选已保存。
- 全局主线、支线、感情线和势力线没有新增上述四条线路。
- 角色关系画布仍只有两条有向关系和一条无向关系。
- 手工创建的伏笔仍在，不受取消影响。

由此可确认“生成章节情报”和“把整包结果写入全局账本”是两层状态。取消是拒绝全局采用，不是删除提取候选；页面应明确使用“候选已生成 / 未采用”，而不是笼统显示“已更新”。

## 七、伏笔管理的人工闭环

全局“设定 → 伏笔管理”显示 1 条进行中伏笔“照片中的第四个人”。新建时虽然填写过“伏笔进展”，之后第一次进入编辑弹窗却显示进展为 0/200，说明创建入口没有可靠持久化该字段，或向导没有把它传到全局实体。

随后从全局伏笔编辑器补写：

> 第四章确认照片只是归档索引；第四人袖口使用二十七年前的旧式工牌夹，B2-17复写目录仅留下“林”字和“值班服，临时借用”的底层压痕。下一步需取回原始归档袋。

保存后出现“保存成功”，卡片直接显示“最新进展”，刷新前后的内容一致。说明全局编辑入口能持久保存进展，但创建向导和全局编辑入口的数据协议不完全一致。

伏笔进展当前仍是一个可覆盖文本框，而不是带章节来源的追加时间线。它能满足最小人工维护，却无法回答“哪一章埋设、哪一章推进、曾经写过什么、正文恢复后哪条进展应失效”。

## 八、真实审稿入口的能力边界

第 1 章《未来维修回执》运行审稿后得到：

- AI 特征 29%，人工特征 71%。
- 总分 92，结论“优秀”。
- 能识别声音细节、悬念层次、节奏和对话等实际优点。
- 建议为湿鞋、真实身份和回执文案增加解释，但没有引用当前完整世界规则。

第 4 章正式稿再次运行审稿：

- AI 特征 23%，人工特征 77%，总分 82。
- 准确识别了广播低语、扫描仪风扇、照片凉意、复写纸压痕、信息钩子和简短对话，说明它能读到“冷峻声景悬疑”的可见特征。
- 唯一具体修改建议是在张子涵攥住林默手腕后补充更直接的心理/触觉反应。
- 仍把第 4 章称作“开篇”，又把旧式值班外套理解成“未来的外套”，没有结合章节序号和已经明确的旧工牌证据。

两次审稿结果都只有“我知道了”，没有把问题绑定到可点击正文范围，也没有生成可选修改、Diff、采用或撤销。它适合作为阅读意见，不是可执行修订器；分数与 AI/人工比例也不应进入正文权威状态。

## 九、对本项目的直接结论

1. 章节向导保留“线路 → 角色 → 伏笔 → 期望 → 章纲 → 确认”的渐进结构，但创建时直接接收目标分卷，避免先产生游离章节。
2. 角色选择必须显式区分必出、可出、仅供上下文和禁止出场；“禁止新增角色”只约束新实体。
3. AI 正文永远是候选，页面同时显示“候选已完成 / 工作稿未采用 / 正式 revision 未建立”。
4. 保存 working copy 不弹分卷选择，也不写角色记忆、线路或伏笔；这些动作分别提交并可独立重试。
5. 情报提取按项复核，每项都能编辑、重分类、匹配已有实体、拒绝和查看来源正文。
6. `relationship` 与 `romance` 是两个类型；调查、同盟、线索交换和对立不能全部落入感情线。
7. 取消提取后保留候选审计，但正式故事账本逐项不变；界面明确显示“未采用”。
8. 伏笔进展使用带章节 revision 来源的追加记录，不用可覆盖单字段。
9. 审稿建议绑定正文范围并生成可选 Diff，不用单一分数替代作者判断。
10. 编辑器、章节树和作品卡使用同一字数口径；当前作品卡显示 4791 字，而各章记录无法简单复算出同一数字，应作为统一计数验收用例。
11. 人工修订、AI 候选和历史恢复可以进入同一 revision 时间线，但每项必须准确标注来源；历史上的情报数量明确区分“章内候选”和“全局已采用”。

## 一、测试问题与隔离方式

本轮只回答四个写作产品问题：

1. 选择私有库风格后，正文是否出现可测量的变化，而不只是在界面上显示“已选择”。
2. 生成历史能否说明当时使用了哪个资产、哪个版本和哪份内容。
3. 编辑资产后，旧候选能否继续复现原始输入。
4. “AI 智选”比较的是作者约束是否落实，还是只比较通用文稿质量。

新账号原本没有作品，因此新建独立测试小说，避免把生成、保存或情报写回混入《零点折城》。整个测试期间没有进入或记录商业额度、会员、字包、价格等页面。

## 二、固定生成输入（历史受控探针）

### 2.1 作品设定

- 书名：黑盐回声实验。
- 笔名：R3测试员。
- 主角：林默。
- 核心机制：未来录音会提前播出次日危险，但每次播放都会改变一处现实细节。
- 故事背景：临江市档案馆地下封存区只在夜间开放；林默发现一盒标注未来日期的录音带。
- 主要情节：林默验证录音、追踪来源、进入地下封存区，并发现录音是未来的自己留下的警告。
- 亮点：用同一段未来录音和不断变化的现实做可验证的悬疑实验，依靠声音、设备和纸张证据推进真相。

首次大纲生成产生主角林默、张子涵，以及配角王建国、陈晓峰、郭晓霞。本轮正文配置只显式选择林默，关闭“允许 AI 新增角色”和“允许 AI 退场角色”，只选择主线，不选择伏笔。

### 2.2 固定章纲

两次正文生成使用同一份 196 字章纲，不在 A/B 之间修改：

> 回声 林默在档案馆地下复制室值夜班，整理陈年档案时发现一盒标为“2041年维修回执”的磁带，封条完整。插入播放器后，录音传出次日自己的声音，求救声嘶力竭，内容提及“别碰封存区”。林默恐慌中反复核对录音，辨识出背景中打印机节奏与地下二层风机频率，确认声源来自封存区。他持手电沿声纹走向探索，在档案架角落发现一台老旧打印机，自动吐出纸页，仅印有一组坐标。林默攥紧纸张，望向封存区铁门，神色凝重。

目标字数固定为 2000。除私有写作风格选择外，其余可见输入保持一致。

## 三、A/B 测试

### 3.1 测试资产 V1

新建私有写作风格：`R3黑盐钟声短句测试`。

V1 内容：

> 每段只写一到三句，句子尽量短；全章必须自然出现恰好三次独特短语“黑盐钟声”；禁止使用成语和排比；每次场景切换都用单独一行“钟停了。”

A 选择“跳过”，即不使用任何私有资产；B 只选择上述 V1 风格。

### 3.2 可见结果

| 指标 | A：跳过私有资产 | B：只选 V1 风格 |
| --- | ---: | ---: |
| 生成历史字数 | 1899 | 1408 |
| 编辑器可见字符计数 | 1882 | 1392 |
| 浏览器提取正文长度 | 1914 | 1502 |
| 非空段落/行 | 33 | 55 |
| 平均每行字符 | 57.0 | 25.3 |
| 中位每行字符 | 55 | 22 |
| 最长一行字符 | 162 | 79 |
| 不超过 30 字的行 | 10 | 41 |
| “黑盐钟声”出现次数 | 0 | 3 |
| “钟停了。”出现次数 | 0 | 2 |
| “2041年维修回执”出现次数 | 1 | 1 |

结果不是轻微随机波动：B 的平均行长下降约 56%，短行比例从 10/33 提升到 41/55，并严格出现三次指定短语。因此可以确认，这项私有资产进入了模型输入或生成约束。这个结论只涉及“是否注入”，不评价文本是否自然、好看或适合长篇。

“钟停了。”只出现两次，不能据此认定违反规则，因为 V1 没有规定场景切换必须发生几次。页面也没有把场景切换识别结果和约束命中证据展示出来。

### 3.3 角色选择不是严格白名单

尽管两次都只选择林默、关闭 AI 新增角色：

- A 仍提到已有角色王建国和陈晓峰。
- B 仍提到已有角色王建国。

这说明“选择角色”至少在当前生成中不是 hard allowlist，更像重点角色或上下文偏好。界面没有说明约束强度，容易让作者误以为未选择角色不会出现。

## 四、资产版本与输入快照

### 4.1 生成前选择器

私有库选择器分为桥段、写作风格、特色词汇、热梗奇思四类，可查看名称和当前内容，并可“跳过”或确认。但生成前和生成后都没有看到：

- 稳定资产 ID。
- 资产版本号或内容哈希。
- 本次生成的选择摘要。
- 约束是必需、偏好、仅上下文还是禁止。
- “使用生成当时版本”与“使用资产最新版”的区别。

### 4.2 生成历史无法审计输入

历史卡片只显示生成次序、时间、状态、字数、正文摘录和“恢复此版本”。对两条历史的 DOM 精确检查均没有找到资产名称、V1 内容、V2 内容或“私有库”来源标签。

随后将同名资产编辑为 V2：

> 改为使用长段落，每段至少四句；全章必须自然出现恰好四次独特短语“铜雪倒影”；禁止出现“黑盐钟声”和“钟停了。”

重新打开私有库选择器时，页面立即显示 V2；B 候选正文仍明显保留 V1 的三次“黑盐钟声”和短段结构。页面没有入口查看生成 B 时实际使用的 V1，也没有“按原始输入重试”。

因此可确认的是：**当前可见产品层无法审计或复用旧生成的资产输入。** 本轮没有权限证明服务端完全没有保存快照，所以不把“后端一定没存”写成事实。

### 4.3 候选历史与当前正文是两套状态

在新标签打开同一章节后：

- 当前正文为空，计数为 0。
- 两次生成历史仍存在。

可得出：生成历史已服务端持久化；生成后的当前候选主要是当前标签/会话状态。只有执行恢复、采用或正式保存，候选才可能进入当前工作稿。页面需要明确区分“候选已生成”“候选历史已记录”“工作稿已采用”和“正式正文已保存”。

## 五、AI 智选实测

### 5.1 流程

当历史存在两个候选时，页面出现“AI 智选”。本轮将：

- 版本 A 选择为第二次生成，即私有风格 B。
- 版本 B 选择为第一次生成，即无私有资产 A。

发起分析后页面给出比较报告，但不会直接采用。作者必须再明确选择某个版本，之后“采用智选版本”才可用，因此比较动作本身是非写入操作。

### 5.2 结果

页面推荐无私有资产的基线版本，并显示“版本B胜出”。可见综合分约为：

- 私有风格候选：82。
- 无资产基线：86。

比较维度为流畅度、生动性、用词准确性、节奏感、情感表达、画面感。报告认为基线版本细节更丰富、节奏和沉浸感更好，同时承认私有风格候选更简洁、有氛围，并把“钟停了。”和带“黑盐钟声”的句子列为亮点。

### 5.3 可审计性断点与结论边界

报告没有显示或引用 V1 资产内容，没有核验：

- “黑盐钟声”是否恰好三次。
- 场景切换是否使用独立一行“钟停了。”。
- 是否使用短句、短段。
- 禁用成语和排比是否落实。

因此页面可见报告只展示了通用写作质量，没有展示“本次资产约束是否落实”的独立核验层。由于本轮作者约束本身是人为探针，不能进一步把“推荐基线版本”解释为质量判断错误；能成立的产品结论只是：作者无法从报告确认系统是否读取、理解并按优先级评估了所选资产。

正确顺序应是：先验证 required/prohibited 约束，再评估本次生成目标匹配，最后比较通用文稿质量。违反 required 约束的候选不得只凭通用分数成为默认推荐。

## 六、结论

| 问题 | 实测结论 |
| --- | --- |
| 私有风格是否真正影响正文 | 是；行长、短行比例和独特短语均出现强差异 |
| 作者能否在历史中复核当时输入 | 不能；历史未展示资产、版本、内容或哈希 |
| 编辑资产后能否查看或按旧输入重试 | 当前可见界面不能 |
| 候选是否自动成为正式正文 | 否；新标签正文为空但历史仍在 |
| AI 智选是否理解私有约束 | 页面不可审计；本次只展示通用六维评分，真实创作效果待复核 |
| 智选是否会自动写入 | 不会；仍需作者明确选择和采用 |
| 角色选择是否 hard allowlist | 不是；未选的已有角色仍会出现 |

## 七、对本项目的强制约束

1. 创作资产每次编辑都建立不可变版本，资产根记录只指向 current_version_id。
2. 每个生成任务固化所用资产版本、名称、类型、内容、条目、顺序、内容哈希和约束策略；旧任务不随资产编辑而改变。
3. 生成历史必须提供“查看本次输入”，至少能看到章纲、角色/线路/伏笔选择、资产版本、模型配置指纹和输入哈希。
4. 重试必须明确分为“按原始输入重试”和“按当前最新资产重试”，后者先展示 Diff。
5. 资产约束分为 required、preferred、context_only、prohibited，不允许所有选择都降格为模糊提示。
6. 生成完成后产生约束核验报告：逐项显示通过、失败、无法自动判断和正文证据位置。
7. 角色、线路和伏笔选择也使用同一约束语义；hard allowlist 违反时在采用前拦截或要求作者确认。
8. 候选、候选历史、工作稿和正式 revision 使用不同状态和明确动词，不能用“已生成”暗示已保存。
9. AI 候选比较分别展示“硬约束合规”“本次目标匹配”“通用写作质量”，不能把它们揉成一个不可解释的总分。
10. 任一候选违反 required/prohibited 约束时，不得自动推荐为胜出；作者仍可人工采用，但必须看到违规项。
11. AI 比较只产生报告，不写入工作稿；最终采用始终需要作者显式动作并生成可恢复 revision。

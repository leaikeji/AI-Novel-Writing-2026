# 短篇创作、自定义模板与智能拆书实测

实测日期：2026-08-22  
测试短篇：拆解测试·末班广播  
测试原则：仅使用本轮自拟设定和站内生成正文，不上传或拆解他人受版权保护的小说正文。

## 一、短篇九步建书

### 1.1 九步结构

| 步骤 | 页面 | 主要字段或动作 |
| ---: | --- | --- |
| 1 | 选择小说受众 | 男频 / 女频 |
| 2 | 创作思路 | 最多 2000 字；AI 生成模板或手动填写 |
| 3 | 选择模板 | 系统模板 / 自定义模板，先选分类再选模板 |
| 4 | 设置目标字数 | 6000—100000，默认 20000；可 AI 生成背景或手填 |
| 5 | 故事背景设定 | 手填最多 500 字，或由 AI 生成 |
| 6 | 角色 | 主角/配角列表，支持新增；可 AI 生成或手填 |
| 7 | 故事主要情节 | 手填最多 2000 字，或由 AI 生成 |
| 8 | 作品命名 | 笔名最多 20，书名最多 50，支持 AI 生成标题 |
| 9 | 选择封面 | AI 智能生成 / 系统封面 / 上传图片 |

手动路径不是一条完全独立的精简向导，而是在每个 AI 步骤提供“我已有……，点击直接填写”的旁路。手动跳过思路自动生成时，空思路会触发浏览器提示“思路不得为空”。

### 1.2 本次测试数据

- 受众：男频。
- 思路：凌晨四点，失忆的地铁检修员必须在一站路内找回妹妹留下的最后一段广播。
- 系统模板：都市 / 都市异能。
- 目标字数：创建时 20000，创建后改为允许的最小值 6000。
- 背景：临江市最后一班地铁只在凌晨四点出现，车上保存着被城市删除的记忆。
- 主角：沈砚，男，28 岁，地铁检修员，冷静果断。
- 主情节：沈砚用个人记忆交换广播坐标，最终发现妹妹已成为维系列车返回现实的锚点。
- 笔名：迟灯。
- 书名：拆解测试·末班广播。
- 封面：系统封面。

系统封面并不是点击一次就完成作品创建：先“生成系统封面”，进入“封面生成完成”，再点击“完成创建”，成功页才出现“立即生成正文 / 返回作品列表”。

## 二、短篇独立编辑器

创建后点击“立即生成正文”进入独立短篇编辑器。它不是长篇章节工作台的简化视图，顶部和底部动作如下：

- 返回列表。
- 复制。
- 下载 TXT。
- 保存。
- 生成/重新生成正文。
- 查看信息。
- 历史。
- 有正文后新增审稿。

正文是 `contenteditable` 编辑区，可直接修改。复制动作实测出现“复制成功”。

### 2.1 作品信息抽屉

“查看信息”包含：

1. 基本信息：书名、笔名、分类、目标字数、修改封面、下载封面。
2. 大纲：创作思路、故事背景、故事主要情节，均可编辑后保存。
3. 角色：主角/配角 CRUD，以及和长篇一致的角色关系网。

目标字数可以在创建后改为 6000 并保存成功。

### 2.2 正文生成前的私有库注入

短篇和长篇使用同一个“选择私有库配置”窗口。类别为：

- 桥段配置：扮猪吃老虎、扮猪吃虎、金手指、退婚流、废柴逆袭等。
- 写作风格：朴实无华、华丽辞藻、幽默风趣、严肃深沉、热血沸腾等。
- 特色词汇：按搞笑、古风、都市、网络、玄幻等词组选择。
- 热梗奇思：按都市、网络、游戏、职场、校园等梗组选择。

窗口还提供“搜索公有库配置”和“快速添加公有库到配置”。本次只验证私有库选择和跳过，不进入发现中心。

### 2.3 生成过程与结果

生成状态显示：

- AI 正在创作短篇小说。
- 正在根据故事背景、主要情节和角色设定进行创作。
- 预计等待时间。
- 生成按钮禁用为“生成中”。
- 正文流式写入，实际字数同步增长。

最终正文：

- 编辑器显示 1810 字。
- 作品列表显示 1734 字。
- 原始正文 JavaScript 长度为 1810，其中换行符 76 个；移除换行后恰为 1734。
- 因此短篇同样存在“编辑器计入换行、作品列表排除换行”的双口径，而且方向与原长篇手写章节观察到的页面语义并不统一。

目标设为 6000，系统却在 1810 字时判定“故事创作完成”，只达到目标约三成。目标字数实际上更像弱提示，不是交付约束。

角色一致性也发生漂移：角色设定中沈砚为 28 岁，正文自述却写成 32 岁。

### 2.4 完成度判断

正文结束后系统自动弹出“故事创作完成”，给出一段完整性说明，判断故事有起承转合、情感闭环和自洽逻辑。它没有展示：

- 判断维度和阈值。
- 目标字数偏差。
- 角色年龄冲突。
- 引用哪些设定得出结论。

因此完成度判断只能作为建议，不能作为自动结束长文本生成的唯一条件。

### 2.5 历史与手动保存

生成历史卡包含：

- 第几次生成。
- 时间。
- 完成状态。
- 字数。
- 正文摘要。
- “恢复此版本”。

实测生成一次后历史为 1 次。随后在正文末尾加入测试标记并点击保存，再恢复原文并再次保存，历史仍为 1 次。由此确认：

- AI 生成自动进入生成历史。
- 手动保存不会创建可恢复历史版本。
- “每次生成都能恢复”不等于“每次编辑都能恢复”。

本项目不能采用这种版本缺口；手动保存、AI 采用、审稿修改都必须产生统一 revision 或至少可恢复检查点。

### 2.6 审稿

审稿声称从六个维度分析。实测报告结构包括：

- 内容特征分析：AI 特征 / 人工特征百分比。
- 编辑寄语、总分和等级。
- 优点亮点。
- 改进建议。
- 读者角度。
- 最终结语。

报告给本次正文 81 分，并提出增加具体记忆细节。最关键的可信度反例是：这篇正文完全由站内 AI 刚刚生成，报告却显示 17% AI 特征、83% 人工特征。

因此该百分比不能解释为可靠的 AI 文本检测。本项目应删除这类伪精确指标，只保留：

- 可定位到原句的风格和一致性建议。
- 可复核的确定性检查，如重复词、人物事实冲突、视角漂移。
- 明确标为模型意见的主观评价。

## 三、作者自定义模板

### 3.1 CRUD 实测

“我的模板”空状态提供“新建模板 / 创建模板”。创建页字段：

- 模板名称。
- 模板分类。
- 一个默认模板字段。
- 添加字段。
- 每个字段只有“字段名称、必填、删除”。
- 保存、返回。

没有字段类型、帮助文本、默认值、最大长度、枚举选项、拖动排序或稳定 key。返回存在未保存字段时没有离开提醒。

本次创建测试模板：

- 名称：拆解测试·都市限时悬疑。
- 分类：都市悬疑。
- 必填：核心谜题、限时目标。
- 可选：反转真相。

保存后列表只显示模板名称、分类、自定义模板标记、日期和删除；点击模板卡可再次编辑。删除有不可恢复确认，测试模板验证后已删除。

### 3.2 建书接入实测

短篇第 3 步切换到自定义模板后：

1. 必须先选择自定义分类。
2. 再选择该分类下的模板。
3. 确认后只显示“都市悬疑 · 自定义模板”。
4. 后续目标字数、背景、角色、主情节页面都没有出现“核心谜题、限时目标、反转真相”的值输入框。

也就是说，模板字段定义对作者不可见，无法验证它们是否进入模型上下文。这是一个严重的信息架构断点。

本项目必须把模板实现为：

```text
template_schema
  -> field definitions
novel_setup_draft
  -> template_values
  -> required validation
  -> visible generation context preview
  -> immutable snapshot on create
```

模板字段不允许只存在于后台 prompt 或成为无效果装饰。

## 四、智能拆书

### 4.1 入口结构

智能拆书首页有三块：

- 场景拆书。
- 全本拆书。
- 拆书历史。

场景拆书明确基于真实文本，支持粘贴或上传 TXT，最大 30000 字。19 个分析维度：

学开局、学高潮、学转折、学对话、学节奏、学冲突、学情绪、学悬念、学人设、学描写、学场景、学战斗、学感情戏、学幽默、学伏笔、学张弛、学氛围、学心理、学切入点。

连续点击多个维度后，只有最后一个按钮保持 active，说明每次只能选择一个维度，不是多选报告。

### 4.2 场景拆书完整实测

输入本轮生成的《反向广播》正文 2101 字，选择“学节奏”。分析完成后的结果只有四个信息块：

1. 分析类型：节奏分析。
2. 写作风格：紧凑悬疑，细节丰富。
3. 风格优势：环境细节、简洁对话、逐步释放信息、层层递进等。
4. 私有库配置建议：一段可复用的文风描述。

不足：

- 没有节拍时间线或段落曲线。
- 没有原文证据定位。
- 没有薄弱段、节奏断点和可操作修改示例。
- 没有区分“从文本可直接观察”与“模型推断”。
- 输出更像文风摘要，而不是深度节奏拆解。

### 4.3 保存到私有库

点击“保存到私有库”后，系统明确提示“写作风格已保存到私有库”。前往查看后，新条目位于写作风格首位：

- 名称：紧凑悬疑，细节丰富。
- 内容：拆书结果中的私有库配置建议。

这验证了“自有文本研究 → 写作资产 → 生成时复用”的闭环。当前没有看到来源文本、分析维度、创建任务或重复检测；从历史再次点击保存，可能生成重复资产。本项目必须保存 provenance 和内容哈希，并在重复保存时提示复用或创建新版本。

### 4.4 拆书历史

历史卡显示拆书类型、时间和查看按钮，但卡片不显示所选维度。查看后可重新打开完整结果，并再次“保存到私有库”。历史缺少：

- 原文名称或作者给出的资料名。
- 文本哈希和字数。
- 分析维度。
- 私有库资产是否已经创建。
- 删除、归档、重命名和对比。

### 4.5 全本拆书

全本拆书没有要求上传全书正文，而是输入：

- 小说名称。
- 作者。
- 平台：起点、纵横、番茄、飞卢、其他。

页面说明它基于 AI 知识库，且小众书可能不准确。这种流程无法证明分析对象、版本和文本来源，也天然容易对不存在或冷门作品生成看似完整的虚构报告。

本项目不实现“只报书名就凭模型记忆拆全书”。全本拆书只接受作者自有、已授权或公共领域文本，并展示导入范围、解析进度、缺章检测、版本和证据引用。

## 五、开发结论

1. 短篇值得保留为独立工作流，但不能把目标字数当装饰。
2. 短篇和长篇应共享角色、私有库、revision 和审稿基础设施，而不是各自实现一套不一致版本逻辑。
3. 自定义模板的字段必须真正收集值、参与校验并在模型上下文预览中可见。
4. 智能拆书只处理有权使用的真实文本，所有建议带原文证据和来源。
5. 拆书保存到私有库是有价值的闭环，但必须去重、版本化和可追溯。
6. 不实现任何计费、字包、会员或价格模块。

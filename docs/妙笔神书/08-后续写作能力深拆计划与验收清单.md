制定日期：2026-08-22；更新日期：2026-08-23  
适用范围：只研究能直接帮助个人完成小说创作的页面、状态和数据流。

## 一、永久范围边界

后续无需再确认，直接按以下边界执行：

- 不进入或研究任何商业规则、商业权益和运营增长页面。
- 不研究新闻、公告、发现内容流、个人中心、投稿、签约、收益或社交功能。
- 不上传、采集或拆解无权使用的他人小说全文。
- 研究对象首先必须是一部能够继续写下去的真实小说；书名、笔名、卷章、角色、关系和私有资产都使用故事内语义。
- 只有真实创作无法区分结构行为时才使用最小受控探针；批次编号、功能名、顺序标记和无意义唯一短语不得进入站内可见对象名或正式正文。
- 允许新增和修改本人自拟内容；作品、章节、角色、关系和私有资产的云端删除仍须在操作当时明确确认。
- 优先验证真实状态变化、跨模块同步、失败恢复和可撤销性，不只抄录页面文案。

> 2026-08-22 方法纠偏：R3—R5 的结构发现仍保留，但早期机械内容不再作为作者体验样本。新账号作品已自然化为《封存区没有明天》，详见 [13](./13-真实小说创作基线与生态有效性修正.md)。

## 三、下一轮值得继续深拆的内容

以下不是为了“把网站每个按钮都点一遍”，而是补齐会直接影响本项目数据安全和写作效率的证据。

### R1：版本恢复与派生情报回滚，最高优先级

要回答：恢复旧正文版本后，角色记忆、关系、线路事件和伏笔进展是否一起回退、失效，还是继续保留新正文提取结果。

测试步骤：

1. 在一次性测试章节生成版本 A，并保存本章情报快照。
2. 修改章纲或正文生成版本 B，让 B 引入一个只有它才有的新事实。
3. 分别记录正文历史、本章情报和全局角色/线路/伏笔状态。
4. 恢复 A，逐项检查新事实是否仍在全局数据中。
5. 再恢复到恢复前版本，确认恢复动作本身是否可逆。
6. 删除测试章节，检查所有来源 B 的派生项是否变为失效、孤儿或仍为正式数据。

记录要求：每个实体必须保存稳定名称、来源章节/版本、恢复前后状态和网站是否提示副作用。若恢复只是正文回退而不处理故事账本，要作为最高风险反例写入正式规格。

### R2：两标签页编辑冲突与离线恢复，最高优先级

要回答：同一章节在两个标签页修改时是否静默覆盖，以及断网、刷新、关闭后的本地草稿如何恢复。

测试步骤：

1. 两个标签打开同一一次性章节，分别记录初始正文哈希和保存状态。
2. 标签 A 保存修改，标签 B 再基于旧内容保存不同修改。
3. 检查是否出现版本冲突、覆盖提示或最后写入者静默获胜。
4. 在离线条件下编辑并刷新，检查浏览器是否保留未同步稿。
5. 恢复联网，确认是合并、选择版本还是直接覆盖。

停止条件：若测试可能破坏《零点折城》证据章节，改用新建测试作品，不在真实证据章节上冒险。

### R3：私有库资产是否真正影响生成，结构证据已完成

早期受控探针用同一固定章纲完成“跳过资产”与“选择强约束风格”的 A/B：

- 私有风格候选的平均行长从 57.0 降至 25.3，指定短语按要求出现，确认资产确实进入生成输入；这不等于风格自然或质量更高。
- 生成历史不展示资产名称、内容、版本或哈希；资产编辑为 V2 后，旧候选仍保留 V1 特征，但页面无法查看或按 V1 原始输入重试。
- 当时新标签正文为空、两条历史仍在，确认候选历史已持久化但候选尚未成为工作稿或正式正文。
- AI 智选只展示通用六维质量，没有显示资产约束核验；由于约束本身是机械探针，不能把它推荐基线版本直接判为质量错误。
- 站内资产已改成真实文风“冷峻声景悬疑”，须用后续真实章节重新判断风格遵循度和候选质量。

完整证据见 [10](./10-私有库资产A-B输入快照与AI智选实测.md)。项目规格已改为不可变资产版本、生成上下文快照、原始/最新输入双重试，以及硬约束优先的候选比较。

### R4：作者生产力工具，结构证据已完成

早期用两个分卷、三个章节和两段最小正文验证了以下结构事实：

- 没有本章/全书搜索替换、批量选择、拖拽重排、快捷键说明和导入入口。
- “复制”只复制正文；章节标题最多 20 字；编辑器内没有保存并新建下一章。
- 跨卷移动只能“移出 → 再添加”，不是原子命令；`↑/↓` 只是标签页内浏览顺序。
- 输入 12 秒后新标签仍为 0 字，没有可见自动保存状态。
- 两章编辑器显示 36/20 字，章节列表显示 38/21 字，作品显示 59 字。
- UTF-8 TXT 包含空章、目录和章名，固定按第 1→3 章输出，但完全丢失两个分卷名称；倒序浏览不改变导出顺序。
- 网站没有导入入口，所以没有臆造回导闭环。

完整证据见 [11](./11-作者生产力工具搜索排序统计与全书导出实测.md)。正式规格已增加搜索替换提案、原子批量移动、连续创作、统一计数和固定 revision 的导出 manifest。

真实第一卷已经完成两次复导：4 章文件为 15026 bytes，5 章文件为 20541 bytes；两次均为 UTF-8，目录和正式正文完整，且都完全丢失“第一卷 未来回声 / 第二卷 改写痕迹”。第五章导出确认读取人工正式稿而非 AI 原稿。结构结论已足够，不再为这一缺陷重复下载。

### R5：关系图的持久化与可访问性，非破坏性部分已完成

已完成节点、连线编辑、缩放、拖动、刷新、反向有向边、键盘入口和删除影响提示检查：

1. A→B 与 B→A 保存为两条独立边；当前已改成“隐瞒调查 / 监视与试探”的真实剧情关系。
2. 未勾选“单向关系”会生成无箭头连线；“共同记忆锚点”已按无向关系保存，但弹窗摘要仍错误使用 `A → B`。
3. 节点位置和缩放刷新后重置，语义关系保留。
4. 角色列表不能编辑关系，Canvas 外层虽可聚焦却没有节点级键盘语义。
5. 页面没有角色搜索、聚焦、适应画布、保存布局或多边避让。
6. 删除角色只给笼统级联警告；真实删除未执行，不能下数据库级联结论。

本项目的既定结论不变：关系语义与画布坐标分离；图之外必须有键盘可操作的列表视图。

完整证据见 [12](./12-关系图反向边无障碍与删除影响实测.md)。角色规模和关系密度只在真实剧情需要新增人物时自然增长，不为制造压力场景批量造人。

### R6：自有文本拆解的质量和去重，中优先级

只继续使用本人拥有权利的真实小说正文：

1. 用同一文本分别运行“开局、冲突、节奏、伏笔”四个单维任务。
2. 检查报告是否引用相同或不同原文位置，是否只是换标签复述同一段套话。
3. 从同一个结果连续两次保存到私有库，观察是否生成重复资产。
4. 从历史再次查看和保存，检查来源、维度和已保存状态是否存在。
5. 归档来源文本或资产后检查双方可追溯性。

不执行“只输入书名、作者和平台”的全本拆书，因为它无法证明文本来源与版本，不能为本项目提供可靠产品证据。

## 五、每轮记录模板

每个测试点都按同一结构记录：

1. 目标问题：本次要验证的单一事实。
2. 前置状态：作品、卷、章、正文版本和相关实体数量。
3. 精确操作：入口、按钮、字段、默认值、限制和确认提示。
4. 可见结果：页面状态、字数、时间、历史项和全局模块变化。
5. 跨模块检查：正文、大纲、角色、关系、线路、设定、伏笔是否同步。
6. 刷新检查：刷新、返回列表、重新进入后状态是否保留。
7. 恢复检查：撤销、历史恢复或删除能否回到前态。
8. 反例与风险：静默覆盖、错分、重复、孤儿数据和不可逆动作。
9. 项目结论：采用、调整或拒绝，并写进对应正式规格与验收用例。
10. 现场清理：明确列出保留和删除的测试数据。

## 六、文档更新协议

每完成一个测试批次，按以下顺序更新：

1. 先补本目录的实测证据，事实和项目建议分开写。
2. 再修改 `docs/开发文档` 中对应的数据模型、状态机、API、失败恢复和验收。
3. 搜索旧结论并标记“第一轮基线”或直接修正，避免同一事实存在两个当前答案。
4. 运行 Markdown 链接、标题、路由命名、领域名和排除范围的一致性检查。
5. 在总索引记录当前作品数量、测试遗留物和下一轮入口。

## 八、阶段退出标准

满足以下条件时，可以停止继续拆竞品并转入项目实现：

- 从灵感、建书、大纲、章纲、正文、版本到故事账本的权威状态和候选状态已经定义。
- 已明确手动保存、AI 采用、恢复和删除对派生情报的影响。
- 关系图语义、布局和无障碍替代视图已经有实现规格。
- 长短篇使用同一 revision、字符统计和创作资产协议。
- 自有文本拆解有来源、证据、去重和权利边界。
- 所有高风险竞品反例都已进入失败矩阵或验收用例。
- 正式开发文档中不存在任何需要实现的商业或运营模块。

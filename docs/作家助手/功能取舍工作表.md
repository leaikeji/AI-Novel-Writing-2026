# 功能取舍工作表

本表用于下一轮沟通范围。它不预设结论，也不代表当前已经立项。填写时以[功能主清单（复核版）](./功能主清单-复核版.md)为事实基线；旧的“功能全量盘点”仅用于查候选细节。

每行可填写：

- `保留 1:1`：本期尽量完整复刻；
- `保留简化`：保留目标，但减少规则/状态；
- `延后`：进入后续版本；
- `删除/不做`：明确排除；
- `待定`：还需要原型、成本或授权调查。

“复杂度”只表示相对产品/工程难度，不是工期估算。

## 新增功能池

这里专门记录原 App 没有，或原 App 做法不适合网站、需要重新设计的能力。新增项先写用户价值和边界，不在本轮预选技术实现。

2026-08-22 已根据[妙笔神书实测](../妙笔神书/README.md)补入创作中心与完整创作工作台候选，并在[建书规格](../开发文档/05-创作中心与建书向导产品规格.md)、[大纲生成规格](../开发文档/07-分阶段大纲生成与作品初始化产品规格.md)和[创作工作台规格](../开发文档/09-创作工作台内容模型与关系图产品规格.md)中给出功能内部优先级；这些项不是作家助手 5.19.0 的已确认能力，也尚未自动进入整个项目核心 MVP。

| 新增编号 | 想新增的功能 | 解决什么问题 | 首期必须？ | 与现有功能的关系/备注 |
|---|---|---|---|---|
| NEW-01 | 可恢复的分步建书向导 | 从点子逐步形成结构化作品，刷新或退出不丢进度 | 建议 P0 | 独立路由；最终一步才创建正式小说 |
| NEW-02 | 私有创作资产库 | 复用桥段、风格、词库和灵感，减少重复提示 | 建议 P0 | 与大纲/角色/设定互补，不等同于个人资料库 |
| NEW-03 | 私有库组合预设与作品快照 | 一键组合创作约束，同时保证旧作品可复现 | 建议 P0 | 作者级资产可变，作品级快照不可变 |
| NEW-04 | Schema 驱动的 AI 作品模板 | 把自由思路转成可编辑、可校验、可扩展的结构 | 建议 P0 | AI 失败时允许直接填写；不硬编码单一题材字段 |
| NEW-05 | 系统封面渲染 | 不依赖图片模型即可完成作品创建 | 建议 P0 | 使用自有授权模板；AI 封面延后 |
| NEW-06 | 可恢复且幂等的 AI 任务 | 刷新、断线或重复点击时不重复生成，失败后可继续 | 建议 P0 | 稳定 job_id、输入/结果哈希、流检查点和错误状态；不做计费或额度系统 |
| NEW-07 | 封面上传与 3:4 裁剪 | 允许作者使用自有视觉资产 | 建议 P1 | 服务端 MIME/解码校验与版权提示 |
| NEW-08 | AI 取名候选 | 降低书名和角色命名启动成本 | 建议 P1 | 返回候选，不自动覆盖用户输入 |
| NEW-09 | 可恢复的分阶段大纲生成 | 分别确定容量、背景、角色、情节和定位，降低一次性生成风险 | 建议 P0 | 正式采用前只写生成草稿；是否进入核心 MVP 待定 |
| NEW-10 | 结构化角色生成与层级 | 让主人公、主要角色和配角可编辑、可追踪 | 建议 P0 | 最终采用后进入角色资料；不静默覆盖已有角色 |
| NEW-11 | 大纲分区版本与局部重新生成 | 避免重新生成整套大纲时覆盖作者修改 | 建议 P1 | 绑定正式 revision，重新生成只产生候选 |
| NEW-12 | 从大纲生成线索/分卷/章纲候选 | 把宏观梗概逐层展开为可写计划 | 建议 P1/P2 | 各自独立确认，不按目标章节数预建空章节 |
| NEW-13 | 无副作用的章节壳与独立移动 | 先写再规划，保存正文时不被迫选卷或改其他模块 | 建议 P0 | 卷归属、标题、正文和章纲各有稳定 ID；移动是独立命令 |
| NEW-14 | 线路/角色/伏笔驱动的章纲向导 | 在写正文前明确本章要推进什么、谁出现、埋收什么 | 建议 P1 | 所有开关只生成候选；“允许新增/退场”默认关闭 |
| NEW-15 | 幂等章节情报复核 | 从新 revision 提取角色、关系、事件和伏笔，同时避免重复同步污染 | 建议 P1 | 逐项采用；同 revision + 提取器 fingerprint 只产生一套结果 |
| NEW-16 | 可编辑、重分类、合并的线路事件 | 修正模型误把同事/师徒归为感情线及漏主线的问题 | 建议 P1 | 人物关系线与恋爱线分开；事件绑定来源 revision |
| NEW-17 | 角色实体匹配与显式合并 | 防止重生成后旧人物被重新建成“未知”档案 | 建议 P1 | 稳定 ID、别名、候选匹配；不得仅按姓名覆盖或新增 |
| NEW-18 | 可访问且可保存视图的角色关系图 | 用缩放、拖动和边编辑理解人物网络，同时保留键盘操作 | 建议 P2 | 关系语义与坐标分离；布局须显式保存；列表是完整替代入口 |
| NEW-19 | 追加式伏笔进展与回收链 | 保留埋设、推进、解决历史，避免覆盖最新进展造成信息丢失 | 建议 P1 | 每条进展绑定章节 revision；解决后仍可追溯和重新打开 |
| NEW-20 | 模板、当前设定、大纲和正文一致性报告 | 发现角色名、时间、数量和规则在多份资料间漂移 | 建议 P2 | 只报告和生成修订候选，不自动重写已确认正文 |

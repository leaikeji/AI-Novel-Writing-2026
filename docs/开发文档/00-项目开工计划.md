## 0. Codex 多子代理并行施工授权

用户于 2026-08-25 明确授权：在已经批准进入施工的范围内，主 Codex 可以自行把工作拆分给多个子代理并行完成，也可以让子代理继续做有边界的下级委派；不需要为每一次创建、补充任务或滚动下一批代理重复请求用户确认。

**授权层不设上限**：用户不对项目累计使用的子代理数量、并行批次、任务总数或合理的嵌套委派设置人为上限。主 Codex 应在任务确实可以独立推进并独立验收时尽量并行，以缩短墙钟时间；不能为了展示代理数量而拆出没有独立产出的空任务。

“不设上限”是用户授权，不是对运行平台无限容量的技术承诺。任一时刻的实际并发仍必须服从 Codex 当前提供的并发槽位、模型/工具限流、本机 CPU/内存/磁盘、数据库连接、任务依赖和 Git 隔离能力。达到瞬时容量后采用滚动批次继续派发，不得绕过平台限制，也不得让多个代理无协调地修改同一文件、迁移序列、公共 API 契约或依赖锁。

主 Codex 始终是唯一集成责任人，必须：

1. 为每个子代理明确目标、文件/领域所有权、前置依赖、禁止范围和验收证据；
2. 优先并行研究、独立模块、测试、文档审计和互不重叠的前后端工作；共享 schema、迁移、接口冻结和最终集成按依赖顺序串行或单一所有者执行；
3. 汇总并复核所有子代理结果，解决冲突，运行全量相关测试和回归，不把“子代理已完成”直接等同于项目完成；
4. 由主 Codex 统一决定最终暂存、提交和推送内容，避免子代理把无关工作区改动带入提交；
5. 保留现有范围、阶段闸门、数据禁区、声音授权、隐私和破坏性操作约束。并行授权不会自动批准尚未立项的功能、外部写入、购买、删除或越权访问。

官方 OpenAI 文档说明，多代理可并行协调可独立拆分的复杂工作并减少墙钟时间；本项目采用该能力，但以可验证交付和集成正确性优先于并发数量。[官方模型指导](https://developers.openai.com/api/docs/guides/latest-model)

所有阶段、扩展包和专项计划的可并行工作、前置依赖、资源锁、文件所有权、串行门禁与验收产物，统一以[Codex 多子代理并行施工矩阵](./21-Codex多子代理并行施工矩阵.md)为直接派发索引。正式施工必须引用其中稳定工作包 ID，不能只写“前端/后端/测试并行”。

## 1. 产品目标

AI小说世界2026 首期是一个面向单人作者、桌面 Web 优先、私密长篇创作为主的 AI 写作工作台。

当前最小 MVP（MVP-0）闭环：

1. 创建一本小说，维护最基本的卷章和写作资料。
2. 打开、编辑并可靠自动保存章节，刷新和故障后内容仍存在。
3. 使用 QwenPaw 原生 AI 助手讨论小说，不自建第二套聊天界面。
4. 小说 Skills 指引 AI 按需调用只读工具，读取当前小说、文档和可用上下文。
5. AI 生成的规划、正文或修改建议先留在原生对话中，由作者手动编辑或复制采用。
6. 模型、工具或网络失败时，不改变数据库正文，未同步本地草稿仍可恢复。

**当前范围决策**：MVP-0 不做计划确认、候选正文、Diff、接受/拒绝、AI 直接写正文、事实自动回写、向量化和 TTS。后四项原有设计保留为测试后的候选增强，不是当前实施命令。文档其他章节若仍描述这些机制，均按“后续候选架构”理解，以本节和[UI 基线](./12-QwenPaw原生UI盘点与小说工作台UI基线.md)为当前优先级最高的范围说明。

## 3. MVP 范围

### 3.1 核心 MVP 必须完成

- 私密小说作品库：基本列表、创建、打开、重命名、归档或软删除。
- 写作工作台：小说/卷/章树、Markdown 正文编辑、预览、数据库自动草稿、字数和基础历史版本。
- 创作资料：总纲、章纲、角色、设定和灵感。
- QwenPaw 原生 AI 助手：沿用原生模型选择、Agent/workspace、消息流、工具安全模式和输入区。
- 小说 Skills 与只读工具：先提供讨论、总纲、章纲、正文草拟、连贯性检查和文风审查指引，以及读取当前小说、文档和基础搜索的能力。
- 最小失败恢复：聊天模型或只读工具失败不影响正文；自动保存失败时保留 IndexedDB 未同步稿。

### 3.2 已有规格、但明确不阻塞 MVP-0

- 高级建书向导：长篇、受众、创作思路、结构化模板、命名、系统封面和最终确认。
- 私有创作资产库：桥段、写作风格、特色词汇、热梗奇思的新增、编辑、归档和预设组合。
- 分阶段大纲生成：目标容量、背景、角色、主情节、作品定位、任务恢复和最终采用。
- 完整创作工作台扩展：章纲向导、大纲安全重生成、章节情报复核、角色实体合并、关系图、可编辑线路事件和追加式伏笔进展。
- 短篇与文本拆解扩展：短篇九步草稿、整篇候选、统一版本、可解释审稿，以及只处理自有/获授权文本的证据化拆解。
- AI 写回扩展：计划确认、候选正文、Diff、接受/拒绝、基线冲突和事实回写。
- 模型派生扩展：向量分块与检索、TTS、媒体缓存和后续图片。

五项均保留完整产品规格，详见[创作中心与建书向导产品规格](./05-创作中心与建书向导产品规格.md)、[分阶段大纲生成与作品初始化产品规格](./07-分阶段大纲生成与作品初始化产品规格.md)、[创作工作台内容模型与关系图产品规格](./09-创作工作台内容模型与关系图产品规格.md)和[短篇创作与文本拆解产品规格](./10-短篇创作与文本拆解产品规格.md)。项目建议先完成基本小说创建和真实写作闭环，再决定这些扩展插入核心阶段还是后续独立交付。

## 5. 领域边界

### 5.1 权威数据

- novels：作品基本信息和当前状态。
- volumes、chapters：卷章结构。
- documents：章节、设定、人物资料和大纲等文档身份及当前正式 revision 指针。
- document_working_copies：PostgreSQL 中可变的当前编辑稿，使用 `draft_version` 和内容哈希做并发保护。
- document_revisions：不可变的正式版本与 AI 讨论前检查点；同时保存权威 `content_markdown` 和由固定解析器生成的不可变 `content_text` 纯文本快照，两者不得与 HTML 预览或向量分块混用。
- document_revision_proposals：AI 计划、候选全文、基线版本、确认和接受/拒绝状态。
- story_facts：已经确认的小说事实权威记录。
- story_fact_candidates：带来源、置信度、冲突和审核状态的持久候选；它是审核记录，不等于正式小说事实。
- embedding_profiles：向量接口、模型、实际维度、距离度量、fingerprint 和索引策略。
- background_jobs：共享持久任务底座；通过 scope_kind/scope_id 覆盖 revision 派生、音色预览、朗读 Edition、分块、向量、事实提取和媒体处理，保存幂等、租约、重试与死信状态。
- media_assets：持久媒体元数据、内容哈希、文件位置、来源 revision、模型和缓存状态；媒体二进制保存在挂载目录。
- novel_conversation_bindings：QwenPaw session 与 novel、document、可见 revision 和本地 owner 的服务端绑定；不能只信任模型传入的 novel_id。
- model_run_records：逐次模型调用的 requested/actual provider、model/revision、耗时、输入/结果哈希、供应商请求 ID 和失败审计；任务状态、租约与重试由 background_jobs 承担，不承载商业计费。
- creative_assets、creative_asset_presets：作者级可复用创作资产。
- novel_prompt_snapshots：作品实际采用的资产与模板快照。
- novel_setup_drafts：最终建书前的可过期向导草稿。
- outline_generation_drafts：正式采用前的分阶段大纲生成草稿；只在该扩展启用时创建。
- characters、character_aliases、character_relationships：角色实体、别名和版本化关系；只在完整角色扩展启用时创建。
- relationship_graph_views：可选个人布局；不承载关系语义。
- storylines、storyline_events：可编辑线路与带来源章节 revision 的事件。
- foreshadows、foreshadow_progress_entries：伏笔生命周期和追加式进展。
- intelligence_extraction_proposals/items：章节 revision 的角色、关系、线路、事件与伏笔复核候选。
- short_story_profiles、short_setup_drafts：短篇专有目标与向导状态；正文继续复用 documents/revisions。
- template_schemas、template_schema_fields：作者模板版本和字段定义；作品保存 schema + values 快照。
- source_texts、text_study_jobs/results/evidence_spans：自有、获授权或公共领域文本的可恢复证据化拆解；只在该扩展启用时创建。
- creative_asset_provenance：拆解结果沉淀为私有资产时的来源、维度、文本哈希和去重依据。

### 5.2 派生数据

- novel_chunks 及其向量。
- 摘要、事实候选、检索缓存。
- Markdown 预览 HTML。
- TTS、图片缩略图及其他可重新生成媒体。

派生数据失败不得回滚或覆盖已经确认的小说、章节和 revision。

## 6. 运行拓扑

MVP 采用以下最小拓扑：

1. QwenPaw：负责本机个人助手宿主、Agent 会话、聊天模型、Skills 和工具调度；QwenPaw 2.1.0 不被当作已核实的多用户身份提供方。
2. 小说 PawApp 前端：React 页面、Monaco 编辑器和最小建书流程；不重做聊天界面。
3. 小说 PawApp 后端：领域 API、自动保存、基础 revision 和只读 Agent 工具。
4. PostgreSQL + pgvector：权威业务数据和向量。
5. Ollama 或公开云服务：作为后续 EmbeddingAdapter 选项，不阻塞 MVP-0。
6. 本地挂载媒体目录：为后续封面、导出、TTS 和图片预留，不阻塞 MVP-0。

具体模型与适配器边界见[架构边界与模型接入决策](./01-架构边界与模型接入决策.md)。

### 6.1 Docker Compose 端口规则

**项目决策**：容器内部保留上游或基础设施的原始端口；发布到 Mac 主机的端口必须是五位数且首位为 `1`，并且只绑定 `127.0.0.1`。容器之间始终通过服务名和内部原始端口通信，不通过主机映射端口绕行。

| 服务 | 容器内部端口 | Mac 主机端口 | Compose 发布示例 | MVP 状态 |
| --- | ---: | ---: | --- | --- |
| QwenPaw | 8088 | 18088 | `127.0.0.1:18088:8088` | 默认 |
| PostgreSQL + pgvector | 5432 | 15432 | `127.0.0.1:15432:5432` | 默认；仅供本机维护工具使用 |
| Portkey Gateway | 8787 | 18787 | `127.0.0.1:18787:8787` | 可选 profile |
| TEI | 80 | 10080 | `127.0.0.1:10080:80` | 后续可选 profile |

对一至四位内部端口，默认主机端口规则为 `1 + 左侧补零到四位的内部端口`，例如 `80 → 10080`、`5432 → 15432`、`8088 → 18088`；最终仍需检查冲突并登记。macOS 原生 Ollama 默认监听 `127.0.0.1:11434`，不属于 Compose 端口映射；容器通过 `host.docker.internal:11434` 访问。若未来把 Ollama 放入 Compose，`11434` 已满足“五位且首位为 1”，可映射为 `127.0.0.1:11434:11434`。

QwenPaw 进程在容器内需要监听 `0.0.0.0:8088` 才能被 Docker 转发；这不等于向局域网开放，因为主机发布地址仍严格限定为 `127.0.0.1:18088`。

### 6.2 持久卷、迁移与降级启动

| 持久数据 | 容器路径或卷 | 规则 |
| --- | --- | --- |
| QwenPaw 工作数据 | `/app/working` | 独立命名卷；随 QwenPaw 升级保留 |
| QwenPaw 密钥 | `/app/working.secret` | 独立 secret 卷；不提交 Git、不进入普通备份日志 |
| QwenPaw 备份 | `/app/working.backups` | 独立备份卷 |
| PostgreSQL | `postgres-data` | 权威小说数据；迁移和备份恢复必须验证 |
| 小说媒体 | `novel-media` 挂载到插件配置目录 | 保存 TTS 和后续图片；数据库保存元数据与哈希 |

Alembic 使用显式一次性 `migrate` 命令或 Compose one-shot profile，不在 PawApp import/startup hook 中静默执行破坏性迁移。数据库不可用或迁移失败时，QwenPaw 原生控制台仍应启动，小说 PawApp 显示“数据库未就绪/迁移失败”的降级页；插件初始化异常不得拖垮上游进程。

小说 PawApp 通过 QwenPaw 官方插件安装接口以本地目录或 ZIP 形式安装并持久化，不把源码复制进 `src/qwenpaw`，也不 bind mount 覆盖核心目录。阶段二先验证官方安装、升级和卸载行为，再决定 Compose 是挂载只读插件发行物还是构建仅包含官方安装步骤的薄 overlay 镜像；无论哪种方式，QwenPaw 基础镜像始终固定 `v2.1.0` digest，并可独立替换验证。

### 6.3 首期小说 Skill 能力基线（可演进）

1. 小说方向讨论。
2. 故事圣经/总纲。
3. 章节大纲。
4. 正文写作。
5. 连贯性与小说账本检查。
6. 文风审查。

以上六项是首期最小能力分类，不是永久固定数量或不可修改模板。后续可以根据真实创作效果优化说明、提示模板、知识结构、输入输出契约和工具使用策略，也可以新增、拆分、合并或退役 Skill；不为追求数量恢复旧项目的 18 个 Skills。

一旦某个 Skill ID 已进入配置、测试或会话记录，重命名和删除需要版本记录、兼容别名或迁移，不能静默改变语义。插件源码中的 Skill 定义是产品默认真源，个人定制应作为明确的 override/派生版本保存，不把 workspace 中可能被 provider 重新同步的临时副本当作唯一源码。

Skills 由官方 Skill provider 安装，但不能默认污染所有普通 QwenPaw workspace。项目建议使用专用小说 Agent/workspace 并只在那里启用；阶段二验证公开接口、更新覆盖行为和实际选择方式。若无法可靠限定作用域，先 `enabled_by_default=False`，不通过未公开实现强行修改 workspace。

## 7. 实施阶段

项目按八个阶段推进；前一阶段未达到退出条件时，不用“先把功能堆出来”代替验证。每阶段的前置依赖、测试、失败恢复和 Codex 有效开发时间见[阶段实施矩阵](./08-阶段实施矩阵.md)，并行施工编号与汇合门禁见[并行施工矩阵](./21-Codex多子代理并行施工矩阵.md)第 4 节。

### 阶段 1：规划定稿与架构冻结（当前）

- 统一产品范围、架构图、核心流程、数据状态机和权限边界。
- 固定依赖与上游升级边界，记录事实、推断、建议和待验证项。
- 明确 QwenPaw 原生入口、设置、Provider、Skills、MCP、工具、聊天和任务页面全部保留，小说 PawApp 只做增量扩展。
- 明确 Docker 回环发布和五位端口规则。

退出条件：索引无断链、文档无已知相互矛盾项、所有真实待决事项有归属阶段，并由用户批准进入初始化。

### 阶段 2：项目初始化与 QwenPaw 兼容性尖峰

- 创建独立 Git 工程和 PawApp 最小前后端骨架。
- 验证官方 manifest、依赖安装、后端路由、工具和 Skill provider 注册。
- 验证宿主 React/ReactDOM/Ant Design 单实例、Monaco Worker、流式 tool-call 和独立小说会话 ID。
- 建立 QwenPaw 原生页面与设置非回归测试。

退出条件：小说入口可打开，最小前后端往返成功；移除插件即可恢复纯 QwenPaw；原生入口、设置与聊天不变。

### 阶段 3：数据库与小说领域核心

- 建立 PostgreSQL、pgvector、SQLAlchemy、Alembic 和领域服务。
- MVP-0 只实现 novels、documents、working copy 和基础不可变 revision；事实、向量、提案、派生任务与媒体表等到对应功能启动时再迁移。
- 完成自动保存需要的乐观锁、事务、幂等、迁移升级/回滚及测试替身。

退出条件：迁移可重复执行；并发写入不会静默覆盖；刷新和服务重启后正文仍存在。

### 阶段 4：基础小说工作台

- 实现最短路径的小说创建、章节树、Markdown 编辑、预览、数据库自动草稿、显式版本检查点和历史版本。
- IndexedDB 只保存尚未同步的崩溃恢复稿。
- 实现保存中、已保存、离线恢复、冲突和失败状态。

退出条件：创建并编辑章节后刷新仍存在；断网、关闭页面、接口失败及并发编辑均不丢正文。

### 阶段 5：QwenPaw 原生助手、小说 Skills 与只读工具

- 验证公开 PawApp 接口能否在工作台旁呈现原生聊天；若不能，使用 `/chat` 原生入口或公开导航切换，不复制私有组件。
- 安装并迭代首批小说 Skills；注册 `novel_get_context`、`novel_get_document` 和基础 `novel_search` 等只读工具。
- AI 可读取当前小说、当前章节、基础资料和允许范围内的前文。MVP-0 搜索可先采用数据库文本搜索；向量检索不阻塞闭环。
- 不注册正文写入、提案接受、事实回写或 TTS Agent 工具。

退出条件：原生助手可在不改变 QwenPaw 页面与设置的前提下工作；Skills 能引导 AI 调用只读小说工具；任意模型或工具失败都不改变正文。

### 阶段 6：测试 MVP-0 并裁决增强范围（暂缓）

- 用真实小说和章节测试“编辑器 + 原生助手 + Skills + 只读工具”的创作体验。
- 记录实际摩擦，再决定是否需要 AI 写回、确认、Diff、向量检索或 TTS。
- 未经用户基于测试结果明确批准，不实现这些增强能力。

退出条件：形成可复核的测试记录和下一阶段范围决定。若现有流程已够用，可以继续优化 Skills 而不增加写回界面。

### 阶段 7：经批准的模型派生与媒体能力（候选）

- AI 接受版本、用户正式检查点和确认导入版本成为当前 revision 后，按策略可靠地分块、向量化、提取事实候选并重试失败任务。
- 冲突事实由用户确认，拒绝的 AI 提案不影响事实账本。
- 实现当前段落/章节朗读、音频持久化和 revision/声音/模型/内容哈希缓存。

退出条件：任一当前有效 revision 能被检索命中；派生服务中断后可续跑；TTS 失败不丢正文或本地草稿。

### 阶段 8：增强闭环验收与本机发布（候选）

- 验收内容只覆盖阶段六测试后明确批准的增强项，不默认要求 Diff、接受/拒绝、向量或朗读。
- 完成备份恢复、日志脱敏、性能、可访问性、版本锁定和 QwenPaw 并行升级验证。
- 在核心闭环验收后裁决高级建书向导、私有创作资产、分阶段大纲、短篇、证据化文本拆解和导入导出等扩展的后续顺序；只有用户明确纳入的项目才另行估算和交付。

退出条件：Docker 只在 `127.0.0.1` 暴露规定端口；验收闭环稳定通过；有可执行的备份、恢复和升级说明。

## 8. 项目级验收门槛

- 基本创建可以生成一本小说并直接进入工作台；重复点击或网络重试不会生成重复小说。
- 作品默认私密，发布属于完全独立的后续流程。
- 正文保存有明确的保存中、已保存、离线草稿、冲突和失败状态。
- AI 返回内容只存在于 QwenPaw 原生对话，除非作者手动写入编辑器。
- MVP-0 只注册读取小说上下文、读取文档和基础搜索等只读 Agent 工具。
- 保存草稿、创建 revision 和任何事实更新均不注册为 LLM 可自由调用的工具。
- 模型任务的状态、耗时、失败和重试能够诊断；产品中不存在报价、扣费或用量账本。
- 任意模型、向量或媒体服务失败都不导致正式正文丢失。
- QwenPaw 原生入口、设置、Provider、Skills、MCP、工具、聊天、会话和任务能力保持原样；卸载小说 PawApp 不影响上游运行。
- 小说数据库或迁移失败时，QwenPaw 原生控制台仍可启动；插件只显示降级错误。
- 页面与 API 全部位于 `ai-novel-world-2026` app_id 命名空间，不注册 QwenPaw 全局 `/novels` 或 `/api/novels` 路由。
- 所有 Compose 主机发布端口均为五位、首位 `1`，且仅绑定 `127.0.0.1`。

如果高级建书向导与私有库被批准进入核心 MVP，还必须追加：向导刷新恢复且不提前创建空小说；最终创建幂等；资产变更或归档后，既有作品仍可复现采用时的模板快照。

如果分阶段大纲生成被批准进入核心 MVP，还必须追加：每一步可手填或 AI 生成；生成刷新可恢复且不重复执行；正式采用前不改变现有大纲和角色；目标章节数不预建空章节；最终采用幂等且只索引正式大纲 revision。

如果完整创作工作台扩展被批准进入核心 MVP，还必须追加：保存正文不触发分卷或情报副作用；同一章节 revision 重复同步幂等；未知角色不直接落正式库；线路可编辑与重分类；关系语义和画布布局分离；伏笔进展不可覆盖历史。扩展包和增量估算见[阶段实施矩阵](./08-阶段实施矩阵.md)。

如果短篇与文本拆解扩展被批准进入核心 MVP，还必须追加：短篇九步刷新恢复；模板字段真实实例化；目标范围不足不误报完成；角色事实冲突在采用前可见；手写与 AI 共用版本；拆解只处理有权文本且结论绑定证据；同一结果保存到私有库不产生静默重复。

## 9. 真正待决事项

- **阶段 4 前**：无。当前只做基本“创建小说”、手动资料和无副作用卷章编辑；现有高级规格均为后续候选。
- **阶段 5 技术尖峰中**：确认 QwenPaw 是否有公开的原生聊天嵌入/并排呈现能力；没有则使用原生 `/chat` 跳转，不改变上游。
- **阶段 6 测试后**：根据实际体验决定是否需要 AI 写回、确认、Diff、向量检索和 TTS；现在不预设答案。

## 本项目参考什么

首期重点参考这些产品模式：

- 作品库卡片、作品名称、字数和更新时间的层级。
- 卷/章树、章节字数、新建章节、筛选和全书搜索的位置关系。
- 中央大面积写作区、章节标题、正文、字数和保存状态。
- 编辑器工具栏、历史版本入口、查找替换和专注写作体验。
- AI 助手作为编辑器侧栏，支持上下文、历史、新对话和工具状态。
- 大纲、人物、设定、灵感等创作资料的组织方式。
- 作者级私有创作资产与作品级上下文快照的分层。
- 从创作思路到结构化模板、命名、封面和最终建书的渐进式向导。
- 背景、角色、主情节和作品定位逐步生成且允许手动降级的模式。
- 线路、角色、伏笔和剧情期望驱动的章纲规划，以及先提取后复核的章节情报模式。
- 可直接操纵的角色关系图和可追溯的线路/伏笔管理；实现时必须补足列表替代视图、幂等和版本来源。
- 灵感卡直达带来源建书草稿，而不是依赖剪贴板。
- 短篇独立作品、作者模板字段实例、自有文本证据化拆解及结果沉淀到私有库。
- 轻量、低干扰、适合长时间写作的间距、色彩和密度。

首个 Web 创作中心映射：

    作品库：私密作品卡片、搜索、排序、新建入口
    建书：独立路由、可恢复草稿、结构化模板、最终原子创建
    私有库：桥段、风格、词库、灵感与组合预设

首个 Web 写作工作台映射：

```text
左栏：小说 / 卷 / 章节 / 大纲 / 人物 / 设定
中栏：Monaco Markdown 源码编辑、独立预览、保存状态、字数、历史
右栏：AI 会话、上下文来源、计划确认、候选 Diff、接受/拒绝
```

## 不复制什么

- 不复制应用源码、图片素材、图标、字体文件、品牌标识或私有接口。
- 不复制妙笔神书的页面文案、模板内容、商业机制或系统封面素材。
- 不复刻阅文投稿、发布、审核、稿酬、好友、社区、任务、墨水、邀请和装扮体系。
- 不把 Electron 的桌面托盘、多窗口、软件更新和私有账号能力硬搬到网站。
- 不因参考 UI 而改变 PostgreSQL 权威数据、revision 冲突保护或 AI 提案确认规则。
- 不在 MVP 复刻富文本所见即所得；正文以 Markdown 源文本编辑，富文本能力以后按真实需求评估。

## 使用方式

1. 先用现有截图、主清单和妙笔神书实测记录完成低保真页面结构，不重新巡检全部产品。
2. 某个关键交互在资料中不清楚时，才对本机 App 做一次只读、有范围的复核并补记录。
3. 设计实现使用 Ant Design 主题 token 和项目自己的 CSS，不提取 App 资源。
4. Playwright 只验证本项目流程，不尝试自动操作作家助手账号或在线服务。

## 首期验收

- 三栏在常用桌面宽度下可调整，中央编辑区始终保持可写宽度。
- 保存中、已保存、离线草稿、冲突和失败五种状态清晰可辨。
- AI 规划、生成中、候选 Diff、已接受、已拒绝不会与正式正文混淆。
- 深浅主题下正文可读，键盘操作、焦点和滚动不互相抢占。
- 页面风格让用户感到熟悉，但不出现阅文品牌、商业模块或复制素材。
- 建书向导刷新可恢复，最终创建前作品库不出现空作品，重复提交不产生重复小说。
- 私有库素材改变后，已创建作品仍能复现当时采用的上下文快照。
- 若启用分阶段大纲生成，目标章节数不预建空章节，正式采用前不改变现有大纲和角色。

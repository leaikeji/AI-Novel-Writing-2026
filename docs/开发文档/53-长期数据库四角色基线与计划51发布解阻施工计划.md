## 3. 核心决策

### 3.1 维护接线而非常驻运行拓扑

新增独立 Compose overlay `docker/postgres-roles/compose.maintenance.yaml`，只在显式 `-f ... --profile database-role-maintenance` 时可见，并只连接调用者指定的 external 数据库网络。它不加载、创建或重建基础 Compose 的常驻 service，普通 `docker compose up` 不受影响。

overlay 只包含三个 one-shot service：

1. `database-role-bootstrap`：管理员 passfile 只读 secret，同时短暂挂载三个独立 pgpass 卷；以 root 运行只为创建／收紧卷内文件 owner 和 mode；
2. `database-role-validate`：只读挂载三卷和管理员 passfile，显式接受 `0035` 或 `0037`，输出不含路径和密码的 catalog 事实；
3. `database-schema-migrate`：以 `65532:65532` 运行，只挂 migrator pgpass，固定 `SET ROLE ai_novel_schema_owner`，不接触 API／worker 凭据。

三个 pgpass volume 使用精确外部名称并预先创建：

- `ai-novel-2026-db-migrator-auth`
- `ai-novel-2026-db-api-auth`
- `ai-novel-2026-db-worker-auth`

管理员 passfile 使用维护窗私有临时目录中的 `0600` 文件，不进入 `.env`、argv、日志、仓库或长期 QwenPaw 卷。完成后只删除该精确临时文件和目录；三套运行 pgpass 卷保留并纳入恢复证据。

### 3.2 不可变迁移根

维护 service 不直接挂当前 dirty 工作树或含中文路径的 host bind。主代理从已验证候选构造 maintenance-root named volume：原候选文件保持不变，另加入本轮冻结的 `docker/postgres-roles/**` 与 `scripts/tts/validate_database_roles.py`；封存后所有 service 只读挂载。分别记录：

- 原 PawApp 候选树摘要；
- 增广 migration root 摘要；
- 每个维护脚本 SHA-256；
- 固定 QwenPaw／PostgreSQL 镜像 ID。

每个 bootstrap、validate、migrate 步骤前重新核对 migration root 摘要。增广根只用于 one-shot 数据库维护，绝不作为 PawApp 安装包。

### 3.3 首次建角色顺序

计划 49 的普通升级顺序假定四角色已存在；本次是首次建立，必须使用下列替代顺序：

1. 在线只读冻结任务、连接、0036 正式记录、插件、数据库和媒体事实；创建即时备份；
2. 停止 QwenPaw，确认容器 stopped、无新 job claim、数据库中无 QwenPaw 会话；Sidecar 与 PostgreSQL可保持运行；
3. 在 `0035` 运行 bootstrap，原子创建角色并转移 owner／ACL；
4. 以 `--expected-head 20260830_0035` 运行 65 表 validator；
5. 以 migrator + `SET ROLE schema_owner` 运行 `upgrade 20260902_0037`；
6. 再次 bootstrap，把 `0036` 新表和 `0037` 索引后的对象纳入 owner／default ACL；
7. 以 `--expected-head 20260902_0037` 运行 67 表 validator；
8. 使用 QwenPaw 公开 CLI 在离线 installer 容器中安装精确 PawApp 候选；安装失败时保持长期 QwenPaw stopped；
9. 启动原长期 QwenPaw，等待 health ready，再做只读验收。

禁止先安装需要 `0037` 的后端再迁移，也禁止用 `ai_novel` 超级用户直接执行 Alembic。

### 3.4 回退分支

- bootstrap 在 SQL 事务提交前失败：数据库目录变更回滚；保留精确失败证据，允许清空并重建仅本计划新建、尚未投入使用的三套测试／凭据卷，长期数据卷不动。
- `0035` validator 失败：保持 QwenPaw stopped；先判断是连接／passfile 证据错误还是 catalog 错误。不得继续迁移；不能靠放宽校验过门。
- `0035 → 0037` 或第二次 validator 失败：因为 QwenPaw 尚未启动且不存在正式 `0036` 选角记录，运行受审 downgrade `0037/0036 → 0035`，再次 bootstrap 和 0035 validator，恢复旧插件后启动；任何 guard／计数不为零则停止自动回退。
- 候选安装失败：保持 QwenPaw stopped，优先恢复旧安装包；若 schema 已为 0037，先按上一条判断能否降回 0035。
- 候选启动后只读验收失败：立即阻断真实使用，重新查询 0036 记录计数；为零时执行完整回退，为非零时进入 `HOLD_0037_COMPAT_PATCH`，不删除记录。

生产不会为了“证明回退”故意来回改写成功环境；完整 bootstrap／迁移／安装／降级／旧包恢复必须先在隔离的长期 dump 克隆上真实演练，生产只在失败时执行回退分支。

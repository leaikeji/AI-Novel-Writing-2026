# 分阶段大纲生成与作品初始化产品规格

状态：完整扩展产品规格草案。是否阻塞核心 MVP，留到阶段 4 前与高级建书向导一起裁决。

状态补充（2026-08-25）：早期“阶段 4 前裁决”已经失效；本规格只保留为完整能力基线。正式派发前先核对当前大纲实现和最新批准范围，不重复实现已有流程。

并行施工标注：正式开发按[并行施工矩阵](./21-Codex多子代理并行施工矩阵.md)第 5.2 节的 O0–O6 工作包派发。五个步骤的模块和页面可以并行编码；同一大纲草稿的实际生成、上游变更后的过期传播和最终采用事务必须串行。

范围说明：本文中的 P0/P1/P2 只表示“分阶段大纲生成”功能内部优先级，不自动等同于整个项目 MVP。核心写作闭环只要求作者可以手动建立和编辑大纲；本文的多步 AI 生成、自动角色和关系网不得阻塞章节编辑、AI 讨论、候选 Diff、检索与 TTS。

证据日期：2026-08-22。

主要实测来源：[《零点折城》立即创建大纲流程](../妙笔神书/03-立即创建大纲流程与实测记录.md)。

## 1. 决策摘要

如果启用本功能，本项目采用以下决策：

1. 大纲生成使用独立路由和可恢复的 outline_generation_draft。
2. 背景、角色、主情节、主题定位均支持“手动填写”与“AI 生成”两条等价路径。
3. 每个 AI 步骤都作为独立、可恢复、幂等的生成任务；不建设报价、额度或计费界面。
4. AI 阶段结果先写生成草稿；最终提交前不改变正式大纲与正式角色。
5. 最终提交在单个事务内写入大纲 revisions、角色资料和目标章节数。
6. 目标章节数是容量规划参数，不预建数百个空章节。
7. 大纲各部分都可独立版本化、比较和恢复；“重新生成”不能静默覆盖已采用版本。
8. 主题亮点、作品简介和宣传文案是不同字段，不用一个文本框混写。
9. 主角、主要角色、配角使用明确枚举，不把“主角”误用为“主要角色”。
10. 大纲生成默认不自动创建线索、关系网、分卷或章节；需要生成时作为独立、可确认步骤。
11. 创建小说成功后，作品列表和其他标签页必须失效重取；“立即创建大纲”必须携带 novel_id 完成真实路由。

| 妙笔神书实测模式 | 项目采用 | 项目调整 |

## 3. 信息架构与入口

推荐路由：

| 路由 | 页面 |
| --- | --- |
| /novels/:novelId/outline | 当前正式大纲 |
| /novels/:novelId/outline/generate | 新建或恢复大纲生成草稿 |
| /novels/:novelId/outline/history | 大纲版本历史与比较 |
| /novels/:novelId/characters | 正式角色资料 |
| /novels/:novelId/clues | 主线、支线、感情线和势力线 |

入口：

- 小说创建成功页：“创建大纲”。
- 作品卡片：“大纲”。
- 大纲空状态：“生成大纲”。
- 已有大纲：“新建候选版本”或“重新规划”，不得直接覆盖。

创建小说 API 成功后必须返回 novel_id。前端用该 ID 生成目标路由，不能只关闭弹窗或依赖作品列表重新查询。

跨标签同步：

- 创建、重命名、归档小说后，向同源标签页广播 novel_changed 事件。
- 作品列表在窗口重新获得焦点时重新验证。
- 收到事件后只刷新相关查询，不丢失另一个标签页尚未同步的编辑稿。

## 4. 状态机

推荐流程：

TARGET
→ BACKGROUND
→ CHARACTERS
→ PLOT
→ POSITIONING
→ REVIEW
→ COMMITTED

生成草稿状态：

- draft：可编辑、可恢复。
- generating：某一 section 正在生成。
- generation_failed：本次 section 失败，可重试或手填。
- ready_to_commit：必填内容通过校验。
- committing：最终事务处理中。
- committed：已经生成正式大纲版本。
- abandoned：用户显式放弃。
- expired：超过保留期限。

同一草稿最多一个 section 处于 generating。用户可以回到已经完成的步骤，但改变上游内容时，系统必须标记哪些下游结果可能过期，并让作者选择保留、重新生成或手动调整。

## 5. 各步骤规格

### 5.1 目标容量

字段：

- target_chapter_count。
- 可选 target_total_words。
- 可选 target_volume_count。

规则：

- 目标章节数必须为正整数。
- 默认值根据作品类型与作者上次选择确定，不硬编码为 200。
- 显示这是规划目标，不会立即创建章节。
- 如果目标规模与当前主情节容量明显不匹配，只做提示，不强行阻止。

P0 只要求 target_chapter_count。P1 增加字数与分卷目标。

### 5.2 故事背景

字段：

- story_background。

内容建议：

- 时空与社会背景。
- 异常规则或力量体系。
- 主要组织。
- 当前危机。
- 不能违反的世界规则。

操作：

- 手动填写。
- AI 生成候选。
- 编辑候选。
- 查看生成所用上下文。
- 恢复本次生成原文。

AI 请求至少使用：建书创作思路、模板快照、受众/题材和目标容量。私有库资产必须由作者显式勾选后才加入上下文。

### 5.3 角色

角色结构：

| 字段 | 说明 |
| --- | --- |
| name | 姓名 |
| role_level | protagonist、major、supporting |
| gender_text | 可选自由文本，不限制二字 |
| age_text | 年龄或阶段 |
| personality | 性格 |
| identity | 身份 |
| biography | 人物小传 |
| motivation | 核心欲望 |
| conflict | 核心矛盾 |
| arc | 角色弧 |

P0 界面可以只展示姓名、层级、性别/年龄、性格、身份和小传；motivation、conflict、arc 可折叠。

规则：

- 只能有一个默认 protagonist，但作者可以显式选择群像模式。
- major 表示主要角色，不与 protagonist 混用。
- AI 结果使用临时 ID；最终提交后生成稳定角色 ID。
- 删除生成草稿中的角色不影响正式角色。
- 如果正式作品已有角色，生成前展示“新增、匹配、冲突”策略，不按姓名静默覆盖。

P1 增加关系网候选；关系边由作者确认后写入，不由角色列表自动推断为正式关系。

### 5.4 主情节

P0 字段：

- main_plot。

P1 结构：

- opening_hook。
- acts[] 或 phases[]。
- climax。
- ending_direction。
- unresolved_threads[]。

长篇主情节不能只是一段从开局直接写死结局的长文本。即使 P0 仍用文本框，AI 返回也应按开端、升级、转折、高潮和结局方向分段，并注明“可调整的结局方向”，避免把候选反派和最终结局误当成不可变事实。

生成输入包括：背景、已确认角色、模板快照、目标容量和作者选择的私有库资产。

输入变化规则：

- 背景改变：主情节标记 potentially_stale。
- 删除主角色：引用该角色的段落标记冲突。
- 目标容量大幅改变：提示重新做阶段容量规划。

### 5.5 作品定位

字段必须分开：

- theme_highlights：主题与核心卖点。
- synopsis：作品简介。
- optional_pitch：可选一句话宣传语。

主题亮点回答“这部作品为什么独特”；简介回答“故事讲什么”；宣传语是展示文案。三者不能共用一个字段和同一个字数上限。

P0 至少包含 theme_highlights 和 synopsis。两项都允许手填或分别生成。

### 5.6 最终复核

REVIEW 页展示：

- 目标章节数、字数与分卷目标。
- 背景。
- 全部角色及层级。
- 主情节。
- 主题亮点、简介和可选宣传语。
- 每一部分的来源：手填、AI 生成、AI 后编辑。
- 每一步的来源、任务状态和是否经过作者编辑。
- 可能过期或冲突的部分。
- 最终提交将写入哪些正式数据，不会写入哪些数据。

最终按钮文案建议为“采用此大纲”，比泛化的“完成”更明确。

## 6. 生成、取消与恢复

每个生成步骤使用统一任务协议：

1. execute：提交 draft_id、section、input_hash、模型配置 fingerprint 和 idempotency_key，返回稳定 job_id。
2. stream：服务端流式返回候选，但服务端持久化任务状态是权威。
3. finish：记录结果哈希、供应商请求 ID、完成状态和必要的错误诊断。

要求：

- 按钮在生成中禁用，但刷新后能够恢复任务状态。
- 客户端断开不等于后端取消；只有服务端确认取消才显示“已取消”。
- 相同 draft、section、input_hash 和 idempotency_key 的重试不重复执行。
- 生成失败显示原因、最后检查点、重试和切换为手填的入口。
- 本项目不显示字包、余额、价格、token 账单或失败计费政策。

竞品的商业确认框不属于本项目需求，也不再作为后续拆解重点。

## 7. 数据与版本

### 7.1 生成草稿

outline_generation_drafts 至少包含：

- id、owner_id、novel_id。
- base_outline_revision_ids。
- target_chapter_count、target_total_words、target_volume_count。
- current_step、state、expires_at。
- section_values_json。
- section_sources_json。
- section_input_hashes_json。
- section_statuses_json。
- section_job_ids_json。
- draft_version、created_at、updated_at。

草稿更新使用 draft_version 乐观锁。大段流式内容由服务端定期保存检查点，刷新后可恢复到最后确认片段。

### 7.2 正式数据

最终采用后：

- story_background、main_plot、theme_highlights、synopsis 作为类型化 outline documents，并创建不可变 document_revisions。
- 角色进入类型化 character documents 或等价的结构化角色实体，并有稳定 ID 与 revision。
- 目标容量进入 novel_planning_settings。
- 每个正式 section 保存来源、生成任务 ID、输入哈希和用户修改标记。
- 生成任务的状态、输入哈希和结果哈希保留为技术审计，不记录商业用量账本。

不在最终大纲事务中创建：

- 数百个空章节。
- 线索事件。
- 关系网边。
- 分卷。
- 正文。

这些内容只能由后续明确操作生成。

### 7.3 最终事务

最终提交必须：

1. 锁定 outline_generation_draft 和目标 novel。
2. 校验 owner、draft_version、状态和必填 section。
3. 校验正式大纲基线没有变化；变化则返回冲突。
4. 为各 section 创建不可变 revision。
5. 新增或合并角色；存在冲突时不得静默覆盖。
6. 更新 novel_planning_settings。
7. 写入必要的派生任务记录。
8. 将草稿标为 committed 并记录正式 revision IDs。
9. 提交。

请求使用 idempotency_key；网络重试返回同一批 revision IDs。

## 8. 推荐 API

| 方法与路径 | 作用 |
| --- | --- |
| POST /api/novels/:novelId/outline-generation-drafts | 创建或恢复草稿 |
| GET /api/outline-generation-drafts/:id | 读取草稿与任务状态 |
| PATCH /api/outline-generation-drafts/:id | 手填或编辑字段 |
| POST /api/outline-generation-drafts/:id/sections/:section/generate | 幂等生成 |
| POST /api/outline-generation-drafts/:id/sections/:section/cancel | 请求服务端取消 |
| POST /api/outline-generation-drafts/:id/commit | 最终幂等采用 |
| GET /api/novels/:novelId/outline | 读取正式大纲 |
| GET /api/novels/:novelId/outline/history | 读取版本历史 |
| POST /api/novels/:novelId/outline/proposals | 已有大纲的重新生成候选 |

前端不能直接调用模型；上下文选择、幂等、stream 恢复、schema 校验和任务诊断都在服务端完成。

## 9. 模块同步边界

| 模块 | 大纲最终采用后的动作 |
| --- | --- |
| 大纲 | 写入正式 section revisions |
| 角色 | 写入确认后的角色；不自动写关系边 |
| 线索 | 保持不变；可从大纲另行生成候选事件 |
| 设定 | 保留原模板；新增目标容量和大纲来源引用 |
| 分卷 | 保持不变；P1 可从阶段结构另行生成候选 |
| 章节 | 保持不变；目标章节数不等于章节实体数 |
| AI 上下文 | 只读取已采用的大纲 revision，不读取未提交草稿 |
| 向量 | 仅对正式大纲 revision 建派生索引 |

## 10. 异常与降级

| 场景 | 预期行为 |
| --- | --- |
| 模型未配置或不可用 | 保留手动填写，不阻塞大纲编辑 |
| 流式连接断开 | 重新读取服务端任务和最后检查点，不重复执行 |
| AI 输出超长 | 服务端截断前记录原因，并要求作者确认或重新生成 |
| AI 输出非法角色结构 | 拒绝该 section，允许修复解析或手填 |
| 返回内容与目标规模明显不符 | 给出质量警告，不自动提交 |
| 用户修改上游背景 | 标记下游情节和定位可能过期 |
| 正式大纲被另一标签页修改 | 最终提交返回冲突并展示差异 |
| 角色同名但内容不同 | 展示合并、新建或跳过，不静默覆盖 |
| 最终提交网络中断 | 使用同一幂等键查询结果 |
| 作品已归档或删除 | 阻止提交，不恢复作品状态 |

## 11. 功能内部优先级

### P0

- 独立、可恢复的生成草稿。
- 目标章节数。
- 背景、角色、主情节、主题亮点和简介。
- 每步手填或 AI 生成。
- 分步任务状态、取消和刷新恢复。
- 最终原子采用。
- 大纲与角色正式版本。
- 创建成功后的正确路由和跨标签查询失效。

### P1

- 目标字数、分卷数。
- 阶段/卷级结构。
- 角色关系候选。
- 大纲历史比较与局部重新生成。
- 从大纲生成线索候选。

### P2

- 批量生成分卷和章纲候选。
- 多套大纲方案并行比较。
- 群像、多时间线和多世界专用 schema。
- 团队协作审阅。

## 12. P0 验收用例

1. 创建小说成功响应提供 novel_id，“创建大纲”进入正确作品。
2. 另一标签页的作品列表在收到事件或重新获得焦点后显示新作品。
3. 进入生成页只创建草稿，不改变正式大纲。
4. 目标章节数明确标为规划参数，不创建空章节。
5. 每个步骤都能选择手填，不出现“AI已生成”的误导文案。
6. 每次 AI 生成创建稳定任务；页面显示进行中、已完成、失败或已取消状态。
7. 生成过程中刷新页面能够恢复任务与已接收文本。
8. 相同幂等键重试不重复生成。
9. 背景生成结果可编辑并保留原始候选。
10. 角色明确区分唯一主人公、主要角色和配角。
11. 正式角色已存在时，冲突必须由作者选择处理。
12. 主情节输出与目标容量不匹配时显示质量警告。
13. 主题亮点和作品简介使用不同字段。
14. 最终复核显示全部内容、来源、任务状态和过期提示。
15. 最终提交失败时正式大纲与角色保持原样。
16. 最终提交重放只返回同一组正式 revision IDs。
17. 大纲采用后，章节、分卷、线索和关系网不会被偷偷创建。
18. AI 上下文和向量索引只使用已采用的正式大纲 revision。

## 13. 非目标

- 不建设字包、额度、余额、价格、报价、扣费确认或作者 token 账单。
- 不把目标章节数直接展开为空章节记录。
- 不把一段故事梗概冒充卷纲或逐章大纲。
- 不让 AI 生成结果绕过最终复核进入正式角色和大纲。
- 不把未采用的大纲草稿加入正式检索、事实或 AI 上下文。
- 不在本流程同时生成正文。

## 14. 后续实测校正：已有作品的重新生成

后续对已有三章的《零点折城》执行完整重新生成，进一步验证了本规格中“候选版本而非直接覆盖”的必要性。竞品本次行为是：

- 重新走 200 章、背景、角色、情节、亮点五步；竞品商业提示不纳入本项目分析。
- 新大纲和新六名角色替换原正式内容；已有分卷、三章标题和正文保留。
- 新大纲主人公与已写章节主人公不同，系统没有在提交前给出引用冲突或 Diff。
- 后续章节情报同步把旧人物按姓名重新创建为资料为“未知”的配角，形成新旧主人公并存。
- 手工编辑亮点、背景和情节可以保存，但局部替换姓名不能自动修复全部角色引用。

因此本项目新增以下硬性验收，不因实现排期而降低：

1. 已有作品重生成前锁定正式大纲与角色基线，并展示预计影响范围。
2. 生成只写新候选；逐 section Diff 和角色实体匹配完成前不能采用。
3. 采用事务不得删除仍被正式章节 revision 引用的角色。
4. 采用后运行一致性报告，但不能自动重写章节正文。
5. 章节情报提取不得用“未匹配姓名”绕过角色冲突策略。

卷章、角色关系、线索和伏笔的完整模型见[创作工作台内容模型与关系图产品规格](./09-创作工作台内容模型与关系图产品规格.md)。

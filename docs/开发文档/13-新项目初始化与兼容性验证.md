# 新项目初始化与兼容性验证

初始化日期：2026-08-23（Asia/Shanghai）。

状态：阶段二历史验收已完成。阶段三至六已经继续实施，当前运行状态与最新证据以[阶段 3–6 实现与验收记录](./14-阶段3至6实现与验收.md)为准。

## 1. 本次初始化范围

已创建：

- `plugin.json`：固定 QwenPaw `>=2.1.0,<2.2.0` 的 `type: app` PawApp 清单。
- `plugin.py` 与 `backend/`：官方 `PawApp`、`PluginApi`、同源健康 API 和 Skill provider。
- `frontend/`：通过 `window.QwenPaw.route.add` 注册 `/apps/ai-novel-world-2026`，共享宿主 React 和 Ant Design。
- `skills/`：六个默认关闭、可版本化优化的小说 Skills。
- `scripts/`：最小发行打包、专用 Agent 幂等配置、运行契约验证和带显式确认的装卸脚本。
- `compose.yaml`：初始化阶段先建立 QwenPaw 和 PostgreSQL/pgvector 的 Mac 回环拓扑；当前版本已把 PostgreSQL、QwenPaw 与 Nano Sidecar 收敛为默认 Compose 拓扑，不再依赖可选 profile。
- Python 与 Vitest 契约测试骨架。

未创建或未实现：

- 小说数据库表、Alembic migration 和领域 CRUD。
- `novel_get_context` 等 Agent 小说工具；阶段三有真实只读领域服务后再注册。
- 章节树、编辑器、自动保存和 IndexedDB 恢复。
- 自定义 AI 聊天面板、确认、Diff、候选版本或 AI 正文写入。
- 向量、TTS、图片和媒体服务。

## 2. 本机工具链

Codex 初始化使用固定的 Node.js 24.19.0 和 pnpm 11.19.0；项目 `package.json` 同时记录该边界。前端构建链固定为 TypeScript 5.8.3、Vite 6.3.5 和 Vitest 4.1.11，与 QwenPaw 2.1.0 的构建代际保持一致。

Python 插件运行边界为 `>=3.11,<3.14`。真实 QwenPaw 容器是 Python 3.11.2；本机契约测试使用独立开发 Python，不把本机系统 Python 3.9 当作插件运行基线。

## 3. 已核实的公共契约

- PawApp 是显式 `type: app` 插件，并通过 `meta.pawapp` 提供应用中心信息。
- 后端入口必须导出 `plugin` 实例；`PawApp` 路由最终挂载到 `/api/{app_id}`。
- 前端由宿主动态加载，通过 `window.QwenPaw.*` 注册路由并共享 React、ReactDOM 和 Ant Design。
- `PluginApi.register_skill_provider` 是公开 Skills 安装接口，支持默认启用状态、频道和卸载清理。
- `PluginApi.register_tool` 支持显式 `enabled=False` 和 `tool_type="internal"`，但 QwenPaw 2.1.0 的卸载清理依赖 manifest `meta.tools`；阶段三注册真实工具时必须同时声明元数据并复测清理。
- 官方前端 API支持注册、包装或替换路由，也支持定制原生聊天，但没有明确提供“把原生聊天组件嵌入 PawApp 任意区域”的组件 API。

## 4. 当前聊天页面决策

初始化页面不复制、不替换 QwenPaw 原生聊天。阶段二已确定使用公开 `route.wrap` 在原生 `core.chat` 页面外围组织小说工作区，同时保持聊天内容原样。

- 普通 `/chat` 直接返回上游 `Inner`，不显示小说外壳。
- `/chat?novel_workbench=1` 显示最小工作台外壳和完整的原生 `Inner`。
- 原生模型选择、Agent 选择、历史、输入框和工具安全控制均由 QwenPaw 渲染。
- 若将来升级后包装不兼容，降级为从 PawApp 跳转普通 `/chat`。

没有公开契约支持时，不读取私有 React 组件、不使用私有 Router、不 iframe 自身页面，也不修改 QwenPaw 源码。

## 5. 开发验证命令

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
python -m pytest
python scripts/package_plugin.py
docker compose config
```

当前验证环境的一键命令：

```bash
# 构建、测试、离线安装、配置专用 Agent 并验证
python scripts/qwenpaw_lab_plugin.py install

# 只读验证 PawApp、Agent、Skills 和工具边界
python scripts/qwenpaw_lab_plugin.py verify

# 完整运行时卸载；必须显式确认精确插件 ID
python scripts/qwenpaw_lab_plugin.py uninstall --confirm ai-novel-world-2026
```

若 `pnpm` 不在 `PATH`，通过 `PNPM_BIN` 指向项目选定的 pnpm 11.19.0。脚本不读取或写入模型密钥。

`frontend/dist` 和 `build/` 是构建产物，不提交 Git；安装 PawApp 前必须先执行 `pnpm build` 和 `python scripts/package_plugin.py`，并只把脚本输出的最小发行目录交给 QwenPaw CLI。不能直接安装项目根目录，否则会错误复制 `.venv`、`node_modules`、文档和测试。安装在 QwenPaw 停止时进行；完整卸载在 QwenPaw 运行时调用官方 API，以执行注销清理。装卸后都要验证原生聊天、模型、Skills、MCP 和插件管理没有回归。

## 6. 失败恢复

- 前端构建失败：不安装插件，QwenPaw 验证环境不变。
- 后端导入或 manifest 验证失败：修正骨架后重新验证，不修改上游源码。
- 插件安装后导致启动失败：先恢复固定 QwenPaw 镜像并尝试运行时完整卸载；只有宿主无法启动时才离线移除插件文件，并在宿主恢复后清理残留注册；不删除 QwenPaw 持久卷。
- Skills 作用域不符合预期：保持 `enabled_by_default=False`，在作用域核实前不自动启用。
- PostgreSQL 尚未进入阶段三：`data` profile 保持未启动，正文数据不会在本轮产生。

## 8. 尖峰发现与修正

1. QwenPaw 以包语义加载插件入口，`plugin.py` 必须用相对导入访问内部模块；绝对导入 `backend.*` 在真实校验器中失败，已修正。
2. 宿主认证请求会补 `/api` 前缀；传给 `host.fetch` 的路径必须是 `/{app_id}/...`，否则会形成双 `/api` 并返回 404，已由真实浏览器发现并修正。
3. QwenPaw CLI 会复制传入的整个插件目录；项目根目录含 `.venv`、`node_modules`、文档和测试，不能直接安装。现已用 `scripts/package_plugin.py` 只生成最小发行目录。
4. PawApp API 卸载能够清理 PawApp 和 Skill provider，但动态注册工具若未同时出现在 manifest `meta.tools`，工具配置可能残留。残留测试工具已经通过带元数据的临时重装和官方插件卸载接口清理；最终 PawApp 暂不注册工具。阶段三注册真实只读工具时，代码注册和 manifest 元数据必须同步，并再次验证卸载。
5. 官方没有把原生聊天组件嵌入任意 PawApp 路由的公开组件 API，但 `route.wrap("core.chat")` 可以在原生路由外围增加工作台布局。查询参数关闭时直接返回原组件，可同时满足独立入口、普通聊天不变和卸载清理。
6. Skill provider 的文件会出现在多个 workspace，但 `enabled_by_default=False` 加上 Agent 作用域 API 可以做到只在 `ai-novel-writer` 启用。Skills 是项目版本化内容，可持续修改，不是固定能力。
7. QwenPaw 离线 CLI 卸载只删除插件文件，不执行运行时注销，可能遗留 workspace Skill 记录。项目完整卸载脚本因此改用运行中的官方 `/api/plugins/{id}` 删除接口；实测可同时清除 PawApp、wrapper 和 Skills。
8. 专用 Agent 创建和 Skill 启用均已做成幂等脚本；重复安装不会重复创建 Agent。

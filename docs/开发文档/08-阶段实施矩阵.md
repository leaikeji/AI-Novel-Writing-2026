# AI小说世界2026 阶段实施矩阵

状态：阶段一规划基线。本文补充各阶段的前置依赖、测试、失败恢复和 Codex 有效开发时间；阶段范围与退出条件仍以[项目开工计划](./00-项目开工计划.md)为主。

估算口径：只计算 Codex 实际分析、编码、测试、排障和文档时间，不含等待用户决定、下载镜像/模型、外部 API 凭证审批和无人值守长基准。阶段二结束后按真实 PawApp 摩擦重新估算。

## 总览

| 阶段 | 范围 | 前置依赖 | 核心测试 | 失败恢复 | Codex 有效时间 |
| --- | --- | --- | --- | --- | ---: |
| 1. 规划定稿与架构冻结 | 边界、状态机、路由、权限、版本、许可证、阶段计划 | 原始需求；QwenPaw/依赖官方资料；竞品研究只读快照 | Markdown 链接、需求覆盖、内部一致性、版本与许可证复核、禁区规则检查 | 不创建工程；发现冲突继续修文档，不以假设冻结 | 3–5 小时 |
| 2. 初始化与 QwenPaw 兼容尖峰 | Git、最小 PawApp、构建、同源 API、工具/Skill/设置契约、Compose 骨架 | 用户明确说“执行新项目初始化”；阶段一获批；固定 QwenPaw 镜像 | 插件装卸、原生入口非回归、API 前缀、React 单实例、Monaco Worker、流式 tool-call、Skill/工具治理 | 禁用/移除插件即可回到纯 QwenPaw；不改上游镜像内部源码；尖峰失败时缩小插件实现 | 8–12 小时 |
| 3. 数据库与领域核心 | PostgreSQL/pgvector、Alembic、Repository、working copy、revision、proposal、facts、derivations | 阶段二插件加载和依赖解析通过；PostgreSQL 固定镜像可运行 | 迁移升降级、CAS 并发、三重基线、接受事务、幂等键、任务租约、进程崩溃恢复 | 显式 migration one-shot；测试备份恢复；迁移失败不拖垮 QwenPaw 原生控制台 | 10–15 小时 |
| 4. 基础小说工作台 | 基本建书、卷章树、Markdown 编辑/预览、自动保存、检查点、历史 | 阶段三领域 API 稳定；Monaco 尖峰通过 | Vitest 编辑状态；API 集成；Playwright 创建/编辑/刷新；断网、冲突、多标签、IndexedDB 恢复 | 数据库保留上一确认稿，IndexedDB 保留未同步稿；冲突不做最后写入者覆盖 | 10–15 小时 |
| 5. AI 讨论、上下文与检索 | 专用小说会话、首期 Skill 基线、只读工具、分块、Embedding profile、检索 | 阶段四保存屏障可用；QwenPaw Provider tool-call 契约通过；至少一个 Embedding profile | 会话与小说隔离、Skill 版本/作用域、工具范围、当前 revision 过滤、profile/fingerprint 隔离、Embedding 停止与重试、固定召回样本 | 保存/检查点失败时明确使用上次 revision；向量失败转 pending/failed，不影响正文和普通显式上下文读取 | 8–12 小时 |
| 6. 计划、候选、Diff 与接受 | 计划确认、候选全文、Diff、接受/拒绝/冲突/继续讨论 | 阶段五上下文来源可审计；proposal 状态机和 UI 单次令牌接口就绪 | 全状态迁移、过期确认、三重基线冲突、重复接受、拒绝零副作用、Diff 可重建、Agent 越权测试 | 任何失败保留当前 working copy/revision；候选可重试或标记过期，绝不强压到新基线 | 8–12 小时 |
| 7. 当前版本派生、事实与 TTS | AI 接受/用户检查点/确认导入的 chunks 与向量、事实候选、段落/章节 TTS、媒体缓存 | 阶段六接受事务及其他当前 revision 事务能写 pending derivation；TTS 供应商或测试替身确定 | kill/restart、租约过期、重复领取、供应商 500、事实冲突、TTS 缓存键、临时 URL 持久化 | durable backlog 可续跑/dead-letter；正文事务不回滚；切换适配器后按 revision/hash 重试 | 7–10 小时 |
| 8. 完整 MVP、本机发布与升级验证 | E2E 闭环、备份恢复、脱敏、性能、可访问性、固定版本发布 | 前七阶段退出条件全部通过；真实模型/TTS 凭证可用或有明确替身边界 | 完整 Playwright 流程、备份还原、媒体校验、只监听回环、日志/存储密钥检查、并行 QwenPaw 升级兼容 | 保留旧镜像 digest、数据库/媒体/QwenPaw 卷备份；升级失败切回旧环境，不在原环境就地修上游 | 6–9 小时 |

合计：**60–90 个 Codex 有效开发小时**。

## 阶段闸门

1. 阶段一未获用户批准，不创建 Git、工程骨架、Compose 文件或依赖锁。
2. 阶段二兼容尖峰未通过，不开始大规模 UI 或数据实现，也不通过 monkey patch 绕开公共接口。
3. 阶段三并发与恢复测试未通过，不把自动保存或 AI 接受接入真实正文。
4. 阶段五必须证明当前 revision 过滤和小说会话隔离；否则不能让 Agent 自主检索。
5. 阶段六必须通过越权与冲突测试；否则不能出现正式“接受”按钮。
6. 阶段七必须证明派生失败不回滚正文；否则 TTS 和事实更新保持禁用。
7. 阶段八备份恢复和并行升级未通过，不称为可发布 MVP。

## 扩展范围不计入核心估算

以下内容已有研究或产品规格，但不自动计入上表：完整私有创作资产库、高级建书向导、分阶段 AI 大纲生成、关系网、批量卷纲/章纲、短篇闭环、自有文本拆解、导入导出、AI 图片以及本地 CosyVoice/ComfyUI。它们只有在用户明确纳入后才增加阶段、测试与时间，不以规格内的 `P0/P1` 字样绕过核心 MVP 范围闸门。

## 创作工作台扩展实施包

下表根据[创作工作台内容模型与关系图产品规格](./09-创作工作台内容模型与关系图产品规格.md)拆分。它是范围评估，不代表已经立项；若选择其中一包，应追加到最早满足前置依赖的核心阶段之后，并重新估算真实 PawApp 摩擦。

| 扩展包 | 功能 | 最早前置 | 必须验证 | Codex 有效时间 |
| --- | --- | --- | --- | ---: |
| W1 卷章增强 | 稳定排序、独立移动、章节壳、章纲 document、统一字数口径 | 阶段 4 working copy/revision 可用 | 树版本冲突、移动不改正文、标题与正文分开计数、空章纲降级 | 4–7 小时 |
| W2 大纲与实体安全重生成 | section 候选 Diff、角色匹配/合并、一致性报告 | 阶段 6 proposal 接受协议可用 | 未采用零正式写入、角色引用保护、分 section 采用、幂等重放 | 6–10 小时 |
| W3 章节情报与叙事数据 | 角色/关系/线路/事件/伏笔提案、逐项复核、直接编辑与合并 | W1；阶段 6 单事务采用；阶段 7 可恢复任务 | 同 revision 重复同步、误分类重改、未知角色拦截、来源 revision 追溯 | 8–12 小时 |
| W4 关系图 | Canvas 或 SVG 图、键盘列表、缩放拖动、显式保存多视图 | W3 稳定角色与关系 ID | 有向/无向一致、布局与语义隔离、刷新恢复、无障碍和 200 节点性能 | 5–8 小时 |

若四包全部纳入，新增约 **23–37 个 Codex 有效开发小时**，核心总估算由 60–90 小时变为约 **83–127 小时**。该数字不含模型质量调优、大规模图性能优化和外部等待。

## 短篇与文本研究扩展实施包

下表根据[短篇创作与文本拆解产品规格](./10-短篇创作与文本拆解产品规格.md)拆分。两个包共享核心 document/revision、任务恢复和创作资产设施，但可以独立上线。

| 扩展包 | 功能 | 最早前置 | 必须验证 | Codex 有效时间 |
| --- | --- | --- | --- | ---: |
| W5 短篇闭环 | 九步草稿、模板字段实例、目标范围、整篇候选、信息/角色、统一版本与审稿 | 阶段 4 document/revision；阶段 6 候选采用协议 | 刷新恢复、创建幂等、目标不足、角色事实冲突、手写版本、恢复与统一字数 | 8–13 小时 |
| W6 自有文本拆解 | TXT/粘贴/项目 revision 导入、权利基础、分维度任务、证据报告、历史与资产沉淀 | 阶段 5 模型上下文；创作资产基础 CRUD | 超限切分、来源范围、单维失败恢复、全稿缺章、重复保存幂等、归档来源 | 7–11 小时 |

W5 与 W6 全部纳入时新增约 **15–24 个 Codex 有效开发小时**。该估算不包含未获授权文本采集、只凭书名的全书推断、AI 文本来源鉴定或公开资产市场，因为这些都不是本项目目标。

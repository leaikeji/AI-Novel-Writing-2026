# 依赖版本基线

版本核验日期：2026-08-22；QwenPaw Docker 运行验证日期：2026-08-23；阿里云向量模型与接口更新核验日期：2026-08-26。来源优先级为官方发行页、官方源码、PyPI、npm Registry、Docker Registry 和官方模型/服务文档。

“最新稳定版”是核验日上游最新非预发布版本；“项目选定版”考虑 QwenPaw 兼容性和 MVP 风险，不保证等于整个生态最新大版本。

**已核实事实**：QwenPaw 2.1.0 官方插件文档同时支持 `plugin.json.dependencies` 和插件根目录 `requirements.txt` 安装 Python 依赖；两者都是公开机制，不能假定只会读取其中一个。

**项目建议**：源码开发以 `pyproject.toml` 和单一锁文件作为依赖真源。阶段二用最小插件验证 QwenPaw 对 manifest 与 `requirements.txt` 的执行顺序、重复项和失败行为，再选择一种发行声明方式；不要长期在两处手工维护同一批无锁版本范围。若必须生成 `requirements.txt`，从锁文件机械导出并做漂移检查；`plugin.json.dependencies` 只保留经验证确实需要由宿主安装的直接项。

## 版本结论

- QwenPaw 2.1.0、Portkey 1.15.2 和 pgvector 0.8.6 保留各自核验结论；TEI/Ollama 的旧版本事实不再构成当前向量方案的选型或施工依赖。
- PostgreSQL 应从此前保守的 17 调整为当前稳定 18.6；所选 pgvector 镜像已有 arm64 的 PG18 变体。
- Python 不能选全局最新 3.14.7，因为 QwenPaw 2.1.0 明确排除 3.14；真实宿主为 3.11.2，插件必须通过 3.11 运行测试，并以 3.13.15 做兼容上界测试。
- 前端业务包更新到核验日版本；TypeScript/Vite 暂不追最新大版本，先对齐 QwenPaw 的构建代际。
- `qwen3.7-text-embedding` 通过现有 `httpx` 调用阿里云 DashScope Native API，不新增 Python SDK、Ollama、TEI 或模型容器依赖；`Portkey`、`ComfyUI`、`Qwen-Image` 也不是 MVP 默认运行依赖。
- 所有 Docker Compose 引用必须使用真实 tag 加 digest；QwenPaw 使用 `v2.1.0`，不能根据 Python 包版本猜测镜像 tag。

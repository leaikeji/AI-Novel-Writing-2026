# 创作中心小说回收站与可恢复删除开发计划

状态：**V0.2 优化复查完成，待作者批准施工。本轮仅修改计划及文档索引；尚未修改 schema、API、前端、长期 `18088` 或任何小说数据。**

日期：2026-09-10（Asia/Shanghai）

本版落实上一轮复查：修正幂等顺序与活动任务状态，增加全域并发协议、在途媒体清理阻断、分级恢复、永久删除维护契约、多标签页草稿保护及停写发布／回退门禁。下文均为目标决策；源码核验依据及仍需施工证明的事项见第 13 节。

## 1. 背景与目标

计划 65 已修复整书永久删除：服务端可在 CAS、活动任务门禁、事务闭包、脱敏审计及媒体身份校验下安全销毁一本小说。但是当前创作中心的“删除”仍然直接进入不可逆确认；数据库／媒体备份属于运维恢复点，不能替代作者可自主使用的回收站。

本计划建立两层删除语义：

1. 作者在创作中心点击“删除”时只把整本小说移入回收站，不删除正文、不可变 revision、人物、故事事实、向量索引、朗读媒体或本地恢复稿；
2. 作者可从回收站恢复小说的原有标识和内容；附件及派生能力异常按 5.2 分级处理；
3. 计划 65 的完整销毁服务只允许处理已经在回收站中的小说，并继续受精确确认、备份和残留检查门禁保护。

本计划不建立第二套正文、第二套数据库或第二个 Agent Runtime，不修改 QwenPaw 核心，不把原生聊天历史并入小说回收站，不触碰私有库素材自身的生命周期，也不自动删除任何现存作品。

## 2. 产品裁决

### 2.1 V1 默认行为

- 创作中心作品卡的“删除”改名为“移入回收站”。确认文案明确“可恢复”，不得继续显示“不可撤销”。
- 回收站默认无限期保留；V1 不自动按 30／90 天清空，不提供“一键清空回收站”。
- 回收站只展示已完成建书的小说。未完成的建书草稿、私有库素材、QwenPaw 原生聊天和 Agent 会话不在本计划范围。
- 恢复只改变小说生命周期元数据，不修改正文内容、不倒拨 revision、不创建伪造的正文 revision。生命周期变化单独写入不可变审计事件。
- 小说移入回收站后，普通创作页面、搜索、Agent 工具、上下文装载、朗读、向量检索和后台任务均不可访问它；只有回收站列表、恢复和受控彻底删除路径可读取最小必要摘要。
- 当前浏览器的 IndexedDB 崩溃恢复稿在“移入回收站”时保留，恢复后仍可由作者确认恢复。浏览器自行清除站点数据或存储被回收不在服务端保证范围；本地稿不能代替数据库备份。永久删除后的浏览器清理范围与回执见 5.3。

### 2.2 V1 不开放普通自助彻底删除

项目安全边界要求破坏性数据操作具备精确目标、动作时确认、事前备份和可执行恢复方案。Web 运行角色不应获得 `pg_dump`、Docker、数据卷或管理员凭据，因此 V1 不让普通 API 自动创建全库／媒体备份，也不依赖 QwenPaw 私有备份实现。

V1 回收站可显示“彻底删除需先完成系统备份”的说明，但不提供无备份的一键永久销毁。永久销毁继续复用计划 65 的维护流程：冻结精确 UUID／version／影响清单，生成并验证数据库与媒体恢复点，作者在动作时再次确认，然后调用只允许回收站小说进入的完整销毁服务。

未来若要开放 30／90 天自动清理或自助“清空回收站”，必须另立计划，先建立公开、可验证的备份回执契约和恢复演练；不得只加定时器绕过备份门禁。

## 3. 状态机与不变量

```text
ACTIVE --移入回收站--> RECYCLED --恢复--> ACTIVE
                              |
                              +--备份门禁 + 再次确认--> PURGED
```

`PURGED` 不是 `novels` 表内状态：数据库闭包提交后该小说已不存在，只留下计划 65 的脱敏 `novel_deletion_audits` 和本计划的脱敏生命周期事件。

必须始终成立的不变量：

- `ACTIVE`：`recycled_at IS NULL` 且 `recycled_by IS NULL`；正常业务按原有权限、授权和数据可用性规则访问。
- `RECYCLED`：两个字段均非空；保留回收时已有的小说权威／派生数据和媒体，正常业务新请求一律拒绝；回收本身不修复此前损坏，也不能阻止应用之外的磁盘损坏或手工删除。
- 移入与恢复都在单一数据库事务中完成，锁定小说行、校验 UUID＋CAS、递增现有 `novels.version` 并写不可变生命周期事件。
- 移入和恢复不删除、重写或新增任何正文 revision；其恢复是“重新可见”，不是历史正文恢复。
- 彻底删除只能从 `RECYCLED` 进入；任何活动小说直接调用旧永久删除 URL 都必须 fail closed。
- 已回收小说不能被 autosave、生成任务、embedding worker、朗读 worker、媒体播放或 Agent 工具重新写入。
- 媒体 GC、孤儿扫描和容量清理必须把 `RECYCLED` 数据视为仍被引用；回收站不是垃圾回收候选。

## 4. 数据模型与迁移候选

新增前向迁移候选 `20260910_0052_novel_recycle_bin.py`。只有计划获批后才创建实际 revision；开工时重新核对 Alembic head，若编号已被其他任务占用，由唯一迁移所有者分配新的后继并同步本计划，不创建竞争 head，不修改 `0051` 或其他历史迁移。

### 4.1 `novels` 增量字段

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `recycled_at` | `timestamptz NULL` | 非空表示已进入回收站；服务端生成 UTC 时间 |
| `recycled_by` | `varchar(120) NULL` | 当前仅允许固定本地作者主体；不接受模型输入覆盖 |

增加成对空值 CHECK；现有行回填为两个字段均空，不重写正文和 revision。复用 `version` 作为生命周期 CAS，每次移入或恢复递增 1。V1 不增加 `purge_after`，避免代码存在一个尚未获准执行的自动销毁时钟。

索引候选：

- `(owner_id, workspace_id, updated_at DESC) WHERE recycled_at IS NULL`，服务正常创作列表；
- `(owner_id, workspace_id, recycled_at DESC, id DESC) WHERE recycled_at IS NOT NULL`，服务回收站稳定游标分页。

### 4.2 `novel_lifecycle_events`

新增不可变、脱敏事件表，不设置指回 `novels` 的外键，以便永久销毁后仍保留审计。待 W0 冻结的字段候选为：

- `id UUID`；
- `novel_id UUID`；
- `action VARCHAR(16)`，仅 `recycled`／`restored`；
- `version_before`／`version_after`；
- `title_sha256`，不保存书名、简介或正文；
- `actor VARCHAR(120)`；
- `idempotency_key VARCHAR(120)`；
- `occurred_at TIMESTAMPTZ`；
- `request_sha256 CHAR(64)`，对版本化规范编码的 action、novel_id、expected_version、固定 actor／scope 求摘要，识别同键异义；
- `result_json JSONB`，只保存可重放的动作回执：event_id、action、version、recycled_at（恢复时为 null）、有限 warning_codes；禁止标题、正文、路径、密钥和任意诊断文本。

唯一约束 `(novel_id, idempotency_key)` 支持丢失响应后的安全重试；增加 action 枚举、正版本且 `version_after=version_before+1`、摘要格式及回执类型约束。事件表采用不可变 trigger，并明确禁止普通 UPDATE／DELETE／TRUNCATE；不得被计划 65 的销毁授权旁路，其 UUID 和脱敏回执是永久销毁后的允许审计残留。迁移后数据库保护表预计从 60 增至 61，必须同步 bootstrap、schema-owner migrator、validator、`protected-tables.sql` 和对应契约测试，以开工实测基线复核数量。

## 5. 领域服务与事务

新增 `backend/novel_lifecycle.py`，作为 UI API、Agent 边界和后台处理共用的生命周期权威，不允许各模块自行解释 `recycled_at`。

公共内部接口候选，由 W0 冻结，W1b 提供可运行实现后供并行包消费。生命周期模块不得反向依赖导入它的 `services.py`；独立异常定义放在 `backend/novel_lifecycle_errors.py`，避免循环导入：

- `require_active_novel(session, novel_id)`：不存在返回 not found，已回收返回稳定错误 `NOVEL_RECYCLED`；
- `lock_active_novel(session, novel_id, expected_version)`；
- `lock_recycled_novel(session, novel_id, expected_version)`；
- `recycle_novel(session, novel_id, expected_version, idempotency_key, actor)`；
- `restore_novel(session, novel_id, expected_version, idempotency_key, actor)`；
- `list_recycled_novels(session, limit, cursor)`。

只读 guard 不提供写并发保护；所有写入口必须使用 5.4 的锁定协议。scope／actor 均从服务端可信上下文取得，输入校验不得只靠函数默认值。动作服务 flush 但不自行 commit，由统一编排层持有一次事务，禁止嵌套提前提交。

### 5.1 移入回收站事务

1. 校验作者访问范围、精确 UUID、正版本与长度受限的幂等键；先查询同键事件，摘要一致直接重放原动作回执，摘要不同返回 409 `idempotency_conflict`；
2. 对尚无回执的新请求，按固定 owner／workspace 和 UUID 锁定小说行，刷新 ORM 缓存，并在拿锁后再次查询同键事件。只有仍无回执才校验 `ACTIVE` 和 `expected_version`；
3. 按 5.4 检查全部活动任务及在途媒体清理。任一阻断则返回稳定错误、保持原状态，不替作者取消任务；
4. 写 `recycled_at`／`recycled_by`，递增 `version`，刷新 `updated_at`；
5. 插入 `recycled` 生命周期事件并提交；
6. 返回已保存的动作回执。发起页在成功后通过 `BroadcastChannel` 通知同源标签页；不新增服务端消息总线。广播失败不得回滚已提交状态，其他入口仍由服务端门禁保护。

不触发媒体删除、embedding 删除、正文保存或模型调用。打开同一本书的其他标签页在下一次请求得到 `NOVEL_RECYCLED` 后停止 autosave／生成／朗读；前端同时使用 `BroadcastChannel` 做即时提示，但广播不是权限边界。

### 5.2 恢复事务

1. 与 5.1 相同，先校验范围并查幂等事件，再锁定小说并重查事件；仅新请求校验 `RECYCLED`＋CAS；
2. 执行下述分级完整性检查，遇到权威损坏或在途物理删除时保持回收态；
3. 清空 `recycled_at`／`recycled_by`，递增 `version`，写 `restored` 事件；
4. 提交后重新出现在创作中心。原文档、revision、人物、关系、故事事实、向量 generation、朗读 edition、媒体和 IndexedDB 恢复稿保持原标识。

恢复检查分级如下：

| 检查结果 | 恢复行为 |
| --- | --- |
| scope 不一致、文档与 working copy／revision 必要引用断裂、检测到权威内容哈希不符 | 409 `restore_integrity_blocked`；保留原状态，返回有限诊断码，维护恢复后重试 |
| 仍有 `deleting` 媒体或未完成的文件销毁执行 | 409 `novel_cleanup_in_progress`；不与物理删除交叉恢复 |
| 派生音频缺失、向量 generation 已退役或授权／Provider 已变化 | 允许恢复，返回 warning_codes；相关能力继续按现行不可用／待重建规则显示，不静默调用模型或续费 |
| 上传原件／声音参考等不可再生附件缺失 | 保留缺失记录并明确警告；正文完整时允许恢复小说，依赖该附件的功能保持不可用，不能以新文件冒充原件 |

普通恢复执行有界结构检查，不在持锁事务中逐文件扫描或全书计算 SHA-256；完整哈希／媒体清单核验属于隔离验收与维护诊断。不能把有界预检宣传成全库完整性证明。恢复动作不改变内容；语义索引旧 generation、媒体已有可用性可能受全局配置影响，须区别“数据保留”和“立即可用”。

幂等重放只证明历史动作成功：即使后来已经恢复、再次回收或永久销毁，同一请求仍返回原 event 回执并标记 `replayed=true`，不重复执行。前端随后刷新当前列表，不用历史回执覆盖当前生命周期。失败且未提交的请求不占用成功事件；改动参数或版本必须生成新键。

### 5.3 彻底删除收口

- `delete_novel_with_narration` 改为只接受 `RECYCLED` 小说及可信维护校验产生的销毁上下文；上下文绑定精确 UUID／version／清单摘要和备份回执摘要，销毁事务内重新比较，不接受模型或 HTTP body 自报验证成功。活动小说或缺少维护上下文时拒绝。
- 移除 narration runtime 不可用时回退到通用 ORM 永久删除的分支；缺少完整运行时必须返回 503，不能降级成较弱删除。
- 在证明调用者已迁走后移除通用 `services.delete_novel` 及其等值旧测试，或将其封闭为不可公开调用的实现细节；不得保留可直接 `session.delete(novel)` 的第二条销毁路径。
- 永久删除仍返回 `deleted_document_ids`；数据库提交后媒体失败继续进入 `media_cleanup_failed` 审计，不误报整笔数据库回滚。重试清理只使用同一审计冻结清单，重新校验文件身份，不重新执行数据库删除。
- V1 不暴露普通自助永久删除路由。新增本项目维护脚本候选 `scripts/maintain_novel_recycle_bin.py`，默认 dry-run；输出精确 UUID、version、文档／媒体计数与影响清单摘要。执行模式必须显式指定目标、预期版本、清单摘要、备份回执路径及动作确认，不支持标题匹配、通配符或批量全清。
- 备份回执由可信本地维护流程产生，包含数据库／媒体备份标识、schema、生成时间、SHA-256、隔离恢复验证记录和目标清单摘要。脚本验证文件和摘要、目标仍为回收态且清单未变；缺失、篡改、目标漂移或恢复验证未完成均拒绝。普通 JSON 中一个 `verified=true` 不是备份证明；Web／Agent 不接收管理员路径和凭据。回执用于约束本地维护操作，不宣称可防御已控制本机的管理员。
- 本地维护脚本无法清除其他浏览器的 IndexedDB。将 `deleted_document_ids` 写入受限权限的维护结果回执；本次浏览器若另执行精确清理则记录其范围，离线设备／其他浏览器记为未检查，不宣称全设备零残留。V1 不为此增加远程清理协议。

### 5.4 写入、任务与媒体清理的共同并发协议

回收事务提交是生命周期切换点。每个短写事务先锁小说行并校验 active，再锁子资源；多小说操作按 UUID 排序拿锁。锁范围覆盖 autosave、候选应用、历史恢复、入队、重试、claim、生成结果发布、媒体删除计划创建，以及可能删除回收态派生数据的全局维护操作。既有 resource／job／asset 锁顺序必须在 W0 逐入口盘点并统一；有冲突的路径不能只追加反向小说锁。禁止跨模型、TTS、全文件哈希或流式播放持有数据库锁。

先获得锁的正常写入在回收前完成；后获得锁的写入刷新状态后拒绝。正文仍使用原文档 CAS，小说生命周期版本不能代替正文版本。模型请求必须在释放锁前留下可审计活动任务；外部调用前与结果发布时复核任务 fence 和生命周期。回收拒绝在途任务，异常迟到结果不得新增候选／正文或重新激活小说；已超时任务只走现有安全收敛路径，不伪造完成状态来通过回收门禁。

活动清单至少覆盖：

- `background_jobs`：实际非终态为 `queued/running/retry_wait/cancel_requested`，不使用该表不存在的 `leased/cancelling`；
- `chapter_generation_jobs`（经 document 定位小说）、`creative_generation_jobs`、情报抽取及 writing-skill dispatch 的在途执行；W0 从当前各自状态机冻结非终态与失联收敛规则，不能将同一组后台枚举套用所有表；
- voice deletion 请求、`media_assets.state='deleting'` 及尚未完成的 GC 文件删除。已完成的历史清理记录不永久阻断回收。

媒体清理先按同一小说锁协议创建并提交 `deleting` 状态和持久清单，再在事务外 unlink。若清理先行，回收见到在途状态后拒绝，待清理结算再重试；若回收先行，清理不得建立新删除计划。全局音色删除、配额清理、孤儿清理和旧向量 generation 退役也必须保护回收态数据，不能只过滤普通 GC 候选。跨小说／全局任务的 `novel_id=NULL` 必须按真实作用域处理，不能因 SQL inner join 被全部饿死，也不能当成绕过检查的通行证。

只读请求在装载时校验生命周期；新请求在回收后必须拒绝。已经返回浏览器或原生聊天的内容无法追溯收回，已经开始的媒体响应也不承诺撤回字节。前端收到事件后暂停播放并清除可恢复的播放 URL／缓存引用；下一次媒体 GET、HEAD、Range 和条件请求必须重新检查生命周期，不能先返回 304 绕过检查。

## 6. HTTP 契约

### 6.1 正常与回收站读取

- `GET /novels`：保持响应结构，只返回 `ACTIVE`；不新增默认包含回收站的兼容开关。
- `GET /recycle-bin/novels?limit=20&cursor=...`：limit 为 1–100，按 `(recycled_at DESC,id DESC)` 稳定翻页，返回 `items/next_cursor/total_count`。仅包含 UUID、标题、删除时间、version、章节数、可见字数和 `media_bytes`。字数与媒体大小按数据库元数据聚合，先限定本页小说再聚合，不扫描正文或磁盘；统计未知返回 null，不能用 0 代替未知。数量徽标消费 total_count。V1 使用系统封面占位，避免回收站封面另开普通媒体访问例外。
- `GET /novels/{id}` 及所有正常子资源：已回收时返回 HTTP 410，detail type 为 `novel_recycled`；未知 UUID 仍为 404。

### 6.2 生命周期动作

- `POST /novels/{id}/recycle`，body：`expected_version`、`idempotency_key`；返回 `{event_id,action:"recycled",version,recycled_at,warning_codes,replayed}`。
- `POST /recycle-bin/novels/{id}/restore`，body 同上；返回同形回执，action 为 `restored`、recycled_at 为 null。响应是动作证据，当前状态按重新读取列表为准。
- 旧 `DELETE /novels/{id}` 在计划切换后不再永久删除活动小说，统一返回 409 `permanent_delete_moved_to_recycle_bin`，防止旧页面或旧客户端绕过回收站。

上述路径均位于 `/api/ai-novel-world-2026` 命名空间。所有动作复用现有宿主公开认证与本地范围校验，严格校验 body；不注册为小说模型工具，聊天指令不替代作者动作。仅有“请求来自 UI”或未注册工具不构成安全隔离；W0 必须核对公开认证／跨站请求保护契约，不发明 Referer 或客户端 actor 作为授权凭证，也不另造第二套登录体系。

统一错误类型候选：404 `novel_not_found`（含不可访问范围）、410 `novel_recycled`（普通入口）、409 `novel_version_conflict/novel_state_conflict/idempotency_conflict/novel_busy/novel_cleanup_in_progress/restore_integrity_blocked`、503 `novel_maintenance_unavailable`。DTO 的 detail 保持现有项目错误包装，只扩展稳定 type 与有界数据。旧 DELETE 的 409 是明确兼容特例；工具返回等价领域错误，不要求工具层伪造 HTTP 状态。

## 7. 全域访问隔离

不能只在 `GET /novels` 加过滤。施工时必须建立并验证以下矩阵：

| 消费方 | `ACTIVE` | `RECYCLED` |
| --- | --- | --- |
| 创作中心／工作台 | 正常 | 仅回收站摘要；普通路由 410 |
| 保存、reorder、历史恢复、候选应用 | 正常 | 拒绝且不写 revision |
| Agent 五个小说工具与助手上下文 | 正常 | 按不可用处理，不返回正文或上下文 |
| 搜索、Context V4、故事账本／人物工作台 | 正常 | 拒绝 |
| 向量检索／索引刷新 | 正常 | 不检索、不入队、不 claim；既有索引保留 |
| 朗读生成、播放、Range、音色操作 | 正常 | 拒绝；媒体保留 |
| background／embedding／narration worker | 正常 claim；全局任务保持现有作用域 | 小说任务按 active 筛选并遵守共同锁协议；全局任务逐目标校验 |
| 媒体 GC | 按现有规则 | 仍视为有效引用，禁止删除 |
| 私有素材 | 绑定正常 | 素材本体仍在私有库，小说绑定保留但不投影 |

所有正常外部入口，包括只凭 document／job／asset／edition ID 的入口，均须由服务端追溯小说范围并检查 active。回收列表、生命周期动作和维护代码是显式例外；不能让全局 active 过滤器把回收站自身也隐藏。静态直接访问 allowlist 只作为辅助检查；验收必须通过行为矩阵证明过滤、拒绝和零写入。普通工具、搜索及上下文不返回回收态标题或正文，最小摘要只开放给作者回收站列表。

## 8. 前端交互

### 8.1 创作中心

- 顶部功能区新增“回收站”入口和数量徽标；不挤占 QwenPaw 原生侧栏。
- 作品卡删除动作改为“移入回收站”。弹窗展示精确书名并说明“正文、历史版本与媒体会保留，可从回收站恢复”。
- 成功后列表递减并把焦点移到下一本作品或空态；失败时保留当前选择并显示服务端稳定错误。
- 当前作品存在进行中后台任务时说明阻断原因，不自动取消任务。

### 8.2 回收站页面

- 列表按删除时间和 UUID 稳定分页；卡片显示书名、删除时间、章节／字数、媒体占用和“恢复”按钮。未知统计显示“暂不可用”。恢复的附件／索引警告用具体能力说明，不把后端枚举直接展示给作者。
- 空态明确“回收站为空”；loading、网络失败、CAS 冲突和完整性异常均有独立状态。
- V1 不显示可点击的“清空回收站”。可展示只读说明：“作品不会自动清理；彻底删除需要先完成系统备份。”
- 恢复确认后返回创作中心并选中该书；不自动打开正文，避免旧聊天／旧路由直接发送上下文。

### 8.3 多标签页与可访问性

- 生命周期变更通过服务端门禁保证，`BroadcastChannel` 只用于缩短其他标签页的感知延迟。
- 收到回收事件的编辑标签页立即停止 autosave 定时器、生成轮询和朗读动作，保留 IndexedDB 本地稿，并提示返回创作中心。
- 生命周期通知包含 novel_id、event_id、action 和 version，不包含正文；按版本去重。卸载时移除监听，不支持 BroadcastChannel 时在窗口重新获得焦点／页面恢复可见及下一次请求时复核状态，避免永久依赖广播。
- 回收通知或 410 使当前编辑会话的请求 generation 失效；迟到的读取、保存、生成成功响应不得重开编辑器、恢复轮询或清掉后来写入的本地稿。恢复小说后重新加载服务器状态，由作者确认本地稿恢复并再次执行文档 CAS，不自动发送旧稿。
- IndexedDB 清理采用事务内“比较后删除”：仅当当前记录与该成功请求对应的本地稿标识／内容摘要及基线一致时删除；保留其他标签页较新的记录。沿用现有库并兼容旧记录，任何存储迁移不得删除 drafts store。写本地稿失败时保留内存内容并提示可复制保存，不能声称已安全落盘。
- 键盘焦点、Escape 取消、确认按钮顺序、屏幕阅读器标题、桌面滚动和 390×844 窄屏均纳入验收；危险色只用于真正的永久销毁，不用于可恢复的“移入回收站”。

## 9. 兼容、升级与恢复

- 新字段 nullable 且现有小说全部保持 `ACTIVE`；迁移本身不移动数据、不调用模型、不触碰媒体。
- 发布严格串行：进入项目维护窗口，停止 PawApp 写入口、后台 worker、模型派发和 GC；确认在途任务与文件清理已安全结束，再生成同一停写点的数据库／媒体备份并验证隔离恢复。通过宿主公开生命周期与项目运行脚本操作，不拦截 QwenPaw 全局原生路由。
- 维护窗口内执行 schema-owner 升级，再切换全部 PawApp API／worker／前端安装树；核验实际 schema 与安装树摘要一致、新服务健康、回收隔离通过后才开放写入。旧后端／worker 不得连接含回收态数据的新库。旧缓存前端访问新后端的永久 DELETE 返回明确 409，不保留删除旁路。
- 卸载 PawApp 不删除回收站小说或生命周期事件。重新安装同版本后状态可恢复。
- `0052` 作为前向迁移，不通过改写历史或清空回收字段回退。开放写入前失败，可保持停写并恢复同批数据库、媒体和旧安装树；隔离演练必须证明旧代码只连已恢复的旧库。开放写入后失败，先暂停项目写入并保存最新完整恢复点，优先前向修复或经验证兼容新 schema 的版本；不能直接恢复旧快照丢弃新创作。确需全库回退时先核对并保存新增创作，提出具体数据影响及恢复方案后由作者决定。
- 所有正式迁移、真实回收和永久销毁操作都由主代理串行执行；测试只使用隔离数据库和新建验收小说，不触碰当前三本保留作品。
- QwenPaw 公开契约变化只能在本项目 PawApp 适配层处理；若生命周期隔离无法通过公开契约完成，停止本功能发布并记录缺口及替代方案，不自动降级为只隐藏列表。历史聊天中的已发送内容不追溯清除，后续小说上下文装载必须拒绝回收态。

## 11. 测试与验收矩阵

### 11.1 后端与迁移

- `0051 → 0052` 隔离升级；现存小说均为 active，内容哈希、revision 数、媒体清单不变；
- CHECK、partial index、事件不可变 trigger、角色 owner／ACL、61 张保护表通过；
- recycle／restore 成功、重复请求幂等、错误幂等键、陈旧 version、未知 UUID、活动任务均有稳定结果；
- recycle 前后每张小说业务表计数和媒体 SHA-256 相同，只有 `novels` 生命周期字段／version 与 lifecycle event 变化；
- 无外部变更的正常回收／恢复样本，全部 ID、正文哈希、revision 链、人物／事实、embedding 数据、edition／manifest、媒体 SHA-256 与大小保持；同一文件系统内原地回收／恢复另外核验 inode。备份还原可能改变 inode，不能以 inode 相同作为跨恢复环境的正确性条件；
- 活动小说不能进入永久销毁服务；narration runtime 缺失不能回退成 ORM 删除。
- 同键并发、成功响应丢失、回收后已恢复再重放旧请求、永久删除后重放历史回执均只生成一个事件；同键不同 action／version 明确冲突；
- 分级恢复覆盖权威引用断裂、原件缺失、派生媒体缺失和全局 Provider／generation 变化，不触发自动模型调用；
- 维护脚本 dry-run 零写入；缺备份、摘要篡改、无恢复证明、清单变化、未确认均拒绝；永久删除后的业务残留扫描仅排除精确列举的脱敏审计表，不用笼统排除全部 JSON／审计目录；
- 事件普通 UPDATE／DELETE／TRUNCATE 被拒绝，持计划 65 删除授权仍不能改生命周期事件。

### 11.2 隔离矩阵

- 回收态小说的普通 GET／PUT／POST／DELETE 子资源全部返回 410 或明确的生命周期错误；
- 五个 Agent 小说工具、助手上下文、搜索和 Context V4 不返回回收态标题、正文或历史快照；已发送的原生聊天历史按非目标保留；
- autosave、候选应用、历史恢复和 reorder 不产生 revision 或 version 漂移；
- background、embedding、narration worker 不 claim 回收态任务，不产生模型／云端／TTS 调用；
- playback 与 Range 拒绝回收态，媒体仍存在；媒体 GC 不生成其删除计划。
- 路由清单包含 PATCH、HEAD、带 ETag 的 304 路径、直接 document／job／asset／edition ID 入口、历史生成快照及建书完成后的关联草稿入口；分页无跨范围泄漏，统计不读正文且查询数量有界。
- 全局无小说任务继续运行；全局向量退役、音色删除及配额清理不能物理删除回收态保留数据。

### 11.2a 必须用真实 PostgreSQL 连接交错验证的竞争场景

| 交错 | 可接受结果与证据 |
| --- | --- |
| autosave／候选应用与回收同时发生 | 写入先提交后回收，或回收先提交后写入拒绝；无回收后内容写入、无死锁 |
| 入队／手动重试／claim 与回收同时发生 | 任务先登记则回收 busy；回收先提交则入队／claim 不执行；记录模型调用计数为零 |
| 模型超时、迟到结果与回收／恢复交错 | 旧结果被 fence 拒绝；恢复后也不能重新采用失效结果 |
| GC／音色删除已提交 deleting，再请求回收 | 回收 cleanup_in_progress，文件清理完成前不切换状态；随后可重试 |
| 回收先提交，再创建 GC／全局清理计划 | 不产生目标删除计划／unlink；证明保护覆盖事务外执行窗口 |
| 恢复与维护永久删除同时发生 | 同一小说锁和 CAS 只允许一方成功；另一方稳定拒绝，零半恢复 |

用显式 barrier／事件控制交错，不以不稳定 sleep 充当并发证明。fake Session 单测不能替代这一组测试；测试库或必要能力缺失记为 HOLD，不记作 PASS。

### 11.3 前端与真实浏览器

- 桌面和 390×844：创作中心可移入、回收站可列出、刷新／重启后仍存在、恢复后重新可编辑；
- 在两个标签页打开同一验收小说，一处回收后另一处立即或在下一请求变只读，不能继续 autosave；
- 回收前制造 IndexedDB 未同步稿，回收后保留，恢复后可继续恢复；
- 网络丢失响应后以同一幂等键恢复结果，不重复递增 version；
- 广播禁用、后台标签页恢复焦点、断网后重连均重新校验；迟到保存响应与另一标签页的新草稿交错时，新草稿不被清除；
- IndexedDB 旧记录兼容、比较删除、落盘失败提示，以及恢复后显式确认＋文档 CAS 路径通过；
- 未出现“不可撤销”误导文案；回收按钮不使用永久危险色；键盘和焦点路径通过；
- 普通 `/chat`、Agent、Provider、Skills、MCP、设置和插件管理保持非回归。

## 12. 阶段退出标准

只有同时满足下列条件，才能把本计划改写为“已完成”：

1. 作者批准 V1 的“无限期保留、无自动清空、无普通自助永久销毁”产品裁决；

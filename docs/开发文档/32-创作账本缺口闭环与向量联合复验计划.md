状态：**2026-08-29 已完成施工、长期安装、真实 2048 维联合复验与三视口验收。** 本计划只修复计划 31 首轮三章实测暴露的闭环缺口，并在修复后新建一部独立实验小说重新验收；不推倒 StoryFact v2、多时间线、私有库或语义索引主干，不建设计费功能。完整运行证据见[创作账本向量联合复验-2026-08-29](./证据/创作账本向量联合复验-2026-08-29/README.md)。

## 1. 已核实缺口与目标

| ID | 已核实缺口 | 本轮目标 |
| --- | --- | --- |
| `CDG-01` | 人物根 revision 与稳定 ID 已存在，但正式改名不会维护 `character_aliases` | 每次人物正式 revision 原子维护当前名和历史名；旧人物用一次性迁移补当前正式名；冲突别名显式标记，不猜测 |

修复后的目标数据链为：

```text
正式人物/章纲/正文映射
→ 稳定人物实例与结构化故事时间
→ StoryFact 确定性投影
→ V3 上下文和普通工作台投影
→ 分层语义索引
→ 语义检索证据（只辅助，不裁决状态）
```

## 2. 冻结规则

- 人物根 ID、人物实例 ID 和 TTS 人物根绑定不因改名变化。
- 人物正式 revision、别名变更和人物目录 CAS 属于同一事务；当前正式名记为 `official_name`，被替换的正式名记为 `former_name`。
- 同一小说内同一规范化别名指向多个人物时，相关别名进入 `conflicted`，调用方不得静默选择人物。
- 普通章纲 UI 可继续显示姓名，但服务端只允许把唯一当前正式名解析为稳定 ID；多时间线或多实例不能唯一解析时返回 `timeline_required` / `character_instance_required`，不使用最近值。
- `RevisionTimelineMappingSegment.story_time_json` 是章节故事时间的权威来源。上下文不解析自然语言 label 来制造时间坐标。
- 年龄只在出生年与故事时间结构化上下界可比较时计算。只有出生年份时，即使当前故事年精确，也返回年龄区间。
- 故事线和关系事件没有显式类型化 `status/progress` 时，只显示“最近确认事件、事件数和证据”，不根据中文关键词推算百分比。
- 伏笔的 `plant / reinforce / reveal / resolve / cancel` 是合法协议枚举，可确定性映射为当前状态；这不是样书关键词规则。
- 向量检索必须先通过小说、revision、时间线、叙事截止点和知识可见性过滤；命中结果不得覆盖 StoryFact 投影。
- 向量模型固定使用已配置的阿里云百炼 `qwen3.7-text-embedding`、2048 维 Dense、cosine。本轮不开发价格、余额、账单或 token 费用页面。

## 3. 数据与接口变更

### 3.1 别名链

- 新增线性 Alembic revision，为别名增加专用人物 revision 来源外键并回填当前 active 人物的正式名；不改旧 revision。原 `source_revision_id` 继续只表示正文 revision 证据，避免跨实体误用。
- 人物 revision 服务写入或恢复时同步 upsert 别名；重复幂等写不新增别名。
- 规范化规则与 TTS 人物别名解析共用同一纯函数。
- 增加改名、恢复旧名、同名冲突、TTS 根绑定不变和迁移回填测试。

### 3.2 章纲 V3 引用

- `save_chapter_brief()` 在单线下把 required 人物的唯一正式名解析为 `CharacterRefV2`，并保存 `_v3`。
- 角色约束未改变时保留现有 V3；发生改变时重新执行严格解析。
- `context_v3_loader` 自己读取 ChapterBrief V3，所有调用方不再各自重复组装。

### 3.3 时间与年龄

- `_story_position()` 读取当前正文 revision 的 mapping head 与 segments。
- 完全相同的时间直接采用；同 calendar 且都有上下界时合并为范围；其他情况返回未知，不静默选第一段。
- `CharacterContextV2` 增加版本化 `age_projection`，包含出生年、故事时间、最小/最大年龄、精度与无法计算原因。

### 3.4 业务投影

- 三个 list API 增加可选 `timeline_id`、`narrative_cutoff`。
- 单时间线省略 `timeline_id` 自动解析；多时间线不能唯一解析时返回现有结构化错误。
- 返回规划根字段，同时增加 `projection`：当前线、截止点、事件数、最新事件、证据 fact IDs、冲突。
- 工作台优先展示 projection 的最新进展与有效状态；编辑表单仍编辑规划根，不把派生值回写为作者定义。

## 4. 新一轮从零验收

修复与部署后，不复用 `雾港失序钟（三章账本验收·20260829）`，新建另一部三章实验小说，每章约 2000 个可见字符，覆盖：

1. 人物初始名、正式改名、旧名检索与 TTS 根 ID 连续性；
2. 章纲 required 人物稳定引用；
3. 三个正文 revision、三份时间线映射和结构化公历年；
4. 出生年到各章故事时间的年龄区间；
5. 人物、关系、故事线、伏笔、知识与世界状态 StoryFact；
6. 私有素材固定版本及更新提示；
7. V3 上下文叙事截止点 1/2/3 的未来泄漏为 0；
8. 已授权小说的 V1 语料索引、2048 维实际向量、语义命中与来源证据；
9. 未授权小说、兄弟时间线、失效 revision、未绑定私有素材泄漏为 0；
10. GET/list/context/search 前后数据库权威表快照一致。

真实百炼只执行连接哨兵、必要索引与固定检索题，不打印 Key，不运行压力测试。若配置、授权或候选 generation 尚未 ready，旧 active 继续服务并记录失败，不绕过门禁。

## 6. 子代理并行施工设计

本任务**不并行写代码**。原因是修复集中在 `backend/creative_services.py`、`backend/services.py`、`backend/context_v3_loader.py`、公共 DTO、唯一 Alembic head、同一前端工作台和唯一长期数据库；这些文件与资源均属于共享锁，拆给多个代理会增加契约漂移和覆盖“向量模型”任务遗留改动的风险。

稳定工作包 ID 仍按第 5 节记录，供证据与回滚定位使用。唯一集成责任人是当前主代理。共享锁为：

- `LOCK-USER-DIRTY-FILES`：保留向量任务的未提交文件；
- `LOCK-MIGRATION-HEAD`：只有 `CDG-AUTH` 新建一次 revision；
- `LOCK-PUBLIC-CONTRACT`：W2 冻结后 W3 才可接前端；
- `LOCK-TEST-DATABASE`：自动化只用隔离测试库；
- `LOCK-LONG-RUNTIME`：仅 W4 串行备份、迁移、安装和重启；
- `LOCK-CLOUD-COST`：仅 W5 运行最小真实调用；
- `LOCK-GIT`：本计划不自行提交或推送，除非用户再次要求。

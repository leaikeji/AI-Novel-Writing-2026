## V1.1：精简强制步骤，不减少 AI 帮助

首稿将 AI 入口收得过深，本轮直接修改原画板，不另留一套重复主视图：

- 建书：创意旁增加“AI 帮我完善创意”；背景、人物、大纲、简介分别提供“自己填写”和“AI 生成”。这些模块仍为可选。
- 章前：增加“AI 拟章纲”和“自己填写”，保留“AI 生成正文”及“先手动写”；章纲不作为正文生成的强制前置步骤。
- 正文：补齐“AI 审稿”“选区 AI 修改”、修改要求输入框和“按要求生成修改候选”。结果仍可比较、采用或取消。
- 章后：补齐“AI 提取本章变化”，点击才发起提取，候选不自动进入故事记录。
- 以上入口同步到四个手机画板。增加[已有内容的模块编辑示例](https://www.figma.com/design/YtKkOkfZTPrtdIV1YrTEXs?node-id=71-358)，明确“填写修改要求 → AI 按要求修改 → 候选”。“保存手动修改”不隐含 AI 调用。

入口规则：空内容显示“AI 生成”；已有内容进入编辑后提供“AI 修改”，章纲同理。重新生成须由作者明确发起，不自动覆盖原内容。按钮调用现有领域任务的目标交互，不要求作者去右侧助手聊天，也不恢复计划58施工。

## 状态与交互交接

Figma 下方另有六张状态卡：生成中 `37:189`、生成失败 `37:201`、候选待采用 `37:211`、未保存 `37:221`、版本冲突 `37:231`、确认完成 `37:241`。

- 生成成功先显示候选；偏离文学目标字数只提醒，不自动重写，不隐式采用。空结果、越权、容量超限等仍需技术校验。
- 选区修改只比较该范围，采用走现有版本／CAS 保护；取消不改原文。
- 保存与确认变化分开；工作稿已保存不等于候选已采用。未同步应提供重试和现有本地恢复入口。
- 审稿唯一准确匹配才可定位；重复匹配需选择，无匹配为待核实；旧报告不能定位新版本。
- 窄屏收起作品侧栏，比较纵向排列；主要操作高度 44 px，长内容随页滚动。真正的键盘顺序、焦点可见、返回焦点和 Escape 行为留待实现及浏览器验收，静态稿不能证明这些行为已通过。
- “确认所选”之后才能显示确认完成；下一章可提示未处理变化，但不能强制清空全部候选。

## 来源、复用与限制

- 依据[方案 60](../../60-写作主流程减重优化方案.md)与 `audit/写作全流程实用审计-20260908/`；采用真实样书《雾宅来信》、人物林澈／许宁、首章《门廊来信》和原文节选，不另编书名。
- 原文“下一章”对白来自样书；“明天”替换是明确标注的设计示例，不是本轮实际模型调用结果。事实候选中的“一定是晚投放”为推测冒充事实的反例示意，不冒充原始抽取结果。2/9 用于呈现选择与待处理关系，不是新增运行状态。
- 这些书名、字数、人物、平静收束等都是可编辑样例值，不得变成写作硬编码规则。
- 布局沿用本项目浅灰画布、白色卡片、橙色主操作与正文优先方向；颜色依据 `frontend/src/styles.ts`。主按钮使用深色文字，提高橙底辨识度。未复制或重画 QwenPaw 设置与管理页。
- 搜索未发现项目 Code Connect 文件或本项目已发布 Figma 库。按钮、输入框、文本域、勾选框使用 Simple Design System 的链接实例并作本稿样式覆盖；它们不是已建立代码映射的 Ant Design 组件，实施时仍复用宿主 React／Ant Design，不引入第二套运行时组件库。
- Figma 缺少产品的 PingFang SC／Microsoft YaHei，中文使用已核实可用的 Noto Sans SC（思源黑体体系）作明确替代；不能声称与浏览器字体像素一致。源项目品牌色没有对应发布变量，样式覆盖保留源色值；未为四张页面另建完整设计系统。
- 建书可选字段、候选采用规则、审稿定位等仍是目标方案，不代表当前后端合同已经支持；产品施工必须完成方案 60 的相应门禁。

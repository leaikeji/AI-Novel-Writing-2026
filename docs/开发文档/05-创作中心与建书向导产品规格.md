## 1. 决策摘要

本项目采用以下产品决策：

1. 作品默认私密，公开发布与建书完全解耦。
2. 建书向导使用独立路由和可恢复草稿，不叠加在任意后台页面上。
3. 最终确认前只保存 novel_setup_draft，不创建正式 novel。
4. 最终创建使用事务和幂等键，一次生成小说、模板快照和系统封面引用。
5. 私有库保留四类用户心智，但后端使用统一资产模型。
6. AI 模板使用 schema 驱动字段，不把某一题材的十个字段硬编码进表结构。
7. 预设引用作者级资产；作品采用时生成不可变快照，保证后续可复现。
8. 系统封面是 P0 默认路径；AI 封面、上传裁剪和 AI 取名延后。
9. 本项目是个人本地工具，不建设额度、字包、价格、报价、扣费或计费审计；AI 任务只保留幂等、进度、取消和错误恢复所需的技术状态。
10. 灵感卡的“开始创作”必须创建带来源的建书草稿并预填思路，不能只复制到剪贴板。
11. 作者自定义模板必须同时具备 schema 和可见的 values 表单；只选中模板名称而不收集字段值视为无效接入。
12. 短篇是独立作品形态，与长篇共享作品、角色、创作资产和 revision 基础设施；具体闭环由独立规格承载。
13. 私有资产每次编辑都创建不可变版本；每个生成任务固化实际采用的版本和完整输入快照，历史不能只显示当前资产内容。
14. 候选比较先核验作者硬约束，再分别评估本次目标匹配和通用文稿质量；违反必需或禁用约束的候选不能仅凭通用质量分自动胜出。
15. 产品验证同时保留结构测试与真实作者场景；批次编号、功能名和无意义唯一短语不得污染作品、卷章、关系或创作资产，文本质量结论必须在可持续创作的小说中复核。

## 3. 信息架构

### 3.1 创作中心

创作中心首期只有三个一级任务：

- 浏览和打开小说。
- 创建新小说。
- 管理私有创作资产。

推荐路由：

以下均为小说 PawApp 内部相对路由；完整宿主 URL 由 QwenPaw 应用入口承载，不允许覆盖同名 QwenPaw 核心路由。

| 路由 | 页面状态 |
| --- | --- |
| /novels | 作品库 |
| /novels/new | 建书向导 |
| /novels/new?draft=:draftId | 恢复未完成向导 |
| /inspirations | 作者自己的灵感卡与来源记录 |
| /templates | 作者模板 schema 列表 |
| /templates/:templateId | 作者模板 schema 编辑与版本 |
| /creative-assets?type=plot | 桥段 |
| /creative-assets?type=style | 写作风格 |
| /creative-assets?type=vocabulary | 特色词汇 |
| /creative-assets?type=idea | 热梗奇思 |
| /creative-assets/presets | 预设 |

### 3.2 建书向导状态机

作品类型选择先决定创建哪一种草稿，不能让长短篇共用一份字段含义不清的半成品：

```text
TYPE
  -> LONG_FORM  -> novel_setup_draft(project_type=long_form)
  -> SHORT_FORM -> short_setup_draft
```

本文的长篇 P0 状态：

AUDIENCE → IDEA → TEMPLATE → NAMING → COVER → REVIEW → CREATED

短篇九步状态机见[短篇创作与文本拆解产品规格](./10-短篇创作与文本拆解产品规格.md)。任何非 CREATED 状态都只是草稿。

允许：

- 向前进入下一步。
- 回到任意已完成步骤。
- 刷新或关闭后恢复。
- 在 AI 失败后停留当前步骤重试。

禁止：

- 未完成必填字段时跳到最终创建。
- 浏览器重复提交创建两部相同小说。
- AI 生成结果绕过作者确认直接写入正式作品。

## 4. 私有创作资产库

### 4.1 资产类型

| 类型键 | 界面名 | 内容结构 | 典型用途 |
| --- | --- | --- | --- |
| plot | 桥段 | name + body | 情节套路、反转机制、冲突设计 |
| style | 写作风格 | name + body | 语气、句式、修辞、节奏约束 |
| vocabulary | 特色词汇 | name + items[] | 稳定词汇偏好与禁用/常用表达 |
| idea | 热梗奇思 | name + items[] | 时效梗、奇思、临时情节点子 |

资产根 `creative_assets` 只保存身份和当前指针：

- id、owner_id、type。
- status：active、archived。
- current_version_id。
- created_at、updated_at、archived_at。

不可变版本 `creative_asset_versions` 保存：

- id、asset_id、version_number。
- name。
- body：plot/style 使用。
- items_json：vocabulary/idea 使用。
- content_hash。
- provenance_kind、provenance_ref：手填、文本拆解或其他明确来源；无来源时不能伪造。
- created_at、created_by_session_id。

编辑资产不是覆盖原行，而是带 `expected_current_version_id` 创建新版本，再原子更新根记录的 current_version_id。旧生成任务、作品快照和预设固定引用具体 asset_version_id，不随根指针变化。

类型校验：

- plot/style 要求 body 非空，items_json 为空。
- vocabulary/idea 要求至少一个非空、去首尾空白后的 item，body 为空。
- name 去首尾空白后必填；同一 owner、type 下重名时给出警告，P0 默认阻止完全重名。
- 单个标签长度、标签数和正文长度均由服务端配置并返回给前端，不只依赖前端校验。

### 4.2 列表与编辑

P0 列表支持：

- 分类切换。
- 名称搜索。
- 新增、编辑、归档。
- 空状态。
- 归档条目筛选和恢复。

P0 不做硬删除。归档前如果条目仍被预设引用，界面必须展示引用数量；归档不破坏已有预设和作品快照。

### 4.3 预设

预设结构：

- 名称和可选说明。
- 零到多个资产引用，按 plot/style/vocabulary/idea 分组。
- 资产引用包含 asset_id、asset_version_id、选择策略和顺序。

编辑资产后，不静默改变已经应用到小说或生成任务的提示词。应用预设时，将名称、内容、标签、类型、版本和内容哈希复制到 novel_prompt_snapshot。作者可主动执行“用最新资产重新同步”，该动作必须展示差异并确认。

### 4.4 作者模板与私有资产的边界

作者模板不是私有库预设的别名：

- 作者模板定义“建书时要回答哪些结构化问题”，保存版本化 schema。
- 私有库保存“生成时可选用哪些桥段、文风、词汇和灵感”，保存可复用内容资产。
- 建书草稿选择模板后必须立即渲染字段值；必填项由服务端验证。
- 作品创建时同时固化 template schema + values 快照与实际采用的私有资产快照。
- 从文本拆解保存的资产必须带 source_text_hash、分析维度和结果项来源；同一结果重复保存应幂等或显式创建新版本。

作者模板的完整字段模型、版本和验收见[短篇创作与文本拆解产品规格](./10-短篇创作与文本拆解产品规格.md)。相同 schema 基础设施应可供长篇复用。

### 4.5 生成时输入快照与约束协议

资产在章节正文、章纲、大纲或短篇生成中被选中时，服务端必须先建立不可变的 `generation_context_snapshots`：

- id、owner_id、novel_id、chapter_id 可空、job_kind。
- outline_revision_id、body_base_revision_id、setting_snapshot_ids。
- selected_character_ids、selected_storyline_ids、selected_foreshadow_ids。
- selection_policy_json：每组选择是 required、preferred、context_only、hard_allowlist 或 prohibited。
- normalized_input_hash、model_profile_fingerprint、created_at。

其中 `generation_asset_bindings` 每条保存：

- snapshot_id、asset_id、asset_version_id、asset_type、display_order。
- name_snapshot、body_snapshot、items_snapshot_json、content_hash。
- constraint_policy：required、preferred、context_only 或 prohibited。

绑定中的内容副本是审计快照，不依赖以后还能读取资产根或版本表。生成历史的“查看本次输入”必须展示这些字段的作者可读摘要，但默认不把全文写入普通技术日志。

资产后来编辑或归档时，旧任务继续引用原始快照。重试必须给出两个明确命令：

- `retry_with_original_context(job_id)`：复用原 snapshot_id。
- `retry_with_latest_assets(job_id, expected_snapshot_hash)`：重新解析最新资产，先展示版本和内容 Diff，再建立新快照。

生成结果附带 `constraint_validation_report`，逐项记录：

- constraint_key、policy、result：passed、failed、not_machine_verifiable。
- evidence_ranges、observed_value、expected_value、message。

短语次数、禁用词、段落长度等可计算约束由程序先核验；场景切换、语气和审美等难以可靠计算的约束标记为 `not_machine_verifiable`，不能伪装成通过。角色 hard allowlist、线路和伏笔选择复用同一报告协议。

候选比较 `candidate_comparison_report` 分成三层：

1. 硬约束合规：required/prohibited/hard_allowlist，具有否决权。
2. 本次目标匹配：章纲、期待、选中资产与叙事任务的符合程度。
3. 通用写作质量：流畅度、准确性、节奏、画面等可解释维度。

比较报告本身不修改工作稿。默认推荐只能从硬约束合规的候选中产生；没有合规候选时显示“无合格候选”，允许作者人工查看、修订或明确越权采用。

## 5. 建书向导

### 5.1 草稿创建

用户进入 /novels/new 时创建或恢复 novel_setup_draft。

草稿字段至少包含：

- project_type：本长篇草稿固定为 long_form；短篇选择会创建另一类草稿，而不是修改此字段偷换类型。
- audience_tags。
- idea_text。
- template_schema_id、template_schema_version。
- template_values_json。
- author_name、novel_title。
- cover_mode、cover_ref。
- current_step。
- status：draft、creating、created、expired。
- expires_at、created_at、updated_at。

草稿自动保存必须防抖，并显示保存中、已保存、失败。离开页面时，如果最后一次保存失败，显示离开提醒。

### 5.2 受众

P0 可先显示“男频/女频”，但 API 使用 audience_tags 数组，避免数据库永远锁死为二选一。

默认不选择。选择后才可进入下一步。

后续可增加题材、节奏、年龄层和内容强度标签，但不在 P0 首屏堆叠。

### 5.3 创作思路

字段：idea_text。

规则：

- 去首尾空白后必填。
- P0 默认上限 2000 个 Unicode 字符。
- 显示实时字数和具体超限数量。
- 提供“AI 生成模板”和“直接填写模板”两条路径。
- 点击 AI 生成后创建可恢复任务；生成结果先成为可编辑候选。
- 从灵感卡进入时预填 idea_text，并保存 inspiration_source_id、source_revision 和来源标签。
- 作者修改预填思路不会改写原灵感卡；只解除或更新本草稿的来源说明。

模板生成请求必须带 idempotency_key。同一个草稿、相同 idea_hash 和相同 key 的网络重试不得重复执行。

灵感入口使用 `start_long_form_from_inspiration(inspiration_id)` 创建草稿并进入思路确认页。剪贴板复制可以保留为次要动作，但不能作为页面间传值协议。

### 5.4 结构化模板

模板不是固定数据库列，而是 schema + values。

P0 的都市异能 schema 可包含：

- protagonist_identity：主角身份。
- special_ability：特殊能力。
- ability_cost：能力代价。
- worldview：世界观。
- core_goal：核心目标。
- organization：组织。
- antagonist_mystery：反派谜团。
- teammate_setting：队友设定。
- story_style：故事风格。
- core_premise：核心设定。

每个字段定义包含 key、label、help_text、input_type、required、max_length、display_order。AI 输出只能写入 schema 声明的 key；未知字段保留在原始响应日志中，但不能直接进入正式模板。

模板步骤支持：

- 编辑 AI 结果。
- 恢复本次 AI 原始结果。
- 重新生成；新结果作为候选，不直接覆盖作者正在编辑的版本。
- 直接填写。
- 确认后进入命名。

### 5.5 命名

P0 字段：

- author_name：必填，默认读取账户笔名但允许本书覆盖。
- novel_title：必填。

规则：

- 标题和笔名长度由服务端配置。
- 标题重复只警告，不以全局唯一约束阻止作者创建同名私密草稿。
- AI 取名为 P1。建议返回 6—10 个候选和简短理由，不自动填入；用户点选后再进入表单。

### 5.6 封面

P0 仅实现 system。

系统封面由受众/题材映射到项目自有、授权明确的模板，并叠加书名和笔名。最终保存的是模板 ID、渲染参数和生成文件引用，便于重渲染。

P1 增加 upload：

- JPEG、PNG、WebP。
- 服务端校验 MIME、像素、大小和解码安全。
- 提供 3:4 裁剪预览，保留原图和裁剪参数。
- 明确用户对上传图片拥有使用权。

P2 增加 ai：

- 执行前展示内容限制、会使用的创作信息和失败恢复方式。
- 输出先进入媒体草稿，作者选定后才写入 cover_ref。
- 不把第三方临时 URL 当作永久封面。

### 5.7 最终复核与创建

REVIEW 页展示：

- 作品类型和受众。
- 书名、笔名。
- 创作思路摘要。
- 模板全部字段。
- 采用的私有库预设或资产。
- 封面预览。
- AI 生成内容的来源标记和仍未采用的候选。

最终创建 API 接收 draft_id 和 idempotency_key，并在一个数据库事务内：

1. 锁定草稿并验证 owner、状态和必填字段。
2. 创建 novel，默认 visibility=private。
3. 创建模板与私有资产的不可变 novel_prompt_snapshot。
4. 创建系统封面媒体记录或引用。
5. 创建默认卷、欢迎页或空工作台所需的最小结构。
6. 将草稿状态改为 created，并记录 novel_id。
7. 提交事务。

同一 draft_id 再次调用时返回既有 novel_id，不创建第二部小说。

成功后跳转 /novels/:novelId/workbench，并显示一次性“创建成功”提示。

### 5.8 创建成功后的路由与多标签同步

最终创建响应必须返回 novel_id、workbench_url 和 outline_setup_url。成功页的“进入工作台”和“创建大纲”都使用服务端返回的目标，不依赖底层页面、旧列表缓存或再次按书名查询。

创建成功后：

- 当前标签页立即失效并重取作品列表缓存。
- 向同源其他标签页广播 novel_created 事件。
- 其他作品列表在重新获得焦点时再次校验，避免长期显示创建前空状态。
- 广播只刷新作品查询，不覆盖其他标签页尚未同步的章节编辑稿。
- “创建大纲”进入 /novels/:novelId/outline/generate；具体流程见[分阶段大纲生成与作品初始化产品规格](./07-分阶段大纲生成与作品初始化产品规格.md)。

成功页不能只关闭弹窗。即使向导由其他页面打开，也必须用返回的 novel_id 进入新作品或明确返回作品列表。

## 7. AI 任务执行与恢复

本项目不实现竞品的字符包、字包、余额、价格或扣费确认，也不提供面向作者的 token 账单。

AI 模板任务使用 execute → stream → finish：

1. execute 提交 draft_id、idea_hash、schema_version、generation_context_snapshot_id 和 idempotency_key，返回稳定 job_id。
2. stream 传递候选内容；服务端持久化任务状态和最后检查点。
3. finish 保存结果哈希、模型/配置 fingerprint、约束核验报告、完成状态和必要的错误诊断。

客户端断线后按 job_id 恢复，不创建第二个任务。技术日志默认不记录创作全文；模型返回的 token 数即使存在，也不进入产品功能、作者界面或领域决策。

## 8. 数据一致性与隐私

- 所有资产、草稿、小说和媒体均按 owner_id 隔离。
- 小说默认 private；建书向导不包含公开发布开关。
- 草稿设置 expires_at，过期前可提醒；清理任务只处理 expired 草稿。
- idea_text、模板和提示词可能包含作者未公开设定，日志默认只记录 hash、长度和结构化元数据，不记录全文。
- 模型请求日志与产品审计日志分离；需要查看原始内容时必须有明确的调试开关和脱敏规则。
- 归档资产和过期草稿不得级联删除正式小说快照。

## 9. 异常与降级

| 场景 | 预期行为 |
| --- | --- |
| 草稿保存失败 | 保留本地字段，显示失败和重试，不前进到最终创建 |
| AI 模板超时 | 停留思路页或模板页，可重试或直接填写 |
| AI 返回非法 schema | 服务端拒绝并记录，不把未知结构渲染为可信字段 |
| 模型未配置或不可用 | 允许直接填写模板，不阻塞建书 |
| 系统封面失败 | 保留命名与模板，允许重试或使用纯色占位封面 |
| 最终创建网络中断 | 用同一幂等键查询结果，成功则跳转既有小说 |
| 重复点击最终创建 | 按钮进入处理中；服务端仍以幂等约束兜底 |
| 资产编辑冲突 | 使用 version 乐观锁，展示差异后重新提交 |
| 灵感来源已归档 | 草稿保留来源快照并提示原卡状态，不清空作者已编辑思路 |
| 模板字段版本升级 | 已有草稿继续固定旧版本，可主动比较并迁移，不静默换 schema |
| 资产生成后被编辑或归档 | 旧任务继续显示并复用原资产版本；按最新版重试前展示 Diff |
| 旧历史只剩当前资产内容 | 视为审计失败；从任务自己的快照读取，不从 asset.current_version_id 反查替代 |
| 必需短语次数或禁用项不合格 | 候选可保留供人工修订，但标记 failed，不能成为默认推荐 |
| 约束无法机器可靠判断 | 标记 not_machine_verifiable，并显示需人工复核，不伪造 passed |
| 通用质量高但违反作者硬约束 | 比较报告解释优点但不推荐为胜出，除非作者明确越权采用 |

## 10. 优先级

### P0

- 长篇私密小说。
- 可恢复建书草稿。
- 受众、思路、直接填写或 AI 模板、命名、系统封面、复核和创建。
- 四类私有资产基础 CRUD、归档、搜索。
- 预设组合和作品快照。
- AI 任务幂等、进度恢复和错误诊断。
- 不可变资产版本、生成输入快照、原始输入重试和约束核验报告。

### P1

- AI 取名。
- 封面上传与 3:4 裁剪。
- 预设差异同步。
- 资产批量导入、导出和更强查重。
- 更多题材 schema。
- 作者模板 schema 编辑、发布新版本和跨长短篇复用。
- 独立短篇闭环与自有文本拆解，详见[短篇创作与文本拆解产品规格](./10-短篇创作与文本拆解产品规格.md)。

### P2

- AI 封面和多候选管理。
- 资产市场或公开分享。
- 团队共享私有库。

## 11. P0 验收用例

1. 首次进入 /novels/new，长篇草稿建立但作品库不出现空小说。
2. 选择受众并输入思路，刷新页面后内容和步骤恢复。
3. 模板生成任务可恢复；重复网络请求返回同一任务且不重复执行。
4. AI 返回字段经过 schema 校验，用户可以编辑后确认。
5. 不使用 AI 时可以直接填写同一 schema 并继续。
6. 书名和笔名未填时不能进入最终复核。
7. 系统封面不调用图片模型，能稳定显示书名和笔名。
8. 最终创建事务失败时作品库不出现半成品。
9. 最终创建请求重放只返回同一 novel_id。
10. 创建成功后进入工作台，作品卡片、模板快照和封面一致。
11. 私有库四类资产均可新增、编辑、搜索、归档和恢复。
12. 归档被预设引用的资产不会破坏预设或已建作品。
13. 修改作者级资产后，既有作品的提示词快照不静默变化。
14. 日志不输出创作思路和模板全文。
15. 创建响应返回可直接使用的 novel_id、工作台 URL 和大纲生成 URL。
16. 成功页“创建大纲”无论从哪个底层页面打开，都能进入刚创建的作品。
17. 另一个已打开的作品列表在收到事件或重新获得焦点后显示新作品，不要求用户手动刷新。
18. 从灵感卡开始建书时，长篇草稿已预填思路并显示来源；不要求用户再次粘贴。
19. 选择作者模板后能看到并填写全部字段，必填字段为空时服务端阻止最终创建。
20. 从拆解报告沉淀的私有资产能回到来源文本哈希、维度和结果项；重复保存不产生静默副本。
21. 用同一真实章纲分别跳过资产和选择“冷峻声景悬疑”等作者风格生成，历史能显示两次不同的输入快照和 `asset_version_id`，作者可追溯两版正文的实际差异。
22. 生成后编辑同名资产，旧历史仍显示旧名称/内容/哈希；“按原始输入重试”复用旧快照，“按最新资产重试”先展示 Diff 并创建新快照。
23. required 世界规则、角色已知信息或场景目标未落实，或候选违反 prohibited 事实时，约束报告标记失败并给出正文证据位置；机械短语次数只用于底层自动化，不作为作者质量验收。
24. 只选择一个角色且策略为 hard_allowlist 时，候选引用未选角色会在采用前失败；策略为 preferred 时只给可见警告。
25. 两个候选比较时分别显示硬约束、目标匹配和通用质量；违反硬约束的高质量候选不自动胜出。
26. AI 比较结束后工作稿和正式 revision 均不变化；只有作者点击采用才建立可恢复 revision。
27. 在新标签打开只有候选历史、尚未采用的章节时，页面明确显示“工作稿为空”，不会把“历史已有候选”误报成“正文已保存”。

## 12. 非目标

- 不复制妙笔神书的视觉、文案、资源单位或私有接口。
- 不假设男频/女频是永久数据模型。
- 不为追求一步完成而牺牲向导恢复、幂等和可审计性。
- 不在 P0 同时实现系统封面、上传封面和 AI 封面的全部复杂度。
- 不把私有库预设直接拼成不可解释的超长提示词；最终发送给模型的上下文必须可见、可选择、可追溯。
- 不把“已复制”当作灵感已经进入建书草稿。
- 不允许作者模板只展示名称而没有字段值实例、必填校验和创建快照。
- 不用资产当前版本冒充旧任务的生成输入，也不允许旧历史因资产编辑而失去可复现性。
- 不用单一“AI 智选总分”覆盖作者明示的 required、prohibited 或 hard_allowlist 约束。
- 不把候选生成、候选持久化、工作稿采用和正式 revision 保存合并成一个含义不清的状态。

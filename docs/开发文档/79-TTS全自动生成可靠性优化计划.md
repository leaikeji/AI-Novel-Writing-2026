# 开发计划 79：TTS 全自动生成可靠性优化

状态：**`CLOSED_PASS` / V1.0 已实施并通过正式环境闭环验收。**

日期：2026-09-13（Asia/Shanghai）

## 1. 目标与非目标

本计划只补齐“一键生成后自己完成”的可靠性：

1. 本地 Qwen-TTS 暂时不可达时，只让已领取的一个句段进入等待，暂停继续领取，恢复后自动续生；
2. 本地短中文音频异常只自动换一个可审计的固定种子再生一次，第二次仍异常才终止；云端不因此自动增加计费请求；
3. macOS 原生 MLX 运行时交给用户级 LaunchAgent 启动和崩溃保活，不放入 Docker；
4. 恢复中页面显示人类可理解的状态，已生成音频与既有播放会话不删除、不重建。
5. 下一版本在后台准备时，旧的不可变朗读版本继续允许播放、跳转和调节；首批新音频发布瞬间的短暂投影 404 由页面做有时限、有次数上限的重读。

非目标：不新增数据库表或队列，不改正文，不降低音频质量门限，不静默更换音色，不在本地／云端之间自动切换，不修改 QwenPaw 上游。

## 2. 已核实根因

- 现行 worker 把每个句段的 `TTS_PROVIDER_UNAVAILABLE` 独立计入最多 3 次尝试，但共享调度循环忽略 worker 返回结果，因此在运行时未启动的几分钟内可以快速耗尽整章任务。
- 本地运行时由 `screen` 人工托管，退出登录或重启后不会自动回来。2026-09-08 的早期 LaunchAgent 曾因缺失 UTF-8 启动上下文撤回；本轮候选显式固定 locale 和 Python UTF-8，只有在真实登录会话通过后才能取代该历史结论。
- `SHORT_CHINESE_DURATION_IMPLAUSIBLE` 之前第一次就终止；这能防止异常 WAV 入库，但没有利用 Qwen 采样的一次有界自恢复机会。
- 正式章节验收发现：新 Edition 首批 Manifest 刚发布时，页面可能先读到已经进入 `partial_ready` 的工作流，再在某个依赖投影上短暂收到 404；旧实现立即拆掉当前播放会话并退回旧版，造成自动生成看似失败。
- 章节面板把所有 `narrationBusy` 都解释成“播放器不可用”，因此后台准备下一 Edition 的约一分钟里，现有旧 Edition 也被错误禁播。

## 3. 最小实现

- `NarrationSegmentWorker` 返回实际 Provider；首次短中文时长异常记为 `TTS_AUDIO_REGENERATION_REQUIRED`，进入一次自动重生。重生种子、基础种子和策略版本纳入每次实际请求的参数摘要与 HMAC 输入摘要。
- 生产 worker 对外标记 ready 前先完成本地健康检查和 `warmup(custom_voice)`。运行中识别本地 Provider 不可达／超时后，以 1、2、4、8、15、30 秒上限退避停止新领取；再次健康且 warmup 通过后自动恢复。
- 新增可重建的 macOS LaunchAgent 管理器，仅引用仓库外 Python、三个模型目录和 `0600` token 文件；plist 不包含 token 值。卸载不删除模型、token、日志、小说或媒体。
- 前端增加 `TTS_PROVIDER_RECOVERING` 的友好文案；加载新 Edition 时把短暂 404 纳入既有 15 秒／30 次上限的投影收敛重读；后台生产不再禁用当前 Edition 的播放、跳转、倍速和音量。继续复用计划 73 的 Manifest 局部刷新与已生成区间播放，不重做播放器。

## 5. 门禁与恢复

- 代码：定向 pytest、全量 pytest、前端 Vitest／typecheck／test／build、插件打包、`docker compose config`、`plutil -lint`、`git diff --check`。
- 正式环境：先备份已安装 PawApp 树、Skill 状态、生产数据库及旧 LaunchAgent 状态；再通过公开更新路径安装。不删除任何数据卷、模型、token 或媒体。
- 中止条件：LaunchAgent 在 UTF-8 上下文仍不能稳定启动，模型身份不匹配，已生成媒体或正文发生变化，或正式数据库备份不可读。
- 回退：PawApp 恢复上一安装树；LaunchAgent 失败则 `bootout` 并恢复本轮前 `screen` 启动方式。回退不倒库、不删除新音频，除非确认数据库或媒体被本轮改写且作者另行授权。

## 6. 完成标准

1. 真实本地运行时不可达时，只消耗当前句段一次尝试，后续任务不被领取；
2. 运行时恢复后等待任务自动续行，不需要作者逐句点“恢复”；
3. 短中文异常最多一次自动重生，实际种子与策略进入摘要，失败音频不发布；
4. LaunchAgent 登录后启动、崩溃后保活，健康端点与冻结模型身份通过；
5. 恢复状态友好显示，计划 73 的局部刷新、已生成区间播放和旧 Edition 保护保持；
6. 正文、旧 Edition、旧音频、音色绑定、数据卷和 QwenPaw 上游均未被破坏。

## 7. 正式验收结论

- 《缺氧：末日地下世界》第1章《签下这栋破楼》真实生成请求共创建 206 个新句段任务，最终 206 个全部成功；连同 4 个安全复用句段，新 Edition 为 210/210 可用、0 失败。
- 生成中受控终止本地运行时后，只有当时正在执行的 1 个任务进入等待并使用第 2 次尝试；其余任务保持排队。LaunchAgent 换 PID 拉起后自动续生，无整章重试风暴、无需逐句恢复。
- 最终 PawApp 通过 QwenPaw 公开热更新原位生效；容器 ID 与镜像 digest 未改变，数据库仍为 `20260913_0056`，12 项小说 Skill、8 项工具及既有模型选择保持。
- 正式章节页面已把新 Edition 切为当前版本，实际播放从第 1 句推进到第 2 句／0:09；暂停并刷新后仍恢复在第 2 句。旧 206/209 Edition 保留在历史版本中。

本计划解决的是已核实的自动生成、保活、局部恢复和页面并发缺口，不承诺外部模型、硬件或云服务永不故障。短中文质量异常第二次仍不合格时仍会终止该句段；云端 Provider 仍不会被静默调用或自动产生费用。

## 1. 目标与完成口径

### 1.1 `TTS55-DEFAULT-FINAL`

- 所有新建小说，无论普通创建还是建书向导，初始旁白都是 `CN 欢迎关注模思智能（onnx.Junhao）`。
- 初始化与小说创建处于同一事务，走既有官方音色 receipt、rights、provenance、幂等和 CAS 服务。
- 不用 Alembic 数据迁移、数据库默认值或前端补写模拟业务动作。
- 两条创建入口任一失败时整本小说创建回滚，不留下半初始化作品。

### 1.2 `TTS55-CHARACTER-FINAL`

- 作者在章节页点击一次“智能朗读”，系统自动发现本小说中拥有已保存正式人物卡、但尚无私人／上传／专属音色的人物。
- 这些人物依次进入现有 VoiceGenerator 链；一次只运行一个重模型任务，成功后自动 CAS 绑定并在后续 Edition 中复用。
- 当前绑定为官方音色时，在专属音色验证成功前继续保留；成功后才替换。私人、上传和既有专属音色永不自动覆盖。
- 页面刷新、关闭抽屉、网络中断或 PawApp 重启后可恢复同一准备命令。
- 单人物失败不改变该人物原绑定，也不抹掉其他人物已成功的结果；页面给出明确汇总和一键重试。

### 1.3 `TTS55-POOL-FINAL`

- 使用 VoiceGenerator 生成并由 Nano 技术验证现有 24 个通用音色槽，形成一个本机 workspace 级、`zh-CN`、可复用且不可被私人音色删除误删的系统音色包。
- 每个槽位拥有独立 seed、描述 digest、双模型证据、参考音频 hash、Nano 验证和状态；只允许逐槽串行生成。
- 有正式人物卡的人物优先使用专属音色；无人物卡或临时人物使用通用音色池；旁白始终使用 Junhao。
- 自动选角只依据已保存的明确证据。不能仅凭姓名猜年龄或声音性别；证据不足时使用中性槽。
- 24/24 全部机器验证、真实章节使用和作者抽样听检完成后，才能表述“通用音色池完成”。

只有三个终点分别通过，才允许表述为“本轮全局默认与自动音色闭环完成”。

## 4. 人物卡自动专属音色准备

### 4.1 单击流程

```text
点击章节“智能朗读”
→ 创建或恢复内部 analyze_only Narration Request
→ 复用现有 analyze_narration_script，冻结 Script Version 与本章实际说话人
→ 创建或恢复 VoicePreparationCommand，并关联 preflight Request／Script Version
→ 读取服务端权威人物名单、人物工作区 digest 和绑定 CAS
→ 保留私人／上传／已有专属音色
→ 本章实际说话人优先，其后按主角、配角、稳定人物 ID 排队
→ 对其余有正式人物卡的人物逐个复用 VoiceGenerator
→ 每人完成 VoiceGenerator → 卸载 → Nano 验证 → CAS 绑定
→ 必要时为失败／无绑定人物执行可见的官方音色匹配兜底
→ 通用槽准备或选择
→ 本章所有说话人均有可用声音后，重新校验章节 draft version、content hash 与 settings version
→ 使用持久 continuation idempotency key 自动创建正式 Narration Request
→ 记录最终 Request ID；其余人物继续在后台串行准备
```

前端只触发一次 VoicePreparation 创建接口；analyze-only preflight 由服务端领域服务创建，后续由持久命令与 worker 推进，不能依赖浏览器循环或客户端串联两个请求才能完成。命令持久化原始作者动作的 actor、`explicit_requested_at`、外部 `Idempotency-Key` 摘要和固定 mode，作为自动创建正式 Narration Request 的授权证据；关闭页面不会取消命令。

父命令可以仍处于 `preparing`，但响应会独立发布 `chapter_ready` 和 `background_remaining`。章节衔接只等待当前章节实际引用的说话人，不等待整本书所有人物；这样既保证当前 Edition 使用已准备的专属音色或明确兜底，也不会让后台全书准备阻塞写作。

preflight 使用当前公开 `analyze_only` 能力，不复制 segmentation、speaker attribution 或 casting 代码。说话人摘要 digest 只由 Script Version 中按序排列的段落 ordinal、segment kind、正文 source range、speaker kind 以及 character／anonymous stable identity 计算；明确排除 voice profile/version、settings、匹配分数、问题提示和处理状态，避免声音绑定本身令摘要自我漂移。正式 Request 仍执行现有分析并校验相同 document revision、content hash 和该确定性摘要；结果漂移时转为 `superseded`，不创建 Edition。内部 preflight 作为审计记录保留，但不在页面显示成第二条朗读任务。

自动续接采用数据库唯一键和 fence：只有仍持有当前 preparation attempt/fence、章节 CAS 未变化且 continuation 状态仍为 `pending` 的 worker 可以写入 `creating`；正式 Request 创建与回写 request ID 必须共享可重放的 continuation key。崩溃或响应丢失后，新 worker 只能找回同一 Request，不能再创建第二条；最终 Request ID 一经持久化不可替换。

### 4.2 选择与覆盖规则

优先级固定为：

`作者上传／私人音色 > 已有专属生成音色 > 本轮新专属音色 > 官方匹配音色 > 通用音色 > 中性兜底`

- 只处理 active、已保存且属于当前小说权威人物目录的人物。
- 官方音色可以在新专属音色验证成功后被替换；CAS 漂移时生成结果进入 `ready_unapplied`，不得覆盖作者新选择。
- 没有可评分证据时不从姓名、职业或刻板印象补全声音特征。
- 同一人物卡 digest、模型 revision、参数和 seed 命中相同 fingerprint 时复用已验证 Version，不重复运行重模型。
- 人物卡更新不自动改变音色连续性；UI 显示“人物资料已更新”，只有显式“重新生成”才创建新版本。

### 4.3 父命令状态

命令状态：

`reserved → preparing → ready | ready_with_warnings | failed | cancelled | superseded`

目标状态：

`pending | preserved | queued | generating | ready_applied | ready_unapplied | fallback_official | failed | cancelled`

统一响应至少包含：

- `server_now`、`progress_current`、`progress_total`；
- `preflight_request_id`、`preflight_script_version_id`；
- `chapter_ready`、`background_remaining`、continuation 状态和自动创建的 Narration Request ID；
- 当前目标、可取消／可重试／是否终态；
- preserved、generated、fallback、failed 的人物摘要；
- 稳定 `failure_code`，不返回完整人物工作区或 VoiceGenerator instruction；
- 关联的既有 VoiceGenerator command ID 和最终 binding/version ID。

每个目标独立 CAS、独立成功，不采用“所有人物全部成功后才一次绑定”。原因是重模型任务耗时长，已验证结果不应因另一人物失败而丢弃；但失败目标必须保持原绑定不变。

取消语义固定为：正式 Narration Request 尚未创建时，取消会阻止自动续接并停止领取新人物；正式 Request 已创建后，取消只停止剩余的后台人物准备，不反向取消正在播放或渲染的朗读任务。已成功绑定的声音不回滚。

## 5. 24 槽通用音色包

### 5.1 不重复建立分类体系

继续使用 `backend/narration/resources/voice_pool_v1.json` 的 24 个 slot key，不新增第二份年龄／性别表：

- 女童、少女、青年女性三种、中年女性两种、老年女性两种；
- 男童、少年、青年男性三种、中年男性两种、老年男性两种；
- 青年／中年中性、男女播报、男女群体。

“青年”包含既有少女／少年和 young-adult 分类。产品文案可显示小孩、青年、中年、老年，数据库继续保留稳定 slot key。V1 只生成 `zh-CN` 包，pack identity、design fingerprint、Profile Version 和小说投影都必须带语言；英文和日文继续使用同语言官方音色，不自动跨语言使用中文通用包，后续语言包需另行立项。

### 5.2 workspace 级资产、小说级投影

- 真实生成的 24 个 VoiceProfile 使用 `novel_id = NULL` 的 workspace library scope，只生成一次，不随每本小说重复占用模型和媒体。
- 新增 workspace 级不可变 GenericVoicePackVersion 和 24 条 PackVersionSlot；生成进度可以逐槽持久化，但只有同一 pack version 达到 24/24 后才能原子激活。
- pack 激活后，每本中文小说在首次需要时一次性物化完整的现有 `GenericVoicePool`／24 条 `GenericVoiceSlot` 投影，slot 指向同 workspace、已机器验证的 library Voice Version；不创建部分小说级 Pool。
- 每个小说级 Pool 必须以受约束的 `source_pack_version_id` 和 language 指回唯一 workspace Pack Version。新 Script 的 resolver 只接受当前 active、未拒绝、同语言 Pack 的投影；active pack 更换后按小说惰性创建下一版完整 Pool。旧 Pool 只供历史 Edition 的既有外键读取，不能再次参与新选角。
- Edition 解析只在 `speaker_kind=anonymous|group|unknown` 且存在当前小说有效 slot 投影时接受 library profile；旁白和正式人物绑定仍必须是该小说 scope，禁止借此放宽所有声音范围。
- 通用包版本不得进入普通私人音色删除入口。首次构建期间拒绝某槽，只把当前候选标为不可激活并创建继任候选；继任候选复用所有仍被接受且 fingerprint 一致的已完成槽，未完成槽继续排队，不要求复制并不存在的 23 槽。已有 active pack 时拒绝某槽，立即把整包标为 `retired_for_new_use`、撤销 `automatic_generic_casting` 并禁止它进入新 Script／Edition；随后复制其余 23 个不可变 slot 创建候选 Pack Version。替代槽验证成功且新包达到 24/24 后再原子切换 active pack。已冻结 Edition 始终继续引用旧 Version。

Pack Version 状态固定为：

`building → ready_to_activate → active → retired_for_new_use`

候选还可进入 `rejected | failed | superseded`；slot 状态固定为 `pending | generating | validated | reused | rejected | failed`。同一 language 最多一个 `active`，激活事务必须先校验 24 个唯一 slot、rights、Nano 技术验证、模型证据和 media hash，再切换 active identity；任一失败不改变旧 active。普通 regenerate 不立即退役仍可接受的旧 active，只创建候选；只有 reject 才会立即禁止旧包用于未来新章节。

### 5.3 生成与调度

- 固定一槽一个 GenericVoiceDesignDraft，描述模板来自受版本控制的本地目录，不调用第二个 AI Agent，也不使用第三方人物声纹。
- 复用计划 40 的原生 VoiceGenerator、重模型互斥、一次性进程、watchdog、模型 identity、Nano 验证和媒体存储。
- 交互式人物专属音色优先于后台通用包；通用包每完成一槽即释放模型和租约，再由调度器领取下一槽。
- 首次智能朗读若通用包尚未完成，当前章节使用明确标记的同语言官方兜底，不阻塞已有可用朗读；后台继续构建。只有 active pack 达到 24/24 后创建的新 Edition 才使用通用槽，不使用部分生成结果。
- `generic_voice_pool` 在 schema、构建服务和状态投影就绪时可见并允许继续构建，即使当前为 missing/building；`automatic_generic_casting` 是全局运行能力，必须等待一个未被拒绝且未退役的 `zh-CN` active pack 达到 24/24、原子投影服务与 resolver 全部就绪才 actionable，不以某一本小说是否已物化 Pool 决定。每次为小说选角前再原子创建或验证该小说的完整当前投影；失败时该次请求使用带稳定原因码的同语言官方兜底，不把全局能力误报为失效。

系统生成音色不涉及第三方参考录音；每槽仍必须保存 `source_kind=voice_generator`、模型与用途 provenance、媒体 hash 和本机私用范围。现有 Pool 契约中的 `rights_approved` 表示来源与用途记录完整，`quality_approved` 表示 Nano 机器技术验证通过，不冒充作者主观满意；作者听检结果单独记录为产品验收证据。

### 5.4 证据到槽位

- 正式人物卡存在：走专属音色，不走通用池。
- 无人物卡但正文／结构化记录明确给出年龄段与声音 presentation：选择对应槽。
- 只明确年龄或只明确 presentation：选择相应中性或最少假设的基础槽。
- 两者都未知：只在中文 active pack 完整时使用 `neutral_young`；否则使用明确标记的同语言官方兜底，不得根据姓名猜测。
- 群体对白：仅在群体 presentation 明确时使用 `crowd_female`／`crowd_male`，否则使用中性兜底。两个槽位都是“未具名群体台词共用的一条单人代表声线”，不是多人合声；当前单声线 VoiceGenerator/Nano 链不得在产品文案或生成描述中暗示能合成多人同时说话。

## 6. 公共契约、API 与迁移

### 6.1 能力契约

升级为 `narration-capabilities/4`：

- `voice_generator`：继续代表单人物生成基础能力；
- 新增 `automatic_character_voice_generation`：要求 `0040` schema、人物工作区、VoiceGenerator 全依赖、父命令 processor／reconciler 和章节衔接服务全部就绪；
- `generic_voice_pool`：加入 `NarrationFeatureReadinessProvider` 管理；
- `automatic_generic_casting`：加入同一 provider 管理，并额外要求 active 24 槽完整、casting resolver 与 projection service 就绪；单本小说尚未物化投影不是全局 unavailable 条件。

前端在滚动升级期间只为兼容读取 `/3`，并把新增动作隐藏；后端新包只发布 `/4`。不得用缺键默认 true 或仅凭 HTTP 路由存在开放按钮。

关闭、重模型 host 失联、Nano 失联、worker／reconciler 崩溃或 schema sentinel 缺失时，先撤销相应 capability，再停止领取新任务。

provider 的 `degraded` 固定表示“至少一个 optional capability 暂不可用”，不是整个 TTS 停止：

- 通用包 missing/building 时只让 `automatic_generic_casting` unavailable；已就绪的单人物 VoiceGenerator、Nano 高级调音和私人音色删除保持各自状态。
- `generic_voice_pool` 表示构建与状态管理服务可用，不等于已经拥有 active pack；数据状态由 `generic-voice-pack/1` 返回。
- PawApp 和 narration production runtime 的总健康不因 optional pack 尚未生成而变为不可用；路由必须逐 capability gate，不能只判断 snapshot lifecycle。
- provider shutdown、共享 scheduler 崩溃或底层存储失效时，仍按受影响范围同步撤销；只有共享依赖失败才统一 fail closed。

### 6.2 新契约

- `narration-voice-preparation-request/1`
- `narration-voice-preparation/1`
- `generic-voice-pack/1`
- `generic-voice-generation-command/1`

客户端不得提交人物名单、整包 slot 列表、人物摘要或绑定版本；这些都由服务端在创建命令时读取并冻结。单槽 reject／regenerate 只允许通过受控 path `slot_key` 指定目标，并由服务端核验它属于当前目录和 expected Pack Version。

### 6.3 API

小说声音准备：

- `GET /novels/{novel_id}/voice-preparation-commands`
- `POST /novels/{novel_id}/voice-preparation-commands`
- `GET /novels/{novel_id}/voice-preparation-commands/{command_id}`
- `POST .../{command_id}/retry`
- `POST .../{command_id}/cancel`

创建请求只允许固定 mode、可选 `document_id` 和章节 CAS；使用 `Idempotency-Key`。全书人物配音页和章节智能朗读复用同一命令，不各写一套循环。

workspace 通用包：

- `GET /voice-library/generic-pack`
- `POST /voice-library/generic-pack/build-commands`
- `GET /voice-library/generic-pack/build-commands/{command_id}`
- `POST .../{command_id}/retry`
- `POST .../{command_id}/cancel`
- `POST /voice-library/generic-pack/slots/{slot_key}/regenerate`
- `POST /voice-library/generic-pack/slots/{slot_key}/reject`

build、regenerate 使用 `Idempotency-Key`；reject 不接受无实际持久化用途的幂等请求头，而由 `expected_pack_version_id`、受控 `slot_key` 和单调状态转换保证重复调用安全。首次候选的 reject 阻止该候选激活；active pack 的 reject 同一事务把整包退役并撤销未来自动选角资格，但不物理删除 Voice Version、已有小说投影或历史媒体。regenerate 创建新候选 Version，不覆盖旧版本；新候选完整前，新章节只使用同语言官方兜底。

所有路由继续位于 PawApp `/api/ai-novel-world-2026` 命名空间，不修改 QwenPaw 上游路由。

### 6.5 `TTS55-C0` 冻结项

- job kind：父命令使用 `narration.voice_prepare`；单人物继续复用 `narration.voice_generate`；通用槽使用 `narration.generic_voice_generate`。三者共享现有重模型互斥，但不共享幂等空间。

- scope：VoicePreparation 必须是 novel scope；通用 Pack／生成命令必须是 workspace＋language scope；小说 Pool 投影必须是 novel＋source Pack Version scope。
- VoicePreparation 创建 mode 固定为 `prepare_missing_dedicated`。`document_id` 为空时只准备全书人物；存在时同时冻结章节 CAS、执行服务端 preflight，并在成功后自动续接正式 Narration Request。

## 9. 测试与验收

### 9.1 自动化

必须覆盖：

- 普通建书与向导建书都以 Junhao 初始化；初始化失败整书回滚；作者后续手动更换不被回正。
- 父命令幂等、刷新恢复、重启恢复、取消、部分失败、重试和 superseded。
- analyze-only preflight 先于人物优先级计算；相同章节 CAS 复用同一 preflight，相同 continuation key 只能创建一个正式 Narration Request。
- 两个 worker 同时续接、响应丢失后重放和 continuation 提交后崩溃均返回同一 Request；正文、说话人摘要或 settings 漂移时零重复 Request／Edition。
- 有人物卡自动生成；无卡不冒充人物专属；姓名不参与年龄／presentation 猜测。
- 官方音色仅在新专属版本验证成功后替换；私人／上传／已有专属永不覆盖；CAS 漂移进入 `ready_unapplied`。
- VoiceGenerator 与 Nano 驻留重叠为 0；一次只领取一个重模型任务；通用包低于交互任务优先级。
- 24 个 slot key 完整、唯一、有设计 digest；不同槽不串 fingerprint，相同输入可复用。
- V1 pack 只允许 `zh-CN`；英文／日文小说不得绑定中文通用槽，也不得静默跨语言降级。
- 0..23 个槽完成时不创建 active 小说级 Pool；24/24 后一次性物化，任一 slot/FK/rights 失败整批回滚。
- 初次构建 reject 可复用已完成且未被拒绝的槽；active pack reject 会立即阻止旧包进入新 Script／Edition并撤销自动通用选角，旧投影和历史 Edition 仍保持可读；新包完整前不部分切换。
- build、reject、regenerate 重复调用、响应丢失与双 worker 并发均只产生一个单调结果；错误 expected pack version 不改变 pack 状态。

## 10. 部署、恢复与数据边界

- 长期部署前备份数据库，记录媒体清单/hash、旧包 hash、bundle hash、镜像 digest、模型 revision 和迁移 head。
- 0040 部署后先保持 `generic_voice_pool`／`automatic_generic_casting` fail closed，再启动后台生成；不能因空表存在就开放能力。
- `generic_voice_pool` 构建服务完成启动自检后可以开放管理界面；`automatic_generic_casting` 仍须等中文 active pack 24/24、原子投影服务和 resolver 就绪，二者不得共用一个布尔值。单本小说的完整投影在首次使用时创建，不反向控制全局 capability。
- 真实写入验收只使用隔离小说和隔离数据库；长期小说部署后先做设置、能力和页面只读核验。
- 已生成通用包后不强制降 0040；故障时关闭自动准备与自动通用选角，保留声音资产和历史 Edition。
- 终止后台构建时停止领取新槽，已持久化目标由下次启动继续；不得删除 PostgreSQL/QwenPaw 卷或批量清理媒体。
- 默认旁白回退方式是部署旧兼容代码并让新书继续显式选择；不得改写已经存在的历史 Edition。

## 11. 复查结论

本计划已经排除以下错误方向：

- 不让章节前端循环点击六个人物按钮来冒充可靠批量任务。
- 不同时加载多个 VoiceGenerator，不与 Nano 同时常驻。
- 不为通用音色创建伪造人物卡，也不按小说重复生成同一套 24 音色。
- 不新增第二个 AI Agent、第二个模型选择器或第二份年龄／性别目录。
- 不根据姓名猜年龄和声音 presentation。
- 不静默覆盖私人、上传、既有专属音色或作者并发选择。
- 不用数据库 migration 运行模型、回填媒体或制造业务审计记录。
- 不在 `0039` 稳定交接前提前创建 `0040` 双头；当前该前置已满足且 `0040` 尚不存在。
- 不把机器验证写成作者已经满意，也不把部分槽位写成完整通用包。
- 不让说话人摘要包含随后必然变化的音色或设置字段，也不让被拒绝的 active pack 继续进入新章节。

终审裁决：**计划 52 与 `0039` 已稳定交接，`TTS55-G0/C0=PASS`，方案具备并已满足源码开工条件。下一步从默认旁白候选复核和 W1 独立模块开始；人物自动生成与通用音色包必须继续按持久命令、逐目标 CAS 和单重模型队列实施。**

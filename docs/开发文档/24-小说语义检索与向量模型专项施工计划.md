## 1. 冻结结论

### 1.1 首个生产配置

| 项目 | 冻结值 | 说明 |
| --- | --- | --- |
| 服务商 | 阿里云百炼 | 首期不支持第二供应商 |
| 协议 | `dashscope-native-v1` | 使用 DashScope 原生 HTTP API，不走 OpenAI 兼容接口 |
| Base URL | 由项目设置页填写 | 例如 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1` |
| 模型 | `qwen3.7-text-embedding` | 单一 active 模型；未来版本通过候选配置升级 |
| 请求维度 | `1024` | 当前官方默认维度，首期固定 |
| 输出 | `dense` | 首期不存 sparse vector |
| 正文角色 | `text_type=document` | 对当前有效不可变 revision 的分块建索引 |
| 查询角色 | `text_type=query` | 用户或 Agent 的检索词只在查询时向量化 |
| 查询指令 | VR0 小说样本验收后冻结 | 仅查询侧生效，优先英文；未通过评测则不启用 |
| 距离度量 | cosine | pgvector 使用余弦距离；分数换算和阈值必须测试 |
| 内部请求批次 | `10` 条 | 官方上限写 20，但示例仍使用 10；先取保守值 |
| 向量存储 | 现有 PostgreSQL + pgvector | 不新增专用向量数据库 |
| 模型运行容器 | 无 | 云端推理，不增加 Ollama/TEI/Embedding Docker 容器 |

### 1.2 固定供应商不等于永久硬编码模型

产品只提供一个 active 向量模型，不提供日常模型下拉框、逐小说供应商选择或静默回退。未来阿里云发布更新版时，所有者可以在同一设置页填写候选模型 ID 和候选维度；系统必须完成连接验证、实际维度校验、固定样本回归和候选索引重建，成功后才能原子切换。

接口协议若仍为 DashScope Native，则复用同一个 `DashScopeEmbeddingAdapter`；协议发生不兼容变化时必须重新立项，不能在通用适配器里堆供应商分支。

## 2. 已核实的阿里云规则与项目解释

官方依据：

- [通用文本向量同步接口 API](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api/)
- [向量化模型、text_type、instruct 与 dense/sparse 说明](https://help.aliyun.com/zh/model-studio/embedding)
- [API Key 配置与安全说明](https://help.aliyun.com/zh/model-studio/get-api-key)
- [模型限流](https://help.aliyun.com/zh/model-studio/rate-limit)
- [合规资质与隐私说明](https://help.aliyun.com/zh/model-studio/privacy-notice)

### 2.1 请求契约

原生 HTTP endpoint 为：

```text
POST {base_url}/services/embeddings/text-embedding/text-embedding
```

请求形状冻结为：

```json
{
  "model": "qwen3.7-text-embedding",
  "input": {"texts": ["..."]},
  "parameters": {
    "text_type": "document",
    "dimension": 1024,
    "output_type": "dense"
  }
}
```

查询请求把 `text_type` 改为 `query`，并只在 VR0 通过后附加固定 `instruct`。领域字段统一叫 `dimension`；OpenAI 兼容接口的 `dimensions` 复数形式不进入本适配器。

成功响应必须校验 `status_code`、`request_id`、`output.embeddings[*].text_index`、向量数量、每条实际维度及 `usage.total_tokens`。只记录请求 ID、Token 用量、延迟、错误类别和摘要，不记录正文、查询原文、完整向量或密钥。

### 2.2 当前模型能力

`qwen3.7-text-embedding` 当前官方列出的维度为 `256/512/768/1024/1536/2048/2560`，北京地域最多 20 条输入、单条最多 128,000 Token。模型上限不是分块目标；小说检索仍需按段落和语义边界生成远小于上限的块。

官方页面当前存在三处内部不一致：模型表和请求规则写最多 20 条，但部分原生 SDK 示例把批次写为 10；维度说明正文的限定标记与模型表排版冲突；请求能力说明 qwen3.7 支持 sparse，但部分响应字段说明仍只列 v3/v4。首期通过 `1024 + dense + 批次10` 避开这些矛盾，并在 VR0 用非敏感合成文本实测实际返回，不从文档排版推断能力。

### 2.3 查询与正文角色

- 正文分块固定 `text_type=document`；正文侧不使用 `instruct`。
- 查询固定 `text_type=query`；`instruct` 仅影响查询向量且会重复计入输入 Token。
- 查询指令、Top-K 或融合权重变化只改变查询策略，不使已存正文向量失效；必须做检索回归，但不全量重建正文向量。
- 模型、实际 revision、维度、正文 text_type、输出类型或分块规则变化会改变索引空间，必须新建候选 generation 并重建。

### 2.4 时效性、成本与隐私

北京地域当前实时价格为每千输入 Token 0.0005 元；当前限流为 24,000 RPM、1,000,000 TPM。价格、免费额度和限流只在 UI 帮助文案中显示核验日期，不作为业务常量或费用承诺。

阿里云当前声明按量付费 API 数据不用于模型训练，同时明确会依法存储模型与应用调用产生的数据。启用前必须明确告知作者：被索引的小说正文分块会离开本机并发送到配置的阿里云 Base URL。撤销云端授权后立即停止新请求；已生成的本地派生向量是否保留由作者另行选择，不能静默删除。

官方当前没有为该向量模型列出日期快照型模型 ID，API 响应也不能保证提供底层不可变 revision。因此需要保存固定非敏感哨兵文本的向量摘要；连接地址或模型服务发生变化时重新生成并比较，变化后不得继续混用旧索引。

## 3. 目标与非目标

### 3.1 本专项目标

1. 建立项目自有、可审计的阿里云向量配置页和 DashScope 原生适配器。
2. 对当前有效不可变 revision 做可恢复、幂等、增量的正文分块与 Dense 向量索引。
3. 在小说范围、当前 revision、profile generation 和文档类型过滤后做 cosine 语义检索。
4. 保留现有词面搜索，并通过 VR0 数据裁决 Dense-only、词面-only 与混合排序方案。
5. 支持候选模型/维度的测试、全量重建、原子激活和失败回退。
6. 云端、数据库或任务失败不得改变 working copy、不可变 revision、候选、故事账本或当前正文指针。

### 3.2 首期明确不做

- 不接入 Ollama、TEI、OpenAI 兼容接口或第二云供应商。
- 不复用 QwenPaw ReMeLight 的私有 Embedding 配置、内部对象、路由或数据库。
- 不新增模型推理容器、向量数据库、消息队列、第二套 Agent Runtime 或通用模型中心。
- 不把 Embedding 用于生成正文、总结、事实裁决或自动写回。
- 不索引每次按键、未同步草稿、未采用候选或未授权内容。
- 不首期实现 sparse vector、dense&sparse 检索、reranker、HNSW/IVFFlat 或跨模态检索。
- 不允许按小说、聊天或查询临时切换模型。
- 不承诺未来阿里云接口、模型别名、价格或向量空间永远不变。

## 4. 架构与上游边界

```text
PawApp「向量检索与索引」设置页
  -> 项目公开 API
  -> EmbeddingConfigurationService
       ├─ 非密钥配置与 CAS 版本
       └─ EmbeddingSecretStore（只写不回显）

不可变 current revision
  -> paragraph-aware chunker
  -> embedding generation / batch
  -> 持久 background job
  -> DashScopeEmbeddingAdapter
  -> 阿里云百炼 DashScope Native API
  -> novel_chunks + pgvector

用户或 Agent 查询
  -> 服务端小说/工作区范围校验
  -> query vector（text_type=query）
  -> current revision + active generation 精确 cosine 检索
  -> 词面通道与候选融合
  -> 带 document/revision/chunk 证据的结果
```

QwenPaw 继续负责聊天 Provider、Agent、Skills、MCP、工具和原生设置。小说 PawApp 只使用公开扩展点，自己的 Base URL、API Key、模型和索引均位于本项目边界。禁用或卸载 PawApp 后不得残留路由包装、工具或任务执行器；不得删除 QwenPaw 数据卷、小说正文或 PostgreSQL 数据。

## 5. 配置页面与 API Key

### 5.1 页面字段

页面位于小说 PawApp 自己的设置区域，暂定名称“向量检索与索引”，不占用 QwenPaw 全局模型页面。字段与状态：

| 字段 | 行为 |
| --- | --- |
| 服务商 | 只读：阿里云百炼 |
| 协议 | 只读：DashScope Native |
| Base URL | 可编辑；保存前规范化、SSRF 校验和连接测试 |
| 推导地域 | 从 Base URL 只读显示，不单独编辑 |
| API Key | password 输入；空值表示保持，替换和清除必须显式操作 |
| 模型 ID | 当前为 qwen3.7；新值先进入 candidate |
| 请求维度 | 当前 1024；候选值以真实返回校验为准 |
| 连接状态 | 未配置/验证中/可用/限流/认证失败/协议错误 |
| 索引状态 | 未建立/排队/构建中/可用/部分失败/已过期 |
| 操作 | 测试连接、保存候选、重建、取消、激活、回退 |

读取 API 永远不返回密钥明文，只返回 `api_key_configured`、可选末四位和更新时间。浏览器不得把密钥写入 LocalStorage、IndexedDB、崩溃草稿、日志或遥测。

### 5.2 密钥存储门禁

设置页配置 API Key 已冻结，但后端存储实现必须先通过 `VR0-SECRET`：

1. 只采用 QwenPaw 已公开且经真实版本验证的 PawApp Secret API；不能猜测或读取私有配置。
2. 若没有可用公开契约，使用项目自有加密 secret record；密文、nonce、算法版本、末四位和更新时间可入库，加密根密钥必须位于数据库之外的项目专用 secret mount/文件。
3. 禁止明文表、可逆固定密钥写入源码、把 API Key 哈希当向量 fingerprint、在异常中回显认证头。
4. 根密钥丢失时只要求作者重新输入 API Key，不影响正文和已生成向量；密钥轮换不触发重建。
5. 若项目自有加密需要新增 `cryptography` 等直接依赖，必须在 VR0-SECRET 说明必要性、固定版本、许可证、宿主 Python 3.11 兼容、镜像增量和无新依赖替代方案；不得依赖未声明的传递包。

### 5.3 Base URL 校验

- 只允许 HTTPS 和经核验的阿里云百炼官方域名；禁止 URL userinfo、query 中密钥、localhost、回环、链路本地、私网及解析后落入私网的地址。
- 首期只接受以 `/api/v1` 结束的原生 Base URL；拒绝 `/compatible-mode/v1` 和用户粘贴的完整 embeddings endpoint，页面给出可修正提示。
- Base URL 与 API Key 必须一起做真实连接测试；认证失败不能保存为 active。
- Base URL 变化先进入 candidate，并执行哨兵向量比较；无法证明向量空间一致时按需要重建处理。

## 6. 配置身份与切换规则

旧计划把所有设置放进同一个 fingerprint，导致查询策略变化也触发全量重建。新方案拆成三层：

### 6.1 `service_connection`

包含规范化 Base URL、credential reference、超时、重试与连接状态。它决定如何访问服务，不直接等同于向量空间。

### 6.2 `index_fingerprint`

至少包含 provider/protocol、请求与实际模型、可获得的 revision、请求与实际维度、`output_type=dense`、`document` 角色、cosine、存储类型、chunker schema/version 和规范化规则。fingerprint 变化必须建立新 generation，禁止原地篡改 ready generation。

### 6.3 `query_policy_version`

包含 `query` 角色、可选 instruct、Top-K、词面/向量融合算法、权重、阈值与结果裁剪。变化需固定评测集回归，但不使正文向量自动失效。

| 变化 | 连接测试 | 检索回归 | 正文向量重建 |
| --- | :---: | :---: | :---: |
| 仅 API Key 轮换 | 是 | 否 | 否 |
| Base URL/Workspace 变化 | 是 | 是 | 哨兵或实际 revision 变化时是 |
| 模型 ID/实际 revision 变化 | 是 | 是 | 是 |
| 维度变化 | 是 | 是 | 是，并重建相关数据库索引 |
| document text_type、output_type、chunker 变化 | 是 | 是 | 是 |
| query instruct、Top-K、融合权重变化 | 否 | 是 | 否 |

切换状态机固定为：

```text
draft -> testing -> candidate -> rebuilding -> ready -> active
                    |              |           |
                    v              v           v
                  invalid        failed      retired
```

任意时刻每个 owner/workspace 只能有一个 active generation。新 generation ready 前旧 generation 继续提供检索；失败不自动降级到未验证模型，也不清除旧索引。

## 7. 数据与任务设计

### 7.1 当前实现事实

- `novel_chunks` 已在最早迁移中预留 `revision_id`、字符串 `embedding_profile`、`chunk_index`、`content_text`、`content_hash` 和无固定 typmod 的 `VECTOR()`；当前没有真实向量生成服务。
- `search_novel()` 当前只对 `DocumentWorkingCopy.content_markdown` 和标题执行 `ILIKE`，不能表述为已实现语义检索。
- TTS 施工正在新增共享 `background_jobs`、attempt、resource policy 和 `model_run_records`；其迁移链从 `0010` 起仍在滚动，本次文档更新期间已经观察到后继 `0013`。向量施工不得写死下一编号，必须在 TTS 门禁后重新发现最终 head。

### 7.2 数据库原则

- 不改写 `20260823_0001_mvp0_ledger.py`；任何 schema 变化新建后继 Alembic revision。
- 向量迁移编号只在 TTS 迁移链通过门禁并冻结 head 后分配，禁止与仍在滚动的 TTS 迁移并行抢 migration head。
- 保留现有 `novel_chunks` 数据和兼容字段；是否增加 profile/generation FK、独立 batch 表或拆分 embedding 表，由 `VR1-SCHEMA` 在真实数据审计后冻结，不能先删除旧列。
- current revision、novel、owner/workspace、profile generation、chunker 和实际维度必须能由数据库约束或查询条件共同验证。
- 向量是可重建派生数据；正文、revision 和当前指针是权威数据，外部调用不得占用长事务。

### 7.3 任务粒度

为兼容共享 `model_run_records` 的“一次 attempt 对应一次模型调用”约束，远程调用按最多 10 个 chunk 的 `embedding.index_batch` job 拆分。generation 协调器只规划批次；每个批次 attempt 恰好发起一次 DashScope 请求，并在短事务中写入整批结果或保持可重试状态，禁止半批次悄悄标 ready。

任务必须具备：内容哈希与 profile 的幂等键、租约、attempt、指数退避、`next_retry_at`、取消、dead-letter、进度和不含正文的错误分类。429、5xx、超时和短暂网络错误可重试；401/403、协议错、维度错和安全校验失败必须停止自动重试并要求修正配置。

## 8. 分块、索引和检索

### 8.1 分块候选与门禁

VR0 用授权合成中文小说材料比较段落感知的候选区间，不把 128K 模型上限当块大小。首轮候选为约 600–1,200 个中文字符、100–200 字重叠，并保留标题、段落序号、原文字符范围和稳定 chunk hash。最终值由 Recall@5、MRR、上下文完整度、重复召回和成本共同裁决。

同一 revision + chunker version 必须生成完全相同的边界与 hash。标题、空白、Markdown 规范化规则发生变化必须提升 chunker version。

### 8.2 索引来源

- 默认只索引当前有效不可变 revision；未采用候选和逐键 working copy 不进入云端索引。
- 接受新 revision 的事务只登记派生任务，不在事务中调用阿里云。
- 新 revision ready 后普通语义检索只返回当前指针仍指向该 revision 的块；旧 generation/revision 可保留用于回退和审计，但不混入普通查询。
- 全量重建从权威 revision 重新分块，不依赖旧向量作为输入。

### 8.3 查询与混合排序

1. 服务端先校验 owner/workspace/novel 范围和查询长度。
2. 使用 active profile 生成一个 `text_type=query` 向量。
3. 仅在同 novel、current revision、active generation、实际维度和允许文档类型内执行 pgvector cosine 精确扫描。
4. 混合排序的词面通道必须搜索与向量通道相同的 current revision chunk 语料；VR0 比较词面-only、Dense-only 和 RRF/其他确定性融合，不直接混加不可比的原始分数。
5. 返回 document、revision、chunk、字符范围、snippet、match channel 和可解释分数；禁止返回其他小说、历史 revision、候选或隐藏资料。
6. 现有 working-copy/title `ILIKE` 保留为兼容与故障降级通道，但不得与不同 revision 的向量结果混排；响应必须标明 `source_state=working_copy` 或 `source_state=current_revision`。云端不可用时只返回明确标注的词面结果，正文保存、采用、恢复和聊天继续工作。

个人小说规模首期不建立 HNSW/IVFFlat。只有真实 chunk 规模和查询 P95 超出门槛时，另行批准固定 1024 维索引；不得为了索引方便截断向量。

## 9. API 与前端契约冻结点

具体字段由 `VR1-CONTRACT` 冻结后才能并行写前后端。最小公开能力：

```text
GET    /api/ai-novel-world-2026/embedding-config
POST   /api/ai-novel-world-2026/embedding-config/test
PUT    /api/ai-novel-world-2026/embedding-config/candidate
POST   /api/ai-novel-world-2026/embedding-index/rebuild
POST   /api/ai-novel-world-2026/embedding-index/cancel
POST   /api/ai-novel-world-2026/embedding-index/activate
GET    /api/ai-novel-world-2026/embedding-index/status
```

所有写操作使用 CAS version 和幂等键。测试连接默认发送项目内置非敏感短句；只有作者明确开启云端索引并确认发送范围后，才允许重建真实正文。

前端必须覆盖：首次未配置、密钥替换/清除、错误 Base URL、测试中、认证失败、限流、candidate、重建进度、取消、旧索引继续服务、激活、回退、无向量的词面降级、窄屏、键盘、焦点和读屏状态。

## 10. 安全、隐私与恢复

- URL、Header、日志、数据库错误、前端状态、证据和测试 fixture 均不得出现真实 API Key。
- 正文和查询不得写普通日志；输入审计只保存带 key version 的摘要和字符/Token 计数。
- 云端测试默认只用非敏感合成文本；真实小说 E2E 需作者当次明确授权、限定小说和预算。
- 查询和索引均强制服务端 scope；模型传入 novel/document ID 不能替代 owner/workspace 校验。
- 禁用语义检索停止新云调用并回退词面；不会删除正文、revision 或 QwenPaw 数据。
- 清除 API Key 不删除本地向量；清理派生向量是独立、明确、可恢复的操作。
- 卸载 PawApp 不删除 PostgreSQL 数据卷；完整卸载只注销项目路由、工具、Skills、任务执行器和公开设置接线。
- 外部失败不得令正式正文写入失败；索引任务可从 revision 和配置快照重建。

## 13. 与当前任务的冲突和工作树策略

- 当前工作区有 TTS、中央 Diff、Skills 等未提交改动；向量代码不得在此脏工作树直接施工。
- 获批施工并满足 TTS schema 门禁后，主代理从双方认可的稳定提交创建 `codex/vector-retrieval` 和独立 worktree；额外文件夹只隔离 Git 文件，不隔离 Docker 卷、数据库、浏览器、端口或云费用。
- TTS 是当前 Alembic head、`background_jobs`、`model_run_records` 和 `backend/models.py` 的唯一 Owner；向量 VR1-SCHEMA 必须等待其接口和迁移通过门禁，不能并行创建另一条迁移分支。
- 配置页可以在 DTO 冻结后与 adapter 并行，但共享前端入口和全局样式由唯一集成 Owner 串行修改。
- 不主动暂存、提交或推送；这些动作需要用户单独授权。

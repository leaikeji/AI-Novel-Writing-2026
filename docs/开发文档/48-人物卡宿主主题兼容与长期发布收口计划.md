### 1.4 V1.1 计划自查修正

1. V1.0 只把 `character-workspace.ts` 和来源查看器列入焦点改造范围，但触发按钮实际位于 `character-state-panel.ts` 与 `character-fact-history.ts`，修正／批次抽屉位于 `character-fact-correction.ts`。V1.1 将这些文件纳入唯一焦点工作包，要求从事件 `currentTarget` 显式传递触发器，不依赖可能已被浏览器清空的 `document.activeElement`。

## 2. 目标、非目标与硬约束

## 3. UI 与主题兼容设计

### 3.1 建立人物卡局部浅色 token

在 `.anw-character-workspace-dialog` 内冻结一组 PawApp 自有 token：

```text
--anw-character-surface: #ffffff
--anw-character-surface-muted: #f8fafc
--anw-character-text: #1f2937
--anw-character-text-strong: #252a32
--anw-character-text-muted: #64748b
--anw-character-border: #e5e7eb
--anw-character-accent: #ff7043
```

实现要求：

- 对话框局部设置 `color-scheme: light`，但不得作用于整个 PawApp 或 QwenPaw。
- 白色表面必须同时声明深色前景；不能只写 `background:#fff` 后继续继承宿主颜色。
- `input/select/textarea/button` 统一继承局部字体和基础前景；primary／danger／disabled 等状态继续使用更具体的组件规则覆盖。
- 优先使用局部 token 和低特异性作用域；只有真实宿主证明确有更高特异性覆盖时才允许最窄范围的 `!important`，并在测试中记录原因。

### 3.2 全部事实筛选器

- 生命周期和健康度保持一行右对齐；在较窄桌面宽度下允许整体换到标题下方，不压缩为不可辨识空框。
- `select` 最小高度继续为 34px，显示明确前景色、白色背景、边框和下拉箭头。
- `option` 同步设置可读前景／背景，避免原生菜单继续继承深色宿主。
- Hover 只改变边框；键盘 `:focus-visible` 使用人物卡橙色焦点环。
- 禁用态必须同时降低前景与背景对比并保留文字，不允许仅靠 opacity 使值消失。
- 受影响普通文字与其表面对比度至少为 `4.5:1`；筛选器边界和焦点指示与相邻表面的对比度至少为 `3:1`。

### 3.3 来源证据与共用抽屉

- 来源证据继续使用 `width:min(720px,72%)`；修正／批次抽屉继续为 480px，不改变计划 46 的桌面布局。
- 72px 抽屉头部固定在抽屉顶部：标题使用 `--anw-character-text-strong`，副标题使用 muted token。
- 关闭按钮至少 36×36px，有明确深色图标、hover 表面、`aria-label` 和 `:focus-visible`。
- 正文、证据高亮、revision 标签、错误／fallback 提示全部使用局部 token，防止深色宿主覆盖。
- 同一套规则覆盖 `.anw-character-source-viewer` 与 `.anw-character-drawer`，不能只修来源查看器而遗漏事实修正和批次撤销。

### 3.4 不回退的现有布局

- 对话框继续 `min(1240px, 100vw - 64px)`、最大高度 `100dvh - 48px`。
- 顶部人物摘要、栏目和底部动作固定；中间只有一个主滚动区。
- 状态与经历继续为“当前写作状态／核对摘要／最近变化／全部事实”。
- 卡片不是表单控件，不增加 `tabindex`；真正可操作按钮和筛选器继续可键盘聚焦。

## 4. 嵌套抽屉焦点与键盘模型

### 4.1 打开

- “查看来源”“修正”或“撤销本次同步”的按钮处理器必须把事件 `currentTarget` 显式传给人物卡控制器，并在任何同步状态切换或异步请求前记录触发元素引用；不得把 `document.activeElement` 当唯一来源。
- 抽屉挂载后，在 microtask／effect 中优先聚焦其关闭按钮；若按钮不可用则聚焦带 `tabIndex=-1` 的抽屉容器或标题。
- 抽屉具备稳定唯一的 `aria-labelledby`；来源、修正和批次标题 ID 由人物卡 `baseId` 派生并作为 props 传入，不得继续使用模块级硬编码 ID。
- 抽屉打开时人物卡摘要、栏目、正文和底部继续 `inert + aria-hidden`；屏幕阅读器和 Tab 序列只进入当前抽屉。
- 来源请求在抽屉打开后继续异步完成；关闭时推进请求世代或设置取消标志，使迟到结果只能被丢弃、不能污染下一次来源查看。

### 4.2 抽屉内导航

- 父人物卡的 Tab 陷阱必须基于“当前可见且不在 inert 区域的焦点元素”计算，不能把隐藏的父关闭按钮算入首尾。
- Tab 从抽屉最后一个控件回到第一个，Shift+Tab 反向闭环。
- Esc 只关闭最上层抽屉。来源读取是可取消的只读操作，加载中允许关闭；事实修正和批次撤销提交中禁止关闭，标题栏关闭按钮、取消按钮和 Esc 使用相同禁用规则，并通过 `aria-busy`／可见文案说明。

### 4.3 关闭与恢复

- 按关闭按钮或 Esc 后，若原触发元素仍连接且未禁用，将焦点恢复到它。
- 若原元素因筛选、分页或刷新已卸载，回退到“最近变化”或“全部事实”标题，再回退到“状态与经历”页签。
- 只有关闭确认真正通过且抽屉状态已经卸载后才恢复焦点；作者取消“放弃未提交修正”确认时，焦点继续留在修正抽屉。
- 关闭人物卡后继续遵循现有鼠标／键盘来源差异：鼠标打开的卡片不留下装饰性焦点框，键盘打开则恢复可见焦点。

## 10. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 宿主高特异性样式再次覆盖 | 局部 token + 真实宿主计算样式断言；最窄范围提高特异性 |
| 统一重置导致 primary 按钮文字变暗 | 基础控件规则与状态规则分层，并为 primary／danger／disabled 建视觉测试 |
| 焦点恢复目标被分页卸载 | 使用连接性检查和标题／页签两级 fallback |
| 父焦点陷阱包含 inert 控件 | 查询时明确过滤 inert、hidden 和不可见元素 |
| 来源请求关闭后迟到并污染下一次查看 | 为来源请求保存世代／取消标志，只有当前仍匹配的请求可以提交 UI 状态 |
| 抽屉硬编码标题 ID 重复 | 全部 ID 从人物卡 `baseId` 派生并由测试断言唯一 |
| 当前 TTS 脏工作区混入包 | 独立工作树、精确文件白名单、包前 diff 清单和迁移清单 |
| 人物卡候选覆盖长期环境较新能力 | 发布前比较当前包哈希与功能矩阵；候选缺少任一已验收能力即停止安装 |
| 长期 18088 包与数据库不兼容 | 本计划无迁移；先隔离安装／卸载／回退，长期前备份 |
| 把旧包 422 误判为新后端缺陷 | 用同一 HTTP 请求对比旧长期包和精确候选包，候选失败才扩大范围 |

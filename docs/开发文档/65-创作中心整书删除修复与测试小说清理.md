## 当前事实、目标与非目标

修复前 `DELETE /novels/{id}` 只调用通用 ORM 删除。后续朗读、媒体、音色和后台任务迁移增加了不可变 user trigger、`RESTRICT` 外键和两组循环引用，故含朗读证据的小说不能沿旧路径删除。这是服务端整书删除闭包缺口，不是页面按钮本身失效。

本次目标是把整书删除改为：校验小说 CAS 与无活动任务，冻结文档和本地媒体身份，在单一数据库事务中清理该小说完整权威／派生闭包，提交后只删除冻结且哈希、大小、设备及 inode 一致的媒体文件，并保存不含书名或正文的删除审计。当前浏览器对应文档的 IndexedDB 崩溃恢复稿随成功响应清理；已完成建书草稿及其命名／模板生成记录也纳入闭包。

## 事务与恢复边界

- 新增 `novel_deletion_audits` 脱敏审计；授权函数只接受同一事务尚未提交且状态为 `purging` 的随机请求 ID。普通事务仍经过全部不可变触发器。
- 不禁用外键、不设置 `session_replication_role`、不修改历史迁移。两条本来声明为 DEFERRABLE 但使用立即 `RESTRICT` 的后台循环外键改为 `NO ACTION DEFERRABLE INITIALLY DEFERRED`；提交时完整性不变，允许同一事务删除完整循环。
- 数据库提交前不删除文件。提交后只通过受控媒体根的 fd-relative 校验删除精确冻结文件；文件身份变化则数据库保留 `media_cleanup_failed` 状态并向页面提示，不误删替换文件。
- 长期数据动作前生成 PostgreSQL custom-format 备份、验证 `pg_restore --list`，并冻结三删三留的版本、数量、后台活动状态和媒体清单。恢复时停止写入，以该备份还原数据库，并从同批文件备份恢复被删媒体；未知未来版本不承诺无适配回退。

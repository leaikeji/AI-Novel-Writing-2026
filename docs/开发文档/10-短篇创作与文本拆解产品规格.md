# 短篇创作与文本拆解产品规格

状态：扩展产品规格草案。短篇与文本拆解可独立交付，不阻塞长篇编辑器和版本基线。

证据日期：2026-08-22。  
主要实测来源：[短篇创作、自定义模板与智能拆书实测](../妙笔神书/06-短篇创作自定义模板与智能拆书实测.md)。

## 1. 决策摘要

1. 短篇是一种作品形态，不是单个长篇章节的别名；它共享通用作品、文档、角色、关系、资产和 revision 基础设施。
2. 短篇向导的每一步都是可恢复草稿；手填和 AI 生成是同一字段的不同来源，不维护两套不一致数据。
3. 自定义模板使用版本化 schema，建书时必须生成可见、可填写、可校验的 values；不能只选择一个模板名称。
4. 目标字数是范围约束。模型结果明显不足时标记 `under_target` 并提供续写/重规划，不把完整性模型意见当作自动完成条件。
5. 角色年龄、身份、关系、禁区和大纲事实进入结构化约束；正文候选采用前运行一致性检查。
6. AI 正文先进入候选文档，作者通过预览或 Diff 采用；生成不能直接替换当前正文。
7. AI 采用、手动保存、恢复、审稿后修改使用同一 revision 体系；不能只有生成历史而没有编辑历史。
8. 审稿把确定性检查与模型建议分开，不提供无法验证的“AI/人工特征百分比”。
9. 文本拆解只处理作者自有、明确授权或公共领域文本；不提供只凭书名和模型记忆生成全书事实的功能。
10. 拆解报告必须引用来源文本范围，至少包含证据、优势、问题、可复用模式和修改练习。
11. 拆解结果可保存为私有创作资产，但必须带来源、维度、文本哈希、任务版本和去重提示。
12. 本项目不建设计费、额度、字包、会员、价格、报价、扣费或作者 token 账单。

## 2. 范围

本文覆盖：

- 短篇九步建书草稿。
- 系统模板与作者模板。
- 整篇候选生成、流式预览、续写和编辑。
- 短篇作品信息、角色、关系、版本和审稿。
- 自有文本场景拆解、全稿拆解、历史和私有库沉淀。
- 长短篇共用的写作资产选择器。

本文不覆盖：

- 不覆盖新闻、公告、发现内容流、会员和个人中心。
- 作品发布、审核、签约、收益和营销。
- 对未获授权作品的全文采集。
- 仅凭模型知识对指定小说给出貌似确定的全书事实。
- AI 文本来源鉴定或学术不端判定。

## 4. 领域模型

### 4.1 通用作品与短篇

复用项目既有 `novels` 权威表，不另建一套通用 `works`：

- id、owner_id、work_type：long_form、short_form。
- title、author_name、audience_tags、genre_tags。
- visibility 默认 private。
- cover_media_id、current_revision_id、created_at、updated_at、archived_at。

`short_story_profiles`：

- novel_id。
- target_character_min、target_character_max。
- idea_document_id、background_document_id、plot_document_id。
- template_snapshot_id。
- completion_state：empty、drafting、under_target、complete、needs_review。

短篇正文仍使用 `documents`、`document_working_copies` 和不可变 `document_revisions`。不能另建只能记录 AI 生成历史的孤立表。

### 4.2 短篇建书草稿

`short_setup_drafts`：

- id、owner_id、current_step、state。
- audience_tags、idea_text。
- template_schema_id、template_schema_version、template_values_json。
- target_character_min、target_character_max。
- background_text、plot_text。
- character_draft_ids。
- author_name、title、cover_mode、cover_draft_ref。
- step_versions_json、last_saved_at、expires_at。
- creation_idempotency_key、created_novel_id 可空。

每一步防抖自动保存。关闭、刷新或跨设备恢复时，界面显示最后成功保存时间和未同步字段。

### 4.3 作者模板

`template_schemas`：

- id、owner_id、name、category、version、status。
- description、work_type_scope。
- created_at、updated_at、archived_at。

`template_schema_fields`：

- schema_id、stable_key、label、help_text。
- input_type：short_text、long_text、number、boolean、single_select、multi_select。
- required、default_value_json、options_json。
- min_value、max_value、max_length、display_order。

要求：

- 同一 schema version 的 stable_key 唯一。
- 已被作品采用的版本不可原地改写，只能发布新版本。
- 建书草稿显示全部字段值和必填状态。
- 模型只能读取作者在“上下文预览”中确认的字段。
- 删除使用归档；已有作品保存完整快照，不依赖活动模板继续存在。

### 4.4 文本拆解

`source_texts`：

- id、owner_id、display_name、source_kind：paste、txt、document。
- rights_basis：self_authored、licensed、public_domain。
- content_hash、character_count、storage_ref、created_at、archived_at。

`text_study_jobs`：

- id、owner_id、source_text_id。
- scope：scene、full_manuscript。
- dimension_keys_json。
- source_revision_hash、model_profile_fingerprint、prompt_version、idempotency_key。
- state、stream_checkpoint、result_id、last_error。

`text_study_results`：

- id、job_id、summary、style_label。
- strengths_json、issues_json、patterns_json、exercises_json。
- created_at、revision。

`text_study_evidence_spans`：

- result_id、item_id、source_start、source_end、excerpt_hash。
- evidence_role：example、counterexample、support。

保存到私有库时新增 `creative_asset_provenance`：

- asset_id、study_result_id、source_text_hash、dimension_key、result_item_id。
- created_at。

## 5. 短篇九步向导

推荐状态：

```text
AUDIENCE
  -> IDEA
  -> TEMPLATE
  -> TARGET
  -> BACKGROUND
  -> CHARACTERS
  -> PLOT
  -> NAMING
  -> COVER
  -> REVIEW
  -> CREATED
```

竞品把封面完成直接当作创建最后一步；项目增加 REVIEW，统一展示所有输入、来源、冲突和空缺。

### 5.1 受众与思路

- audience_tags 使用数组，不把男频/女频写死为永久二选一。
- idea_text 默认最多 2000 个 Unicode 字符，由服务端返回规则。
- 从灵感卡建书时自动填入 idea_text，并保留 inspiration_source_id。
- 手填、粘贴和 AI 候选都显示来源标记。
- AI 生成失败不阻塞手写。

### 5.2 模板

系统模板和作者模板使用相同选择器：先筛分类，再选 schema version。选择后立即渲染 template values 表单，而不是只显示模板名称。

进入下一步前：

- 服务端验证必填字段。
- 显示将发送给模型的字段预览。
- 允许关闭某个非必填字段的模型使用开关。
- 未填字段不会被模型臆造后静默写回草稿。

### 5.3 目标范围

目标不是单个模糊数字，保存：

- target_character_min。
- target_character_max。
- preferred_character_count。

默认范围可按体裁配置。生成结束后用统一可见字符计数器判断：

- 低于 min：under_target，提供“按当前大纲续写”“补足薄弱场景”“接受当前长度”。
- 范围内：complete_candidate。
- 高于 max：over_target，提供裁剪候选，不自动截断正文。

### 5.4 背景、角色和主情节

- 背景、主情节使用版本化 document 草稿。
- 角色先保存稳定 character_draft_id，再由名称显示。
- 性别、年龄允许自由文本，但可以选择结构化年龄范围供一致性检查。
- 每个 AI 步骤返回候选；作者可编辑、拒绝、重试或继续手填。
- 生成下一步前只读取已确认版本。

### 5.5 命名和封面

- AI 标题返回多个候选、理由和冲突提示，不直接覆盖输入框。
- 系统封面 P0；上传和 AI 封面分别作为 P1/P2。
- 系统封面先生成可重渲染参数，再在 REVIEW 采用。
- 上传封面保留原图、3:4 裁剪参数和授权确认。

### 5.6 创建事务

最终创建在一个事务中：

1. 锁定 draft 并验证 owner、状态和版本。
2. 创建 novel 和 short_story_profile。
3. 固化模板、角色草稿、创作字段和资产选择快照。
4. 创建空正文 document 与初始 revision。
5. 固化封面引用。
6. 标记 draft=created 并返回 novel_id。

重复请求只返回同一 novel_id。

## 6. 短篇编辑器

### 6.1 基本区

- 稳定 URL、返回作品库、作品名和保存状态。
- 统一可见字符数和目标范围进度。
- 复制、TXT/Markdown 导出。
- 正文 working copy 与自动保存状态。
- 生成候选、续写候选、审稿、版本。

基本信息、大纲、角色和关系可以用抽屉或独立路由，但都写同一领域实体。

### 6.2 生成任务

生成输入快照包括：

- 已确认 idea/background/plot revisions。
- template schema + values snapshot。
- 角色 revision IDs 和事实约束。
- 选择的私有资产版本。
- 目标范围、禁区和模型配置 fingerprint。

流式内容进入 `document_proposals`，不直接修改 working copy。中断后按 job_id 恢复。完成后运行：

- 角色事实冲突。
- 设定事实冲突。
- 目标范围。
- 重复段落和截断迹象。
- 开端/结尾基本完整性。

作者可查看全文、Diff 和冲突报告，再采用、局部采用或拒绝。

### 6.3 版本与恢复

以下动作都创建 revision 或检查点：

- 作者显式保存/建立检查点。
- AI 候选被采用。
- 历史版本恢复。
- 审稿建议被采用。
- 导入或替换正文。

版本卡展示来源、时间、作者/模型、字符数、父 revision、所用输入快照和恢复影响。恢复只改变正文当前 revision，不静默改角色、关系或大纲。

### 6.4 审稿

确定性检查独立运行：

- 人名、年龄、身份和关系冲突。
- 已知设定冲突。
- 重复句段、标点、超长段落。
- 视角标记和时态提示。
- 目标范围和疑似截断。

模型审稿提供：

- 具体问题。
- 引用原文范围。
- 修改理由。
- 一个或多个候选改法。
- 主观程度标记。

不输出“AI/人工概率”、平台违规结论或保证性评分。总分如保留，必须展示维度、权重和证据，默认不进入作品质量状态。

## 7. 文本拆解

### 7.1 新建任务

作者输入：

- 粘贴文本、TXT 或项目内已有文档 revision。
- 显示名称。
- 权利基础确认。
- 拆解范围和一个或多个维度。

项目可支持多维任务，但每个维度生成独立、可恢复的子任务，避免一个超长 prompt 导致全部失败。上限由服务端配置；超限时提供按章节或段落切分，不静默截断。

### 7.2 报告结构

每个维度必须至少输出：

1. 观察摘要。
2. 证据片段和位置。
3. 做得好的地方。
4. 薄弱或风险点。
5. 可复用写法模板，但不长篇复刻原文。
6. 针对作者自己作品的练习或改写建议。
7. 模型不确定项。

节奏分析额外提供段落/场景节拍表：位置、事件、冲突强度、信息增量、情绪变化和钩子。曲线只是这些可复核记录的可视化，不允许只有一条无法解释的 AI 曲线。

### 7.3 全稿拆解

全稿拆解使用真实导入文本：

```text
导入
  -> 编码与章节解析
  -> 缺章/重复/顺序检查
  -> 作者确认目录
  -> 分章节子任务
  -> 汇总结构、人物弧、节奏和伏笔
  -> 证据索引
```

不接受“书名 + 作者 + 平台”作为事实分析的唯一输入。若用户只给元数据，系统只能创建待导入研究项目，不能生成确定性全书报告。

### 7.4 保存到私有库

从报告选择一个 pattern/style/vocabulary/idea 项目后，先预览将创建的资产：

- 资产类型、名称、内容。
- 来源研究和维度。
- 相似资产候选。
- 是否新建、合并或创建新版本。

采用后写资产和 provenance。再次从同一 result item 保存必须幂等，不制造重复条目。

## 9. 失败与恢复矩阵

| 场景 | 必须行为 |
| --- | --- |
| 向导刷新 | 恢复最后成功步骤和未提交本地字段 |
| 自定义模板升级 | 草稿继续固定旧版本，可主动比较升级 |
| 必填模板字段为空 | 阻止进入 REVIEW，定位具体字段 |
| 单步 AI 失败 | 保留手写内容和此前确认版本 |
| 整篇生成中断 | 按 job_id 续流；当前正文不变 |
| 结果明显低于目标 | 标记 under_target，提供续写/接受，不误报完成 |
| 角色事实冲突 | 在采用前阻止一键接受或要求确认例外 |
| 手动保存失败 | 保留 IndexedDB 工作稿，不丢当前正文 |
| 恢复历史版本 | 正文可回退；大纲/角色只产生一致性提示 |
| 拆解文本超限 | 显示切分方案，不静默截断 |
| 拆解任务中断 | 已完成维度可查看，其余可独立重试 |
| 重复保存私有资产 | 返回既有资产或版本选择，不新增重复项 |
| 来源文本归档 | 研究结果保留哈希和证据引用，访问时说明来源状态 |

## 10. 验收用例

### P1：短篇闭环

1. 九步草稿在每一步刷新后恢复，最终创建请求重放不生成第二部作品。
2. 自定义模板三个字段都在向导中出现；未填必填值不能创建。
3. 灵感卡进入短篇时 idea_text 已填且来源可见。
4. 目标范围保存后，作品信息、生成任务和完成判断使用同一值。
5. 设定角色 28 岁而候选写 32 岁时，采用前显示精确冲突。
6. 整篇生成中断不污染当前正文；重连恢复同一任务。
7. AI 候选被拒绝后正文哈希不变。
8. 手动保存和 AI 采用都出现在统一版本历史。
9. 恢复任意版本后可再次恢复到恢复前版本。
10. 作品库、编辑器和导出使用同一可见字符计数规则。
11. 审稿每个可操作建议都能定位原文；不展示 AI/人工概率。

### P1：文本拆解

12. 没有权利基础确认时不能启动导入文本拆解。
13. 场景拆解每条关键结论至少绑定一个来源范围。
14. 节奏报告包含节拍表、优势、问题和练习，不只有风格赞美。
15. 多维任务中一个维度失败不丢失其他已完成维度。
16. 全稿缺章或重复章节时先要求作者确认目录。
17. 只输入书名时不会生成确定性全书事实。
18. 同一报告项重复保存到私有库只得到一个资产或一个显式新版本。
19. 私有资产详情能回到来源研究、文本哈希和分析维度。
20. 归档来源文本后，派生资产仍可用但明确展示来源已归档。

## 11. 非目标与禁止实现

- 不复制竞品九步页面文案或视觉。
- 不让模板字段成为没有值实例的装饰。
- 不把目标字数当作无反馈的弱提示。
- 不让模型完整性判断掩盖明显的目标或事实冲突。
- 不只记录 AI 生成版本而丢失手动编辑历史。
- 不展示无法验证的 AI/人工特征百分比。
- 不拆解未获授权的全文，不绕过登录、下载限制或反爬。
- 不凭书名和模型记忆生成貌似精确的全书事实。
- 不让拆书结果重复污染私有库。
- 不建设计费、字包、会员、价格、报价、扣费或作者 token 账单。

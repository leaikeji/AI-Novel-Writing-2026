## 三、范围与非目标

### 3.1 本轮目标

- 默认播放器固定为中间写作区域底部的单行控制条；只有生成、失败、旧稿或正文不一致等上下文状态才在控制条上方增加一条临时状态带。
- 正常状态显示当前朗读角色、播放控制、单一时间/句段进度、倍速、音量入口和更多入口；当前播放内容由章节编辑器中的段落高亮表达，不在播放器中重复。
- 朗读脚本与当前正文不一致时，播放器显示明确提醒和“更新朗读”动作；内容一致时该提醒完全不占位。
- 生成、失败、旧稿、历史版本和更新要求只在相应状态出现。
- 朗读版本、脚本复核、重新生成和完整声音清单退出默认层。
- 正常成功消息只通过无障碍 live region 宣告，不长期占用视觉空间。
- 修复播毕恢复和重新播放语义。
- 延续 QwenPaw 当前暖白、浅灰、橙色强调、圆角和字体体系，不重做章节编辑器或宿主导航。

### 3.2 非目标

- 不修改 MOSS-TTS-Nano、VoiceGenerator、音色绑定、智能选角或采样参数。
- 不修改 Manifest、Edition、媒体、HTTP API、数据库表或 Alembic 迁移。
- 不增加连续时间轴音频重混、波形、字幕导出或音频下载。
- 不修改正文编辑器、章节树、AI 审稿、同步进展或历史版本功能。
- 按用户当前要求不实施或验收移动端；现有移动端兼容代码不得在无独立裁决时破坏。
- 不修改 QwenPaw 上游核心。

## 四、布局归属与冻结信息层级

### 4.0 三栏归属硬约束

章节编辑页的产品结构固定为“章节目录｜写作区域｜原生助手”三块；播放器不是第四块，也不是跨三栏的全局底栏。所有设计和实现必须满足：

- 播放器继续挂载在 `.anw-editor-content.has-chapter-narration` 内，位于中间写作区域底部；不得挂到 `.anw-workbench-main`、页面 `body` 或全局 portal 中形成跨栏底座。
- 播放器左右边界跟随正文纸张的可用宽度和中间区域内边距，浏览器几何差值各不超过 1px；播放器底边与章节目录、右侧助手的工作台底部基线差值不超过 2px，不得保留悬浮式底部空隙。
- 播放器不得侵入左侧章节目录或右侧 QwenPaw 助手，也不得让这两个区域为播放器预留垂直空间。
- 章节目录折叠、助手宽度调整以及窗口从 2K 切换到 1080p 时，播放器只在中间区域内部自适应；不得以整个 viewport 宽度计算布局。
- “更多”菜单、详情浮层和音量浮层的锚点都归属于播放器，并限制在中间区域可见边界内；不得覆盖右侧助手的输入区。
- 视觉图必须完整画出三栏边界，并清楚显示播放器只对齐中间正文；上一轮未满足该条件的三张图已删除，不得作为施工依据。当前基于图 2 的最新三次修订图同时使用选定图和实测页面截图为输入，并满足中栏归属、共享底部基线和三段式控制条约束。

### 4.1 默认播放器

核心信息层：

- 当前朗读角色，只显示 `speaker_label`（例如“旁白”“沈砚”），不附带声音 preset、角色类型或正文摘录；
- 上一句、播放/暂停、下一句；
- `当前时间 / 可播放总时长`；
- 当前倍速；
- 音量入口；
- “更多”入口；
- 只有存在失败时额外显示“失败 N 句”。

单行控制条固定使用三段式网格，不以左右内容的实际宽度挤偏播放主控：

- 左区固定承载当前朗读角色，并与播放器左内边距对齐；角色名过长时单行省略，不得挤压中区。
- 中区承载上一句、播放/暂停、下一句；播放主按钮相对整个播放器内容盒几何居中，左右按钮与主按钮等距，三个控件的点击目标均不小于 44px。
- 右区承载时间、倍速、音量与“更多”，按固定间距右对齐；常驻句数从视觉层移除，继续通过滑杆 `aria-valuetext` 和 live region 提供。1080p 空间不足时先压缩非交互文字间距，不得移动中区主按钮或隐藏常用操作。
- 实现优先采用 `grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr)`；右区在自身网格单元内靠右，禁止用左右两区“看起来差不多宽”的 flex 估算居中。

进度层：

- 唯一句段进度条；
- 拖动或键盘调整时通过编辑器高亮预览目标段落，不在播放器中复制正文。

正文联动层：

- 播放、跳句或拖动后，播放器更新当前朗读角色，章节编辑器高亮当前目标段落；播放器不显示当前句摘录。
- 屏幕阅读器通过可见角色名与非视觉 live region 获知当前句序号；删除正文摘录不等于删除无障碍状态。

图 2 三次修订方向固定为单行三段式控制条；异常状态带不属于第二套常驻播放器。作者最终确认后由 `TTS50-C0` 冻结具体间距、控件顺序和状态投影，施工中不得自行混搭旧方向。

### 4.2 删除的日常元素

- 完整生成后的“全章生成 100%”与第二条生成进度。
- “当前”和“可播放”两组重复的时间及句数。
- 正常当前稿下的“当前稿”标签。
- 默认栏中的当前句摘录；保留当前朗读角色名。
- 正常成功态的常驻“本章朗读已经准备完成”。
- 未生成态的全部零值指标和“音色身份不可用”。
- 默认栏中的 Edition/冻结声音数量。
- 用户界面中的稳定 UUID。
- 展开态的第二个同义关闭入口。

### 4.3 按需元素

- 生成中或部分可播：显示一条“已生成 N/总句，可播放 M 句”和唯一生成进度；完成后自动退出。
- 失败：显示失败数量和重试入口；不让历史失败覆盖当前正常 Edition。
- 旧稿或历史版：显示不可忽略的来源标签；当前稿不显示来源标签。
- 当 `sourceKind === "working-copy-diverged"`、工作副本内容 hash 漂移或 `explicit_update_required` 为真时，在播放器控制条上方显示唯一提醒“朗读内容与当前正文不一致”和“更新朗读”；更新完成且重新一致后整条提醒消失并释放空间。
- 自动跟随暂停：只在作者手动滚动或编辑后显示“返回当前朗读位置”。
- 音量：默认使用带准确可访问名称的扬声器按钮，点击后打开滑杆；倍速保持直接可见。

## 五、详情与次要操作

“更多”首先打开紧凑菜单，包含：

- 朗读版本；
- 本版本声音；
- 复核脚本；
- 重新生成朗读；
- 只有需要时出现的失败句段。

当内容需要更大空间时再进入独立详情浮层或抽屉；不得把完整状态表直接铺在正文上方。详情规则：

- “本版本声音（N）”默认折叠；展开只显示显示名与来源类型。
- 稳定标识、revision、digest 和内部错误细节不进入作者日常 UI。
- 朗读版本选择明确标记“当前”和“历史”，不可播放版本保持禁用并说明原因。
- 只保留一个明确关闭入口；Escape 关闭并把焦点还给“更多”。

当前图 2 修订方向属于中间写作区内部的视觉目标，不改变以上信息与安全边界。作者最终确认后，在 `TTS50-C0` 冻结具体布局。

## 六、状态与行为语义

| 状态 | 默认视觉 | 主按钮行为 |
|---|---|---|
| 加载中 | 轻量骨架或“正在读取朗读” | 禁用 |
| 未生成、正文已保存 | 一句空态说明 | 生成朗读 |
| 未生成、正文未保存 | 提示先保存 | 禁用并聚焦保存路径 |
| 生成中、尚不可播 | 唯一生成进度 | 等待 |
| 部分可播 | 生成进度＋可播放范围 | 从首个可播句开始 |
| 完整可播、从未播放 | 标准播放器 | 从第一句播放 |
| 中途暂停/恢复 | 显示上次停在第 N 句 | 从保存位置继续 |
| 已播完 | “已播完”，进度在末端 | 从第一句重新播放 |
| 正在播放 | 当前句高亮并自动跟随 | 暂停 |
| 手动滚动暂停跟随 | 保持音频播放，显示返回入口 | 返回当前朗读位置 |
| 旧稿/历史版 | 显示来源警告 | 播放冻结版本，不冒充当前稿 |
| 朗读与当前正文不一致 | 在控制条上方显示“朗读内容与当前正文不一致”及“更新朗读” | 创建或切换到与当前正文一致的新朗读；未更新前不冒充当前正文 |
| 失败或缺口 | 显示失败数量与范围 | 不跨过缺口静默播放 |

`toggleNarrationPlayback()` 必须显式区分 `idle`、`paused`、`ended` 与“idle 但存在恢复点”。当状态为 `ended`，或权威进度已到末句末尾时，播放入口固定从 ordinal 0、offset 0 开始。不得仅修改文案而保留播放最后一句的旧行为。

## 十、测试与桌面验收

### 10.1 自动化

至少覆盖：

- 未生成态不渲染零值指标和音色不可用。
- 完整态不渲染“全章生成 100%”和重复成功文案。
- 默认播放器渲染当前句段的 `speaker_label`，但不渲染正文摘录；编辑器当前段落高亮与播放/跳句状态同步。
- 默认播放器 DOM 明确分为角色区、运输控制区和工具区；播放主按钮不依赖左右两区内容宽度决定位置，上一句与下一句到主按钮的逻辑间距一致。
- 从旁白切到人物对白、从人物切回旁白及连续人物对白时，角色名与当前 ordinal 原子更新，不短暂显示上一句角色。
- `working-copy-diverged`、内容 hash 漂移和 `explicit_update_required` 都投影为唯一的不一致提醒及“更新朗读”，内容重新一致后提醒与占位消失。
- 生成中、部分可播、失败、旧稿和历史版仍显示必要状态。
- 从未播放、中途恢复、暂停、播毕和重新播放行为。
- `ended` 与末句末尾恢复从第一句重播。
- 更多菜单 Escape、焦点圈定、关闭后焦点恢复。
- 稳定 UUID 不出现在作者可见 DOM；安全观察器字段保持受控。
- 倍速、音量、上一句/下一句、句段跳转和保音高播放链非回归。
- 失败句段重试、偏好冲突、脚本复核和 Edition 切换非回归。

执行定向 Vitest 后，按影响运行：

```text

pnpm typecheck
pnpm build
.venv/bin/python scripts/package_plugin.py
.venv/bin/python -m pytest tests/test_manifest.py tests/test_skill_contract.py tests/test_qwenpaw_integration_contract.py
git diff --check
```

### 10.2 真实浏览器

只覆盖用户指定的桌面视口：

- `1920×1080`
- `2560×1440`

每个视口必须验证未生成、生成中、部分可播、完整可播、播放、暂停、跳句、拖动、播毕、重新播放、旧稿、历史版、失败、详情和偏好状态。要求：

- 不遮挡当前句和章节底部操作；详情不占据默认正文高度。
- 播放器必须完全落在中间编辑容器内，左右边界与正文纸张差值各不超过 1px，底边与两侧工作台区域差值不超过 2px；`player.left >= chapterTree.right` 且 `player.right <= assistant.left`。
- 折叠章节目录、调整助手宽度后重新测量上述边界；播放器只能随中间编辑容器缩放，不得横跨或挤占其他两栏。
- 无横向溢出、裁切、不可点击重叠或失焦。
- 常用操作无需打开“更多”。
- 正常态无常驻成功提示和重复指标。
- 默认态播放器左侧必须显示当前朗读角色，且不得出现当前正文摘录；当前段落只在编辑器内高亮。
- 播放主按钮中心与播放器内容盒水平中心的偏差不超过 1px；上一句、下一句到主按钮的中心间距差不超过 1px，三组控件垂直中心偏差不超过 1px。
- 时间、倍速、音量和“更多”在右区形成连续紧凑工具组，不得与中区重叠，也不得用大段空白把同组信息割裂；作者可见默认栏不得出现常驻句数。
- 人为制造正文与朗读脚本不一致后，提醒与更新入口必须出现；更新成功后提醒自动消失。
- 生成/失败/旧稿等关键信息不因减重而隐藏。
- 键盘可完成播放、菜单、版本选择、关闭和焦点返回。
- 控制台无 error/warning，失败网络状态可恢复。

## 十二、自查结论

- 计划把结构减重与播毕行为修复同时纳入，避免只改外观后仍从最后一句播放。
- 删除项均有保留边界：成功视觉提示可删除，但 live region、失败恢复、旧稿警告和冻结身份不能删除。
- 当前不引入新后端、迁移、依赖或第二套播放器。
- 移动端明确不在本轮验收范围，同时禁止无意破坏已有窄屏兼容。
- 上一轮三张图没有准确表达播放器只属于中间写作区域，已从生成目录移除。作者随后明确选择图 2；最终源码已经按“角色在左、运输控制几何居中、时间与工具在右”落地，不再保留未选方向。
- 当前脚本段已经提供权威 `speaker_label`，该视觉需求不需要新增角色推断、后端字段或 API。
- 正文不一致检测复用现有 `workingCopyDiverged`、脚本/工作副本内容 hash 和 `explicit_update_required`，不需要为本轮新增后端字段或迁移。
- 自查发现并修复暂停态恰好位于末句末尾时仍调用 `resume()` 的语义缺口；现在该状态与 `ended` 一样从首句重播，无效 ordinal 或空章节也不会复用无关 offset。
- 浏览器几何复核发现系统滚动条使旧候选在 1080p 右侧超出正文纸张约 11px、在 2K 整体右偏约 5.45px；现由组件测量滚动条实际占位并写入局部 CSS 变量。最终 1080p 左／右边界差为 `0px / 0.124px`，2K 为 `-0.062px / 0.062px`，均小于 1px。
- 隔离浏览器 harness 只用于渲染真实组件和冻结状态，已经从最终源码及最终构建删除；没有写入长期小说、数据库、音频或 QwenPaw 上游。
- 长期真人复验发现“更多”展开后焦点停在触发按钮时 Escape 无法关闭；已把详情和音量的 Escape 处理收口到播放器根层，删除两处重复的局部处理器。最终从触发按钮或浮层内部均可关闭并返回原按钮。
- 真实播放验收只读取既有音频并写入正常播放进度；结束后使用公开播放进度 API 和部署前备份把 ordinal、offset、合法起点及倍速精确恢复到原状态。
- V1.1 自查又发现并关闭一个恢复态缺口：页面刷新后播放器状态可能没有当前音频元素的 `durationMs`，但 Manifest 已保存末段真实时长。现在面板文案和播放入口共用 `chapterPlaybackHasEnded()`，工作台也把同一 Manifest 时长传给 `resolveChapterPlaybackStartPosition()`，不会出现“显示可恢复、实际应从头播放”的分裂判断。
- 详情触发器现在使用 `aria-expanded`/`aria-controls` 控制命名 `region`，不再谎报 `aria-haspopup=dialog`；Escape 仍由播放器根节点统一处理并恢复焦点。
- 删除详情内重复的可见“朗读版本”标题和已无调用者的标题样式；版本选择、来源/播放状态、冻结声音与维护动作各只保留一个入口。

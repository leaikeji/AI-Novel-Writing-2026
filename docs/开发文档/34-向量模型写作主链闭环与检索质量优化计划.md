# 向量模型写作主链闭环与检索质量优化计划

状态：**2026-08-29 已完成源码、迁移、安装和主要验收；真实正文长度门禁部分通过。** 本计划只闭合 V1 语义索引与正文写作链路，不启用结构化 V2 corpus，不建设计费、ANN、第二套向量数据库或第二套任务系统。可复核结果见[VM34 验收记录](./证据/VM34-向量写作闭环-2026-08-29/README.md)。

计划日期：2026-08-29（Asia/Shanghai）

## 1. 冻结目标

将现有“可连接、可索引、可手工搜索”的阿里云百炼 `qwen3.7-text-embedding` 接入正文生成、章纲、整章审稿和按策略启用的选区编辑。向量固定为 2048 维 Dense、cosine，存储继续使用 PostgreSQL + pgvector 精确扫描；结构化故事状态继续由 StoryFact／Context 确定性投影裁决。

发布 `novel-embedding-consent/2`。v2 明确披露章纲要求、工作稿选区和自定义指令可能作为 query 发送给百炼；旧 v1 授权可继续维护已明确授权的正式语料索引，但自动写作 Dense 查询必须重新确认 v2。

## 2. 冻结契约

- `StoryPositionV3` 分离一基章节顺序 `narrative_sequence` 与世界事件截止点 `story_sequence_cutoff`。单线缺省使用 `single-timeline-identity/1`；多线缺少可比较 mapping 返回 `timeline_mapping_required`。
- `ChapterTimelineContextV3`、`NovelContextEnvelopeV4` 与 `WritingContextSnapshotV1` 是新生产路径。历史 V3 snapshot 只读，不再生产。
- `EmbeddingGeneration` 是不可变模型空间／renderer／chunker 代次；`EmbeddingGenerationNovel` 是同一工具链下可增量更新的小说内容投影。
- 新增 `semantic_source_refreshes`；source 通过 `pending -> current` 原子发布，旧 current 转 retired。网络调用不占用数据库长事务，发布前重验授权、head、绑定和内容 hash。
- `semantic_sources` 分别保存 narrative 与 story sequence 范围；`semantic_chunks.token_count` 改为 `estimated_token_count` 并增加 estimator version。
- 查询策略单独版本化。查询策略变化只重新评测，不重建 document embedding。

## 3. 写作触发与降级

自动检索：正文生成、章纲、整章审稿、选区 rewrite／expand／dialogue／review。polish／shorten 不检索；custom 仅在作者显式开启“参考全书资料”时检索。不得用生产关键词规则猜测意图。

本地词面召回始终可用；Dense 只在 v2 授权、active index ready、Key 可用时调用，默认 8 秒超时后降级。未授权或撤销后云端请求为 0。实际证据、来源、分数、generation/index version、request ID、Token、延迟和降级原因冻结进 generation snapshot；手工 search 保持数据库零写入且不记录 query 原文、完整向量或密钥。

上下文按实际正文模型有效窗口动态预算。required 和作者本次显式选择素材不可静默丢失；preferred/context_only 在 Dense 不可用时做当前固定版本的本地词面回退。只按完整逻辑块省略并记录诊断；强制内容超过真实硬上限时返回 `context_overflow`。

## 4. 检索与分块门禁

候选 A 为 512/64 字，候选 B 为 800/120 字。使用同一套非自查询 query-label 比较；满足门禁后按 MRR 选择，差值不超过 0.01 时选择 B。若两者都不达标，旧 active 继续服务。

检索必须先按 owner/workspace/novel/current revision/固定绑定/timeline/章节截止点/知识可见性过滤，再计算 pg_trgm lexical 与精确 cosine，网络返回后重新校验 scope 和 index version。融合使用版本化 RRF、逐 corpus 配额、来源去重、相邻块扩展及最低相关度；低于阈值合法返回空结果。

本轮保留真实端点验证后的单条 document batch；不创建 HNSW/IVFFlat，不截断 2048 维向量。

## 5. 公共接口与 UI

- `SemanticSearchRequestV2`：purpose、timeline、narrative/story cutoff、perspective、corpora、top_k。
- `SemanticSearchResultV2`：generation/index/policy version、lexical/dense/fused 分数、request ID、Token、延迟、降级与省略诊断。
- 小说 rebuild 重建 active generation 的当前小说内容；全局 candidate rebuild 只用于模型空间、renderer、chunker 变化。
- 全局维度改为只读 2048；小说卡片显示 ready/updating/outdated/partial_failed/revoked、权威与已发布摘要、v2 授权升级。
- 不增加价格、余额、账单、扣费或费用管理。

切换后删除 Context V3 新生产路径、semantic-search v1 内部调用、旧重复融合器和 candidate-only 小说重建限制。证明 `novel_chunks` 无调用者且为空后，用新迁移删除 ORM/表；历史迁移、证据和旧 generation 保留。

## 7. 验收

固定评测至少 36 个非自查询案例：manuscript/planning/private_asset 各 8 个正例，以及未来章节、兄弟线、失效 revision、未绑定素材、未揭露知识和无答案共 12 个负例。

门禁：Recall@5 >= 0.85、MRR >= 0.70、hybrid 不低于 lexical-only、无答案正确拒答率 >= 0.90、所有隔离泄漏为 0、确定性重建 hash 一致、candidate 失败时 active 继续服务。

最终使用新合成实验小说生成三章、每章约 2000 字；每章正式化后等待增量索引再生成下一章，验证必要前文召回和未来／兄弟线隔离。真实正文模型限三次章节正文生成，其他触发矩阵使用 stub。完成自动化后安装并重启长期 PawApp，在 1920x1080、2560x1440、390x844 验收。

Git 提交与推送不属于本计划的既有授权，完成后仍需用户当次明确指令。

## 8. 实施结果

- `VM34-EVAL` 至 `VM34-INT` 已完成；新生产路径使用 Context V4 和 WritingContextSnapshot V1，旧 Context V3 只保留历史展示。
- 迁移 `20260829_0030` 已接入线性 head；长期环境随后连同不属于本计划的 TTS `20260829_0031` 一并升级。空 `novel_chunks` 表和 ORM 已删除，历史迁移仍保留。
- 36 例冻结非自查询评测 Recall@5/MRR/拒答率均为 1.0、泄漏 0；这是冻结离线排名集，不冒充真实线上语义质量统计。
- 合成小说 v2 授权、三章正式化、每章后增量发布、稳定人物 ID 改名、固定私有素材、兄弟线和未来章节隔离通过；最终为 6 个来源、34 个块、0 失败，authority/published digest 一致。
- 三次真实正文模型调用分别得到 1295、1995、2526 个可见字符，只有第二次满足 1700–2300 验收带。第一、三章改用明确标记的作者合成恢复稿完成后续向量链验证；不追加第四次云调用，也不把恢复稿写成模型成功。
- 1920×1080、2560×1440、390×844 已检查向量配置页；小说语义索引卡片已在桌面和窄屏检查。无页面横向溢出，浏览器仅记录一条 QwenPaw 宿主 `AppCenter` 模块缺失警告。

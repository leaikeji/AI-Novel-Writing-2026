# ADR-0008：写作检索位置坐标、增量索引与授权边界

状态：**已接受，随 34 号计划进入施工。**

日期：2026-08-29（Asia/Shanghai）

## 背景

V1 语义索引已能真实生成 2048 维向量并手工检索，但正文生成没有实际查询；active generation 只能整代构建；`narrative_sequence` 同时承担章节顺序、故事事件顺序和知识揭示截止点；现有 v1 授权也没有明确覆盖工作稿选区和章纲要求作为 query 发往云端。

## 决策

1. 章节叙事顺序与世界事件顺序使用两个字段。正文未来章节隔离使用 `narrative_sequence`；时间线继承、StoryFact 与知识揭示使用 `story_sequence_cutoff`。单线可使用版本化 identity mapping，多线必须显式可比较。
2. Embedding generation 只表示不可变向量空间和索引工具链。正式内容变化在同一 active generation 下以不可变 source replacement 增量发布；模型、维度、renderer 或 chunker 变化才建立 candidate generation。
3. 新来源先 pending，所有 embedding 成功并重新校验权威 head、授权和 hash 后，单事务切换 current/retired。失败或过期结果不得发布。
4. 写作检索自动、可降级。结构化状态由确定性投影决定；向量结果只提供有来源的补充证据。
5. 模型固定为 `qwen3.7-text-embedding`、2048 Dense、cosine；继续使用 PostgreSQL + pgvector 精确扫描。本阶段不建设 ANN、专用向量数据库或计费功能。
6. `novel-embedding-consent/2` 明确覆盖为检索目的发送的章纲要求、工作稿选区和自定义指令。v1 不授权自动写作 Dense query；未授权或撤销后云端 query 为 0。
7. 手工 search 对数据库只读。查询内容和完整向量不落普通日志；生成任务只冻结实际命中证据、摘要元数据和脱敏运行证明。
8. 上下文预算由实际正文模型窗口派生，不设置任意固定总字符硬门槛；只按完整块省略，required 无法装入真实窗口时显式失败。

## 被否决方案

- 每次正文变化重建所有授权小说的 candidate generation：成本和等待范围过大。
- 在 active generation 中直接覆盖 source 或 embedding：无法审计并会让迟到结果污染当前索引。
- 用章节序号继续代替世界事件序号：闪回、分支和知识揭示会被错误过滤。
- 对选区内容静默发起 query：超出现有授权披露。
- Dense 失败即阻止正文生成：把派生增强错误提升为正文权威故障。
- 为 2048 维提前建立近似索引或截断向量：没有真实规模依据且破坏向量空间一致性。

## 后果与恢复

写作任务会得到可复核的语义证据，同时保留无 Key、未授权和云端故障时的本地可用性。代价是新增 source refresh 生命周期、Context V4 和更严格的双坐标测试。

数据库只通过新的线性 Alembic revision 演进。新 candidate 未通过评测时旧 active 继续服务；旧 generation、历史 snapshot 和迁移保留用于审计与回退，不作为新生产写入路径。

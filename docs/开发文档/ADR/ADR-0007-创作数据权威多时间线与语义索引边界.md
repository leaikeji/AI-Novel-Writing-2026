# ADR-0007：创作数据权威、多时间线与语义索引边界

状态：**已接受并于 2026-08-29 随 31 号统一计划完成本地发布；真实百炼连接按用户要求保持未验证。**

日期：2026-08-29（Asia/Shanghai）

## 背景

当前实现同时存在正式大纲投影与 `OutlineDraft`、大纲人物 JSON 与正式 `NovelCharacter`、可覆盖故事线／伏笔进度、无稳定人物／时间线引用的 `StoryFact`、原地覆盖私有素材，以及只面向正文 revision 的空 `novel_chunks`。这些结构在测试小说中已经产生角色漂移、未来事实混入、来源证据不稳定、GET 写库和样书关键词进入生产逻辑等风险。

项目将接入阿里云文本向量模型，但向量无法替代事实权威、时间投影、人物身份或知识边界。若在权威未收敛前把所有内容直接嵌入一个向量池，会把旧 revision、平行世界、未揭露身份、候选和私有素材混成不可解释上下文。

## 决策

### 1. 权威分层

采用且只采用：

1. 文档／规划不可变 revision；
2. 稳定实体及实体 revision；
3. 作者确认的 `StoryFact v2` 追加事件；
4. 只读确定性投影；
5. 可重建语义索引。

候选、草稿、生成快照、投影和向量均不得成为正式故事真相。

### 2. 时间线

单时间线是多时间线模型的默认特例：只有一条活动线时服务端可唯一补全，UI 隐藏高级能力。作者建立第二条线后，章节、人物实例和故事事件必须显式选择时间线。

多时间线使用“无环主继承 + 可成环显式因果链接”：分支只继承分叉锚点前状态；穿越、记忆传递、循环与汇合通过显式 link 和目标线事件表达。系统不自动复制跨线事实、不求解悖论、不以最后写入消解冲突。

正文 revision 的时间线映射采用三层结构：head 指向不可变 mapping revision，mapping revision 再拥有一个或多个带精确字符区间的 segment。这样既保留映射修正历史，也能对每段时间线外键和 offset 做约束；不把整组区间藏进不可校验 JSON。

### 3. 人物身份

人物根表示跨时间线叙事身份，人物实例表示具体连续个体。姓名是显示属性，不是引用键；别名可以绑定根或实例并带时间线、有效期、身份层和知识范围。平行版本和穿越者使用不同实例 ID，可在同一目标线并存。TTS 默认继续绑定人物根。

### 4. 事件与投影

人物、关系、故事线、伏笔、故事时间、知识和世界状态共用受 schema 约束的 `StoryFact v2`。模型只能提出候选；作者确认后写入。投影同时接受叙事截止点、目标时间线、故事位置和观察者，先过滤来源 revision 有效性，再计算继承、状态、年龄和知识。冲突返回全部依据，不静默选择。

### 5. 私有库

私有素材使用稳定根和不可变 version；小说绑定与预设固定具体 version，生成 job 再复制输入快照。素材不会静默成为小说设定或故事事实。未绑定素材不进入小说云端索引。

### 6. 向量模型与页面

首个生产适配器固定为阿里云百炼 DashScope Native 的 `qwen3.7-text-embedding`、正式默认 2048 维 Dense、document/query 双角色和 cosine；候选维度只允许 `256/512/768/1024/1536/2048/2560`。使用现有 PostgreSQL + pgvector，不新增向量数据库或模型容器。

2026-08-29 已按阿里云官方[模型页](https://help.aliyun.com/zh/model-studio/qwen3-7-text-embedding)、[同步接口](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)和[限流页](https://help.aliyun.com/zh/model-studio/rate-limit)完成只读文档复核：上述模型、2048/Dense、受支持维度白名单、document/query 和 Native endpoint 当前成立。官方单请求上限当前为 20 条；本项目的 10 条是内部保守批次。文档核验不替代业务空间双角色连接哨兵，未实测 candidate 仍保持 `unverified`。

PawApp 提供全局“向量模型接入”页配置连接、write-only API Key、active/candidate 模型、重建、激活和回退；Key 只显示“已配置”或数据库末四位掩码，不返回末八位。小说内提供一次授权与语义索引卡片。授权按小说，明确覆盖作者秘密和已绑定私有素材。检索先做确定性 scope/time/knowledge/current-source 过滤，再做分 corpus 向量与词面融合。结构化状态永远由投影裁决。本项目不建设计费、价格、余额、扣费或费用管理功能。

全局配置根必须显式保存 active/candidate/previous generation 指针和凭据引用；generation 必须有逐小说构建状态与逐批次幂等证据，只有所有当前授权小说均通过门禁后才能原子激活。API Key 不得进入 ORM 明文字段、日志、前端工作区上下文、选区、IndexedDB 或 localStorage。

SecretStore 使用项目专用 secret mount 中的独立根密钥，以 AES-256-GCM 加密 credential record；数据库只保存不透明引用和非敏感元数据。为此固定 `cryptography==48.0.1`（Python 3.11+，Apache-2.0 OR BSD-3-Clause，macOS/Linux ARM64 wheel 可用），并保持与 QwenPaw 2.1.0 所带阿里云 SDK 的 `<49` 约束兼容。该密钥不得复用朗读 HMAC key；根密钥丢失时失败关闭并要求重新输入 API Key。

现有后台任务的表可以复用，但当前执行路径与朗读 executor/resource 固定绑定，不能把向量重建伪装成朗读任务。先抽取通用 background execution core，使每种已注册 job kind 显式声明 executor 和资源类别；向量使用独立 `embedding-worker` epoch 与 `dashscope-embedding` 资源槽，同时继续复用租约、attempt、取消、重试和模型运行证据。

### 7. 2026-09-02 账本一致性补充裁决（计划 51 G0）

隔离 PostgreSQL 结构体检、长期环境只读数据盘点和 500／2,000／10,000 条合成基准证明：现有 `StoryFact v2`、`DerivedSourceBinding`、`StoryEventLink`、`IntelligenceCommitBatch` 与小说根版本足以表达本轮一致性语义。本轮不新增 Adoption 表、通用 Operation 表或 snapshot 表；缺口应由共享解析、事务和读取契约修正，而不是再建第二套权威。

当前纳入解析必须按 **fact 自身** 聚合来源 binding、来源 revision、supersedes 和批次状态，不能继续以 revision-wide 单一 validity map 替代。解析输出保持两条独立轴：`included_in_current_projection`／`effective_state`／稳定 `reason_codes` 表达权威生命周期；面向作者的冲突、来源缺失和歧义继续由独立 health 分类表达，不能合并成一个状态枚举。

继续扩张单一 `Novel.story_ledger_version` 作为完整故事账本快照版本，不引入复合根版本：所有会改变账本实时 join 结果的冻结命令必须在同一业务事务中锁定小说根，实际变化精确推进一次；no-op、精确幂等回放和失败回滚不推进。账本读取须在首条查询前建立只读 `REPEATABLE READ` 快照，并返回绑定小说 ID 与账本版本的不透明 `ledger_snapshot_token`；分页游标同时绑定该 token、筛选指纹和稳定的 `created_at DESC, id DESC` 锚点。

现有语义 schema 不需要迁移。全书分页查询必须先在数据库选出本页 ID，再批量 enrichment；G0 的查询计划证明现有索引会随全书规模扫描，窄查询索引是否落库仅在 W2 最终 SQL 冻结后由单独批准的 `L51-MIG-QUERY` 决定。查询索引不得夹带旧列、旧 endpoint 或历史数据删除；公开兼容项的收缩使用独立窗口和独立裁决。

## 被否决方案

- 每个领域各建一套事件真相：会与 StoryFact 和来源绑定重复。
- 所有时间线事实自动跨分支传播：会替作者解决语义冲突并制造悖论。
- 所有平行人物共用一个状态 ID：无法表达两个自己同时存在。
- 把数据库全部行直接字符串化并放入同一向量池：无法可靠隔离权威、时间、知识和私有素材。
- 只接入正文向量、不冻结未来全类型 metadata：后续扩展会再次迁移和重写检索边界。
- 每本小说重复配置向量密钥与模型：会造成密钥扩散和配置漂移。
- 直接复用写死 `narration-worker/moss-nano` 的执行路径：会造成资源归属、取消、并发和运行证据失真。
- 只用 generation 总状态而不保存逐小说／逐批次证明：无法安全判断候选代是否可以激活或精确重试失败项。

## 后果

正面：单线写作保持轻量；长篇可审计地支持改名、闪回、平行世界、穿越、身份揭示和正文恢复；私有素材与小说 canon 分离；语义检索可以证明来源和可见范围。

代价：需要多阶段线性迁移、人物实例、时间线映射、统一上下文 assembler、分 corpus renderer 和更大隔离测试矩阵。结构化 V2 语义索引必须逐 corpus 放行，不能一次全部启用。

## 恢复与兼容

所有 schema 采用新 Alembic revision，不改写历史迁移。实验小说重建与 schema upgrade 分开，执行前备份和再次授权。旧表与必要兼容投影在首个发布周期保留；功能回退优先回退 PawApp 并恢复测试库备份，不删除 PostgreSQL/QwenPaw 数据卷。

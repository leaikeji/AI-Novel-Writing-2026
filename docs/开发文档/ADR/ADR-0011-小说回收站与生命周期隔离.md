# ADR-0011：小说回收站与生命周期隔离

状态：V0.5 已实现并部署；作者自助删除采用两步回收＋逐字确认，备份回执降为可选运维加强模式
日期：2026-09-10（Asia/Shanghai）

## 决策

小说生命周期采用 `ACTIVE → RECYCLED → ACTIVE`；永久销毁只从 `RECYCLED` 执行。回收站无限期保留、不自动清空；作者可在回收站对单本小说逐字输入 `确认删除`，Web 路由把严格确认转换成只绑定当前 UUID＋version 的服务端上下文并调用唯一完整销毁服务。活动任务、版本／文档／媒体漂移继续 fail closed。逐目标备份回执保留为可选运维加强模式，不再阻断普通作者删除；Agent 不暴露永久删除工具。

`novels.recycled_at/recycled_by` 是唯一生命周期权威。所有普通读取、写入、模型派发、后台 claim、朗读、播放和媒体清理先验证小说为 active；子资源入口必须反查所属小说。回收和恢复在一笔数据库事务内锁小说行、执行 CAS、递增 `novels.version` 并写不可变脱敏事件。

## 冻结契约

- `POST /api/ai-novel-world-2026/novels/{id}/recycle`
- `GET /api/ai-novel-world-2026/recycle-bin/novels?limit=&cursor=`
- `POST /api/ai-novel-world-2026/recycle-bin/novels/{id}/restore`
- `POST /api/ai-novel-world-2026/recycle-bin/novels/{id}/purge`
- 动作请求：`expected_version: positive int`、`idempotency_key: 1..120 chars`。
- 动作响应：`event_id`、`action`、`version`、`recycled_at`、`warning_codes`、`replayed`。
- 普通入口访问回收态返回 HTTP 410，`detail.type=novel_recycled`；未知或越权仍为 404。
- CAS、幂等冲突、活动任务、清理中和恢复完整性异常均为 409；维护运行时不可用为 503。
- 旧 `DELETE /novels/{id}` 固定返回 409 `permanent_delete_moved_to_recycle_bin`。
- 销毁请求仅含 `expected_version` 与固定短语 `confirmation_text="确认删除"`；备份路径、摘要、actor 和管理员声明不得来自 HTTP body。服务端作者路径不要求预生成回执；可选运维路径仍完整校验 `novel-purge-backup-receipt/2`，两条路径最终汇入同一销毁服务。

## 幂等与锁序

可信 scope 和请求摘要验证后先查事件；未命中则按 owner/workspace、小说 UUID 锁 `novels`，刷新后重查事件，再校验状态/CAS。写事务统一采用 `novel → document/resource → job → asset` 锁序；外部模型、TTS、文件散列与 unlink 不持数据库锁。

同键同摘要永远重放原回执，即使小说后来恢复、再次回收或销毁；同键异义拒绝。`novel_lifecycle_events` 不受整书销毁授权旁路，永久删除后仍保留脱敏审计。

## 活动与清理门禁

- `background_jobs`: `queued/running/retry_wait/cancel_requested`。
- `chapter_generation_jobs`、`creative_generation_jobs`: `running`。
- `media_assets`: `deleting`；未完成 `media_gc_deletion_plans` 和声音删除计划同样阻断。

普通业务对 RECYCLED 的新请求必须零内容返回、零业务写入、零新外部调用。已发送的原生聊天字节和历史不追溯删除。

## 发布与恢复

迁移是 `0051` 后继前向迁移。长期发布必须停 PawApp 写入及 worker，形成同一停写点的数据库／媒体备份并完成隔离恢复，再统一切换 API、worker 与前端。开放写入后优先前向修复，不盲目恢复旧快照丢弃新增创作。

## 1. 决策范围与继任关系

ADR-0003 的上下文协议、role=user 数据边界、短期 `context_ref`、Selection Registry、字段 Adapter、完整哈希、UTF-16 选区、保存/CAS、撤销事务、正式资料工具、Agent 作用域和 QwenPaw 上游隔离继续有效。

本 ADR 只替代 ADR-0003 决策 6 中以下“默认交付与审阅 UI”内容：

1. 点击固定选区动作后默认复制 slash 命令，并要求作者在原生输入框粘贴、再次发送。
2. 结构化候选的完整正文默认显示在 QwenPaw 聊天消息内的工具卡片中。
3. 聊天工具卡片直接承担替换、插入、撤销和放弃的主审阅面。

ADR-0003 的历史验收事实不会被重写；从本 ADR 实施后，上述路径只作为显式兼容/历史结果路径，新的默认主路径以本 ADR 为准。

## 2. 背景

真实浏览器审计确认旧路径虽然遵守公开 QwenPaw 契约和显式采用边界，但存在两个产品问题：

- 点击“润色/改写”并不会开始任务，作者还要切到右栏、粘贴和再次发送；这覆盖剪贴板并增加会话、选区过期和误操作风险。
- 完整候选嵌入“右侧助手 → 消息流 → 工具结果 → 候选文本”后，原文和候选分处两个滚动面，不具备 IDE 的同文档差异审阅语义。

项目现有基础已经足以走更直接的公开路径：PawApp 通过 `get_novel_generation_ctx` 和公开 `ctx.chat` 执行“AI 小说作家”受控生成；`CreativeGenerationJob` 记录模型和幂等证据；前端已经有字段 Adapter、Selection Registry、哈希/CAS 和 `AIEditTransactionManager`。

因此无需修改 QwenPaw 核心、私有输入框或聊天 store，也无需建设第二套模型运行时。

## 3. 决策 1：选区动作成为 PawApp 编辑任务

- 润色、改写、扩写、缩写、增强对白、检查问题从选区工具条直接创建 PawApp `selection_edit` 任务。
- “自定义”先收集一次作者要求，再创建同类任务。
- 任务通过项目 API 与公开 PawApp `ctx.chat` 执行，强制使用 `ai-novel-writer` Agent；模型仍由其 effective-model 决定。
- 任务使用独立、项目可审计的生成 session id，不占用、改写或伪造作者当前可见的 QwenPaw 聊天会话。
- 不向 QwenPaw 私有输入框写值，不模拟点击发送，不复制命令到剪贴板，不新增第二个聊天客户端。
- requested Provider/模型在任务开始时记录；回复的 actual Provider/模型必须一致，否则结果作废。

真实 Provider 传输中允许存在单层 reasoning/代码围栏外壳。项目适配层只从单次响应中提取**唯一一个**严格形状的 `{replacement_text, short_summary}` 对象，并在进入领域结果前丢弃外壳；多个对象、重复键、非法常量、额外字段、状态胶囊或工作语句仍然关闭失败。该规范化不改变模型权威、结果 DTO 或 requested/actual 一致性规则。

选区 delivery 由单一 session 绑定扩展为互斥联合类型：

```text
editor-task(job_id) | chat-session(session_id)
```

默认是 `editor-task`；作者显式选择“发送到助手”时才使用 `chat-session`。同一选区一旦绑定一种 delivery，不能静默改绑。

## 4. 决策 2：复用 CreativeGenerationJob 并披露有界留存

- 在现有 `creative_generation_jobs` 中增加逻辑 kind `selection_edit`，首选方案不新增表和迁移。
- 文档字段绑定 document scope；其他工作台字段绑定 novel scope，并由项目服务重新验证作品、文档、实体和字段枚举。
- input hash 覆盖 selection id、操作、作者自定义要求、目标字段、完整字段哈希、UTF-16 范围、选区文本、前后文、Agent、requested 模型和契约版本。
- 默认重复点击复用相同 running/ready job；明确重新生成才增加 attempt。

这是 ADR-0003 “普通页面上下文不持久化原始草稿”的一个窄例外：作者明确点击编辑操作后，项目数据库会保存本次有界选区、前后文、作者要求和候选，用于幂等、恢复和审计。

边界如下：

- 选区最多 12,000 字符，前后文各最多 1,500 字符，自定义要求最多 2,000 字符。
- 不持久化当前页面的其他完整字段，不写入 QwenPaw 可见聊天历史、Memory、Agent 文件或普通日志。
- 不把 selection job 的输入冒充正式 revision 或故事事实。
- 刷新后只在当前字段完整哈希和范围仍匹配时提示恢复审阅，绝不自动应用。

若现有表无法满足真实门禁，施工必须暂停并单独裁决迁移；不得改写历史 Alembic revision 或无审计地塞入其他业务表。

## 5. 决策 3：中央/字段主工作面是唯一完整审阅面

- 章节正文使用获选方案 1，在中央编辑区显示统一 Diff。
- 其他已经注册的标题、章纲、总体大纲、人物、关系、故事线、伏笔和设定字段使用相同 `SelectionEditReviewSurface`，挂载在该字段所属页面或弹窗的主工作面。
- 右侧 QwenPaw 助手继续显示原生对话；不再显示完整候选正文和嵌套候选审阅器。
- PawApp 助手外壳状态区可以显示轻量任务状态，但不能伪造助手消息。
- `chat.toolRender` 只为历史结果或作者主动在聊天中生成的结构提案提供紧凑桥接：“在编辑器中打开 / 复制 / 放弃”；不得再次成为完整候选阅读面。

1920×1080 和 2560×1440 均默认统一 Diff。左右对照不是本 ADR 的生产模式。

## 6. 决策 4：审阅决定与正式写回分离

- 模型只返回纯文本 replacement、摘要和警告；字符数、哈希和结构化 Diff 由项目代码计算。
- Diff 必须严格重建原选区和候选；无法安全细分时降级为一个整体 replacement hunk。
- 逐处接受/拒绝只更新内存 `reviewDraft`，不调用字段 Adapter，不产生多次自动保存。
- 未决定变更不能被默认接受。
- “接受全部”或“应用已接受修改”将决定合成为一个 replacement，并在完整校验后只执行一次 `AIEditTransactionManager.apply`。
- “拒绝全部”与未应用的“退出审阅”不改变字段。
- 应用前和异步校验后都要重新读取 Adapter；Agent、作品、文档/实体、字段、context revision、tab、job、完整 SHA-256、UTF-16 范围和原选区任一不匹配即进入冲突态。
- 正文继续走恢复草稿、自动保存和 CAS；显式保存字段保持 dirty，原保存按钮仍是唯一持久化入口。
- 撤销整次审阅事务继续走同一 Adapter 和原保存策略。

模型、网络、取消、超时、JSON、Diff、渲染、路由、冲突或保存失败都不能改变权威正文。

## 7. 决策 5：取消、失败和兼容降级

- 浏览器取消表示 UI 停止等待并与任务脱离。如果上游公开接口不能真正中止模型调用，后端任务可以继续完成，但不能自动打开或写回。
- 迟到的 ready 结果只作为可恢复候选；字段基线不匹配时只允许复制或放弃。
- 新编辑任务不可用时保留普通编辑器和原生聊天，明确显示失败。
- “发送到助手”是作者显式选择的兼容路径；不得自动覆盖剪贴板或操作私有输入框。
- QwenPaw 公开契约变化时，关闭 editor-task 入口和 bridge renderer，保留手工编辑；修复留在 PawApp/适配层。
- 插件卸载必须注销 route wrapper、renderer、payload hook、Middleware、Skills、工具和 PawApp；项目小说数据与审计任务按既有卸载策略保留，QwenPaw 核心不留拦截。

## 8. 不采用

- 继续把 Clipboard 粘贴/二次发送作为默认路径。
- 操作 QwenPaw 私有 DOM、Router、聊天 store、数据库或内部模块来模拟一键发送。
- 新建第二套聊天前端、Agent Runtime、模型选择器或 Provider 配置。
- 在右侧聊天中继续显示完整候选审阅卡，只通过去边框把它称为 IDE 审阅器。
- 把方案 2 左右对照作为 1920 或 2K 默认模式。
- 每接受一处就立即写字段、触发自动保存或创建多个互相依赖的撤销事务。
- 自动解析普通聊天文本为修改，或让模型返回 HTML/Markdown 后直接渲染。
- 候选生成后自动应用、自动保存显式表单或绕过 CAS。

## 9. 影响与代价

正向影响：

- 选区动作符合“一次点击即开始”的直接预期。
- 原文与候选进入同一阅读面，消除聊天和候选的多重滚动。
- 右侧助手回归正常对话，不再同时承担编辑器职责。
- 显式任务可以记录模型、attempt、输入哈希和失败证据，并在安全基线下恢复审阅。
- 一次性 Adapter 应用保留现有正文安全和撤销语义。

代价：

- 前端需要新的审阅状态机、主工作面 Host、结构化 Diff 组件和多字段接线。
- 后端需要扩展 creative generation kind、Skill 映射、严格结果规范化和 Diff 生成。
- 显式 selection job 会在项目数据库保存一小段作者文本与候选；UI/文档必须披露该边界。
- 浏览器 Abort 不一定能取消已经进入上游的模型计算，需要区分“停止等待”和“后端取消”。
- 历史聊天中的旧工具结果必须安全降级，不能因 renderer 变化失去复制能力。

## 10. 验收结果

本 ADR 的实现已重新验证：

1. 七种操作的一键创建、幂等、requested/actual 模型一致和三题材真实结果。
2. 中央/字段内统一 Diff 的重建正确性、逐处决定、一次性应用、撤销和冲突。
3. 1920×1080、2560×1440、200% 缩放、键盘、焦点、中文 IME composition 自动化契约和非颜色语义。
4. 普通聊天、其他 Agent、原生新会话、附件、停止、历史、Provider、Skills、MCP 和设置非回归。
5. 插件安装、幂等升级、完整卸载、重装、项目数据保留和 QwenPaw 原生恢复。

实际结果：

- 前端全量 `38` 个文件、`303 passed`，TypeScript typecheck 与生产构建通过。
- 明确隔离 PostgreSQL 全量 `251 passed, 0 skipped, 1 warning`；测试库迁移到 `20260825_0009` 后销毁，正式数据影响为 0。
- 三本真实题材作品覆盖七种操作，requested/actual 均为 `minimax-cn / MiniMax-M2.7`；拒绝与退出零写入，显式应用后可整次撤销并恢复原哈希。
- 1920×1080、2560×1440、200% 等效缩放与同视口参考图复核通过；中央审阅区不会被右侧助手压缩到不可用宽度，弹窗字段审阅保持在焦点作用域内。
- 完整卸载后 PawApp、插件 Skills 和小说工具注册均为 0，普通 QwenPaw 新对话恢复；重装后工作台、九个 Skills、五个小说工具和四章正文哈希保持正确。
- 打包产物不包含 `__pycache__`、`.pyc` 或 `.pyo`。人工中文 IME 候选窗和人工读屏顺序保留为非阻断发布前建议，不冒充已人工执行。

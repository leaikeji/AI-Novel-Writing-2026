# ADR-0010：Qwen TTS 双 Provider 与可替换本地运行时

状态：**已接受，施工中**
日期：2026-09-08
替代：[ADR-0005 MOSS-TTS 本地运行拓扑与资源边界](./ADR-0005-MOSS-TTS本地运行拓扑与资源边界.md)

## 背景

文章编辑会频繁使局部朗读失效。全部使用云端会产生不必要的调用成本，也使网络、隐私和限流成为编辑主链依赖；只用本地又无法覆盖低等待或本机资源紧张时的选择。当前 MOSS 专用参数、双模型流程和 24 槽通用池已把业务层与运行时绑定过深。

## 决策

1. 建立统一 TTS Provider 边界，提供 `local_qwen3_tts` 和 `aliyun_qwen_audio_tts` 两个实现。
2. 本地采用 Qwen3-TTS-12Hz 1.7B 的 CustomVoice、Base、VoiceDesign 三类能力，当前优先 MLX 社区实现；模型按操作串行加载并可卸载。
3. 云端采用阿里云 Qwen-Audio 3.0 TTS，默认 Plus，可显式选 Flash。
4. Provider 由作者显式选择，不静默回退。缓存、模型证据和声音版本包含完整 Provider/runtime/model 身份。
5. MLX 是可替换实现，不是领域契约。未来切换官方 PyTorch 只改本地 adapter/sidecar，但必须重新验证模型资产、派生 voice prompt、性能和输出。
6. 保留通用朗读基础设施，删除 MOSS/Nano/VoiceGenerator/24 槽池专用模式。声音产品收缩为官方预设和人物专属声音。
7. 云端 TTS 使用独立作品级同意；不同于说话人分析同意。未同意、同意撤销或密钥缺失均 fail closed。

## 理由

- 本地承担频繁编辑和重复生成，云端承担作者主动选择的质量/速度路径；
- 明确切换比自动回退更容易理解费用、隐私和声音差异；
- 统一边界使业务恢复、缓存和 UI 不依赖 MLX 或云端 SDK；
- 三模型按需加载符合 16 GiB 机器约束，又不为未来引入模型常驻调度平台。

## 结果

- 同一逻辑声音可能需要本地和云端两个 Provider 版本，不能跨 Provider 冒用缓存；
- 首次模型加载、声音准备或云端声音注册有显式等待与状态；
- MLX→官方实现不要求改业务接口，但权重和派生缓存不能直接假定兼容；
- 历史 MOSS 文档与迁移保留审计事实，现行产品和运行配置不再依赖它们。

## 回退

新链验证前保留当前可运行路径。若本机 Q0 或双 Provider 发布门失败，关闭新 capability 并保留纯文本功能；不清旧数据。新链验证并执行正式清理后，回退只允许回到上一个代码/镜像和数据库快照的前滚恢复方案，不恢复已明确弃用的 MOSS 产品模式。

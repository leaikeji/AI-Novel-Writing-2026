# 写作 Skill 自动路由与可扩展分类接入优化计划

状态：V1.2 复查修订方案，待用户批准施工；本轮按“同意，请优化计划”修订本文及导航。未实现、未部署本计划，不授权修改模型、调用真实 Provider、迁移数据库、重装插件或提交／推送 Git。

原始日期：2026-09-03；V1.2修订：2026-09-05（Asia/Shanghai）。前置：计划57的两份分类／机制 Skill 已由作者批准并在专用 Agent 启用，但所有入口自动装载尚未完成。

V1.1已落实五项复查结论：路由调用前持久化防重复；路由与生成共用任务资料白名单；单独验证辅助调用的工具／递归／次数边界；题材与机制分别判断；共同基础、按钮、原生聊天和语义增强分别设门禁。旧版草案在本文直接修正，不另建冗余流程副本。

V1.2追加落实三项复查结论：稳定动作身份先于可变输入指纹查重；受管请求以服务端方法清单为唯一装载依据；确定性样本、语义样本与各入口实测分别计分。沿用原施工架构与40次辅助路由＋8次短生成预算，不新建另一套路由或评测流程。

## 1. 目标与作者体验

作者按平常方式选择作品、编辑设定、写章纲、点击生成或直接聊天，不必记住 Skill 名称。系统基于本次任务允许读取的分类、故事资料、当前章节／选区和作者要求，选择并实际装载适用方法；没有匹配模块时使用通用方法。以后新增已批准分类模块，应只增加模块及其声明、样例和发布记录，不再逐处修改路由代码、安装名单、前端选项和固定数量测试。

默认不增加分类问卷、不要求逐章勾选 Skill、不强制写评审理由。输出继续是作者要的正文、章纲或审稿意见，机器内部路由结果不混入文章。界面用一行状态说明本次装载的方法，详情按需展开。

“自动”不是“所有 Skill 一起加载”，也不是“模型说自己用了就算使用”。验收必须分开：可发现、符合条件、已选择、方法内容已组装、请求已派发，以及最终写作质量。提供方法不能证明模型一定遵守，更不能证明写作增益。

### 范围

- 本计划包含分类发现、作品与任务识别、组合与预算、按钮及原生工作台接入、任务级证据、可选纠错、安装升级和回退。
- 保留九个通用任务 Skill；悬疑和金手指作为第一批正式模块，不新增尚无材料的言情／历史等正式方法。
- 仍只有 `ai-novel-writer` 作为产品生成模型权威。无第二个写作 Agent、第二套聊天前端、固定 Provider 白名单或逐模型 Skill。
- 不改 QwenPaw 核心，不重做 Context V4、故事账本、正文权威链、TTS、研究评测或建书向导。不要把本计划当成计划28或其他待批准计划的施工授权。
- 不把一本书的设定配置写成单书 Skill；不自动重新拆书、下载正文、发布小说或训练模型。

交付顺序：先完成动态发现、确定性选择、真实装载和调用证据；按钮与原生聊天按各自公开接口门禁独立推进；再为通过隔离与计数验证的入口启用语义补选。跨设备方法偏好可后置，不阻断核心自动调用；任务级防重复和装载证据不能后置。部分入口可用不等于全目标完成。

技术推断：可复用项目领域服务、公开 PawApp 调用和 Middleware 建立统一路由。但原生当前请求装载、历史隔离、请求级无工具辅助调用仍待公开合同实测。第7节按能力拆分门禁，不用一个尚未验证的原生能力阻断全部按钮工作，也不把推断写成已实现事实。

### 待批准的新决策

1. **可扩展模块替代固定两类清单。** 计划23的“最多一个分类入口”和计划57的“本次两个模块”不再作为未来分类总数上限；继续保留避免分类×任务复制矩阵的原则。
2. **题材与机制独立判定，语义按需补选。** 确定性规则已解决所有相关维度、可复用结果或没有足够资料时零辅助调用；命中“悬疑”不能替代对金手指等机制的判断。仍有可判断的未决维度时，才考虑一次可见辅助判断，仍用本任务冻结的 `ai-novel-writer` 有效模型。
3. 上述辅助判断扩展了现有“不增加隐藏模型调用”的边界：**语义功能初始关闭**。只有对应入口的 `G-SEMANTIC-*` 通过且该阶段及真实调用预算已获批准，才可发布为按需自动；作者仍可关闭。不因批准编写／实施计划就静默启用。确定性先行版本须明示“隐式情节补选尚未启用”。
4. 首期拟新增一个窄的请求认领／方法证据表；已有生成 job 继续保存任务快照。跨设备偏好表作为独立后置包，未启用时使用明确默认策略与本次覆盖值，不另建数据库、队列或运行时。数据方案见第8节；批准施工不等于允许直接迁移唯一运行库。

## 3. 一套服务，覆盖全部入口

```text
原生工作台聊天／选区   章节正文／章纲   设定／人物／审稿
          \                |                 /
           服务端范围核对＋任务白名单资料快照
                            |
           已发布且已启用的模块目录（动态发现）
                            |
           请求认领 → 题材／机制分别确定性判断
                            |
             已过门禁且仍未决 → 一次语义补选
                            |
           冲突处理＋内容装配＋预算＋不可变指纹
                            |
              原来的任务 Skill／输出封套
                            |
             QwenPaw 公开调用 → 候选／审阅
                            |
                 方法使用证据与界面状态
```

路由属于项目领域能力，不由前端或每个 API 复制一套。模块只有方法来源，不获得正文写入、模型切换、范围选择或执行任意脚本的权限。

### 入口覆盖矩阵

| 入口／任务 | 主要任务边界 | 分类／机制策略 |
| --- | --- | --- |
| 章节正文、续写、重写 | `prose-writing`；原字数、JSON/纯文、候选与CAS规则 | 完整接入，按作品及当前章任务选模块 |
| 章纲、章节情节建议 | 章纲产物；现有受控接口仍遵守自身封套 | 接入分类和阶段方法，冻结目标字段 |
| 总纲背景／人物／情节／亮点 | 设定或对应人物任务产物 | 只加载影响本次目标的规则，不重生成其他字段 |
| 人物草稿／人物性格补全 | `character-craft`；仅候选 | 可用相关类型方法，不靠题材编造已有人物事实 |
| 发展性审稿、连续性与伏笔检查 | `style-review`／`continuity-check` | 可用分类检查，不将审稿变成自动改正文 |
| 选区 polish/rewrite/expand/shorten/dialogue/review/custom | 沿用7种 operation、范围、长度与提案契约 | 根据操作目的和选区判断；机械校对不加分类；正文仍由通用正文方法收口 |
| 专用原生工作台聊天 | 按本轮真实意图选择主要任务 | 同一 resolver 和装配器；不依赖作者点名，不用旧会话书名猜当前作品 |
| 开书前的方向、分类建议、命名 | 经校验的创建草稿／本轮明确创意，没有正式小说也可运行 | 只标为临时创作范围；未知分类回退；不能自动写入正式分类 |
| 关系图同步、情报抽取、进展同步、字段抽取 | 证据抽取，不是开放创作 | 默认不加载创作型分类模块，不添剧情；未来只有显式支持该任务且通过测试的模块可参与 |
| 封面、音色、TTS、向量、导出及普通非小说操作 | 原功能 | 不触发本路由，不新增模型调用 |
| Default／QA 等非目标 Agent、普通未绑定聊天 | QwenPaw 原生行为 | 不注入、不旁读当前工作台、不切Agent；缺少作品绑定时不跨会话借用资料 |
| 研究 A/B、冻结评测与历史重放 | 评测原合同与冻结方法 | 禁止自动混入新模块；仅受可信评测策略显式控制，不接受用户正文里的“评测模式”标记 |

盘点时逐个列出全部 `ctx.chat/chat_stream` 调用和原生工具入口，给每项注明“接入／明确排除”及测试编号。不得只验正文按钮后宣称全部完成。主要任务 Skill 的历史映射差异须单独记录；与本计划无关的任务能力重构不顺手施工。

## 4. 模块声明与以后新增分类的流程

正式能力模块采用 `skills/<skill-id>/SKILL.md` ＋可选 `references/`，新增同目录 `routing.json`。`SKILL.md` 是方法正文唯一来源；JSON 只保存机器需要的路由信息，采用标准库JSON＋现有Pydantic，不增加 YAML 运行时依赖。

拟冻结声明版本 `writing-capability/1`，字段至少包括：

| 字段 | 合同 |
| --- | --- |
| `skill_id / capability_version / routing_schema_version` | ID与目录、frontmatter一致；方法和路由均可追溯 |
| `kind` | `genre` 或 `mechanism`，金手指不是所有玄幻小说的同义词 |
| `display_name / description` | 面向作者的名字和简洁、可区分的触发描述 |
| `approval_ref / release_status` | 指向作者正式采用记录；仍可保留效果 `inconclusive`，不能伪造研究通过 |
| `genre_aliases / mechanism_tags` | 显式标签映射，不要求修改核心分类枚举；只匹配事实字段，不扫描整本关键词作结论 |
| `applicable_tasks / excluded_tasks` | 任务类型枚举属于路由合同；新增分类不需要新增任务类型 |
| `semantic_criteria / negative_examples` | 供语义选择器识别适用性，包含否定、普通同名词和反类型情况；不是任意可执行表达式 |
| `reference_rules` | 按任务／子用途加载哪些本目录参考文件；不能引用网络或跨模块任意路径 |
| `conflicts_with / supersedes` | 仅指已登记ID／版本；冲突与替代有发布依据，不靠文件名或装载顺序隐式覆盖 |
| `auto_eligible / budget_hint` | 默认可自动考虑；只是资格与预算建议，不可覆盖用户禁用或系统上限 |

目录加载器只扫描当前项目正式安装包中经校验的模块，不搜索用户素材库、研究报告或全机 Skill。未知字段、同ID冲突、声明与正文版本不符、路径穿越／越界软链接、参考文件缺失、格式错误均拒绝进入可用目录；不能执行模块提供的路由代码。

动态目录摘要由源码生成、由安装包携带并核对哈希，不手工维护第二份方法或名单。测试从发现结果校验能力集合，不把11/12等固定总数当永恒合同；原九个基础任务可以保持明确基础合同。

`approval_ref` 在发布时解析为随包携带的最小批准索引（批准记录标识、来源、方法版本与文件摘要），不要求运行容器访问研究仓库的本机绝对路径，也不在每次写作时联网查询。声明自称“已批准”不足以放行；必须与受信发布包批准索引一致。研究报告保留原位置，索引不复制小说内容。

新增分类标准流程：制作并审核方法 → 补同目录路由声明和正反场景 → 结构／路由／预算／原创性校验 → 用户批准该方法 → 正常打包安装 → 专用Agent作用域和启用检查 → 目录版本变化使缓存失效 → 下一次相关写作自动发现。**不需要改 Python 分支、Agent名称清单、前端下拉选项或固定数量断言。**若新增能力需要新的工具、任务类型或外部权限，属于接口扩展，仍需另行设计，不承诺任意模块零代码接入。

原生宿主“可发现／启用”与本项目“可自动注入”要取交集。不得因为服务器读得到模块就绕过用户在 QwenPaw 的停用选择。升级前保存公开状态：新模块可按已批准发布策略为专用Agent启用；已有模块保持用户启用／停用决定。其他Agent不自动启用。

## 5. 依据分类和情节选择：分层、可解释、不改小说事实

### 5.1 先冻结输入

先用现有入口的白名单生成不可变 `TaskModelInputProjectionV1`，再派生 `RoutingInputV1`；不是先为路由读完整小说再另裁剪正文 prompt。两者共用范围、任务／intent、来源版本和可见性基线。路由内容必须是该任务获准模型资料的子集，加上不含小说内容的目录／预算／策略元数据。服务端控制字段不必全部发送模型。

- **大纲：**沿用 `build_outline_generation_snapshot()` 的任务字段白名单；`fresh` 路由和生成都不得读取旧目标，`refine` 才允许当前目标。`audit_context.previous_target`、审计哈希和仅供审计的资料不进入路由输入、理由、情节缓存或选择特征。
- **正文／章纲／人物／选区：**复用各自 Context V4 或现有任务投影，只使用已授权、对当前位置可见且本任务允许的资料。范围校验先于取数；不能旁路读取未来章、全书设定、其他时间线或未绑定私有素材。作者规划与人物已知继续分层。
- **原生聊天：**以经核验的本轮请求和同一范围投影为输入，不能只凭旧会话猜作品。原生投影和历史隔离未验证时，该入口不能借用按钮通过的结论。
- **开书前：**显式区分 `scope_kind=novel` 与 `creation_draft`；临时草稿需要owner/tab绑定、版本和有效期，只接收本轮授权创意。不为路由创建假小说，不把缺少 `novelId` 自动解释成可旁读其他作品；原生草稿支持单列验收。
- 小说目前没有统一持久化 `mechanism_tags` 字段。目录中的同名字段只是模块触发词表；机制依据来自任务允许的明确设定／本轮要求或有来源的语义判断，不假定数据库已有该字段，也不另建机制事实库。
- 网页草稿保留 `dirty`／临时状态，只有当前任务允许该草稿时才纳入；不据此改正式分类。书名、榜单标签和普通关键词均不能单独定类。路由只做有界提取，不额外调用模型来总结路由资料。

冻结 `source_projection_hash` 与来源版本用于认领和复查；异步路由后若来源、授权或目标已变，不把旧路由拼接新生成资料，按原CAS冲突语义停止该次请求。安全反例须检查方法ID、理由、缓存和生成输入，防止“未直接发送旧稿、却用旧稿选方法”的间接泄漏。

### 5.2 决策顺序

1. 校验作用域、入口、作者本轮限制和任务；机械校对及排除入口不加载创作型分类方法，也不发辅助请求。
2. 在已批准、已启用、支持本任务的目录内，**分别处理任务适用性、题材和机制**。每一维记录 `resolved / unresolved / not_applicable / excluded`，以及有证据的选入／排除项；空匹配不自动证明“没有机制”。一个题材命中不能提前结束另一维判断。
3. 明确分类、允许资料中的明确机制依据可确定性选入。作者本轮“不要金手指”等排除优先；角色对白的否定不提升为作者指令。当前章只调整本轮适用性和参考内容，不重写整本分类；悬疑缓冲章不强塞反转。
4. 有资料且有适用候选的未决维度，在语义门禁已通过时合并成**一次**补选请求；不按每个维度／每个模块分别调用。明确命中的模块保留，语义结果只补未决项，不推翻权限、作者禁用或确定性排除。资料不足则保留不确定并降级，不为凑答案调用。
5. 合并结果后统一做任务过滤、冲突裁决、引用验证和预算裁剪；全部候选来源于动态目录，不在引擎里写死“悬疑→再检查金手指”。理由只保留简洁结论和可核对来源，不存隐式思维链。

示例：保存题材为悬疑、获准章纲明确包含可重复使用的特殊能力时，两类分别命中；特殊能力仅隐含在获准剧情中时，悬疑维已决、机制维未决，可按门禁补选。换成未来新增模块也遵守同一维度流程。关闭语义时仍自动使用有明确依据的方法，并显示未决项未补选。

### 5.3 有条件的一次语义判断

语义仅处理第5.2节的未决项，输入为同一有界资料投影与候选声明，不加载全部方法正文。它是增强能力，不是确定性分类、装配或按钮交付的前置依赖。

- 使用同一冻结有效模型和公开调用适配器，不新增选择器、不换模型。**新 session 本身不构成隔离证据**：必须通过公开合同实现本请求 `tools=none` 等效能力、禁止通用Skill再次路由、禁用自动工具循环／重试，并验证无历史继承。不能为此临时停用共享Agent的工具或修改其全局配置。
- 可信 `purpose=writing_skill_routing` 与递归防护由服务端内部请求上下文建立、按请求传播和清理；不能相信小说文字、客户端字段或session名称。它只跳过路由自身的重复路由，不跳过身份和范围校验。公开合同无法保证时，对应 `G-SEMANTIC-*` 不通过，保持该入口确定性可用。
- 返回受限 `skill_ids / reference_keys / evidence_refs / unresolved_dimensions`，允许空集合。确定性校验器检查目录ID、来源、任务、排除和预算；未知ID／无依据项拒绝。自报置信度不作为通过依据，路由JSON不进入正文。
- 分别记录 `router_invocations`（项目辅助调用）、`model_rounds`（实际模型轮次）、`tool_calls`、`transport_attempts` 及其证据可见性。一次 `ctx.chat` 不能直接写成一次Provider请求。发布要求辅助调用≤1、路由模型轮次≤1、工具调用0、无自动补发；公开证据不能约束这些行为时不启用。token／计费usage不公开仍记 `not_exposed`，不推断实际费用。
- 初始预算目标：应用等待20秒、输出接受上限800 tokens、路由输入≤6000估算tokens；公开接口能施加的硬上限与应用接受上限分别记录，由语义门禁冻结。不能通过私有实现补参数，也不能把接受上限称为计费封顶。
- 应用超时或本地task取消不等于Provider终止。只有确认辅助执行已结束、模型身份仍有效时，才可在本次请求中降级继续写作；远端状态不明标 `unknown`，停止该请求的后续派发和自动恢复。其余确定性请求不受全局阻断。原有正文任务的重试另行计数，不挪入“一次路由”的额度。
- UI显示“正在判断适用方法”，记录额外调用及耗时；确认结束的无匹配／无依据输出可退回确定性结果。模型前后身份按ADR-0009核对，身份错配／postflight失败停止本次执行，不能以通用降级绕过。
- 缓存只保存派生选择。键包含允许资料投影、任务／intent／本轮要求、范围／可见性、目录／方法／策略版本、偏好与有效模型；不按书ID粗缓存。稳定题材匹配与请求情节缓存分开，输入框编辑、页面预览、切换和轮询零辅助调用。
- 所有辅助网络请求必须在第8节的持久化认领之后执行。重复点击、重复回调和重启先查已有结果；未知调用不自动补发，不能只用进程内锁或假定现有job锁已经覆盖。

此机制让未来只声明自然语言适用条件的新分类仍可被理解，但不承诺无限分类、任意模糊剧情100%识别。若候选目录超过输入预算，先按可信分类／任务缩小；仍无法完整判断则显示目录截断与通用降级，不暗中只取字母顺序前几项。

## 6. 真正装载、组合与上下文预算

优先级：权限／产品安全与可信输出封套 → 作者本轮明确要求及正式事实边界 → 本任务分类／机制方法 → 通用写法偏好。主要任务 Skill 负责交付物，分类模块不接管存储、调用模型或输出格式。

### 6.1 受管请求的唯一方法清单

- 受管按钮与已接入的绑定原生请求，由服务端生成可信 `managed_skill_dispatch` 上下文，绑定动作、范围和冻结方法清单。它由已验证的公开调用链传递，不能通过作者文字、客户端自报或session命名开启。普通未受管聊天继续现有Agent路由。
- 受管请求的主任务、附加能力、参考文件及必要通用依赖均以冻结清单为准；Agent不能在生成阶段再次选择分类、加载清单外的Skill／参考或重复读取已装配块。`generic_only`禁止附加分类／机制模块；通用Skill保留的原有通用原则不冒充分类模块已启用。
- 分类技能已启用只表示可供路由选择，不表示当前请求允许自行加载。Agent提示的路由段应明确受管／普通两种行为；主要Skill的“按需再调用某Skill／读取参考”也要服从可信清单。通用依赖须在派发前确定、计入预算和证据，不由模型在冻结后扩张。只调整接入合同，不顺带改文学方法；涉及SKILL文本时独立记录版本并校验。
- 工程门禁必须通过公开接口验证后续装载：包括Skill调用入口、参考资料读取，以及重复装载。清单外的装载在内容交给模型前拒绝；重复项复用已提供块，不再增加输入。不能仅凭一段“不要再加载”的提示声称已控制，也不能在发现越界后补记证据冒充事先允许。正常小说资料／选区提案工具仍遵守原有权限与任务合同，不为了限制Skill关闭整个Agent的工具。
- 若宿主公开接口无法限制或观察相关装载通路，该入口不得宣称“仅通用／已排除／预算受控”通过，记录具体缺口；其他已通过入口独立推进，不修改QwenPaw核心或共享Agent全局开关。

### 6.2 装配与预算

- 一个主要任务 Skill；默认最多两个附加能力模块（主分类＋机制或次分类），此为单请求预算上限，不是注册分类总数上限。显式选择冲突时按作者主体验、明确分类、可核对的任务相关性裁决；平局不能随文件遍历顺序改变结果，稳定排序并记录被省略项。
- `SkillInvocationPlanV1` 包含精确ID／版本、选择依据、参考文件清单、冲突裁决和回退原因。`SkillInjectionPacketV1` 包含实际装载的正文／参考块及哈希，不只把名称传进提示。
- 通过统一 `compose_writing_request()` 将同一packet用于各按钮；继续只给 `ctx.chat` 一个主任务 Skill，附加方法由项目适配器组装，不伪造 `skills=[...]` 或多个技能名拼接参数。
- 注册模块的全部参考文档不默认加载。声明选择的参考块必须完整、可定位，缺失／非法不能静默跳过后声称完整加载；不可运行时让模型自行总结成另一份未经版本化的方法。
- 接入现有预算链，预留主要任务、输出和不可省略事实后分配分类预算。初始建议附加方法合计上限6000估算tokens且不超过有效输入预算15%，以更低者为准。过大时先删非必要参考，再省略低优先级辅助模块；单个核心块不可从中截断。预算异常展示降级，不挤掉关键禁写项／前文事实。
- 主任务Skill由宿主加载的内容同样需要预算证据；公开接口未暴露宿主隐藏开销时使用标明来源的保守预留，不能把项目prompt估算当作最终Provider完整token数。
- 计划57暂保留的通用悬疑重叠参考，只有两条路径的新装载都通过后才能收敛；删除前证明相关入口已有替代且通用降级仍安全。未知分类的通用原则继续保留，不新增“停用分类后依然暗加载其完整规则”的旁路。

## 7. 分支门禁与公开接入

不再使用会阻断所有工作包的单一G0。下列门禁各有范围、前置和结果，`PASS`不能跨入口借用；技术通过也不代替真实调用预算、长期部署授权。

| `G-BASE` 共同合同 | 范围／任务白名单、目录与维度DTO、预路由认领／最终hash、状态机、入口清单、错误码及兼容合同冻结；现有白名单基线核验 | 只修共同设计，不派依赖该合同的施工包；不要求先证明原生或语义能力 |
| `G-BUTTON` 受控入口 | `G-BASE`；各按钮的确定性发现、真实字节装配、范围／输出格式、稳定动作幂等及失败恢复通过；第6.1节清单外装载／重复加载验证 | 该按钮不发布；不因原生未通过而挂起全部受控入口开发 |
| `G-NATIVE` 原生入口 | `G-BASE`及共同组件；公开当前请求装载、逐发送关联、清单唯一控制、角色分离、切书／关闭／压缩隔离与原生非回归实测；小说／创建草稿范围分别记结果 | 失败范围不启用自动装载，列明缺口；按钮仍可独立验收和经授权交付 |

### 7.1 按钮：先认领，再路由，再建立最终job

现有job锁只保护最终输入hash之后的部分，不能直接覆盖新增的路由调用。顺序固定为：身份与动作所属范围核验 → 按稳定动作ID查重 → 新动作才冻结白名单资料及配置并原子认领 → 确定性／可选语义选择 → 复查来源与撤销状态 → 装配方法并计算最终输入hash → 在原job锁下创建／复用任务 → 原模型调用。动作已存在时先遵守第8节复用／冲突规则，不能用最新目录或模型重算key后重新认领。

继续／重放已有job时读取原快照，不重新用最新目录选择；旧快照没有方法证据则标 `legacy_unrecorded`，不伪造已装载记录。升级方法需要新输入和新候选。原有任务的验证重试如仍存在，复用同一方法packet并另计调用次数；本计划不顺手修改其策略。

### 7.2 原生工作台：当前请求可控才接入

复用公开 Middleware、`context_ref` 和session／Agent／范围绑定。前端只能传范围引用与本次偏好，不能传本地路径或自称可信的方法字节。只有取得本轮真实请求后才判断任务；同步 `requestPayload` 变换器不运行异步路由、不替换原生发送按钮。

- `context_ref` 是可复用的范围引用，**不是逐发送ID**。必须使用已验证的公开发送标识，或本项目协议分配的稳定 `action_id`，关联请求认领、返回状态和重试；普通再次发送是新动作，同次传输重试复用标识。不能只按session／context_ref展示“最近一次”结果。若需要准备票据，应接现有公开准备链并验证缓存／连续发送行为，不能凭假定新增拦截。
- `novel` 与 `creation_draft` 使用可区分的范围合同、服务端绑定和测试。现有要求 `novelId` 的接口不直接放宽成任意空值；草稿分支未验证时明确不支持，普通未绑定聊天仍不旁读工作台。
- 方法装载与 `role=user` 页面数据分离；不替换宿主system prompt、不读私有Agent／memory／toolkit。验证**当前输入**中的方法字节和来源角色确实进入公开下游请求，而非只看模型复述。
- **历史与压缩隔离是原生发布条件：**切书、改类别、切任务、关闭模块、压缩后，上一轮方法不能继续成为本轮有效指令。优先用公开最终输入扩展点处理本插件可识别的方法块，不删除用户记录或其他插件内容。若压缩已丢失身份、公开接口不能可靠排除，判该分支不通过；仅要求每次新建会话不算完整验收。
- 原生语义子调用还须独立验证可信purpose传播、预认领、递归隔离和取消链；“同一Agent＋新session”不能代替证明。公开合同不足就保持该增强关闭，不导入私有实现、不修改QwenPaw核心。

## 8. 持久化、可追溯、并发与恢复

### 8.1 路由前防重复，不靠最终hash倒推

分开动作身份、输入指纹与最终方法指纹，职责不得混用：

| 标识 | 生成时机与材料 | 用途 |
| --- | --- | --- |
| `action_id`与动作唯一键 | 一次明确操作产生、在首次发送前保存；唯一键绑定owner／Agent／入口命名空间与action_id，不含目录、模型、正文版本或输入hash | 所有传输重试先据此查原记录；小说／目标范围是记录中不可变绑定，同ID换目标直接拒绝 |
| `route_request_key` | 首次认领时冻结的服务端范围、任务／intent／操作、允许资料hash与版本、本轮要求、目录／策略／有效偏好及模型的规范化摘要 | 用于输入比较和跨动作复用候选判断；不替代动作唯一约束，不因重试读到新版本而重算成新认领 |
| `method_input_hash` | 选择和装配完成后；规范化的方法ID／版本／正文与参考hash、顺序、规则性排除、任务／资料／策略边界 | 冻结真正提供的方法；不含随机ID、时间、耗时或模型生成的解释措辞 |
| 最终job `input_hash` | 原任务输入＋版本化方法指纹＋既有模型／生成合同 | 沿用业务job的防重复与候选恢复，不以dispatch ID替代 |

1. 普通按钮一次待处理操作、双击及网络重传复用已保存的action_id；明确再次生成／`force_new`产生新动作。同一次新尝试重传不再生成ID，刷新通过已存动作／任务引用恢复。原生逐发送产生新动作，传输重试保持原标识；相同文本不等于相同动作。无稳定动作的旧客户端须经版本化兼容入口分配／返回可恢复动作，未建立该合同的入口不启用辅助路由。
2. 身份核验后先按动作唯一键查记录：同ID且本轮提交内容／目标一致，返回原状态或结果；同ID携带不同目标、要求或输入版本，返回冲突且不调用模型。外部目录、模型、资料或偏好变化不会创建新动作：处理中记录保持原快照，派发前仍按第5项检查；已完成记录可只读返回，不能借此发起新生成。
3. 新动作在短事务中用动作唯一约束＋CAS认领 `WritingSkillDispatch`，冻结输入、记录owner／执行代次（fencing token），提交后才允许外部路由调用。并发竞争失败者重新读取胜出记录并比较，不重算key另起请求。不同动作的同输入可按原有job规则复用已完成结果；若复用进行中路由，须原子关联同一执行owner，不能绕过动作身份或取消边界。
4. 记录 `claimed → routing_started → route_ready → assembled → dispatch_started → dispatched` 的事实边界，保留失败／取消／未知／来源过期分支；无语义时跳过 `routing_started`。认领状态不冒充模型执行状态。路由、写作等待都不占数据库长事务；回写需匹配owner代次，旧执行者不能覆盖新状态。可能已发出调用的崩溃窗口标 `unknown`，不能因租约超时自动重发；只有明确未开始外部调用的认领可安全重取。
5. 取得路由后再核对来源基线、目标范围、模型身份、启用／撤销和取消状态；变化则停止该次请求，不重新读取资料拼接旧方法。最终job创建／关联与dispatch状态更新在同一短事务完成，避免存在未关联但重复派发的任务。动作记录的失效不等于允许重用ID；保留期／最小去重标识需覆盖恢复窗口，过期旧动作返回已过期，不自动当新请求执行。
6. 已确认结束的辅助失败才可冻结降级结果；重复请求复用该结果，不重新抽签。`unknown`需要明确的新尝试操作及风险提示，使用新action_id并关联原动作；不能换配置后沿用旧ID解锁调用。本计划保证应用不静默补发，不承诺网络故障下Provider恰好一次执行或绝不重复计费。

### 8.2 数据取舍（拟新增，不是当前已有）

- **首期必需 `WritingSkillDispatch`：**兼任请求认领与方法证据，不另外建队列表。保存范围／action_id／key、owner代次、来源与策略版本、阶段状态、方法计划和可重放字节或不可变包引用、公开调用计数／模型证据、job关联及有界诊断。无完整小说副本、无隐式推理链、无密钥；范围必须由服务端核验。
- `ChapterGenerationJob.generation_context_snapshot` 与 `CreativeGenerationJob.input_snapshot` 增加版本化 `skill_invocation` 引用与方法指纹；正文与任务状态仍归原job。旧快照只读兼容，不补写历史方法证据。现有生成job无法覆盖无job的原生聊天或生成job创建前的路由，所以不能只复用它们代替认领表。
- **后置可选 `NovelWritingMethodPreference`：**小说外键、owner范围、CAS版本，保存 `mode=auto/generic_only`、`semantic_mode=auto/off` 和排除ID。未做该包时使用发布策略与本次覆盖值；语义最终生效取“该入口发布门禁允许 ∩ 作者偏好允许”，无记录绝不越过未通过门禁。偏好不塞进 `template_data` 或故事账本，关闭语义不等于禁用确定性分类。
- localStorage只能辅助UI恢复，不作为服务器认领／方法证据权威；进程内日志不能代替持久化；不复用绑定background attempt的TTS `ModelRunRecord`。后置偏好未完成时，不声称已支持跨设备保存。
- `G-BASE` 冻结首期表的字段、唯一范围、索引、保留／失效策略和缺省兼容；可选偏好另冻合同。迁移由唯一owner按执行时head新增revision，不预占0041、不改旧迁移。只在隔离库先验证升级和旧应用兼容；长期迁移另获授权，降级保留记录，不删除用户数据。

### 8.3 证据语义

`selected`＝已选出，`assembled`＝真实方法字节已进入应用请求，`dispatch_started`＝准备交给公开链路，`dispatched`＝已确认交给公开链路；失败／取消／未知分开记录。只有公开最终输入可观察才记 `final_input_observed`，否则为 `not_exposed`；均不宣称Provider已读取或模型必然遵循。`selected`可作为计划证据字段，不强迫数据库阶段枚举复制每一诊断字段。

展示用理由、耗时和可见性诊断与规范化业务hash分开。方法升级形成新指纹和新候选，不改旧运行；重放需有原字节或不可变发布包，仅有hash时标无法重放，不能偷换当前文件。理由也遵守第5节白名单，不能以“审计”名义保存被禁止参与判断的旧稿。

### 8.4 缓存、失败与隔离

- 缓存只是加速，不是权威。新增模块、停用、版本改变、分类／设定／章纲更新、故事位置／可见性变动、模型身份变化使对应缓存失效；命中缓存也须走请求认领、范围／取消检查和证据关联，每次派发前再验启用／撤销状态。
- 同一job的处理中方法冻结不被热升级替换；紧急撤销时停止派发／标记失效，不改写已完成证据。原生逐轮更新不改变正在生成的一轮。
- DB认领才是正确性机制。浏览器刷新、双击、重复原生回调、进程重启分别验证，不能拿单进程锁测试替代数据库并发测试。
- 普通无匹配、已确认结束的语义超时／空输出／无依据匹配、预算不足：允许通用降级并给可见原因；远端是否终止不明时按unknown处理。越权、无有效模型、身份变化、篡改、必需输入不足：停止，不用通用方法掩盖安全失败。
- 安装损坏或找不到作者明确必用的方法时，提示不可用；不得悄悄生成后说已遵从。自动模式下某可选模块不可用，可明确降级继续。

## 9. 轻量界面与 API 合同

不新增第二套分类选择器。沿用小说现有题材／细分类编辑入口；首期提供方法状态、本次覆盖与恢复入口，跨设备偏好为后置可选设置，均不要求作者填写问卷。

- 生成前：`自动选择写作方法`，只表示预览／待判定，不显示“已调用”。
- 派发后：`本次已装载：通用正文 · 悬疑 · 金手指`；准确用“已装载到请求”，不写“保证使用／写作提升”。详情显示版本、依据、是否额外判断、降级原因；正文不混入这些字段。
- 模式：自动／本次仅通用／本次关闭语义；首期明确显示“语义补选未启用／已按需启用”。小说级保存排除或开关在后置偏好包提供，CAS失败保留未保存选择；不修改正式设定、其他小说／Agent开关。发布能力关闭时，客户端要求开启也不能越过门禁。
- 纯预览API只做本地确定性推算，不能因刷新或轮询调用模型。具体情节的语义路由只在作者发起真实写作时进行。
- UI在PawApp拥有的状态栏／任务结果区域展示，复用宿主React/Ant Design，不插手原生聊天气泡、模型菜单和输入框内部；按owner／tab／scope／action_id过滤，session只作辅助条件。一次context_ref连续发送两次应显示各自证据，不串窗口、不以旧成功遮盖本次失败。

首期拟在 `/api/ai-novel-world-2026` 提供 `GET /writing-skills`（发现／启用／入口能力状态）、`GET /writing-skill-dispatches/{id}`（只读证据）；生成请求／job响应增加动作标识、本次覆盖和dispatch引用。原生准备协议的逐发送关联与创建草稿范围在 `G-NATIVE` 分支验证后版本化接入，不先假定宿主有不存在的字段。

`GET/PATCH /novels/{id}/writing-method-preference` 随后置偏好包提供，首期不放一个不能保存的空壳API。所有入口共用领域服务与权限；原生关联协议不提供调用任意模型或自动改写正文的端点。

### 10.1 分组评分，不能用总体平均替代语义通过

首轮冻结40个自写场景，分为互不重叠的D组20题、S组20题。每题预标任务、题材／机制维状态、允许ID集合、应否辅助调用、来源和禁止项；合计覆盖两正式模块各至少10个正例及10个排除／反例，并包含混合与仅测试未来模块。分类由fixture预定，不能看结果后把失败题移到另一组。

| 验收组 | 样本与运行方式 | 独立通过条件 |
| --- | --- | --- |
| D：确定性选择 | 20题明确分类／明确机制／排除／机械任务／无资料；预期辅助调用0 | 20/20符合预标集合与调用策略；工程合同及安全负例全部通过 |
| S：语义判断 | 20题均有获准资料但存在需理解的未决项；每个正式模块至少4个语义正例、4个语义排除例，至少4题混合／隐含机制、至少2题测试未来模块，覆盖可重叠 | **只在S组**计算微平均precision≥95%、recall≥90%、完整集合正确≥18/20；两正式模块分别recall≥90%，正确拒绝的空集单列；实际成功返回不足18题不得通过 |
| E-B／E-N：入口接入 | 从S组预先选8个覆盖正例、排除、混合、未来模块的场景，按钮／原生各用新测试动作实调8次；显式记录模型、版本、入口和字节证据 | 每个入口8/8符合预标可接受集合、方法装配与调用合同；分别裁决，不能只重放缓存代替另一入口执行 |

S组失败／超时／不确定仍留在20题分母；正例遗漏计FN、无依据选择计FP，执行失败即使恰好空集也不算集合正确。预期辅助调用却跳过时计失败，不把该题降为D组。多个可接受集合须预先登记，并用冻结规则计算。题材命中但漏掉明确机制、禁用／越权／机械任务误触发、清单外装载为关键错误，要求0。

总体40题成绩仅作摘要；D组高分不能补S组低分，S组通过也不能代替E-B／E-N。阈值只衡量路由，不证明文学质量。原生与按钮共享确定性输入／冻结语义结果时须完全一致；真实语义调用按预标可接受集合判定，不要求随机解释措辞逐字一致。测试第三模块只存在于受信fixture，不进入正式包。

### 10.2 预算与失败处理

首轮总预算仍为**最多40次辅助路由＋8次短生成**：S组20次＋E-B 8次＋E-N 8次＋公开隔离／取消探针最多4次；D组、其余并发／故障注入用fake。执行前冻结样本和预算台账，技术探针先行、通过后才跑语义集；各分支未获准或未过技术门禁时不消耗其额度。40是项目辅助调用上限，实际模型轮次、transport尝试和不可见项另报，不称为40次Provider计费保证。

8次短生成按按钮／原生各4次分配，各含2次确定性与2次语义场景；后者接续E组已冻结路由、不再额外分类。其他E组场景验证到真实方法装配及派发边界，以测试适配器拦住正文调用，不伪称已完成真实正文生成。真实接续至少覆盖本次仅通用与混合方法，验证普通工具／选区提案非回归另以fake及既有合同测试完成。

两入口的E组单列分母，不能挪用未运行分支额度“刷过”另一分支。失败先修原因；修订改变路由逻辑、提示、模型或方法后，受影响的旧结果不得混算为同版本通过，新一轮所需预算明确另列。没有足够同版本结果时报告未通过／样本不足。本轮修订未授权真实调用，进入该阶段前按计划批准预算。

真实模型验收只用当前有效模型和获批的自写／授权测试材料，按上表提供应用侧证据和有限输出观察，遵循ADR-0009；普通请求辅助调用0，语义必要请求≤1，同动作重传不递增。公开取消无法确认远端结束时如实记unknown，不把停止正文派发称为已取消计费；该故障探针不混入S组质量题。本地路由暖启动p95目标≤100ms（不含DB／模型），未测不得写达标。

UI覆盖1920×1080、2560×1440及390×844窄屏：状态不挤正文、详情可滚动、键盘焦点、取消、错误恢复、多窗口结果不串。无权限时不显示内容性选择依据。

# 向量模型早期本地与云端方案（已被替代）

状态：**历史方案，已于 2026-08-26 被替代；不得作为当前施工依据。**

本文件原先规划同时支持 Ollama、本地 Qwen3 Embedding、OpenAI 兼容云服务、多供应商和任意维度。用户现已确认项目固定使用阿里云百炼，通过 DashScope Native HTTP API 接入 `qwen3.7-text-embedding`，首个生产 profile 使用 1024 维 Dense 向量；模型未来升级仍走同一供应商的候选配置、重建和原子切换流程。

当前唯一权威方案和施工门禁见：

- [小说语义检索与阿里云向量模型专项开发计划](./24-小说语义检索与向量模型专项施工计划.md)

替代范围包括：

- 删除 Ollama、TEI、本地模型基准和额外模型容器路线；
- 删除 `OpenAICompatibleEmbeddingAdapter` 和多供应商产品配置；
- 固定项目自有 `DashScopeEmbeddingAdapter`，不复用 QwenPaw ReMeLight 私有配置；
- 固定首期 `qwen3.7-text-embedding + 1024 + dense + cosine`；
- Base URL、API Key、候选模型和维度由小说 PawApp 的“向量检索与索引”页面管理；
- 区分索引 fingerprint 与查询策略：查询侧 instruct、Top-K 或融合权重变化不要求重建正文向量；
- 保留 pgvector、不可变 revision、可恢复派生任务、候选 generation、失败回退和禁止混用向量等仍然有效的工程原则。

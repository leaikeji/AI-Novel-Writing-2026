# 原生助手智能 Skill 路由与升级兼容优化计划

状态：**`PROPOSED` / V0.1。** 方案已制定，尚未批准施工／发布；当前授权仅覆盖核查升级影响和制定计划。

日期：2026-09-13（Asia/Shanghai）。范围：桌面 Web、现有 PawApp 内的原生助手写作入口。实施前按本文门禁推进，不能把章节按钮的通过结论视为原生助手通过。

## 1. 目标与升级承诺

作者在现有小说工作台中向原生助手提出正文写作要求，系统自动结合当前任务、分类和允许读取的故事资料，选择并实际装载适用 Skill。组合题材复用“通用任务＋题材／机制模块”，不要求作者记模块名字或逐章手选。

本功能必须保持 QwenPaw 可正常升级：所有改动留在 PawApp 和公开适配层；宿主基础镜像可独立替换；禁用／完整卸载插件后恢复原生行为；用户模型、Skill 选择、workspace、小说数据与核心数据卷保留。未来公开契约变化可能需要本项目适配，不能承诺未知版本永久零适配。若所需能力只能修改宿主核心才能实现，该增强不发布，保留可用的原生聊天和已验收章节按钮。

本轮不升级 QwenPaw。后续真正升级须另按项目偏好记录旧／新版本与 digest、公开契约差异、备份、可执行回退、正式切换和原生非回归；本计划的验收材料可作为输入，不能代替升级验证。

## 3. 最小交付范围与作者体验

第一批正式放行：工作台内、已绑定小说与章节、当前明确提出“写正文／续写正文”的原生请求。必须覆盖正常口语，如“帮我生成本章正文”，不可要求作者背固定前缀。单纯讨论“金手指是什么意思”、否定写作、引用中的命令不触发写作路由。

章纲、人物、选区、开书草稿等现有能力保持非回归，但本批不新增其语义放行。成功后才能准确表述为“原生助手正文写作支持智能 Skill”；不得表述为所有助手操作全部通过。计划58的完整原生门禁保留，不能由此局部关闭 `G-FULL`。

操作顺序保持：打开章节 → 原生助手输入要求 → 发送 → 阅读候选 → 使用原有确认／保存路径采用。继续使用原生输入框、停止、流式消息、模型与 Agent 控件。

唯一拟调整的 UI 位置：小说工作台原生助手区域已有的“本次写作方法”提示。复用 `frontend/src/writing-skills/native.ts` 及现有 notice 组件，显示本次已装载方法或准确失败原因；详情按需展开。无新增页面、强制弹窗、分类问卷或逐次开关。作者主动停用的 Skill 必须持续保持停用；升级不能重新全开。

## 4. 接入与失败行为

1. **公开契约先核实。** 列出 hook／前端扩展的公开来源、签名、2.2.1实测结果与撤销路径。常量 true 不作为通过依据；使用已有能力描述记录经验证能力，缺失时只关闭对应增强，避免全局拦截。
2. **每次发送绑定一次动作。** 复用服务端 `writingActionId` 与 `context_ref` 准备链；前者关联动作，后者标识页面范围，两者不混用。新发送产生新动作，同次传输重试识别旧动作；刷新、连发、双标签页、切书／章后不得借用旧方法回执。同步 payload 转换器不承担异步模型调用。
3. **意图与故事内容分开。** 当前作者操作决定是否写正文；正式分类、当前章纲／设定及本次要求决定方法。路由资料必须是当前写作请求同样允许使用的有界资料；页面正文是数据，不能变成路由指令。已有 projection 缺资料时补同一范围投影，不旁读全书或历史会话猜分类。
4. **复用共同选择与语义链。** 使用现有 catalog、resolver、composer、semantic runtime、dispatch；如需将 `complete_button_route` 泛化为中性命名，在原模块内完成并迁移调用者，避免复制一套原生实现。明确分类先确定性选择，有可判断的未决机制才最多一次辅助调用；悬疑与金手指分别判断，组合去重和预算沿用共同契约。缺少证据、未发布模块、用户排除／停用时不硬选，不为每个题材组合新建 Skill。
5. **辅助判断与正常助手分开计数。** 辅助请求严格一次、零工具、不可递归；跟随本次冻结的 `ai-novel-writer` 有效模型。正常写作允许既有范围内的读资料及受控提案链，沿用宿主工具审批与迭代边界，不把辅助请求的“一次／零工具”限制套到整个助手。每个正常模型轮次重新验证当前作用域并装载同一冻结方法，辅助判断不重跑。私有库维护、普通聊天不被正文分支接管。
6. **方法仅在当前请求生效。** 页面数据与可信方法保持不同角色；方法只在公开的最终模型输入边界附加，不写 Agent 全局提示或长期记忆。公开历史可能保留作者资料／模型回复；隔离目标是禁止旧插件方法继续作为新轮有效指令，不删除或伪称清除历史。若发现方法进入历史／压缩且无法通过公开边界可靠隔离，关闭增强并恢复原生能力，不持续让普通聊天报错。
7. **错误状态明确。** 未识别为正文请求／缺有效页面上下文：原生发送照常，提示本轮未启用智能方法；已认领请求的取消、范围变化、模型变化、未知传输结果：记录原动作，停止插件后续执行，不自动重放。辅助调用失败沿用共享失败语义，本轮明确失败，不偷偷改为通用生成或切模型；未来作者主动新发送才产生新动作。分清“未匹配专属模块，通用方法正常”与“智能判断失败”。
8. **证据与正文分开。** 回执记录 action、范围、Skill版本／hash、选择依据、组装／派发状态、辅助次数、正常模型轮次及 requested/actual 模型证据；公开链未暴露 actual 或最终输入时写 `not_exposed`。界面只把确认装载的模块说成“已使用”，模型自述不作证据。路由成功、生成质量与作者采用分别记录。

服务端原生语义发布控制独立于章节按钮，默认关闭，正式门禁通过后持久开启；实现时优先复用既有配置方式。后端对未知／不支持能力给出可观测状态。作者正常使用不需要每次恢复开关。

## 6. 验收与质量标准

### 代码校验

使用项目根目录与 `.venv/bin/python`。后端至少执行：

```bash
.venv/bin/python -m pytest tests/writing_skills tests/test_skill_contract.py tests/test_qwenpaw_integration_contract.py tests/test_assistant_install_contract.py
.venv/bin/python -m pytest
pnpm test -- frontend/src/writing-skills/native.test.ts frontend/src/assistant-context-ref.test.ts frontend/src/assistant-request-payload.test.ts frontend/src/assistant-route-wrap.test.ts
pnpm typecheck
pnpm test
pnpm build
.venv/bin/python scripts/package_plugin.py
git diff --check
```

数据库代码验证只用工作区临时库；skip不算通过。若改动Compose，增加 `docker compose config --quiet`。同候选无新增疑点时不重复跑相同全量检查。

### 正式环境必需证据

- 直接使用 `127.0.0.1:18088`，所有小说内容通过正常UI操作；每个操作步骤截图并评价，记录模型与方法实际证据、延迟、产出、恢复和作者可见结果。已有《危楼余火》等作品先检查当前稿与并发状态，选可继续创作的章节；所有新标题／内容像真实作品并保留。
- 首批8个原生真实写作动作预先冻结输入与可接受方法集合：明确悬疑、隐含金手指、悬疑＋金手指、无专属方法、作者明确排除、已停用模块、切书后新题材、同一章节连续两次不同写作要求。辅助次数必须0或1，选择／排除／方法字节与回执全部符合冻结判定。模拟未来模块只在代码层做，正式环境不安装未批准Skill。
- 同时覆盖普通聊天、其他Agent、快速连续发送、同次重试、刷新、双标签页、切章、用户停止、传输未知、历史压缩及恢复。不为凑截图空点击；失败／中断选真实写作任务执行，保留可继续创作价值。公开压缩无法观测时门禁保持未通过，不以短会话替代。
- 正常助手至少完成一次“查当前正式资料→写候选”；选区提案与私有库明确维护指令继续按现有权限运行。正文按钮保留同哈希已有证据；若共享代码变化影响它，补真实正文生成回归。
- 至少一章目标2500字且不少于2000字，评查人物行动、资源／能力限制、因果、情节推进、前文一致性和协议文字污染。路由正确但正文不可用也必须记录问题；无对照证据不宣称Skill带来确定增益。本计划不接管TTS优化，既有采用及朗读入口保持非回归。
- 8个动作与长章尽量重叠；调用前在台账记录本计划专属预算、已用与剩余，既往39次／40次预算不可当作未消耗额度。实施阶段承接当前有效模型授权；本轮文档工作不发模型请求。需要额外重跑先记录原因与增量，禁止循环试到通过后隐去失败。
- 本轮涉及公开中间件与释放逻辑，必须在正式环境完成安装／原位更新、重复更新保态、禁用恢复原生、完整卸载零残留、重装恢复作者选择与候选回退。集中一次生命周期窗口执行，既有同候选同范围可复核证据可引用，不能用旧隔离结果替代。原生聊天／Agent／Provider／模型／Skills／MCP／工具／设置是共同非回归基线。

## 7. 发布、升级兼容与恢复

发布前取得唯一正式环境锁，确认无活动写作／朗读任务，记录当前QwenPaw版本、镜像digest、PawApp包hash和实际Agent／模型／Skill／工具选择。对项目数据库、宿主配置／workspace及必要媒体建立可复核备份，保存当前可安装包和本次候选，记录精确公开安装／回退命令。不能只写“有问题再恢复”。

优先公开热更新PawApp；不改已安装副本、不修改上游核心、不无故重启Docker。工作区有计划74／79等并行改动，发布源必须明确：仅包含本计划候选和已在正式部署且可证明来源的基线；禁止直接打包整个脏工作区夹带其他未验收修改。

中止条件：公开模型／压缩hook缺失、普通聊天／工具失效、Skill选择漂移、跨书装载、动作重复执行、正文被静默覆盖、卸载残留或候选来源不明。先关闭本计划原生增强，再按固定包通过公开更新路径回退；若配置漂移，按备份清单恢复精确配置。保留期间产生的作品与revision，不整体回滚业务数据库抹除新增创作，不删除卷。

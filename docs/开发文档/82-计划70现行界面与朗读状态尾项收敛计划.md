# 开发计划 82：计划 70 现行界面与朗读状态尾项收敛

状态：**`PROPOSED` / V0.1。** 已完成当前源码复核与实施规划，等待作者批准施工；尚未修改产品代码、正式环境或用户数据。

日期：2026-09-14（Asia/Shanghai）

## 1. 目标与结论

本计划接管计划 70 在 2026-09-14 当前源码中仍可确认的界面、恢复和朗读状态尾项。它不是重启计划 70 的 Skill 文学评测、九章写作或原生助手范围，也不接管计划 76／80。

冻结为两个产品结果：

1. 创作中心、建书、章节向导和章节保存只显示可证明的状态，不把加载失败说成无作品，不把手工操作说成 AI 生成，不默认允许 AI 改变角色，也不在正文生成完成后抢占式引导下一次模型调用。
2. 朗读更新、失败恢复和版本切换使用同一权威 Edition／Manifest 状态；作者明确更新并选定新版本后，刷新不回旧版，暂停／停止／切版有可理解且安全的路径。

详细逐项证据见[计划 81 残留复核](../../audit/plan81/residual-audit.md)。

## 2. 范围与非目标

### 2.1 必修范围

- 创作中心加载失败／空列表分离，建书草稿恢复提示，手写／AI／文字封面来源文案。
- 作品卡章节数量使用中性准确语义；模板字段显示中文名。
- 正文生成完成后不自动弹“同步进展”；大纲和正文长任务显示真实阶段与已用时间，不显示固定 42% 或虚假预计秒数。
- AI 新增／退场角色默认关闭；“跳过”明确只跳过本次追加资料。
- 已归卷章节直接保存，移动分卷和“保存并新建下一章”分离；返回列表保持当前章节所在分卷。
- 活动 Edition 的制作计数与最新 Manifest 一致；失败恢复文案服从最终 `retryable/retry_reason_code`。
- “更新朗读”在请求前明确告知会创建新版本，并在新 Edition 达到合法可播条件后由同一次作者意图确认设为 current；失败或取消不改 current pointer。
- 提供单章停止／退出播放动作，停止或安全切版后再允许选择 Edition。

### 2.2 复现后才修改

- 章节目录字数即时同步 `F70-UI-17`；现有源码已有同步调用，先补精确回归和桌面复现。
- 章纲固定高度、禁用态、方法提示首屏位置、助手展开横滚，只在目标桌面尺寸仍复现且修改不扩大布局范围时一起收口。
- 长模板字段与空章节文案属于同文件低风险优化，不作为独立发布阻断。

### 2.3 非目标

- 不继续计划 70 的文学增益 A/B、真实 8 格、九章逐字听感或新 Skill 分类研究。
- 不施工计划 80 的原生助手逐发送路由，不改变 QwenPaw 核心、原生模型设置页或上游重启反馈。
- 不扩建模板分类系统，不新增数据库表、迁移、队列、第二套播放器、第二套模型选择器或移动端布局。
- 不自动调用正文／大纲／TTS 模型，不创建、改写或删除正式作品作为代码施工前置。
- 不放宽音频质量阈值，不静默切换声音或 Provider，不删除历史 Edition／Manifest／媒体。

## 3. 冻结交互与安全合同

### 3.1 建书与章节

- 加载状态互斥：`loading`、`loaded-empty`、`loaded-with-items`、`error`。只有成功返回空数组才显示“创建第一部小说”；`error` 保留“现有作品状态未知”和显式重试。
- 恢复建书草稿时显示作品草稿的可证明摘要、最后步骤和“继续／重新开始”选择；重新开始只新建／重置当前建书草稿，不影响已创建作品。
- 模板、名称、封面显示来源枚举，不通过“字段非空”猜测 AI 是否调用。若后端缺少必要来源，只新增最窄兼容字段或从已有 generation job 回执派生；不得凭 UI 本地状态伪造。
- AI 新增／退场角色默认 `false`；改变选择必须出现在最终确认摘要。除非另行批准持久化，不跨作品或跨浏览器静默记忆。
- 正文生成完成先把正文、目录和恢复状态稳定同步；“同步进展”保留为作者主动按钮，不自动弹出。取消同步不影响刚完成的正文。
- 已有合法 `volume_id` 的章节点击“保存”只保存当前工作稿／检查点；“移动分卷”和“保存并新建下一章”分别提供独立动作，并继续执行 CAS、有效分卷校验和失败恢复。

### 3.2 朗读版本

- `current Edition` 是刷新后的默认朗读版本；`active Edition` 只表示当前会话正在查看／播放的不可变版本。两者不相等时必须明确显示且不能宣告更新完成。
- 点击“更新朗读”即是明确的生成意图，但不是对未知结果的盲目切版授权。开始前说明“成功后将请你确认使用新版本”；新 Edition 首个合法 ready range 出现后，在自动播放前提供“设为当前并播放／仅试听／保留旧版”三种明确结果。
- 只有“设为当前并播放”调用已有 confirmed CAS switch。CAS 冲突时重新读取 context，让作者基于最新 pointer 再决定；不能覆盖并发选择。
- “仅试听”可以载入新 Edition，但页面始终标为预览；刷新仍回 current，不显示“更新已完成”。
- 暂停只冻结当前位置；“停止本章朗读”清理当前播放意图、保存派生进度并回到可切版状态。若选择器直接支持暂停时切版，切版必须先原子停止旧会话并通过 session generation fence。
- Manifest 原地刷新继续保留计划 73 的 player lease；活动 Edition 的进度标签从最新 Manifest 派生，不因刷新 history 投影而拆掉播放器。
- 失败恢复完成后先读取最新失败投影。若目标已不可重试，提示必须来自 `retry_reason_code`，不再保留“稍后重试”；已恢复或缺失则给出成功状态。

## 6. 验收门禁

### 6.1 自动化

至少覆盖：

1. 创作中心请求失败只显示“状态未知＋重试”，成功空列表才显示首本小说空态。
2. 恢复草稿与新建草稿分支不会覆盖已完成作品；手写／AI／文字封面文案由真实来源驱动。
3. 空章节不称“已完成”；内部模板 key 不直接展示。
4. AI 新增／退场默认关闭；最终确认与请求快照一致。
5. 大纲和正文长任务使用单调已用时间，卸载后清理 timer；不出现固定百分比和虚假预计秒数。
6. 正文完成不自动打开同步进展确认；作者点击后仍执行原有模型确认与候选流程。
7. 已归卷章节直接保存，移动分卷／保存并新建下一章独立；CAS 冲突和无效分卷失败关闭。
8. 返回章节列表保持当前分卷；无卷、删除、倒序、刷新和分卷失效有确定降级。
9. Manifest 多次推进时活动播放器实例和 lease 不变，版本标签计数随最新 Manifest 更新。
10. 失败恢复由最终投影决定文案；不可重试不再建议稍后重试。
11. 更新朗读的三种作者选择与 pointer 结果一致；CAS 冲突、取消、失败、仅试听和刷新均不误切 current。
12. 暂停、停止、切版、切章和 dispose 不留旧播放意图、请求、timer 或 object URL。


纯前端候选不因为打包成功就自动构成正式产品验收。

### 6.2 正式桌面

- 1920×1080 与 2560×1440；补一个助手展开、宿主侧栏挤压但仍是桌面窗口的场景。
- 断网／服务失败通过安全可逆方式验证错误态，不能停止正式数据库来制造列表失败。
- Edition 复核优先使用已有 current／historical 版本；若没有合法新版本可验证更新确认链，必须先向作者说明将产生的本地 TTS 调用和目标章节，再按正常 UI 执行一次，不循环生成。
- 全程记录正文、current pointer、历史 Edition、媒体和 Skill 状态的前后不变量；不做 SQL 直写。

## 7. 发布、恢复与退出

发布前保存当前 PawApp 安装树、数据库备份、12 项小说 Skill／工具状态及当前版本指针摘要；记录候选 hash、正式基础镜像和中止条件。通过公开原位更新，不覆盖 QwenPaw 核心，不删除数据卷或媒体。失败时恢复上一安装树；本计划默认无迁移，因此不倒库。若最终确需 schema 变化，必须新增 Alembic revision、补升级／回退计划并重新获得范围裁决。

退出条件：第 2.1 节全部通过相称自动化和正式桌面验证；第 2.2 节每项都有“已复现并修复／当前未复现并关闭”的结果；计划 70 顶部已指向本计划且标记 `CLOSED_WITH_LIMITS`；计划 82 再标记 `CLOSED_PASS`。HOLD 的文学增益、外部模型质量和上游页面问题不转化为本计划失败。

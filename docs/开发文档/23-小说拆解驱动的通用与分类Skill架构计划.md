## 0. 结论

1. 不新增一个包办全部工作的“大通用 Skill”。现有九个 Skill 已按创作任务分工，它们共同组成通用写作能力层。
2. 分类能力不复制成“七种题材 × 九种能力”的大量 Skill。候选方案只新增一个 `genre-guidance` 分类路由 Skill，不直接产出正文；每个分类放在它自己的按需参考文件中。因此候选写作 Skill 总数最多从九个增加到十个，而不是随分类数量无限增长。
3. `genre-guidance` 只在分类确实会改变创作决策时调用，最多加载一个主分类和一个次分类；纯事实检查、普通校对、字段整理等任务不机械调用。
4. 最终结果仍由任务 Skill 负责：正文最后由 `prose-writing` 输出，章纲由 `chapter-outline` 输出，人物设计由 `character-craft` 输出，审稿由 `style-review` 输出。
5. 小说拆解是研究输入，不是自动训练或自动改 Skill。拆解结果必须经过“来源证据 → 跨作品复现 → 候选规律 → 反例检查 → 同模型 A/B → 作者批准”，才可进入正式 Skill。
6. 只在分类层无法表达一种稳定且独有的完整工作流，并有重复失败证据时，才考虑把某一分类升级为独立顶层 Skill；首版禁止这样做。

## 1. 当前实现事实与问题

### 1.1 当前事实

- 项目当前有九个 `0.4.0` 源码候选 Skill：`novel-direction`、`story-foundation`、`character-craft`、`chapter-outline`、`scene-craft`、`dialogue-craft`、`prose-writing`、`continuity-check`、`style-review`。
- 九个 Skill 只在 `ai-novel-writer` Agent 中启用，正文写作必须经过 `prose-writing`；QwenPaw 的模型选择仍以该 Agent 的有效模型为唯一权威来源。
- 作品已经保存 `genre` 与 `subgenre`，工作台页面上下文也包含 `settings.genre` 和 `settings.subgenre`；不需要再增加第二套分类选择器。
- 当前只有 `prose-writing/references/genre-promises.md` 集中描述年代/重生情感、东方玄幻成长、悬疑/近未来推理与长篇连载。方向、人物、章纲、场景、对白和发展性审稿没有统一的分类资料入口。
- 既有计划已经记录 Skill 选择存在随机波动。增加大量相似顶层 Skill 会扩大误路由和提示重复风险。
- `0.4.0` 自动化、打包和安装契约完成不等于写作质量通过；既有 S4 真实模型盲评仍待执行。

### 1.2 要解决的问题

- 通用能力与分类惯例混在同一正文参考文件中，无法让章纲、场景、对白和审稿复用同一分类结论。
- “玄幻”“言情”等宽标签不足以决定具体写法；东方成长、宫廷权谋、都市异能等需要不同的读者承诺和推进机制。
- 一本作品可能是混合分类，不能由多个互相覆盖的专用 Skill 抢夺最终输出。
- 从一部热门作品观察到的个人写法，容易被误写成全分类规则或所谓市场规律。
- 如果拆解页面直接把报告写入 Skill，会污染所有作品并绕过作者确认和质量评测。

## 2. 目标架构

```text
作者请求 + 当前作品正式资料
              |
              v
      AI小说作家 Agent 路由
              |
              +--> 选择一个主要任务 Skill
              |
              +--> 分类影响结果时调用 genre-guidance
              |       `-- 读取 1 个主分类 + 最多 1 个次分类
              |
              +--> 按需调用 0–2 个辅助任务 Skill
              |
              `--> 主要任务 Skill 形成最终候选
                       `-- 正文任务始终以 prose-writing 收口

拆解研究证据 --> 候选规律 --> 反例/盲测 --> 作者批准 --> 通用规则或分类资料新版本
```

架构中只有 `ai-novel-writer` 负责组合 Skill；不新增第二个写作 Agent、模型选择器、Provider 分支或自动回退模型。

## 3. 通用写作能力层是什么、怎么用

### 3.1 九个通用任务 Skill

| 任务 Skill | 通用职责 | 典型触发 | 是否形成最终结果 |
| --- | --- | --- | --- |
| `novel-direction` | 前提、读者承诺、核心冲突、故事发动机与方向取舍 | 定题材、选方向、比较创意 | 方向任务是 |
| `story-foundation` | 故事设定总表、总体大纲、世界规则、主线和承诺回收 | 建立或校准全书基线 | 全书资料任务是 |
| `character-craft` | 欲望、误判、能动性、关系压力、人物弧线与声音 | 人物卡、人物关系、人物驱动情节 | 人物任务是 |
| `chapter-outline` | 章节入口/出口、场景链、升级、揭示和章末推动力 | 章纲、分场、章节重构 | 章纲任务是 |
| `scene-craft` | 单场目标、阻力、策略变化、空间、转折和余波 | 场景卡、场景重构 | 场景设计任务是 |
| `dialogue-craft` | 对白目的、人物声音、潜台词、权力变化和动作节拍 | 对话设计、对白修订 | 对白任务可作为最终结果 |
| `prose-writing` | 根据正式事实、作者要求和近场声音输出连续正文 | 续写、重写、扩写、润色正文 | 所有正文任务必须是 |
| `continuity-check` | 人物知识、状态、时间、物件、因果、规则和伏笔 | 跨章检查、事实审计 | 检查任务是 |
| `style-review` | 发展性、场景、行文和校对分层审查 | 审稿、文风诊断、保声修订 | 审稿任务是 |

“通用”表示这些能力适用于所有分类，不表示每个请求都调用九个 Skill。一次请求默认只有一个主要任务 Skill；辅助 Skill 只解决明确的前置难点。

### 3.2 通用层调用规则

1. Agent 先根据作者要交付的结果选择一个主要任务 Skill，而不是根据文本中出现的术语堆叠 Skill。
2. 只有当前结果依赖另一种能力时才增加辅助 Skill，通常不超过两个。
3. 需要正文时，人物/场景/对白 Skill 只做前置设计，`prose-writing` 最后输出连续正文。
4. 作者只要求方向、人物、章纲或诊断时，不擅自进入正文。
5. `continuity-check` 负责事实与状态；`style-review` 负责修订层级与读者体验，两者不能互相冒充。
6. 正式资料与已采用正文冲突时，以权威 revision 和作者当前明确决定为准，并报告过期资料；Skill 不能用分类惯例覆盖事实。

### 3.3 常见任务组合

| 作者请求 | 主要 Skill | 可选辅助 | 最终输出 |
| --- | --- | --- | --- |
| “帮我确定这本书的方向” | `novel-direction` | 分类明确时 `genre-guidance` | 方向方案 |
| “设计这个人物为什么不肯离开” | `character-craft` | 分类显著影响关系结构时 `genre-guidance` | 人物动力方案 |
| “做第五章章纲” | `chapter-outline` | `genre-guidance`；必要时 `character-craft` | 章纲 |
| “把审讯场景写成正文” | `prose-writing` | `genre-guidance`、`scene-craft` 或 `dialogue-craft` | 一次正文 |
| “检查前后两章时间和物件” | `continuity-check` | 无 | 证据化检查报告 |
| “只校对错字和病句” | `style-review` | 无 | 校对建议或候选 |
| “审查悬疑线索是否公平” | `style-review` | `genre-guidance`、必要时 `continuity-check` | 带证据的发展性审稿 |

## 4. 分类能力层是什么、如何调用

### 4.1 候选文件结构

```text
skills/genre-guidance/
|-- SKILL.md
`-- references/
    |-- profile-contract.md
    |-- suspense-mystery.md
    |-- eastern-fantasy-progression.md
    `-- period-emotional.md
```

首个候选版本只新增用户批准的第一个分类资料，不为空建齐七个目录。后续分类沿用同一入口和同一资料合同，因此不会为每个分类新增一个顶层 Skill。

现有 `prose-writing/references/genre-promises.md` 只在新路由通过测试后原子迁移；最终不得同时维护两份生效规则。迁移前保持 `0.4.0` 基线不变，迁移施工由唯一集成人处理。

### 4.2 `genre-guidance` 的唯一职责

`genre-guidance` 只把“分类标签”翻译为当前任务可执行的分类约束，不直接写整章、章纲、人物卡或审稿报告。它按需读取一个分类资料，并形成内部分类约束卡：

- `profile_id` 与版本；
- 核心读者承诺及本轮要推进的承诺；
- 常见场景发动机与升级维度；
- 回报、揭示或关系推进节奏；
- 人物知识、信息公平和代价边界；
- 对白、叙述距离与语言密度的适用倾向；
- 常见失效模式；
- 本书已明确的反类型选择和作者例外；
- 支撑规则的评测编号与研究证据编号。

分类资料不能包含外部小说长段原文、仿写某位作者的指令、固定剧情模板、项目数据写权限或模型配置。

### 4.3 资料选择来源

按以下顺序确定分类，不使用书名联想：

1. 作者本轮明确指定的主分类、次分类或反类型要求；
2. 当前作品已保存的 `genre`、`subgenre` 与作者已确认的读者承诺；
3. 页面中尚未保存的 `dirty` 分类字段只能作为当前候选，并明确其未保存状态；
4. 若仍无法确定，继续使用通用任务 Skill；只有方向决策确实依赖分类时才请求作者选择。

宽分类只负责初步路由，细分类资料必须按读者承诺选择。例如“玄幻”本身不能自动等于“东方成长”；无法匹配已验证资料时不猜测，也不把最相近资料强行套用。

### 4.4 何时调用

以下任务通常调用：

- 方向、总体架构、章纲和场景的读者承诺设计；
- 分类明显影响人物关系、对白策略或信息分配；
- 正文生成、较大范围重写或发展性审稿；
- 作者明确要求检查某一分类的满足度。

以下任务默认不调用：

- 单纯错字、标点、格式或病句校对；
- 只核对时间、位置、伤势、数量、物件或人物知识；
- 标题、字段或选区的窄机械操作，且不改变读者承诺；
- 作者明确要求分类中性或故意偏离惯例。

### 4.5 混合分类

- 最多装载一个主分类和一个次分类；主分类决定主要重复体验，次分类只补充一组明确承诺。
- 两份资料冲突时，以作者为本书确认的分类约束卡为准，不由模型自行取平均。
- 三种以上标签不继续加载更多资料，应先由 `novel-direction` 把它们压缩成“主要体验、次要体验、仅作背景”三层。
- 作者可以明确拒绝某条分类惯例；该选择属于单书配置，不反向修改通用或分类 Skill。

### 4.6 冲突优先级

从高到低：

1. 系统安全、权威正文保护、作者授权和数据范围；
2. 作者本轮明确要求、禁止项及已经采用的正式事实；
3. 人物知识、因果、连续性和视角等通用硬边界；
4. 本书经作者确认的读者承诺与反类型选择；
5. 主分类资料；
6. 次分类资料；
7. 通用写法偏好和模型默认习惯。

分类规则是可检验的创作建议，不得推翻上层事实；作者可以有意识地偏离非安全规则。

## 5. 小说拆解如何进入 Skill

### 5.1 研究对象与权利边界

- 只处理作者自有、明确授权或公共领域的真实文本。
- 热榜、评分、星数和销量只能帮助选择研究样本，不能证明一条写作规则有效，也不授权获取全文。
- 不接受“书名 + 作者 + 平台”作为全书事实分析，不依赖模型记忆补全，不绕过登录、验证码、下载限制或反爬。
- 原始文本、来源哈希和证据位置留在研究证据区；打包 Skill 只保留抽象规则、适用边界和证据编号。

### 5.2 拆解维度

每部作品使用相同的核心维度，另加一个分类专项维度：

1. 开篇承诺与首次有效回报；
2. 主角目标、误判、策略变化和代价；
3. 章/场入口状态、出口状态与因果连接；
4. 信息揭示、人物知识和读者解释变化；
5. 关系位置、对白目的、潜台词与声音差异；
6. 叙事视角、句群节奏、具体性和说明密度；
7. 中长线承诺、回收、连载节奏与中段维持；
8. 当前分类特有的读者承诺及常见失效。

每条结论必须包含原文位置、观察、可能作用、反例或不确定项；只写“节奏很好”“很有代入感”不算有效拆解。

### 5.3 规律状态机

```text
单书观察
  -> 跨书候选
  -> 通用/分类/单书归类
  -> 反例检查
  -> 写作任务候选规则
  -> 同模型匿名 A/B
  -> 作者批准
  -> 正式规则新版本
  -> 继续监测退化或废弃
```

状态说明：

- **单书观察**：只说明这一段或这一本如何工作，不进入任何 Skill。
- **跨书候选**：多部作品出现相似作用，但仍只保存在研究报告。
- **分类候选**：只在一个分类中稳定有效，准备进入分类资料的候选区。
- **通用候选**：跨分类有效，准备进入现有九个任务 Skill 的候选区。
- **正式规则**：通过门禁并经作者批准后，才进入版本化 Skill。
- **废弃规则**：保留失败证据和版本记录，不从历史报告中静默删除。

### 5.4 首版晋级门槛建议

| 去向 | 最低研究证据 | 最低评测要求 |
| --- | --- | --- |
| 单书配置/私有资产 | 一部作品即可，但必须有来源与适用范围 | 不得影响其他作品 |
| 分类资料候选 | 同一细分类至少五部独立作品、至少三位作者，且包含一个反例或失败样本 | 分类专项 A/B 通过，通用维度无实质退化 |
| 通用 Skill 候选 | 至少三个不同分类、每类至少两部独立作品 | 跨分类同模型 A/B 通过，不能靠单一分类拉高总分 |

样本不足时宁可保持候选，不用“热门”标签替代证据。若合法文本数量无法达到门槛，可增加项目自写对照任务，但不能把合成样本冒充市场证据。

### 5.5 首本整本拆解执行合同

- 整本使用 `full-text`；`range-study` 只用于第 1—100 章或任意预先冻结的连续章节区间，不能冒充整本覆盖。
- 长篇默认 `adaptive`：所有章节都有可定位证据支持的基础卡；前 10 章、案件开启／反转／揭晓／结案、关键线索重解释、嫌疑人实质增减、高潮和公平性风险章节做深拆。
- 轻量章节也必须检查状态变化、信息变化、回报／代价和章末推动力；不能只凭“看起来不重要”跳过，以免漏掉隐藏线索。
- 前 10 章校准单独创建 `opening` 运行，检查文本完整、章节边界、证据定位、案件／线索／嫌疑人／知识差字段，以及结果能否转成可测试写作约束。通过后创建新的整本运行，不修改校准任务。
- 成本证据记录输入字符数、分块数、成功／失败尝试、深拆章节数和模型调用；前 10 章后重估整本工作量，不冻结未经实测的小时数。
- 首本只形成单书观察。正式写作 Skill、分类资料或页面仍需后续跨书、反例和同模型评测门禁。

## 6. 评测合同

### 6.1 前置基线

先完成 `0.4.0` 既有 S4：十二个冻结任务、同一真实模型与参数、旧/新版本各两次独立生成、匿名顺序和全量失败样本保留。没有这个基线，无法判断分类层带来提升还是仅来自随机波动。

### 6.2 路由与加载门禁

- 每个测试请求只能确定一个主要任务 Skill；正文任务最终必须包含 `prose-writing`。
- 保存的已知分类能选择正确资料；未知分类不猜测、不加载相近资料。
- 混合分类最多加载一主一次，且顺序稳定。
- 纯连续性与普通校对请求不调用分类层。
- 分类资料失败或缺失时，安全降级到通用任务 Skill，不静默改模型。
- 分类资料不能改变正式事实、人物知识、写入权限或选区范围。

### 6.3 写作质量门禁

沿用 `0.4.0` 的确定性门槛和六项匿名评分，并为每个分类增加 2–4 个可观察维度。例如：

- 悬疑推理：线索公平性、解释竞争、调查行动的因果反应、揭示后的证据重排；
- 东方成长：能力边界、练习/判断的可复现性、回报与代价同步、对手适应；
- 年代情感：时代条件实际影响选择、关系通过行动推进、误会不空转、人物声音区分。

首版候选至少满足：

- 安全、事实和纯净输出通过率不低于通用基线；
- 分类专项匿名偏好胜率不低于 65%；
- 分类专项平均分相对通用基线提高至少 15%；
- 通用六维没有任何一项下降超过 0.25 分；
- 不出现来自研究文本的长段复现或作者声音冒充；
- 所有失败、平局和退化样本保留。

### 6.4 拆解本身的评测

拆解报告也需要验收，不能只评生成正文：

- 关键结论都能回到真实来源范围；
- 事实观察、技术推断、项目建议和不确定项分开；
- 同一文本重复运行时，核心证据和主要结论不能大范围漂移；
- 把原文隐藏后，评审能根据证据判断结论是否成立；
- 规则抽象不会保留可识别的长句、专名或独有剧情排列；
- 不把一个作者的习惯误写成分类必需规则。

## 7. 调用示例

### 7.1 东方成长正文

```text
请求：按本章章纲写一场东方成长题材的试炼正文
路由：genre-guidance（东方成长）
   -> scene-craft（试炼目标、规则、策略与代价）
   -> prose-writing（最终连续正文）
```

### 7.2 悬疑线索审稿

```text
请求：检查这一章的线索是否公平，先不要改正文
路由：genre-guidance（悬疑推理）
   -> continuity-check（人物知识与线索来源）
   -> style-review（形成带证据的发展性审稿）
```

### 7.3 普通校对

```text
请求：只改错字、标点和明显病句
路由：style-review
说明：不调用 genre-guidance，不借校对改写分类风格
```

### 7.4 混合分类

```text
作品：言情为主、悬疑为次
请求：设计关系推进同时暴露一条新线索的章纲
路由：genre-guidance（主：关系情感；次：悬疑推理）
   -> chapter-outline（最终章纲）
约束：关系状态变化是主回报，线索推进是次回报；不得加载第三份分类资料
```

## 10. 非目标、失败回退与待用户裁决

### 10.1 非目标

- 不为每个模型、Provider、分类或单本小说建立一套复制 Skill。
- 不从热门小说抓取全文，不把排名或高分等同于技法有效。
- 不模仿在世作者的可识别声音，不把原句、专名或独有剧情排列写入 Skill。
- 不自动修改权威正文、故事设定总表、正式大纲、私有资产或 Skill。
- 不在本文内开发文本拆解页面、数据库 schema、向量检索、TTS 或第二套 Agent Runtime。
- 不因分类资料缺失而切换模型、伪造资料或阻塞普通通用写作。

### 10.2 回退

分类候选失败时保留研究与失败报告，恢复最后一个通过门禁的九 Skill 包和原 Agent 路由；不删除 QwenPaw 或 PostgreSQL 数据卷，不改写迁移历史。分类资料只属于可重建的 Skill 源，不应成为用户正文或正式故事事实的唯一存储。

### 10.3 后续仍需用户裁决

1. 是否批准“九个通用任务 Skill + 一个 `genre-guidance` 分类路由 Skill”的正式目标结构；
2. 首本完成后是否批准第二、第三本跨书验证；
3. 是否接受本文的分类／通用规则晋级门槛；
4. 何时完成 `0.4.0` S4 基线并允许正式写作 Skill 候选改动；
5. 是否在至少两轮人工拆解闭环后另立页面施工计划。

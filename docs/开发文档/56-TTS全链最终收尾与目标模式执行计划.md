## 1. 目标模式与完成边界

本计划不再只交付一项新增功能，而是核销当前已承诺 TTS 写作工具链的全部已知欠账。通过的既有实现保留，发现真实缺陷就修复、复测；不重写已通过的模块，不把安装成功、健康检查成功或隔离样例成功单独当作全部完成。

### 1.1 一个施工目标，四步连续完成

- 原规划目标已完成；本轮启动下述施工目标，不再把计划定稿作为任务完成。
- 四步为“核实与保全 → 修复与补验 → 正式启用 → 集中验收交付”。阶段完成不结束总目标；不设置未经用户要求的token预算。

> 在当前 main 的正式代码与固定本机双模型拓扑上，完成本文 TTS56-01 至 TTS56-12 的必要验收、正式 24/24 中文通用音色包初始化、当前候选发布或同包核验、作者听检与恢复证据保全。消除范围内全部已知 P0/P1 和影响正常操作的功能缺陷；其余发现逐项修复或交由作者明确裁决，不静默延期。默认旁白、18 官方音色、官方匹配、人物专属生成、通用选角、整书与章节朗读、高级调音、私人音色生命周期、桌面 UI、播放与模型空闲释放均有可追溯证据；正式部署状态与隔离验收状态分别记录。只有满足第 11 节才完成执行目标。不得修改 QwenPaw 上游、权威小说正文或未授权真实绑定；不得删除正式数据／媒体／恢复材料；不得自行提交或推送。模型／网络失败可恢复后继续，缺少作者听检、生产授权或外部 Provider 条件时保存检查点并报告具体缺口，不伪造 PASS。

目标模式用于保存结果导向的终点与持续推进约束，不会扩大授权，也不能代替真人听检。执行前冻结允许修改与允许生产写入的范围；完成与阻塞必须有证据。[OpenAI 官方 Goals 说明](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)

### 1.2 本轮“全部”的含义

指第 3 节已承诺的本机写作朗读能力，不承诺未来永无缺陷。以下不是偷偷延期的必交付功能：多人同时合声、章节情绪表演引擎、英文／日文通用生成包、导出／下载、云端服务、新模型、新硬件、QwenPaw 升级、API／worker 数据库运行角色切换。

第三方参考录音上传克隆当前仍有独立发布门禁，不能因为内部 VoiceGenerator → Nano 参考音频链可用就宣布上传克隆可用。本计划保护既有上传音色与相关范围校验，不自动启用这项独立能力。最终报告必须明确这些边界，不使用不带范围的“任何 TTS 功能都能用”。

计划47场景表达实验保留原`NOT_RUN`记录，**移出本轮执行范围和完成门槛**。不新建实验脚本、不额外生成24条风格音频，也不宣称实验已完成或证明模型不支持；正常写作朗读完成不再被探索性研究阻塞。

## 4. 授权、运行环境与数据边界

### 4.1 批准施工后可连续执行的范围

本轮已批准main上范围内源码修复、文档、单元／集成测试、隔离QwenPaw／PostgreSQL、已安装模型的有界真实推理，以及精确本轮证据保全。只调用当前AI小说作家Agent的有效模型，不新增Provider／密钥或绕过权限。

正式写入另设一次明确授权包，不为每槽反复询问：

1. 备份后，使用公开 API 在正式 workspace 建立一份完整中文通用包，允许对失败／作者拒绝槽创建继任版本；不删除旧包。
2. 如代码有改动，安装同一验证候选并重启；无代码改动则不无故重装。
3. 如要补真实书写入，必须由作者确定 novel ID／document ID 白名单及是否允许成功后更新该书人物绑定、创建新 Edition。默认**不写真实书**；隔离功能全链＋正式服务／资产只读核验是基本发布口径。

Git 提交／push、真实音色或小说删除、其他项目 Docker 清理、模型下载、上游升级不在本计划文本的自动授权内。若需要，明确说明精确动作后取得单独授权。

### 4.2 隔离验收样本

- 使用一套独立Compose项目／数据库／媒体目录，优先复用已有受控悬疑样本及四章、六人物证据。必须新建时只补代表章节与所需人物；自然标题和正文，不写测试占位文本；环境／证据明确标为隔离。
- 优先从已授权、可恢复的受控样本复建，不在正式作品库反复新增“测试书”。官方选角、专属准备、删除分别保存干净基线／快照，避免前一用例留下的私人声音使后一用例全成 preserved 假通过。
- 中文六官方音色而旁白＋六人物共七目标：必须分别测“未耗尽子集不重复”和“七目标合理复用”，不能提出七个互不重复中文 preset 的不可能断言。
- 本轮删除、漂移、崩溃、unlink、停 worker、Provider 失败注入均限隔离环境。恢复演练使用正式备份的隔离副本，不覆盖正式库。
- 复用现有固定 Python／pnpm／浏览器，schema 测试库与 head 业务测试库分开；绝不对正式连接运行 pytest 或 disposable DB 脚本。

### 4.3 16 GiB 模型运行纪律

沿用用户已接受的 16 GiB 原生 VoiceGenerator 路径，不重设“必须剩余 4 GiB”门禁。保留互斥、watchdog、租约／fence、取消、进程回收；OOM、持续失去进展、磁盘写入失败仍需停止领取并恢复，而非无限重试拖垮电脑。

- 同一时刻一个 VG 或 Nano 重模型阶段；主代理持有全局锁，隔离与正式不同时推理。
- 每完成一个槽／人物，持久化结果并释放重模型；交互任务优先于后台补池。
- 技术性瞬态失败每目标最多自动重试 2 次，复用同一持久身份和服务重试语义；模型证据／scope／hash 安全失败不自动重试。
- 作者拒绝只重做该槽／人物，不能重建整包；每次反馈最多连续尝试两版，仍不满意先询问具体听感，不无界烧模型。
- 记录单项耗时、RSS／系统压力、进程重叠、磁盘及失败码，不承诺未实测的固定总工期。

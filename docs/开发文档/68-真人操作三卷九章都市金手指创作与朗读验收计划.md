## 3. 原创故事设计：继承危楼与末日地下避难所

### 3.1 书名、主角与开篇承诺

书名：《末日：我把危楼建成地下堡垒》。题材：现代都市起点、丧尸末日、基地建设、资源经营、建设型金手指。发生地为虚构临江市；叙述采用贴近主角的第三人称。

主角林照，男，26岁，做过物业设备巡检和零散维修，有基础动手经验，长期玩《缺氧》，习惯盯资源收支、预留管线路径和给关键设施做备用。他刚办完舅公遗留楼房的交接，原想靠收租摆脱漂泊，开门却发现整栋楼墙皮脱落、线路老化、地下室积水，剩下的几户住客也准备搬走。

开篇当天，异常天光掠过城市，街上与楼内相继有人异变为丧尸；林照同时觉醒与这栋楼绑定的“避难所建造视图”。继承危楼、金手指觉醒、丧尸爆发必须在第一章发生，不用数章铺垫或靠简介代替正文。

简介：林照继承了一栋楼。六层，漏雨，停电，地下室的水没过台阶，租客见到新房东的第一句话是退押金。他还没算清这笔烂账，街上的人先开始互相撕咬。与此同时，一张只有他看得见的楼体剖面在眼前亮起。别人抢车往城外逃，他看着遍地碎砖、楼里的水箱和封死的地下入口，想起自己在《缺氧》里一次次救活的基地。这一次没有暂停键，也没有读档。他要让这栋楼先撑过今夜，再让地底亮起不会轻易熄灭的灯。

核心阅读回报：危楼变牢固、暗房亮灯、水流恢复、住客睡上干燥床铺、地下多出可用房间。丧尸与资源压力推动建设，建设成果改变人的处境。主角有明确优势，能快于常人完成改造；不把所有建设都写成失败，也不将基地文写成连续外出杀怪。

时间尺度：第1–3章覆盖异变当天至第3天；第4–6章覆盖第4–10天；第7–9章覆盖第11–21天。九章完成“这栋危楼成为可持续运转的第一处避难所”的完整阶段，不声称三周解决全球丧尸危机或达到永久自给。

### 3.2 游戏经验、原创能力与现实劳动的关系

已核实事实：Klei 官方简介将《缺氧》描述为殖民地模拟游戏，并提及氧气、温度与食物等生存压力。来源：[Klei 官方游戏页](https://www.klei.com/games/oxygen-not-included)，核验日期2026-09-10。这里只引用概括性机制，不依赖当前版本的具体配方、数值或漏洞。

创作决定：主角迁移的是“先看收支、先保生命支持、分区、留余量、不要扩张过快”的游戏经验；游戏不是现实工程教材。未知环境要勘测，设备要测试，楼里有经验的人可以纠正他。所有超常施工效率归因于本书原创金手指，不能用一句“玩过游戏”解释普通人徒手挖地基、造完整工业设备或无成本产氧。

原创能力“避难所建造视图”：

- 绑定继承楼体及其正下方范围。只有主角看得见空间分区、已勘测材料与设施状态；未进入或未勘测的空间保持未知。能力不能读心、识别所有感染者或直接告诉主角唯一最优建设方案。
- 初始具备“勘测、蓝图预演、材料重构”。主角画定用途并选择范围，能力提示材料需求、施工等待和可见影响，主角确认后才实施；它不是会聊天、替主角管理住客的万能管家。
- 材料重构能用范围内已收集的砖石、金属和木料修补构件、装配兼容的现有零件。不能凭空生成材料、药物、食物、燃料、复杂芯片或完整设备，也不能把有毒水一句“净化”变成无限饮水。
- 同时只施工一处隔离区；搬运、分拣、观察与协调需人参与。初始能力只整理现有空间；第一阶段稳定后解锁地下勘测/加固式开拓，第二阶段稳定后扩大可同时监测的设施范围。奖励改善可执行动作，不恢复消耗掉的水、电与粮。
- 大型重构使用已接入的现实电力，材料、耗电与用时在施工前可见；首次觉醒附带一次“小范围门框与封闭构件修复”的免费施工机会，当场兑现第一章救命优势。免费机会是一次性的，不靠反复拆建刷奖励。
- 运行设施仍会耗能、发热、损耗耗材；“联通/完工”和“安全可用/运行验证通过”分开。成长节点只在已铺垫的能力范围内扩展，不因临时危机赠送万能制氧、无限空间或僵尸清除技能。

能力不替人做价值决定：住客想喝热水、要单间、怕被隔离、要找亲属，都可能与系统效率发生冲突。林照需要把自己的计划讲清楚，给出可兑现的生活改善，并争取协作。

### 3.3 楼体、资源与人物写前基线

楼体初始为地上六层＋屋顶＋现有地下一层。外观破败，局部构件损伤和设施老化，哪些区域可住必须由勘测与加固确认；不把视觉破旧等同随时整体倒塌，也不把继承文书当作结构安全证明。楼梯、竖井、出入口和承重区域在首轮勘测时确定；正式全文保持空间连续。

| 空间 | 初始情况 | 三卷建设方向 |
| --- | --- | --- |
| 一层及前后出入口 | 空商铺、损坏门框；街面丧尸压力大 | 先封闭可守区域，再形成入口缓冲、物资交接与工具间，保留逃生通道 |
| 二、三层 | 少量留守住客；可居住区域需要清理和检查 | 第一生活区、独立观察区、休息与共用空间；卧室不得临时变为先前未写出的机房 |
| 四至六层 | 空房、漏水、部分空间暂不可用 | 分阶段回收材料和整理备用空间，本书不将每层瞬间全部改好 |
| 屋顶与竖向通道 | 旧水箱、设备残件、暴露风险 | 勘测现有储水与设备，安排观察和管线；供水、采光、排热都付出维护成本 |

| 新建地下二层 | 开篇不存在；不能突然发现一座现成高科技基地 | 第二卷铺垫下方地质与加固能力，第三卷耗费材料/能源/工时开拓小规模扩建区 |

### 3.5 每章连续性与质量约束

人工维护“避难所状态表”，内容包括日期、人数、每层可用区域、门/楼梯/通道关系、水与食物收支、用电与备用状态、设施输入/输出及废物去向、材料库存、施工进度、能力已解锁内容、人物所知与伏笔。仅通过UI维护正式设定，证据表是复核副本，不直接同步后台。

每个重要建设节点至少有：为什么现在需要 → 从哪里拿材料/能源/人手 → 如何选择与执行 → 完成后改变什么生活 → 增加什么维护负担。并非每章机械打印五项；允许明确的小回报、日常与人物交流。至少三处《缺氧》经验实际改变行动，至少两处由现实情况或他人经验纠正游戏直觉。

第3/6/9章各做一次“楼体和资源盘点”。新增设施不得占据既有逃生通道而无人反应；地下空间不得前后换层、瞬间出现；初期作物不承担全员口粮；金手指不临时失效卡主角，也不无铺垫包办尸群危机。施工写到叙事需要的选择与结果，不编造可照做的危险工程教程。

## 4. 真人操作与逐步截图规范

## 5. 字数、文学质量与声音门禁

字数主口径冻结为项目现行 `visible_character_count`：正文经 `markdown_to_text` 转换后，按Unicode码点统计非空白字符，计入中文标点、数字及字母，不按JavaScript UTF-16长度计数。不含书名、章名、章纲、目标说明和日志，正文内不重复粘贴章名。主计数 `N` 须达到2500–2800；`N<2000`硬失败，`2000≤N<2500`继续修订。大于2800不自动截断，审查节奏并记录偏离目标的理由。

独立复核仅使用从编辑器正常全选复制得到的同一份已保存正文，在本地以同等转换规则只读计数；不得从数据库/API取正文。记录正文校验摘要、计数器规则版本、界面值 `N_ui` 与复核值 `N_copy`，相等后以该值作为 `N`。若不同，先查保存状态、复制范围及转换规则并记录问题，未解释前字数验收待定；不取含糊的“保守结果”。汉字数 `H` 单独记录为辅助指标，不套用2000/2500阈值；标点堆积、重复句和大段面板凑字由质量门禁拒绝，不用更换口径解决。

`chapter-checks.md` 逐章记录字数、重开保存结果、规则一致性及八项质量评估：开篇吸引力、人物主动选择、能力因果与建设回报、避难所建设与生存质感、场景推进、对话辨识度、信息/连续性、收束与承接。各项1–5分，作为本次编辑判断，目标平均≥4且无单项低于3；评分不能替代具体段落证据。说明自写自评存在偏差，无真实读者实验。发现弱场景通过UI重写并更新证据；不调用应用 AI 审稿。

“一键自动朗读”按用户少操作意图设以下验收目标：

1. 新书未手填任何语音参数，点击一次朗读主按钮即可自动准备音频并开始播放；不能把先配置、先生成、再播放的多步流程记成一键。
2. 第一章试读验证冷启动，定稿后九章均可完整朗读，使用保存后的最新正文；部分句段可播不等于全章完成。
3. 全书按卷章顺序连续播放，跨章不要求再次配置或手点八次；这是本计划对全书“一键”体验的目标解释，当前源码缺口按第7.1节修复并实测，不将“已生成9章音频”算成连播。
4. 用户不需要选择 Provider、Key、旁白或人物音色；使用现有本地默认能力。若首次准备慢，要显示可理解且可恢复的进度。
5. 实测播放、暂停/继续、句段切换、跨章、最后结束及刷新后恢复。重开浏览器后的声音播放限制单独记录；不能把系统限制引发的额外手势隐瞒为全自动。
6. 每章核对首、中、末音频与正文，以及角色对话、数字/专名（含《缺氧》）、楼层称谓、短面板提示、漏读、重复、长停顿、爆音。全程播放完成记录与抽样听检分别保存；没有音频访问/听取能力时声音质量保持待验证，截图或进度条不足以证明听感。
7. 第一章试读后、全文定稿前有一次真实文字修改，核查旧朗读提示与更新入口；更新后以新正文验收。不通过删音频、改状态或后台补绑定制造成功。
8. 通过现有可用的只读调用证据与源码路径核查本轮操作未使用QwenPaw AI助手，记录旁白来源、分段方式和TTS Provider；不将“没打开聊天栏”当成零助手调用的证据。证据不足记待验证。无需助手的默认单旁白可满足基础可听，不能强迫智能选角或人物分析。

如果无需助手的基础单旁白已经满足零配置，应先保证完整可听；多角色演绎可以评价，但不是必须新增的产品范围。现有UI只能逐章朗读时，记“章节可听通过、全书一键未通过”，进入本计划范围内的缺口评估。

一键验收分三道门：`TTS-1` 第一章首次制作后自动出声；`TTS-2` 两章真实连播（第二章无需预先手点生成）；`TTS-9` 定稿9章和8次衔接全程。等待合成允许，额外配置/手动选角/正常跨章再点播放不允许。浏览器首次手势应由主按钮接入现有音频后端；若异步等待后仍被策略拦截，显示明确继续入口并记录“一键未通过”，不能改浏览器安全设置或以例外冒充通过。刷新后的恢复允许一次明确“继续”，不要求绕过浏览器策略自动出声；应恢复同书/章/句段及原队列顺序，不能误播旧书或重头朗读。

## 本轮修复与加固

- 每个 fresh run 从 fixture 派生确定性的 run-unique 中文句段，防止重复验收退化为全缓存，同时保持基础 fixture 与修正规则不变。
- 同 novel 的跨 request 缓存复用不再因历史 render request ID 不同而拒绝媒体；跨 novel 和其余 owner/workspace/Edition/segment/fingerprint/hash/ETag 校验继续 fail-closed。
- partial-ready coordinator 只核验自身拥有的冻结字段，validator 后补的正式人物集合不再制造伪 scope 漂移。
- local operator 现在保留 `RuntimeObserverError.code`、五类固定 `ControllerEvidenceAssemblyError.code` 和证据校验 allowlist 内的 Collector code；未知异常及文件／写入／发布／binding 类错误仍统一返回 `CONTROLLER_LIFECYCLE_FINALIZE_HOLD`。以后真实重跑可以区分 browser/layout/pending-gap/runtime DTO、collector gate 和内部发布失败，同时不泄露私有细节。
- 容器内 exact launcher 停止顺序改为 `SIGINT 60 秒 → SIGTERM 10 秒 → SIGKILL 10 秒`，每次升级前重新核验 sealed argv；宿主 `docker exec` wrapper 即使 helper 失败也会继续回收。此次加固只保护恢复收口，不创建 daemon、OS service 或签名权威。
- fresh staging 的 `verify-stage` 只对指定瞬时失败做一次 0.5 秒只读重试；不重复复制、改权限或清理。

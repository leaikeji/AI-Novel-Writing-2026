## 作者结论

作者实际试听 canonical run `270ea179-e3cf-4095-a928-56b414070719` 后明确指出：第 1、4 份样本的大部分语音无法听懂，听起来不是正常中文；其余样本没有问题。该结论已经按同一 run、novel/document、fixture、Edition 和输出 hash 绑定为 `HUMAN_LISTENING_FAILED`。本轮不得重标 PASS，T4-K、T4-GATE 与公开 capability 继续 HOLD。

随后作者试听同一篇 146 字中文文本的 `onnx.Zhiming`、`onnx.Junhao`、`onnx.Xiaoyu` 官方 manifest 默认参数样本，三段分别为 31.30／32.10／31.62 秒，并最终裁决官方预设与官方参数完全可用。该较新裁决不篡改上段历史失败，而是把产品主路径从 seed 0／seed 1 项目候选切换为固定官方 prompt codes、manifest 默认生成参数及运行时初始 RNG seed `1234`。`fixed_seed_1` 结果文件和 fixture 继续作为可复核诊断证据，状态统一为 `SUPERSEDED_DIAGNOSTIC_NON_PRODUCT`，不得用于新产品 Voice Version／Edition。

## 精确绑定与根因证据

四份播放媒体均为有效 48 kHz 双声道 AAC-LC，哈希链闭合且无削波；UTF-8、`zh-CN`、preset 映射、相邻人物对白绑定和转码没有发现串错。分段器按产品契约把“人物说道：”保留为旁白段、把相邻引号内对白保留为人物段，这保证句段级编辑器跟随和双音色边界，因此不能直接把两个段合并。

当前最强根因是：MOSS-TTS-Nano 在“极短中文说话提示语 + 中文冒号 + fixed sampling + seed 0”的精确组合上发生确定性解码退化。重复提示语复用同一 render fingerprint，所以坏结果会在整章中稳定复现，不是单个试听文件损坏。

## 已完成的修复防线

- Sidecar 已对非 NFC、U+FFFD、surrogate 和非允许控制字符 fail-closed，稳定返回 `TEXT_INVALID`；这防止真实 Unicode 损坏被送入模型，但不将本次已确认的解码退化误报成编码问题。
- worker 已在转码和媒体发布前执行短中文时长门禁：对不超过 32 个字符、含汉字且只含常用中文标点的文本，上限为 `1200 + 400 × 字符数` ms。两条 5 字坏样本的上限为 3200 ms，3760 ms 与 22080 ms 都会在零媒体发布前以不可重试 `NANO_AUDIO_INVALID` 隔离；21／22 字正常旁白不受影响。
- 人工听检 schema 已升级为 `moss-tts-chapter-listening/1.1`，新增必填布尔项 `all_samples_intelligible_mandarin`；总验收器已同步要求六个检查全为 true，旧 1.0 记录不能用于本次放行。
- 本地编排已精确传播 `HUMAN_LISTENING_FAILED`，只有该精确已完结人工失败可进入受控 cleanup；当前恢复证据 schema 3.2 必须给出三项布尔恢复事实、精确的新权威记录数和被封存结果的 2.3 schema 标记，不得猜测。历史 3.0／3.1 只可按原语义恢复，不能生成当前门禁 PASS。
- 已新增无 DB／无 I/O 的 `nano-zh-attribution-sampling/2` 历史策略解析器。真实 seed 0 诊断除冒号两条坏样本外，还确认 `沈川说道。` 句号变体为 9040 ms；现行正式开关固定为 `disabled`，仅允许读取历史 v4 证据，不再为新产品 render 选择 fixed seed 1。

## 1. 双轴 fact resolver

### 1.1 唯一分工

- `StoryFact.status` 只表示事实自身生命周期：`active/source_restored` 可参与解析，`superseded` 表示事实已被撤销或替代，`invalid/source_superseded` 表示事实自身当前不可纳入。
- `DerivedSourceBinding.validity_state` 只表示该 fact 与某个来源 revision 的证据关系；不得再按 revision 建一个会互相污染不同 fact 的全局布尔值。
- `StoryEventLink(link_type=supersedes)` 表示 replacement source fact 替代 target fact；链接不原地改写历史事实。
- `IntelligenceCommitBatch.state=reverted` 是批次撤销证据；resolver 用 binding 的 `commit_batch_id` 解释 `batch_reverted`，不得让已撤销批次因正文 restore 被重新激活。

### 1.2 权威纳入／effective-state 优先级

按 fact 计算，禁止按 revision 汇总后套给其他 fact：

1. 若 fact 的 owning binding 指向 reverted batch，且没有仍有效的独立 provenance，`included=false`、`effective_state=batch_reverted`、reason `batch_reverted`。
2. 若存在入向 supersedes link，或 fact lifecycle 为 `superseded` 且不是上一步，`included=false`、`effective_state=superseded`，reason `superseded_by_fact`／`fact_status_superseded`。
3. 若 lifecycle 为 `invalid/source_superseded`，`included=false`、`effective_state=source_invalid`，reason `fact_status_invalid`。
4. `source_revision_id` 为空时不要求 binding，reason `source_not_applicable`；非空时只核对**该 fact 且匹配其 immutable `source_revision_id`** 的 binding。至少一条 `current/source_restored` 且非 reverted 才通过；其他 revision 的失效 binding 不污染它。缺失／全失效分别为 `source_binding_missing`／`source_binding_invalid`，均 `included=false`、`source_invalid`。
5. 来源通过后，再应用 timeline inheritance 与 narrative cutoff。越界为 historical，reason `timeline_out_of_scope`／`after_narrative_cutoff`；需要排序而缺 sequence 时为 historical，并把 `story_sequence_ambiguous` 交给 health。
6. 进入投影且被选为当前槽位的状态 fact 为 `current`、reason `projection_current`；有效但非当前槽、事件流水或旧值为 `historical`、reason `projection_historical`／`non_state_event`。

`included_in_current_projection` 是独立布尔结果；`effective_state` 是作者展示分类。消费者使用布尔结果决定 Context V3/V4、story-state、embedding 和人物／全书投影是否纳入，不得各自重算 revision validity。

### 1.3 health 轴

health 不改变生命周期。优先级为 `conflict > ambiguous > ok`，同时保留多个 reason code：

- conflict：`explicit_contradiction`、`same_position_conflict`；
- ambiguous：`source_reference_incomplete`、`source_hash_mismatch`、`source_coordinate_invalid`、`story_sequence_ambiguous`、`entity_reference_missing`；
- ok：无 health reason。

因此 current fact 可以是 conflict，historical fact 可以是 ambiguous；不得用 `source_invalid` 覆盖 conflict，也不得让 health 直接决定 `StoryFact.status`。

## 2. 完整 snapshot 契约

- 选择扩张单一 `Novel.story_ledger_version`，不增加 snapshot 表或复合根版本列。
- `ledger_snapshot_token` schema 为 `ledger-snapshot/1`，服务端编码至少包含 `novel_id + story_ledger_version`；客户端只做原样保存和比较，不解析、不拼装。
- 读请求必须在新 Session 的第一条数据库操作前进入只读 `REPEATABLE READ`；token、ID 页选、summary 与本页 enrichment 全部在同一事务快照中完成，禁止 check-then-read。
- cursor schema 为 `story-ledger-cursor/1`，绑定 snapshot token、规范化 filter SHA-256、`created_at DESC/id DESC` 最后一项。token/filter 不匹配返回 HTTP 409 `stale_page`，并提供当前 token；不静默混页。
- impact preview 返回 `preview_snapshot_token`；最终 correction/revert 必须匹配它。现有 numeric `story_ledger_version` 可作为诊断／兼容字段，但服务端只能从同一 token/version 事实源校验。

## 3. 版本命令矩阵

| 业务动作 | 当前事实 | 冻结行为 |
| --- | --- | --- |
| 新建小说／补默认主线 | `ensure_default_story_state` 有新增才 +1 | 保留；同一业务事务只 +1 |
| timeline patch/fork/link/merge | 多数有 ledger CAS；merge 会按子调用多次 +1 | 实际变化 +1、no-op/replay 0；merge 整个事务只 +1 |
| StoryEventLink | 新建 +1，精确重复 0 | 保留；payload 冲突不得伪装 replay |
| character instance create/patch | +1；同值 patch 仍可能 +1 | 同值 0，实际变化 +1 |
| instance profile save/restore | revision replay 0，新 revision +1 | 同 operation+payload 先 replay；实际新 revision +1 |
| correction | key+payload replay 优先，实际修正 +1 | 保留；token/CAS 统一错误结构 |
| batch revert | 已撤销时不核对 key/payload；空 batch 也可 +1 | 同 key+payload replay；异 payload `idempotency_conflict`；无可逆变化不可进入可撤销 committed batch，no-op 0 |
| intelligence commit | 客户端无 expected ledger；关系先物化；只有 created fact 才 +1 | 同 commit key/payload replay优先；新 key 过期冲突；fact/关系任一权威变化整事务 +1；精确重复回 `already_committed/no_change` 且 0 |
| checkpoint / candidate adopt / revision restore | reconcile 会改 binding/fact status，但不推进 ledger | reconcile 返回结构化 changed；改变纳入结果时整事务 +1，无变化 0 |
| revision timeline mapping | 新 revision +1 | replay/no-op 0，实际变化 +1 |
| character root create/update/archive/restore | catalog/version 独立；名称等可改变 ledger 显示但多数不推进 ledger | 保留现有实体/catalog CAS；锁 Novel，实际影响显示时整事务 +1 |
| relationship create/update/archive/restore/batch | entity version 独立，不推进 ledger | 锁 Novel；实际变化每业务事务 +1，batch 只 +1，同值/replay 0 |
| storyline create/update/delete | 不推进 ledger | 锁 Novel；实际变化 +1，同值 0 |
| foreshadow create/update/delete | 不推进 ledger | 锁 Novel；实际变化 +1，同值 0 |
| document title/位置/volume/reorder/delete | 可改变来源标题、章序或移除 binding，不推进 ledger | 影响账本来源显示或纳入时整事务 +1；纯 working-copy 编辑不推进 |
| relationship graph layout、声音、TTS、私有素材、普通 UI 偏好 | 不属于账本读结果 | 明确排除，不推进 ledger |

所有矩阵内 writer 都先锁同一 Novel 聚合根；已有实体 `expected_version`／catalog CAS 继续保留，不为兼容旧客户端强制给每个根 CRUD 新增第二个客户端 CAS 字段。对 correction/revert/ledger 命令，expected snapshot 是强制条件。

## 4. 幂等优先级

统一顺序：

1. 查找同 scope + `operation_key` 的已完成证据；
2. canonical payload hash 相同则回放原成功结果，即使客户端携带的 expected snapshot 已过期；
3. 同 key 不同 hash 返回 HTTP 409 `idempotency_conflict`；
4. 只有新 key 才校验 expected snapshot，过期返回 HTTP 409 `story_ledger_version_conflict`；
5. 实际执行，no-op 返回结构化 `changed=false/no_change`，不推进版本；
6. 成功结果保存 key/hash/结果所需证据后提交。

canonical payload 排除瞬时 UI 字段，集合排序、字符串 trim、JSON key 排序；reason 属于 correction/revert 的业务 payload。前端相同意图和 payload 的超时重试复用 key，payload 改变才轮换。

## 5. StoryFact 类型／实体覆盖

| 类型 | 首选实体 | 缺失／已删除时显示 |
| --- | --- | --- |
| `character_state` | instance → character root | 保留 fact，使用 immutable `subject` 并标“历史实体／未关联” |
| `knowledge_event` | observer instance → character root | 同上，不因缺 instance 丢失知识事件 |
| `relationship_state` | relationship root | 使用 fact subject/predicate/object 与安全 details 快照，不伪造关系 |
| `storyline_event` | storyline root | 使用 subject 快照并标根已删除／未关联 |
| `foreshadow_event` | foreshadow root | 使用 subject 快照并标根已删除／未关联 |
| `story_time` | 无实体也合法 | 显示 story_time + subject，不制造实体 ID |
| `world_state` | 无实体也合法 | 显示 subject/dimension |
| `general_fact` | 无实体也合法 | 显示 subject/predicate/object |

所有类型都保留 source snapshot、timeline、effective-state、health 和 reason codes。实体实时 join 仅用于当前显示名；任一会改变 join 结果的根写入必须推进聚合版本。

## 6. 测试矩阵最低集合

- lifecycle × binding：active/restored/superseded/invalid × none/current/restored/invalid/mixed-other-revision；
- batch × supersedes：reverted、active provenance、入向 supersedes、组合优先级；
- projection × health：current/historical/out-of-scope/missing-sequence × ok/conflict/ambiguous；
- 每个命令：stale CAS、实际变化 +1、同值 0、同 key 同 payload replay 0、同 key 异 payload冲突、新 key过期冲突、回滚 0、组合事务只 +1；
- 所有消费者对同一 fixture 的 included fact ID/effective state/reason 一致，health 仍独立。

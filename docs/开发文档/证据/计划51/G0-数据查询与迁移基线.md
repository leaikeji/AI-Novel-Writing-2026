## 2. fallback 历史候选分级

高可信候选必须同时满足：

- `fact_type=character_state`；
- `predicate=在本章正文中出现`；
- `object_text=参与本章事件`；
- `dimension=presence`；
- `event_kind=observed`。

歧义候选定义为同一 fact type 且上述四个形状信号命中三个，但不满足全部四个。长期只读 SQL 和 10 个作品的公开 GET 交叉结果均为：高可信 0、歧义 0。

即使以后出现高可信候选，也只形成作者可审阅修复提案；无 provenance 专用标志时禁止自动删除真实事实。

## 4. EXPLAIN 与窄索引裁决

当前 10,000 条全量 projection 查询为 `Seq Scan 12,500 rows -> filter 10,000 -> Sort 10,000`，shared hit 781，执行 16.106 ms。这里 12,500 是同库三档 fixture 总量；查询正确过滤到目标作品 10,000 条，但仍全部读入。

冻结的全书默认顺序为 `created_at DESC, id DESC`。当前 schema 下，为 20 行页选得到：

| 目标作品 | 无新索引扫描／返回 | 无新索引执行 | 临时窄索引扫描／返回 | 临时窄索引执行 |
| ---: | ---: | ---: | ---: | ---: |
| 500 | 500 / 20 | 0.552 ms | 20 / 20 | 0.020 ms |
| 2,000 | 2,000 / 20 | 0.720 ms | 20 / 20 | 0.019 ms |
| 10,000 | 12,500 扫描、10,000 命中 / 20 | 2.475 ms | 20 / 20 | 0.024 ms |

临时索引仅在测试库创建后删除：

```sql
CREATE INDEX ... ON story_facts
  (novel_id, created_at DESC, id DESC)
  WHERE schema_version = 'story-fact/2';
```

它把三档计划都收敛为 `Limit -> Index Only Scan`。因此裁决为：

1. W2 必须先冻结最终 list 过滤和 cursor SQL；
2. 若最终 SQL 仍采用上述全局最近顺序，则 `L51-MIG-QUERY` 已满足“有必要”的事实门槛，只允许增加这一用途的最小索引；
3. 创建 revision 仍需单独批准，并必须验证升级、回退与写入成本；G0 不创建迁移；
4. `L51-MIG-COMPAT` 不与查询索引混装。

## 5. W2/W5 查询预算

- list 默认／最大 page size 为 20／100；ID 页选只返回 `limit + 1` 个 ID。
- list SQL 数硬上限 10；StoryFact ORM load 不超过 `limit + 1`，binding/link/batch enrichment 只允许与本页 ID 成比例，不允许全书 `IN (...)`。
- summary 使用独立聚合，返回固定类型／状态桶；不得实例化 StoryFact ORM 行。
- 2,000 条为发布硬门禁：默认页索引扫描目标不超过 64 行；若组合筛选选择性导致更高扫描，必须记录真实计划并保持不装载全书对象。
- 10,000 条为 soak：默认页 Python 峰值不得超过 2,000 条结果的 2 倍，证明内存不再随全书线性增长。
- 每次读在同一只读 repeatable-read 快照中取得 token、summary/page 和 enrichment；不把低毫秒数替代一致性与行数证据。

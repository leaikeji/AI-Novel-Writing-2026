- 源视觉真相：本轮浏览器批注中用户提供的“编辑角色”截图，1636×1229；目标由批注明确为“性别与年龄同一行、身份独占下一行并可上下拖拽调高”。
- 实现截图：`implementation-final.jpg`，1636×1229 像素。
- CSS 视口：1636×1229；浏览器 DPR 2；浏览器截图按 CSS 像素输出，未做密度缩放。
- 状态：角色页打开“苏晚”的编辑角色弹窗。
- 全图比较：源图与实现均为相同路由、相同角色、相同视口和相同弹窗状态。
- 聚焦比较：弹窗在全图中占 720×908 CSS 像素，字段标签和右下角缩放柄清晰可辨，无需额外裁切。

## Findings

- 无遗留 P0/P1/P2 问题。
- 初始状态 [P2]：性别、年龄、身份被排在同一行，身份仅为单行 Input，与用户指定结构不一致。
- 修复后：性别和年龄各占二分之一宽度；身份独占 670px 下一行，并改为 textarea。

## 必查保真面

- 字体与排版：沿用项目现有标签和输入控件字重、字号、行高；未改变弹窗标题及按钮排版。
- 间距与布局：性别和年龄同轴、等宽；身份与上下字段保持 16px 表单节奏，单独占满一行。
- 颜色与令牌：身份 textarea 沿用项目输入框边框、聚焦色及统一浅灰滚动条令牌。
- 图片与资产：该弹窗没有需要新增或替换的图片资产。
- 文案与内容：字段文案保持“角色类型、角色姓名、性别、年龄、身份、性格、人物小传”；角色数据未被修改。

## 交互验收

- 身份控件实测标签：`TEXTAREA`。
- 初始高度：64px；最小高度：64px；最大高度：220px。
- `resize: vertical`、`overflow: auto`，宽度固定为 670px，只允许上下调节。
- 性别与年龄实测宽度均为 328px，横坐标分别为 483px 与 825px，处于同一行。
- 保存按钮保持启用；页面控制台 error/warn：0。

## 比较历史

1. 批注截图确认三字段误排在同一行，身份无法提供多行可调空间。
2. 将人口属性行收敛为性别＋年龄双列；身份移动至独立字段。
3. 将身份由 Input 改为可纵向缩放的 TextArea，并限制 64–220px，避免撑破桌面弹窗。
4. 重新构建、部署并在相同 1636×1229 状态复查，未发现新的 P0/P1/P2 问题。

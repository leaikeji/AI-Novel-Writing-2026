## 缺陷 1：工作台内新建对话跳回主页

- 修复前：点击原生 `spark-newChat-fill` 后 URL 进入裸 `/chat`，路由状态机清除 workbench owner，章节工作台消失。
- 修复后：同一运行期有效 owner + tab-scoped owner/novel 双匹配时，`/chat/{旧 session} -> /chat` 转为 `workbench-no-session`；新 session 生成后继续绑定。fresh/direct `/chat` 的新状态机仍清理旧存储。
- 真实结果：点击新建对话后 URL 为 `/chat`，章节目录、当前正文编辑器和 QwenPaw 原生空白助手同时保留。

## 缺陷 2：选择正文后点击润色没有可执行动作

- 已核实公开契约：QwenPaw 2.1.0 的 `chat.sender` 只公开 `set` 和 `addSuggestion`，未公开命令式 send/prefill。
- 修复：点击选区动作即复制完整 slash 命令并展开原生助手；工具条与 toast 明确提示在原生助手粘贴后点击发送。复制失败时保留公开 suggestion 和手工命令。
- 边界：不操作 QwenPaw 私有 DOM/store，不自行调用第二套聊天发送器，不绕过原生流式、停止按钮和工具安全状态。

## 缺陷 3：取消选区后操作栏残留

- 修复前：正文已有选区时，把焦点移到右侧原生助手，`selectionStart/selectionEnd` 仍由 textarea 保留，选区工具条也继续悬浮；同字段把范围收成光标时，旧 selection、suggestion 和工具条也可能残留。
- 修复后：同一受控字段的范围收成光标，或焦点转到工作台内与发送无关的区域时，会注销未发送的 selection、移除 slash suggestion、清空页面感知选区并关闭工具条。
- 发送边界：点击右侧 `.anw-assistant-pane` 只隐藏工具条，不删除仍需粘贴/发送或结构化审阅的逻辑选区；已经进入 `sent` 阶段的 registry 记录继续保留，避免候选卡因移动光标而提前失效。
- 防误关：工具条自身的按钮事件被排除；用户在异步散列阶段取消时，旧 capture generation 立即失效，工具条不会稍后重新出现。
- 真实浏览器：在第 6 章正文使用 `Meta+A` 形成 UTF-16 `0–1181` 选区，“润色 / 改写 / 扩写 / 缩写 / 增强对白 / 检查问题 / 自定义”全部出现；点击 QwenPaw 原生输入框后工具条立即消失，助手上下文仍显示 `选区 1181 字`，证明交接未断；重新激活选区后点击章节标题，textarea 虽按浏览器原生行为仍保留 `0–1181` 范围，工具条和页面感知中的选区均立即清空；刷新后无残留。
- 数据影响：未输入、保存或应用任何正文，章节仍为原 1169 字。

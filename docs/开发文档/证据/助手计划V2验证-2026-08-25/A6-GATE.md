# A6-G：结构化提案、受控应用与撤销门禁

- 状态：✅ 通过
- 日期：2026-08-25
- 范围：`A6-A` 至 `A6-F` 的集成门禁；只裁决结构化提案、页面应用、保存边界、冲突与安全降级，最终安装/数据库/性能/三题材质量仍由 A7 裁决。
- 真实宿主：QwenPaw 2.1.0，PawApp `ai-novel-world-2026@0.3.0` 正式安装态。
- 真实模型：目标 Agent“AI 小说作家”，有效模型 `minimax-cn / MiniMax-M3`。

## 1. 实现结论

- 后端新增纯提案工具 `novel_prepare_selection_edit`。工具严格校验 schema、UUID、操作枚举、候选正文、摘要和 warnings，只返回结构化结果，不写小说、正文、revision 或故事资料。
- 工具只安装到 `ai-novel-writer`；Default 与 QA Agent 仍无小说 Skills 和小说工具。六个小说 Skill 与专用 Agent 使用同一规则：选区直接修改必须返回工具卡，普通建议只回复文本。
- 前端 renderer 已按 QwenPaw 2.1 的真实 `{data}` 工具消息封装解析，并兼容旧 `{result, sessionId, messageId}` 公共形态；嵌套输出使用有限深度、有限数组和有限字符递归解包，最终仍必须通过严格 schema。
- 卡片显示操作、字段、摘要、原文/候选字数、候选文本和状态；支持替换、插入、复制、撤销、放弃。坏结果、异常、过期和冲突只保留复制/放弃，不执行页面写入。
- 应用前重新校验 Agent、session、作品、文档、字段、上下文版本、完整字段 SHA-256、UTF-16 范围和原文片段。所有写回只经过页面 `EditableFieldAdapter` 和独立 `AIEditTransaction`。
- 正文应用/撤销沿用恢复草稿和 600ms 自动保存；标题、章纲、人物、线索和设定只更新显式保存草稿并标记 dirty，不替作者点击原保存按钮。
- 真实宿主会在流式/工具消息期间重挂载 wrapped route。选区控制器现将宿主重挂载视为 `suspend()`，保留已绑定的在途记录；真正离开工作台才 `stop()` 并清理。
- 标题、章纲、人物、关系、线索和设定弹窗的选区工具栏通过宿主公开 ReactDOM Portal 渲染到 `document.body`；这些助手感知弹窗使用非阻塞交互层，弹窗和右侧原生助手可以同时操作。

## 2. 真实写回闭环

作品《潮声替我说晚安》、第 4 章《退回的旧木盒》原始正文为 1067 个 UTF-16 字符，服务端原始 `content_hash` 为 `50e8638661675e79fba021d15a102791874b9d97e48b3890917754a1532a9650`。

| 环节 | 真实结果 |
| --- | --- |
| MiniMax-M3 整章润色 | 返回 1030 字结构化候选；最新卡片为 `ready`，Agent/session/选区校验通过 |
| 替换选区 | 正文从 1067 变为 1030；仅正文目标范围变化；卡片进入 `applied` |
| 自动保存 | 服务端 `draft_version` 从 4 递增到 5，`content_hash` 变为候选哈希 |
| 撤销替换 | 正文逐字恢复为 1067；服务端 `draft_version` 递增到 6，原始 hash 恢复；刷新后仍逐字一致 |
| 标题改写 | “退回的旧木盒”返回“盐霜未干的木盒”；应用后仅标题弹窗草稿变为 7 字，页面显示 1 个未保存字段，服务端 title 仍是原值 |
| 撤销标题 | 草稿恢复“退回的旧木盒”；未调用保存接口，服务端 title/version 不变 |
| 作者并发修改 | 候选 ready 后作者把标题改为“作者刚刚修改的标题”；卡片立即转为 conflict，替换禁用、复制保留 |
| 放弃候选 | 卡片进入 discarded；未修改页面或服务端 |
| 插入到选区后 | 1067 字原文保持为前缀，仅在选区后追加 1022 字候选，总长精确为 2089；撤销后原文与 hash 再次恢复 |
| 普通对话 | “请用一句话告诉我当前作品名，不要修改任何内容。”仅回复“当前作品名：《潮声替我说晚安》。”；候选卡数量保持 7，正文 draft_version/hash 不变 |

最终恢复核验：标题仍为“退回的旧木盒”，正文长度 1067，`draft_version=8`，正文 hash 与门禁前一致。门禁没有把 AI 候选留在用户权威正文或标题中。

## 3. 真实问题与修复

本阶段真实环境先后暴露并修复四个自动化桩未覆盖的问题：

1. QwenPaw 动态工具参数模型不能解析延迟枚举 forward ref；工具签名改为运行时可解析的内联 `Literal`，并增加真实注解内省测试。
2. QwenPaw 2.1 renderer 传入 `{data}` 工具消息而非旧 `{result}`；补充真实消息封装、AgentScope 输出解包和历史卡片兼容。
3. 宿主响应期间重挂载 route 会提前清空 tab-local selection registry；拆分 `suspend()` 与真实 `stop()` 生命周期并增加回归测试。
4. 模态遮罩/层叠上下文使弹窗内工具栏和右侧助手不可连续点击；工具栏改用公开 ReactDOM Portal，助手感知弹窗改为非阻塞交互层，并用真实标题改写完整复验。

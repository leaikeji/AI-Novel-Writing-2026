# L52-W4：自动化与长篇复测

日期：2026-09-02（Asia/Shanghai）
状态：**QA PASS；长期发布已在后续 `L52-RELEASE` 完成**

## 1. 本轮结论

计划 52 的前后端源码候选已完成主要结构收缩：打开作品不再返回整书正文，卷章目录按游标分页并虚拟化，Context V4 先有界选择再水合正文，Prompt 只从同一预算账本组装，Dense／lexical／本地降级都限制应用候选，每次生成的检索结果以脱敏摘要呈现给作者。

新建小说不保存额外“默认偏好”；只在当前 active embedding 配置、Profile 和凭证均有效时，直接为新书创建它自己的 `NovelEmbeddingConsent`。既有小说不批量改变，每本书仍可单独撤销。配置不可用或提交后排队失败不回滚新书和合法授权，也不发起云端请求。

`novel_get_context` 曾是最后一条全量读取链：输出虽有 40,000 字限制，但会先读取全部文档并组装 Context V3。现已改为数据库窗口定位、最多 20 章且总正文不超过 40,000 字，并共用有界 Context V4。生产调用者归零后，旧 `context_v3` 模块、loader 和只服务旧实现的测试已删除，不保留双轨。

## 2. 100 万／500 万字复测

环境与 G0 相同：Apple M4，16 GiB，Python 3.12.13，PostgreSQL 18.6，pgvector 0.8.6；只使用精确命名的 `ai_novel_world_2026_plan52_test` 隔离库和合成正文，每路径 5 次预热采样，云端 Provider 调用为 0。原始证据见 `L52-W4-long-novel.raw.json`。

| 路径 | 100 万 P95 | 500 万 P95 | 500 万 SQL | 500 万峰值 | 500 万响应 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 作品列表 | 6.395 ms | 3.332 ms | 1 | 0.043 MiB | 2,297 B |
| 打开作品元数据 | 3.401 ms | 2.892 ms | 2 | 0.024 MiB | 628 B |
| 单章读取 | 4.198 ms | 4.186 ms | 4 | 0.050 MiB | 6,969 B |
| 助手有界上下文 | 142.559 ms | 141.230 ms | 21 | 2.087 MiB | 352,960 B |
| Context V4 | 104.881 ms | 147.693 ms | 17 | 2.002 MiB | 228,762 B |
| Prompt builder | 0.750 ms | 0.662 ms | 0 | 0.224 MiB | 68,644 B |
| 无向量本地降级 | 95.424 ms | 367.760 ms | 5 | 0.084 MiB | 3,285 B |
| 生产有界 lexical | 73.412 ms | 98.387 ms | 3 | 0.138 MiB | 3,039 B |
| 作品搜索 | 34.206 ms | 135.615 ms | 4 | 4.515 MiB | 1,263 B |

相比 G0，500 万字助手上下文从 P95 1,708.506 ms／72.521 MiB／2,060,912 B 收缩到 141.230 ms／2.087 MiB／352,960 B。Context V4 从 5,968.369 ms／5,011 SQL／142.988 MiB 收缩到 147.693 ms／17 SQL／2.002 MiB。旧 indexed lexical 基准会把 7,500 条全部返回 Python；复测已调用真正生产 `execute_bounded_retrieval`，返回约 3 KB。

应用候选和响应体已受界，lexical 在当前 7,500 chunk 上仍可由 PostgreSQL 扫描后只返回最多 80 个候选。当前 P95 低于 250 ms 门槛，所以仍无事实依据增加 ANN 或新索引；若未来 active chunk 或并发显著增长，需重新以质量与写放大证据裁决。

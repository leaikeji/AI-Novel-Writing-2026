## 1. 第二次复查结论

第一次方案仍然偏重：它主要修复隐藏重试和错误文案，却保留了七屏建书、五步大纲、六步建章、正文生成前两层阻塞、成功后的同步追问，以及四次跨模型发布验收。

本次把目标从“修好三个向导”改为：

```text
快速建书（默认 0 次模型调用）
  → 可选完善作品（模块化、每次最多 1 次调用）
  → 创建章节（单页、可 0 次调用）
  → 写正文（手写或 1 次模型调用）
  → 作者需要时再同步进展
```

冻结原则：

- **0 个新 Agent、0 个新模型选择器、0 个逐模型 Skill。**
- **0 张新表、0 个 Alembic revision、0 个任务队列、0 个新运行时依赖。**
- **0 处 QwenPaw 上游修改；不读取或操作其私有会话 store。**
- 复用现有 draft、job、候选、working copy、不可变 revision、幂等键与 CAS。
- 默认建书不调用模型；任何 AI 按钮一次点击最多一次模型调用。
- 失败不自动重试、不自动换模型、不触发后续 AI 任务、不改变正式正文或故事账本。

## 3. 目标作者流程

### 3.1 快速建书：两页，默认零模型调用

#### 第 1 页：作品定位

同屏填写受众、题材／子题材、创作思路和可选模板。

- 当前只支持长篇，固定显示“长篇小说”，不再提供单独选择页，也不展示点击后报错的短篇入口。
- 模板不再是建书硬前置。默认“自由创作”，作者可展开系统模板，也可显式点击一次“AI 匹配模板”。
- AI 模板失败只影响模板候选，不阻塞作者继续建书。

#### 第 2 页：作品信息

同屏填写小说名称、作者名称，并选择文字封面、系统封面或上传 JPEG。

- 默认选择文字封面并立即预览；作者不处理封面也能创建作品。
- “AI 取名”是可选动作，结果显示为候选列表；只有作者点选的一个书名进入 `title`。
- 不再新建 `novel_cover` 任务。历史 job 与既有 `cover_mode=ai` 只读兼容；新建和设置 API 拒绝新的 `ai` 写入。
- 页面底部用一行摘要显示“长篇／受众／题材／封面”，点击“创建作品”即完成，不再增加完成确认屏。

#### 草稿恢复

- 继续使用 `NovelCreationDraft`；页面字段 1 秒合并保存。
- 保存实现为单飞队列：同一时刻最多一个 PATCH，只保留最新待保存快照。
- 切页、关闭和创建前 flush；失败时保持页面打开并保留本地输入。
- CAS 冲突停止自动保存并提示刷新／重新决定，不用旧响应覆盖任一侧新版本。
- AI 书名候选继续从 `naming_generation_job_id` 恢复，不把多个候选拼入标题字段。

### 3.2 作品准备：单页模块，不再强迫五步串行

大纲编辑页显示目标章节数和四个模块：故事背景、角色、主要情节、亮点与简介。每个模块只保留手工编辑、AI 生成、基于当前优化 `refine` 和另写一版 `fresh`。

- 作者只改某一模块时，不再从“章节数”重新走完整向导。
- 四个模块不自动连锁生成；修改背景不会偷偷重做角色、情节或亮点。
- AI 结果仍先写 `CreativeGenerationJob`，再经 job 归属、源版本、重复判定和草稿 CAS 自动采用到 `OutlineDraft`。
- 正式小说的大纲和角色只在作者点击“应用到作品”后由现有事务更新；生成失败保留原草稿与正式数据。
- 大纲是推荐准备项，不阻止作者先创建空章节并手写。

本目标将取代文档 07 中“编辑已有大纲仍使用五步页面”的最新 UI 决策；只有用户批准施工后，才同步追加新的状态补充，不改写历史记录。

### 3.3 创建章节：单页章前卡

继续使用 `ChapterCreationDraft` 保留恢复和 CAS，但 UI 不再暴露六步状态机。

默认可见：章节标题（默认 `第 N 章`）、目标字数（默认 2500）、本章期待／章节大纲和可选“AI 拟章纲”。故事线、角色、伏笔、禁止事项及是否允许新角色／角色退场折叠在“高级约束”中。

- 允许创建只有标题的空章节；章纲可在编辑器内稍后补充，AI 正文生成前再校验必要输入。
- 移除新 UI 的“AI 智能推荐线路”调用。章纲生成直接读取当前小说的有效线路、角色、伏笔和作者选中的高级约束。
- “AI 拟章纲”一次只创建一个 job；260—500 字校验失败时显示实际长度，由作者编辑或显式重试。
- 创建按钮直接完成章节并打开编辑器，不再经过最终摘要确认页。

### 3.4 章节正文：一个主入口，一次调用

- 空正文只显示一个主动作“AI 生成正文”和一个次动作“直接写作”；删除同屏重复入口。
- 私有库素材改为按钮旁的“使用素材（N）”可选设置；未选择时点击生成直接开始，不先打开素材弹窗。
- 按钮旁显示“AI 生成任务模型：Provider／Model”和最长等待；点击即为明确授权，不再弹通用模型确认。
- 现有正文非空时，保留一次“生成新工作稿会替换当前 working copy”的确认；不增加第二层确认。
- 首次生成 `force_new=false`，网络重放命中同一 running／ready job；只有作者明确点击“重新生成”才使用 `force_new=true`。
- 正文任务一次点击只调用一次模型。长度不合格、格式错误、超时或网络失败都停止，界面展示事实并提供手工重试。
- 成功候选继续按现有规则进入 working copy，不自动创建正式 revision；页面明确显示“已写入工作稿，正式版本未发布”。
- 成功后不自动弹出“同步进展”。同步、审稿和建立检查点继续是相互独立的显式动作。

### 3.5 创作中心与模型边界

- 返回创作中心、创建／删除／移动章节和窗口重新获得焦点时，按既有公开 API 重取作品摘要；作品卡、分卷和章节列表使用同一章节集合与字数口径。
- 已分卷章节存在时，不再显示无说明的“暂无章节”；若保留该区域，明确命名为“未分卷章节”。
- 作品区把“当前有效模型”改称“AI 生成任务模型”。
- 页面上下文状态增加固定说明：“右侧模型只影响原生聊天；本页生成按钮使用 AI 小说作家 Agent 的有效模型。”不读取 QwenPaw 私有状态。
- 当前 route 已进入新作品但宿主仍显示旧 current session 时，继续拒绝向旧 session 注入新作品上下文，并提示作者使用原生“新建对话”；不删除旧历史。
- 继续复用 QwenPaw 原生助手和现有 route state machine；不清空历史、不复制聊天前端、不自动切换聊天模型。

## 4. Agent 与 Skill 的轻量架构

### 4.1 一个 Agent、一个模型权威

所有产品生成任务继续使用 `ai-novel-writer` 的 `follow-agent-effective`：请求前读取公开 effective Provider／Model；每个 job 使用独立 session，不携带原生长聊天历史；requested／actual 不一致时作废；不静默回退，不在 PawApp 再建模型选择器。

右侧原生聊天可以显示另一个会话模型，但它不参与页面生成按钮的 job。产品只把职责讲清楚，不接管 QwenPaw 会话。

### 4.2 静态任务—Skill 映射

| 受控任务 | 唯一 Skill |
| --- | --- |
| 可选模板、取名 | `novel-direction` |
| 大纲背景／情节／亮点 | `story-foundation` |
| 大纲角色 | `character-craft` |
| 章节章纲 | `chapter-outline` |
| 章节正文 | `prose-writing` |

不为展示“九个 Skill 都在用”而强行接线。关系网、角色补全、审稿、选区编辑和原生咨询沿用各自现有入口，本计划不改其契约。`chapter_storyline_recommendation` 历史 job 可读取，但新 UI 不再创建；`novel_cover` 新任务关闭。

该映射是一个普通常量和契约测试，不建立动态路由器、模型画像、Skill 叠加器或通用工作流引擎。QwenPaw 2.1.x 没有公开逐请求工具硬禁用参数时，继续使用当前提示词级禁止工具约束，不修改上游补造开关。

## 5. 失败、安全与等待上限

### 5.1 调用规则

- 结构化辅助任务上限 180 秒；正文上限 300 秒。
- 超时取消并丢弃晚到结果；不重试、不换模型、不继续下一任务。
- 页面在 30 秒后可显示“仍在等待模型返回”，但不显示虚假百分比或“预计 8—15 秒”。
- 一次作者动作最多一个 model call；按钮 busy 与后端 input hash／job 锁共同防双击和网络重放。

### 5.2 最小失败分类

不新增数据库字段：Creative Job 使用现有 `output_json.failure_code`，章节任务继续使用 `validation_state`。

| 任务失败码 | 含义 |
| --- | --- |
| `timeout` | 截止时间内没有有效结果 |
| `invalid_output` | 结构不完整或无法解析 |
| `model_mismatch` | requested／actual 不一致 |
| `transport` | Provider 或网络失败 |
| `cancelled` | 作者离开或请求被取消 |

正文长度继续使用既有 `below_target／above_target／meets_target`；草稿 CAS 冲突继续使用 HTTP 409／领域冲突，不塞进模型失败码。前端不得匹配中文错误字符串判断类别。

日志只记录既有 job ID、kind、requested／actual、起止时间、耗时和失败码；不新增工具计数，不打印正文、Prompt、reasoning、密钥、工具参数或私有 session 数据。

### 5.3 其他安全修复

- 建书完成与作品设置共用服务层上传封面校验：data URL、Base64、`image/jpeg` MIME、JPEG 文件签名和既有字节上限。
- 模型输出只进入候选、草稿或 working copy；正式 revision 和故事账本继续需要作者现有显式动作与 CAS。
- 生成期间不持有数据库长事务；失败只留下可诊断 job。

## 6. 两个可独立验收的施工切片

### 切片 A：先修真实性与隐藏调用

关闭新 AI 封面；删除章纲与正文自动重试；素材改为可选；取消正文后的自动同步提示；修正模型职责、超时／长度状态、创作中心统计和章节空态；落地静态 Skill 映射、等待上限、幂等和最小失败码。

切片 A 不改变主页面结构，可先独立上线并回归。

### 切片 B：再压缩完整作者流程

建书压缩为两页；大纲改为单页四模块；建章改为单页章前卡；章纲核心字段与高级约束分层；删除重复正文入口。

切片 B 复用切片 A 的 API 和错误语义，不增加基础设施。

## 8. 验收门禁

### G1：流程与调用数

- 默认建书完整创建成功：**0 次模型调用**。
- AI 模板、AI 取名、任一大纲模块、AI 章纲、AI 正文：每个按钮一次点击最多 **1 次**调用。
- 新 UI 不创建 `chapter_storyline_recommendation` 或 `novel_cover`。
- 不存在自动章纲重试、自动正文重试、自动换模型或正文成功后自动同步。
- 建书为两页；大纲为单页四模块；建章为单页；空正文只有一个 AI 主入口。

### G2：数据安全与恢复

- 任何超时、无效输出、模型不一致、网络失败、取消、长度失败和 CAS 冲突均不改变正式正文、revision 或故事账本。
- 建书草稿单飞保存，切页／关闭／创建前 flush；刷新后恢复字段与单个书名候选选择。
- 大纲候选只进入 OutlineDraft；作者显式应用后才改变正式大纲和角色。
- 空章节可恢复；AI 正文前校验必要输入；候选采用只改变 working copy。
- 上传封面坏 Base64、错误 MIME、非 JPEG 签名和超限内容均被服务端拒绝。

### G3：产品真实性

- 创作中心、作品侧栏、分卷和章节目录章数一致；返回中心后不依赖旧列表缓存。
- GLM、DeepSeek 或 MiniMax 超时都只显示真实任务状态，不出现“正在校准”或虚假百分比。
- 页面明确区分“AI 生成任务模型”和“右侧聊天模型”。
- 只有现有正文被新 working copy 替换时出现一次确认；默认生成没有素材弹窗和通用确认。
- 素材、同步进展、审稿和正式保存都是相互独立的显式动作。

### G5：最小真实运行

发布验收不再切换 DeepSeek、MiniMax、GLM 三个共享 Agent 模型。经用户另行明确授权后，只在隔离样书中使用**当时当前有效模型**：

1. 一次章节章纲任务；
2. 一次 2500 字正文任务。

两次都禁止自动重试，正文候选不建立正式 revision，记录 requested／actual、Skill SHA、输入／输出哈希、耗时和失败码。三模型对比属于独立诊断，只在用户再次明确要求时执行，不作为本计划放行门禁。

浏览器验收覆盖桌面和受影响窄屏，检查两页建书、模块大纲、章前卡滚动、键盘焦点、错误恢复、工作稿状态和三栏宽度；证据进入新的 `docs/开发文档/证据/开书流程轻量优化-YYYY-MM-DD/`。

## 9. 恢复与非目标

恢复：

- 本计划无 schema 变更，代码回退不需要数据库降级。
- 失败 job 和未采用候选不影响正式数据；working copy 继续由现有 revision／恢复机制保护。
- 历史 `novel_cover`、`chapter_storyline_recommendation` 和旧草稿只读兼容，不批量删除。
- 助手改动只调整职责文案和错误上下文注入，不删除聊天历史。

非目标：

- 不建设 AI 图片、短篇、自动连续生成、模型排行榜、动态路由、流式队列、通用工作流引擎或可观测平台。
- 不修改九个 Skill 的写作方法正文，不把计划 22 的候选 Skill 混入本计划。
- 不重做创作中心品牌视觉，不复制 QwenPaw 聊天，不顺带施工角色轨迹、关系图、TTS 或其他专项。
- 不承诺模型更快；只保证没有项目侧隐藏重试、无关上下文和额外阻塞。

## 10. 工期与批准边界

预计有效开发时间仍为 **16—24 小时**：切片 A 5—8 小时，切片 B 8—12 小时，集成、全量回归与浏览器 QA 3—4 小时。该估算不含独立卸载 hook 热修、等待共享文件锁或三模型对比。

轻量化体现在删除步骤和复用现有领域对象，不通过低估测试、恢复或兼容工作来制造短工期。

用户当前只要求继续复查并优化方案。后续明确批准施工后才从 `LFW-0` 开始；任何需要新增 Agent、模型选择器、数据库表、依赖、QwenPaw 私有接口、静默模型回退或自动连续生成的情况，都必须停止并重新裁决。

## 0. 结论先行

现在不继续扩充分类、不扫更多榜、不建设完整拆书页面，也不修改九个正式写作 Skill。只完成下面这一条纵向闭环：

```text
一条已通过拆书门禁的桥段机制
  -> 拆书候选
  -> 作者审阅／修改／拒绝
  -> 私有库桥段资产 v1
  -> 固定绑定一部实验小说
  -> 进入一次章节生成快照
  -> 形成章节候选 A/B
  -> 作者决定保留、修改或淘汰
```

本计划解决的不是“再增加一种故事账本事实”，而是补上研究证据与正式私有资产之间缺失的**候选账本层**。桥段、风格、词汇和奇思仍是创作资产，不进入 `StoryFact`；未批准的拆书候选不得进入小说上下文、向量索引、正式大纲、故事事实或正文。

第一轮只处理 `plot`。写作风格、特色词汇、热梗奇思和分类 Skill 是否继续，必须等本闭环真实跑通后再裁决。

## 1. 当前实现事实

1. 项目已有 `PrivateAssetVersion`、`NovelAssetBinding`、不可变版本、精确版本绑定和 `required / preferred / context_only / prohibited` 使用策略。
2. 私有资产版本已经能保存 `metadata`、`source`、`rights`，但当前主页面和主 API 基本只让作者填写、查看名称与自由文本内容。
3. 当前四类资产在选择器中按同一种“勾选后影响生成”的方式呈现，尚未向作者解释不同类型的作用、来源、适用范围、失败条件、版权边界和具体版本。
4. 当前 Context V4 能载入固定版本，但主路径会把私有素材压平成标题和内容，桥段类型、结构化机制、来源与权利没有形成类型化写作约束。
5. 文档 10 规划的 `text_study_jobs`、`text_study_results`、`text_study_evidence_spans` 和 `creative_asset_provenance` 尚未形成当前产品代码；因此不能把“规格中写过”表述成已经存在的拆书入库流程。
6. 当前工作区还有计划 35／37 及 Context V4、创作服务、工作台等共享文件的未提交施工。本文施工前必须重新核对归属并取得共享锁，不得覆盖现有改动。

## 2. 目标与非目标

### 2.1 唯一目标

用一条现有、合法、已通过 G0—G7 的 `mechanism-candidates.json` 机制候选，证明以下七件事：

1. 来源、证据、权利、适用条件、代价和失效条件不会在入库过程中丢失。
2. 候选与正式私有资产物理隔离，未批准时对任何小说和生成任务不可见。
3. 作者能看懂原研究结论与准备入库内容的差别，并可保存草稿、批准或拒绝。
4. 批准动作幂等地产生一个稳定资产根和一个不可变版本，不重复污染私有库。
5. 小说只绑定作者选择的精确资产版本；后续资产升级不静默改变旧绑定。
6. 章节生成记录本次实际使用的资产版本、哈希和策略，只产生候选，不覆盖正文。
7. 一个同模型、同任务的最小 A/B 能让作者判断该机制是保留、修改还是淘汰，但不据此修改正式 Skill。

### 2.2 明确非目标

- 不建设完整文本拆解任务页、后台分块任务、全稿导入和报告历史。
- 不新增或安装 `genre-guidance`，不修改九个正式写作 Skill，不调整 Agent 模型选择。
- 不为悬疑、言情、玄幻等每个分类复制一套顶层 Skill。
- 不处理 `writing_style / vocabulary / idea`，不批量导入既有拆书结论。
- 不自动扫榜，不自动下载或读取未授权小说，不把榜单热度当作有效性证据。
- 不把来源原句、专名、独特桥段排列、角色组合或作者声音写入项目资产。
- 不自动绑定所有小说，不允许第一轮使用 `required`，不自动写入预设。
- 不新增向量基础设施、不调用真实百炼、不重建现有索引；仅验证未批准候选不会进入任何索引来源。
- 不自动采用章节候选，不修改正式正文、正式大纲、故事设定或 StoryFact。
- 不修改 QwenPaw 上游核心，不提交、不推送。

## 3. 冻结的领域分层

| 层 | 权威内容 | 能否进入写作上下文 | 退出方式 |
| --- | --- | --- | --- |
| 拆书研究证据 | 固定语料版本、主张、证据、反例和机制候选 | 否 | 保留在研究目录 |
| 拆书候选 | 准备入库的抽象机制、来源与作者决定 | 否 | 批准、拒绝或撤回 |
| 私有资产版本 | 作者批准的桥段机制 v1/v2… | 仅绑定后 | 新版本或归档，不原地改写旧版本 |
| 小说资产绑定 | 小说、精确资产版本和使用策略 | 是 | 显式归档／改绑 |
| 生成输入快照 | 本次生成实际使用的精确版本与哈希 | 是，只对该任务 | 永久留作任务证据 |
| 章节候选 | 模型输出 | 否，直至作者采用 | 采用、拒绝或保留历史 |
| 正文 revision | 作者确认后的正式正文 | 是 | 恢复时创建新 revision |

硬规则：任何向右流动都必须显式发生；不存在“拆书完成即进入 Skill”“批准资产即全局启用”或“生成成功即覆盖正文”的捷径。

## 4. 候选账本最小合同

### 4.1 新增候选根

施工时新增 `private_asset_candidates`，第一版只接受 `proposed_asset_type=plot`。候选是可恢复 working copy，批准后的 `PrivateAssetVersion` 才是不可变创作资产。

最小字段如下：

| 字段组 | 字段 | 约束 |
| --- | --- | --- |
| 身份 | `id / candidate_key / proposed_asset_type` | `candidate_key` 由来源、语料版本、run 和机制 ID 规范化计算并唯一 |
| 状态 | `status / version / operation_hash` | `pending_review / approved / rejected / withdrawn`；所有编辑和状态变化使用 CAS |
| 提案 | `title / content / mechanism_json` | `mechanism_json` 使用 `plot-mechanism-candidate/1` |
| 来源 | `provenance_json` | 使用 `deconstruction-provenance/1`，绑定 `source_id / corpus_version / run_id / scope / analysis_profile / method_version / mechanism_id / claim_ids / evidence_ids / source_hash` |
| 权利 | `rights_json` | 使用 `reuse-rights/1`；至少记录处理依据、允许的抽象层级、`verbatim_reuse=false` |
| 风险 | `risk_json` | 原创性风险、相似资产、禁止复制项和人工复核结果 |
| 决策 | `decision_history_json` | 追加保存草稿、批准、拒绝、撤回、重新审阅的时间与理由，不静默抹掉拒绝记录 |
| 产物 | `materialized_asset_id / materialized_asset_version_id` | 只在批准事务成功后写入；同一候选最多对应一个首次入库结果 |
| 时间 | `created_at / updated_at / decided_at` | 服务端生成 |

候选不复用 `PrivateAsset.archived` 冒充状态，也不先创建一个“隐藏私有资产”等待批准，避免它被旧列表、预设、绑定或索引路径误读。

### 4.2 `plot-mechanism-candidate/1`

第一版桥段不保存具体剧情模板，而保存以下变量关系：

- `trigger_conditions`：什么人物、信息、关系或风险状态下才适用；
- `operation`：叙事具体改变哪个变量；
- `observable_state_change`：行动、知识、关系、冲突或章末问题发生什么可观察变化；
- `expected_payoff`：对期待、理解、情绪或继续阅读动力的可能作用，明确标记为推断；
- `cost_tradeoff`：篇幅、可信度、节奏、角色空间或后续债务；
- `failure_conditions`：何时会拖延、重复、突兀、廉价或无效；
- `counterexamples`：拆书中已发现的反例或替代解释；
- `applicable_scope / excluded_scope`：适用与禁止场景，不把悬疑观察写成通用必需规则；
- `originality_guard`：禁止保留的人名、专名、原句、独特事件顺序和角色组合；
- `confidence / suggested_usage_policy`：研究置信度与建议策略。

### 4.3 批准与绑定

1. `approve` 必须在单事务中调用现有私有库领域服务，创建稳定资产根和 `PrivateAssetVersion v1`，再封存候选与产物 ID。
2. `metadata` 保存结构化机制、适用范围、代价、失效条件、原创保护和候选 ID。
3. `source` 保存研究引用、哈希和方法版本，不复制正文片段到创作资产。
4. `rights` 明确 `abstract_mechanism_only=true`、`verbatim_reuse=false` 和处理依据。
5. 重放相同 `operation_key` 返回同一资产和版本；中途失败不得留下半个资产或“已批准但无产物”的候选。
6. 批准后默认仍不绑定小说。作者在下一步选择一部实验小说及精确 v1，第一轮只允许 `preferred` 或 `context_only`，默认 `preferred`。

## 5. API 与导入边界

候选 API 使用现有 PawApp 命名空间，冻结为：

```text
POST  /api/ai-novel-world-2026/private-asset-candidates/import
GET   /api/ai-novel-world-2026/private-asset-candidates
GET   /api/ai-novel-world-2026/private-asset-candidates/{candidate_id}
PATCH /api/ai-novel-world-2026/private-asset-candidates/{candidate_id}
POST  /api/ai-novel-world-2026/private-asset-candidates/{candidate_id}/approve
POST  /api/ai-novel-world-2026/private-asset-candidates/{candidate_id}/reject
POST  /api/ai-novel-world-2026/private-asset-candidates/{candidate_id}/reopen
```

- `import` 只接受规范化候选 envelope、幂等键和可校验的研究引用，不接受任意本地路径、整章原文或 Cookie。
- 第一条候选通过受控脚本 `scripts/import_deconstruction_asset_candidate.py` 从一个已完成运行的机器文件中读取；脚本必须支持 `--dry-run`，不得改写研究运行。
- 导入时重新核对 run 状态、G0—G7 校验结果、机制 ID、哈希和权利范围；缺一项即拒绝。
- `PATCH` 只允许修改准备入库的标题、抽象内容和结构化机制；来源、语料哈希、run、证据 ID 和权利依据只读。
- `approve / reject / reopen` 均要求 `expected_version` 和幂等键。
- 小说绑定继续复用现有 `novel_asset_bindings` API，不创建第二套绑定模型。

## 6. 页面与作者流程

不新增第五种私有库资产类型。只在“桥段配置”内部增加二级入口：

```text
桥段配置
  ├─ 已采用资产
  └─ 拆书候选（数量）
```

候选审阅抽屉分成两列：

- 左侧“研究依据”：来源、run、机制 ID、支持／反证数量、适用边界、权利和原创性风险；只读。
- 右侧“准备入库”：标题、抽象机制、适用／禁止条件、代价、失效条件、原创保护；可编辑并 CAS 保存。

底部动作固定为“保存草稿”“拒绝候选”“批准入库”。拒绝需要可选原因但不删除记录；批准后显示资产 ID、`v1`、内容哈希和“绑定到实验小说”。

绑定和生成前必须显示：

- 资产名称、类型、精确版本和使用策略；
- 本次只影响哪个实验小说／章节；
- “生成会创建新候选，当前正文与历史不会被覆盖”；
- 关闭该绑定或拒绝生成后如何恢复。

桌面与窄屏均需覆盖键盘焦点、标签关联、抽屉滚动、错误态、空态、保存中断和 CAS 冲突。现有“重新生成将放弃当前内容”的误导性文案在本计划影响范围内改为真实的候选／历史语义。

## 7. 类型化写作注入

只有 `approved + active binding + exact asset_version_id` 才能进入 Context V4。第一版桥段 renderer 形成下面的模型约束，而不是一段无类型自由文本：

```text
【桥段机制｜preferred｜资产 v1】
适用条件：...
可执行操作：...
必须产生的可观察变化：...
预期回报（研究推断）：...
代价与取舍：...
失效条件：...
适用／禁止范围：...
原创保护：只迁移变量关系，不复制来源专名、表达、角色组合或事件顺序。
```

上下文优先级保持：作者本轮要求与正式事实 > 连续性和人物知识 > 本书确认约束 > 私有桥段资产。机制与正式事实冲突时跳过并记录诊断，不让素材覆盖故事权威。

`WritingContextSnapshot` 必须保存精确资产版本、内容哈希、策略和选择来源。研究证据 ID、来源书名和正文片段不进入模型提示；它们只供作者审阅和审计。未批准、已拒绝、已撤回、未绑定或跨小说候选在上下文和语义检索中的命中必须为 0。

## 8. 最小 A/B 与退出裁决

### 8.1 冻结实验

- 只使用一部隔离的合成实验小说和一个章节任务，不读取或改写真实用户正文。
- A 为无桥段绑定的基线；B 只增加同一桥段资产 v1，其余正式资料、章前要求、模型、参数和上下文截止点保持一致。
- 记录 requested／effective／actual 可用状态；身份无法比较、调用失败或输入快照漂移时本次 A/B 作废，不挑好看的结果补分。
- 第一轮只做一组作者可读对照，用于决定是否继续，不宣称统计显著或正式写作能力提升。

### 8.2 硬门禁

1. A 与 B 的输入差异只能是目标资产块及其选择证据。
2. 未批准候选、来源原句、专名、独特事件顺序和研究目录路径不得出现在输出。
3. 正式人物、时间、知识、案件规则和章前要求无冲突。
4. B 若使用机制，必须产生合同声明的可观察状态变化，同时表现相应代价；不能只复述资产名称。
5. 生成前后当前 working copy 和正式 revision 哈希不变；只有作者采用才创建新 revision。

### 8.3 作者只做一个决定

作者对 A/B 选择以下一种结果：

- `keep`：该资产保留并允许进入下一轮“写作风格候选”计划；
- `revise`：修改适用条件、操作、代价或失效条件后，创建资产新版本再复测；
- `reject`：归档绑定，候选与失败证据保留，不进入其他小说和 Skill。

单次 `keep` 只证明这条私有资产对这个实验任务有继续研究价值，不足以晋级分类资料或正式 Skill。分类 Skill 仍遵守文档 23 的多书、反例、同模型 A/B 和作者批准门槛。

## 11. 验收矩阵与命令

必须覆盖：

- 相同来源机制重复导入只得到一个候选；不同 payload 使用同一幂等键返回冲突。
- 未批准、已拒绝、已撤回候选在私有资产列表、预设、绑定、Context V4、生成快照和向量来源中的命中均为 0。
- 批准成功恰好创建一个资产根和一个不可变版本；批准重放不重复；任一步失败全部回滚。
- 候选来源字段只读；来源哈希或 G0—G7 状态失效后不能批准。
- 批准资产不含正文片段、专名或研究目录路径；`rights` 明确禁止逐字复用。
- 小说绑定固定 v1；资产发布 v2 后旧绑定和旧 generation snapshot 不变。
- `preferred / context_only` 语义可见且可解释；`required` 在第一版 UI 和 API 均拒绝。
- 生成失败、取消、拒绝 A/B 或关闭页面后，当前正文和正式 revision 哈希不变。
- 禁用或卸载 PawApp 后不残留路由包装、工具或 Skill 改动，QwenPaw 原生功能恢复。

施工后最低命令：

```bash
.venv/bin/python -m pytest tests/private_asset_candidates
.venv/bin/python -m pytest tests/context_v4
.venv/bin/python -m pytest
pnpm --dir frontend test
pnpm --dir frontend typecheck
pnpm --dir frontend build
docker compose config --quiet
.venv/bin/python scripts/package_plugin.py
git diff --check
git status --short
```

数据库迁移只在隔离测试库运行；施工开始时重新发现唯一 Alembic head，不在本文预猜 revision 编号。真实浏览器至少覆盖 1920×1080 和 390×844。真实正文模型调用、长期安装、数据库备份与 Git 操作都需要到达相应 Gate 并取得当次明确授权。

## 12. 失败恢复与后续顺序

- 导入失败：研究运行保持只读，候选不创建；修正 envelope 后使用新操作重试。
- 审阅中断：保留最后成功 CAS 草稿和本地未同步提示，不生成私有资产。
- 批准失败：事务回滚，候选仍为 `pending_review`，可幂等重试。
- 绑定失败：已批准资产仍安全存在但不进入任何小说上下文。
- A/B 失败：保留输入、输出和失败原因，解除实验绑定即可回到基线；正文不需要恢复。
- 候选效果不佳：作者选择 `revise` 或 `reject`，不修改 Skill，也不继续增加样本掩盖失败。

只有本计划通过 `DA38-G5-EXIT`，下一份计划才允许依次考虑：

1. 写作风格候选；
2. 作者自有文本的特色词汇；
3. 带日期、过期和风险字段的热梗／奇思；
4. 多书分类资料候选；
5. 跨分类且通过同模型 A/B 后的正式 Skill 窄更新。

在此之前，唯一下一步是批准或修改本文，不再同时推进其他拆书产品化方向。

# 阶段 7：章节候选与情报提案闭环

执行日期：2026-08-23（Asia/Shanghai）。

状态：**PawApp 0.3.0 已实现并部署首个 AI 写作纵向闭环；模型只能生成候选，作者显式采用后才建立正式 revision，情报逐项确认后才进入故事账本。**

## 1. 本轮范围

```text
章节任务书
  -> QwenPaw 正文生成任务
  -> 不可变输入快照
  -> AI 候选稿
  -> Diff 复核
  -> 采用整稿并建立正式 revision / 拒绝
  -> 对当前正式 revision 提取情报提案
  -> 作者逐项勾选或拒绝
  -> 所选项进入故事账本
```

本轮没有赋予 Agent 正文写工具。模型调用由 PawApp UI 发起，结果先进入候选表；正式采用仍是作者命令。

## 2. 新增权威边界

- `chapter_briefs`：保存目标字数、本章期望、章纲、禁区，以及 `required / allowed / context_only / forbidden` 四类角色约束；使用版本 CAS。
- `chapter_generation_jobs`：保存生成状态、输入哈希、正文基线、任务书版本和不可变上下文快照。
- `candidate_revisions`：保存生成基线、候选正文、哈希和采用状态；候选不会出现在 working copy 或正式 revision 中。
- `intelligence_proposals` 与 `intelligence_proposal_items`：绑定精确章节 revision；人工改稿或建立新版本后，旧提案变为 `superseded`。
- `story_facts`：本轮作为故事账本的统一落点；只有明确选中的提案项能新增正式事实，并保留来源 revision、证据句和原模型建议。

采用候选时同时校验 `draft_version` 和生成基线正文哈希。模型运行期间作者继续编辑，采用返回 409，不覆盖新稿。

## 3. UI

章节编辑器新增五个入口：

1. `章节任务书`：编辑生成控制面。
2. `生成候选稿`：调用当前 `ai-novel-writer` Agent；正文保持不变。
3. `候选历史`：查看成功、失败、已采用和已拒绝候选，以及统一 Diff。
4. `章节情报`：从当前正式 revision 提取、逐项选择或拒绝。
5. `故事账本`：查看 active 与来源已过期的故事事实。

弹窗限制在当前窗口内并提供内部滚动；任务书输入具有可访问名称。当前 Diff 支持整稿采用，分块采用延后。

## 5. 当前限制

- 生成和情报提取当前使用同步 HTTP 请求；后台队列、断线恢复和流式候选属于下一轮。
- Diff 目前只能预览后采用整稿，尚未支持逐段采用与手工合并。
- 故事账本先使用通用 `story_facts`；角色、关系、线路和伏笔的类型化实体与追加式进展尚未全部落表。
- 模型提取质量仍需作者复核；本轮真实短文提取出 10 条候选，说明逐项确认不可取消。

## 6. 回退

- 禁用或卸载 PawApp 不影响 PostgreSQL 权威正文。
- 数据库迁移 `20260823_0002` 只新增五张工作流表；回退会删除这些新增表，不触碰原有小说、working copy 和 revisions。
- 拒绝候选和取消情报复核均不会修改正文或故事账本。

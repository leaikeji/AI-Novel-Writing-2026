## 0. 结论先行

扫榜和拆书的最终验收不能是“保存了多少报告”，而应是：在不读取来源作品、不复刻作者表达的全新写作任务上，同一个 AI 模型因为调用了一条经过验证的能力候选，稳定做出更好的叙事决策。

本计划把研究链冻结为：

```text
扫榜市场信号
  → 合法样本组合
  → 证据化拆书运行
  → 单书知识包
  → 跨书复核与反例
  → 写作能力候选
  → 同模型、同参数、同题 A/B
  → 作者批准
  → 现有任务 Skill 的候选版本
  → 真实写作反馈与退化监测
```

必须分开五种状态：

1. `run-completed`：拆书运行通过 G0—G7；
2. `knowledge-ready`：单书知识包通过 H0—H2；
3. `candidate-ready`：多书、反例和替代解释通过 H3；
4. `writing-gain-supported`：来源无关 A/B 通过 H4；
5. `skill-promoted`：作者批准，目标 Skill 候选通过契约、回归、安装和回退门禁。

前一状态不能冒充后一状态。补齐图谱和有用内容会提高可检索性，但只有第四、第五状态才支持“AI 写作能力提高”的结论。

## 2. 外部方法复核与采用边界

本轮只学习公开 GitHub 项目的方法，不引入运行时依赖或复制实现：

- [BookNLP](https://github.com/booknlp/booknlp)：实体、别名、引语说话人、事件与文本位置；采用稳定对象和位置思想，不直接采用其英语模型。
- [ChapterWise Plugins](https://github.com/ansonphong/chapterwise-plugins)：不可变来源、分析历史、单书 Atlas 和增量派生；采用“运行权威与派生视图分开”。
- [StoryWeave](https://github.com/Shashank-ssls/StoryWeave)：事实／关系的揭示章节和证据来源；采用 reveal／knowledge-state 思想，不引入图数据库。
- [Calabash](https://github.com/Guesswhat-Studio/Calabash)：关系、线索、推理的怀疑／确认／推翻状态；采用生命周期，不复制 UI。
- [LUMEN](https://github.com/john-paul-ruf/novel-engine/blob/main/agents/LUMEN.md) 与 [APODICTIC](https://github.com/anotherpanacea-eng/apodictic)：配角功能、场景必要性、反向大纲、读者体验和揭示经济；只转成原创研究字段。

仓库成熟度和许可证各异，以上只能作为方法对照，不是需求权威。任何明确要求保留原作结构进行改写、模仿作者声音或批量获取未授权正文的路线继续排除。

事实标签：仓库链接与公开能力说明属于“已核实事实”；把稳定对象、揭示状态和读者体验视图引入本库属于“技术推断／项目建议”；若未来要复制代码、安装依赖或形成产品实现，仍须重新核验当时提交、许可证、语言适配和安全边界，当前没有完成这一步。

## 4. 单书知识包合同

研究库新增 `deconstruction-knowledge-package/1`，保存于：

```text
05-单书拆解/<source-id>/derived/<run-id>/<derived-id>/
├── manifest.json
├── book-atlas.json
├── reader-experience.json
├── useful-content.json
└── report.md
```

### 4.1 不可变与范围

- 每个知识包精确绑定一个已完成运行、任务哈希、运行方法版本、派生器版本和产物哈希。
- 历史0.5.0运行可以生成0.6.0知识包，但不修改历史运行；修正派生结果创建新 `derived_id`。
- `opening`、`first-arc`、`range-study` 和抽样 `whole-structure` 都必须在包内声明范围受限；只有全章覆盖的 `full-text` 才能使用完整单书口径。
- 运行 0 错误只证明来源运行有效；派生包仍要独立通过 H0—H2。

### 4.2 三个机器视图

`book-atlas.json`：

- 稳定实体 ID、别名候选、人物／地点／组织／物件／能力／概念；
- 关系的建立、变化、确认和推翻；
- 事件参与者、原因、行动、状态变化、叙事顺序、可得时的故事时间与可靠性；
- 事实／解释的首次揭示、人物知识、读者知识和后续重解释。

`reader-experience.json`：

- 承诺、读者问题、张力、信息、回报、代价和余波；
- 场景功能、配角／对手功能、主题母题、重复和新鲜度风险；
- 动作、对白、说明、内省的相对配置及其场景作用。

`useful-content.json`：

- 桥段机制、人物功能、关系模式、设定规则、揭示方式、情绪回报、场景模式、语言机制和失败模式；
- 每条绑定写作阶段、现有九个 `target_skill_ids`、适用／禁止条件、变体、代价、失效、原创守卫与成熟度。

所有条目引用原运行存在的 `claim_id`／`evidence_id`；无证据则保留不确定或不登记。来源书名、作者、研究路径和原文片段不进入写作提示。

## 5. 能力候选合同

写作能力候选使用 `writing-capability-candidate/1`，进入研究库 `07-写作规律候选`。最低字段：

1. `candidate_id`、版本、单书／分类／通用范围和精确来源集合；
2. `target_skill_ids` 和写作阶段；
3. 触发条件、禁止条件；
4. 可执行步骤；
5. 必须产生的可观察状态变化；
6. 待验证的读者作用；
7. 代价、失效、反例和替代解释；
8. 原创性守卫；
9. 冻结 A/B、评分项和停止条件；
10. `candidate_status=single_book_observation|cross_book_candidate|evaluation_ready|evaluated|promoted|rejected`，以及独立的 `writing_gain_status=not_evaluated|evaluating|supported|revise|rejected`；不得用“已评测”冒充“已进入 Skill”。

候选按它改变的决策进入现有任务 Skill：

| 能力内容 | 首要目标 Skill | 可能辅助 |
| --- | --- | --- |
| 市场承诺、题材方向 | `novel-direction` | 未来获批的分类资料 |
| 世界规则、长期承诺 | `story-foundation` | `continuity-check` |
| 主角、配角、关系功能 | `character-craft` | `dialogue-craft` |
| 章节因果、揭示、回报排布 | `chapter-outline` | `scene-craft` |
| 单场行动链、策略、状态变化 | `scene-craft` | `dialogue-craft` |
| 潜台词、权力和关系变化 | `dialogue-craft` | `character-craft` |
| 成文执行、信息密度和节奏 | `prose-writing` | `scene-craft` |
| 时间、知识、物件、伏笔和揭示一致性 | `continuity-check` | 无 |
| 读者体验、重复、主题、语言和发展性诊断 | `style-review` | `continuity-check` |

不得为每本书、每位作者或每条机制新建顶层 Skill；一个请求仍由一个主要任务 Skill 收口。

## 6. 写作评测合同

评测使用 `writing-capability-eval/1`，保存到研究库 `08-写作评测`。

### 6.1 唯一变量

- A 与 B 的模型、Provider、参数、题面、正式上下文、目标 Skill 版本、篇幅和尝试规则完全一致。
- A 不加载候选，B 只加载精确候选版本；不能同时修改其他 Skill 或加额外提示补偿。
- 题目必须与来源作品无关，使用项目合成、作者自有或明确授权内容。

### 6.2 两层门禁

先检查事实、人物知识、时间、物件、规则、输出纯净度、原创性、必须／不得出现的状态变化和输入哈希。任一硬门禁失败，不能靠主观高分抵消。

再隐藏 A/B 和实现说明，评价吸引力、人物可信度、因果／场景推进、语言自然度、类型满足和可继续修改性，并增加候选专项指标。

### 6.3 晋级阈值

- 私有资产小试只做 `keep / revise / reject`，一次 `keep` 不宣称分类或通用能力提升。
- 分类／通用候选沿用计划22／23：匿名偏好胜率目标不低于65%，专项平均分相对基线提高至少15%，通用维度无明显退化，失败／平局／退化全部保留。
- 模型身份不可比较、输入漂移或一侧失败时，本对比不计入胜率；不更换模型或删除失败样本补分。

## 7. 写作装载与反馈

### 7.1 装载规则

- 先确定本轮交付和主要任务 Skill，再按分类、故事状态和触发条件检索。
- 默认只装载最相关的少量已验证能力卡；灵感卡是可选参考，不能覆盖能力卡或正式事实。
- 优先级：作者本轮要求与权威事实 > 人物知识与连续性 > 本书确认约束 > 已验证能力 > 可选灵感。
- 冲突、条件不满足或代价不可接受时跳过候选并记录原因；不得机械执行。

### 7.2 反馈

实际写作只记录候选版本、任务、输入快照和 `helpful / neutral / harmful`。反馈进入评测层：

- 有效：缩小并确认适用边界，不自动扩大为通用；
- 无变化：检查候选冗余或题目未触发；
- 有害：记录具体退化，修订或否决；
- 新模型、新 Skill 或新题材：创建新实验，不让旧结论永久外推。

## 12. 失败恢复与退出判断

- 文档或 Skill 合同失败：只修候选源，不生成新运行，不触碰历史完成运行。
- 方法升级后，历史 `completed`／`failed` 运行静默保留原版本／指纹；活动运行若版本或指纹不是当前值则停止恢复并新建运行。本轮已核对现有5个运行均为 `completed`。
- 知识包失败：删除未发布的临时目录或创建新 `derived_id`；已发布包不覆盖，来源运行无需恢复。
- 跨书证据不足：保持单书观察或灵感，不通过继续扫更多热门书掩盖反例。
- A/B失败：保留全部输入输出，`revise` 或 `reject`；正式 Skill 不变。
- Skill候选退化：恢复最后一个通过门禁的包；不删除 QwenPaw／PostgreSQL 数据卷，不改正文。

`DW41-G1-SKILL` 通过后，本轮只能结论为“拆书流程和开发文档已优化，能力闭环合同可执行”；只有 G4、G5 通过后，才允许写“拆书候选提高了 AI 写作能力”。

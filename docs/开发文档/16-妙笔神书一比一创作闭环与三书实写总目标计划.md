# 妙笔神书一比一创作闭环与三书实写总目标计划

状态：执行中
制定日期：2026-08-23
唯一验收模型：MiniMax M3
目标环境：QwenPaw 2.1.0 内的 AI小说世界2026，桌面端 1920×1080 与 2560×1440

## 1. 总目标

在现有项目中筛选并一比一还原妙笔神书所有与真实长篇写作直接相关的功能、UI、交互和步骤，完整打通：

> 创建作品 → 故事设定 → 大纲 → 角色/故事线/伏笔 → 卷章规划 → 章节任务 → 私有库 → 正文生成与编辑 → 情报/故事账本 → 版本历史 → 导出 → 下一章

所选功能不得只做相似外观：页面结构、尺寸、排版、字体、颜色、控件、弹窗、文案顺序、状态变化、输入校验、前后端数据行为均须按已冻结的妙笔神书参考状态还原。会员、充值、邀请、活动、发现、社交、签约、收入等与个人真实写作无关的模块不进入范围。

## 2. 不可降低的完成标准

1. 只测试桌面端：1920×1080 与 2560×1440；本目标不包含手机端。
2. 所选功能必须同时满足视觉一比一、步骤一比一、行为一比一，不能只摆静态 UI。
3. 所有 AI 环节固定使用 MiniMax M3，包括建书辅助、大纲、章纲、正文重写和情报提取。
4. 每次生成记录实际模型标识、输入快照、目标字数、输出字数和结果状态，验收时可追溯。
5. 完成后通过用户可见界面新建三本真实小说；禁止数据库直接灌入、测试 fixture 或“测试/示例/演示”命名。
6. 每本小说为 1 卷 10 章，共 30 章；每章正文可见字数必须 `>= 3000`。
7. 字数口径：排除章节标题、Markdown 标记、空白和系统元数据后的正文可见字符数；UI 计数与独立验收计数必须一致。
8. 任一章节低于 3000 字，状态不得成为“已完成”，必须使用 MiniMax M3 重新生成整章，直到达标。
9. 章节不得用重复段落、系统说明、提示词残留或无意义堆字凑数；还须通过人物、时间、地点、因果和伏笔连续性检查。
10. 三本书都必须验证关闭重开、自动保存、正式版本、历史恢复、情报入账、跨章上下文、导出和重新导入核对。
11. 所有实现和验收问题全部解决后才能把目标标记为完成；完成 29 章、只有两本书通过或仍有 P0/P1/P2 视觉问题都不算完成。

## 3. 一比一还原范围

### 3.1 纳入

- 创作中心中与作品创作直接相关的作品列表、作品卡和入口。
- 长篇/短篇前置选择中本目标需要的长篇路径。
- 长篇六步建书：受众、思路、模板、命名、封面、完成。
- 私有库：桥段、写作风格、特色词汇、热梗奇思，以及条目维护和生成选择。
- 五步大纲：目标章节数、故事背景、角色、主要情节、亮点与简介。
- 工作台：章节、大纲、角色、线索、设定。
- 卷章管理：创建、编辑、删除、排序、跨卷移动、真实统计和导出。
- 六步章节创建：故事线、角色、伏笔、预期情节、目标字数与章纲、最终确认。
- “我已有正文”的手写旁路。
- 正文生成前私有库选择、生成进度、编辑器、保存、修改章纲、情报、历史。
- 与正文一致的角色、关系、故事线、伏笔进展和故事账本。
- 连续写作所必需的上一章、下一章、保存并新建下一章、搜索和导出。

### 3.2 排除

- 会员、VIP、字包、充值、价格和商业计量。
- 邀请、活动、新闻、二维码、发现中心和公开素材市场。
- 投稿、签约、收入、社交、社区和排行榜。
- 只凭书名/作者推断整本书的拆书功能。
- 缺乏可核验依据的 AI 写作比例或单一总分审稿。
- 与写作无关的个人中心和运营后台按钮。
- 妙笔神书商标、品牌标志和运营宣传资产。

## 4. 执行阶段

### 阶段 A：冻结参考真相与验收矩阵

1. 在当前登录态逐页、逐状态采集纳入范围的页面。
2. 每个页面采集 1920×1080 与 2560×1440 状态；不做手机端。
3. 记录 DOM、控件名称、字体、颜色、间距、圆角、阴影、图标、弹窗尺寸、滚动方式和状态转换。
4. 采集默认、填写、校验失败、加载、成功、空状态、历史状态和主要交互状态。
5. 给每个参考状态分配稳定编号，建立“源截图 → 本地路由 → 组件 → API → 验收用例”映射。
6. 参考状态未采齐的功能不得开始编码，避免凭记忆仿制。

退出条件：纳入范围的所有页面与核心状态都有源截图和状态说明。

### 阶段 B：清理并冻结当前工程基线

1. 复核当前 5 个未提交文件，确认属于上一轮章节生成与 UI 调整。
2. 运行前端测试、类型检查、生产构建、后端单元测试和数据库集成测试。
3. 清除项目中的演示卷、演示章节和跨小说静态回退数据。
4. 修复当前小说与大纲、角色、线索、设定、AI 会话之间的数据隔离。
5. 形成独立 Git 检查点，再开始大规模新功能。

退出条件：工作树基线清楚；全部非外部依赖测试通过；数据库集成测试不再被跳过。

### 阶段 C：补齐领域模型、迁移与 API

按 UI 流程的真实状态机建设：

- 建书草稿与六步状态。
- 私有资产、资产版本、组合预设和生成输入快照。
- 大纲生成草稿、五阶段内容和最终提交。
- 角色、关系、故事线、伏笔及伏笔进展。
- 卷章排序、移动和统计。
- 章节六步规划与版本。
- 生成任务、MiniMax M3 模型记录、输出字数与失败原因。
- 正文、正式版本、情报提案、故事账本来源和恢复影响。
- 导出任务和可核验的卷章结构。

所有修改命令都必须有小说作用域、幂等键或版本条件，不能再用前端演示数据补页面。

退出条件：领域/集成测试证明每个状态可创建、刷新恢复、修改和隔离。

### 阶段 D：一比一还原创作中心、私有库与建书

1. 还原创作中心和作品卡。
2. 还原私有库四类资产的列表、编辑、空状态和生成选择。
3. 还原长篇六步建书全部页面、校验、前进、后退和完成状态。
4. 页面只能显示纳入范围的写作入口，不复制运营按钮。
5. 每完成一个状态即做同尺寸源图/实现图并排比较，P0/P1/P2 未清零不得进入下一组页面。

退出条件：六步建书可真实创建一本结构完整、无演示数据污染的小说。

### 阶段 E：一比一还原大纲与作品工作台

1. 还原五步大纲生成和最终确认。
2. 还原章节、大纲、角色、线索、设定五个模块。
3. 打通角色 CRUD、关系、故事线、伏笔时间线和正文事实来源。
4. 打通卷章创建、编辑、删除、排序和跨卷移动。
5. 处理所有空、加载、失败、冲突和无内容状态。

退出条件：从新书可完整建立故事资料，并在关闭重开后保持一致。

### 阶段 F：一比一还原章节任务与正文写作闭环

1. 还原六步章节创建及“我已有正文”旁路。
2. 还原正文生成前私有库选择和生成进度状态。
3. 还原正文编辑、修改章纲、重新生成、情报和历史入口。
4. 保留现有自动保存、统一版本和逐项情报的可靠实现，但不得改变参考流程的可见顺序与状态。
5. 增加上一章、下一章、保存并新建下一章、全文搜索和带卷结构导出。
6. 打通“正文 → 情报提案 → 作者确认 → 故事账本 → 下一章上下文”。

退出条件：一章能够从规划到正文、入账、恢复、导出并自然进入下一章。

### 阶段 G：MiniMax M3 与 3000 字硬门槛

1. 验收前确认宿主当前激活模型为 MiniMax M3。
2. 每次 AI 调用把实际模型标识写入生成记录；模型不符则该次结果作废。
3. 正文目标设置为足以稳定超过 3000 字的区间，但最终以实际正文计数为准。
4. 输出不足 3000 字时归档失败尝试并重新生成整章，不以追加空话补足。
5. 分离正文和模型说明；技术尾注、检查胶囊和提示词不得写入正文。
6. 对重复段落、角色越权、时间矛盾、未授权新设定和伏笔冲突做自动检查与人工复核。

退出条件：连续生成多章时，模型身份、字数和正文纯净度均可核验。

### 阶段 H：自动化、功能与视觉总验收

1. 后端单元和 PostgreSQL 集成测试全部通过。
2. 前端单元测试、类型检查和生产构建全部通过。
3. 使用真实界面完成建书、大纲、章节、生成、保存、恢复、情报和导出 E2E。
4. 1920×1080 和 2560×1440 下，将源截图与实现截图放进同一对比画面。
5. 逐项检查字体、字号、行高、间距、尺寸、颜色、图标、文案、滚动和交互状态。
6. 所有 P0/P1/P2 问题必须修复并重新截图复核；最终 `design-qa.md` 必须为 `final result: passed`。
7. 验证三本书之间无角色、线索、大纲、章节、AI 上下文和缓存串写。

退出条件：技术测试和视觉阻断项全部清零。

### 阶段 I：三本真实小说创作验收

三本书暂定为：

1. 《风从一九八八的操场吹来》：年代重生校园言情。
2. 《烬海藏锋》：东方玄幻冒险。
3. 《雾港回声》：近未来悬疑推理。

每一本都必须通过同样的真实创作流程：

1. 从创作中心通过六步向导创建。
2. 完成故事背景、角色、主要情节、亮点简介和私有库资料。
3. 创建 1 卷 10 章。
4. 每章完成六步章节规划。
5. 只用 MiniMax M3 生成正文。
6. 每章独立核验 `>= 3000` 字，不足即整章重写。
7. 每章保存正式版本、提取情报、确认入账，再进入下一章。
8. 每本书完成后关闭重开，核对卷章、字数、角色、线索、伏笔和历史。
9. 导出整书，核对卷名、章名、顺序和正文总量。

最低成品规模：3 本、3 卷、30 章、90000 个以上合格正文可见字符。

### 阶段 J：最终回归与交付

1. 对三本书执行跨书隔离、刷新、重启、历史恢复和导出回归。
2. 核对 30 章全部达到字数门槛且无系统文本污染。
3. 核对 MiniMax M3 调用记录完整。
4. 复跑全部自动化测试与双分辨率视觉 QA。
5. 输出功能对照、视觉对照、三书统计、遗留 P3 和 Git 提交记录。

只有上述内容全部通过，才能把总目标标记为完成。

## 5. 计划复查结论

### 5.1 当前工程事实

- 前端测试：5 项通过。
- TypeScript 类型检查：通过。
- Vite 生产构建：通过。
- 后端单元测试：13 项通过、6 项数据库集成测试因环境未连接而跳过。
- 当前有 5 个未提交文件，属于上一轮章节生成、编辑器和样式调整，必须先形成基线检查点。
- 现有领域层已经具备 Novel、Volume、Document、Revision、ChapterBrief、Generation、IntelligenceProposal 和 StoryFact 等基础。
- 仍缺建书草稿、私有资产、大纲阶段草稿、正式角色/关系/故事线/伏笔、完整卷章命令和导出等实体，因此先补领域模型再铺完整 UI 是必要顺序。
- 既有记录证明 MiniMax M3 已能在 QwenPaw 中工作，但长正文存在超长、设定漂移和 Skill 遵循波动，因此必须加入模型指纹、字数门槛和连续性检查，不能只靠提示词。

### 5.2 顺序复核

原先“先把 UI 全画完再接功能”的顺序不适合本目标，因为本次要求 UI、步骤和真实功能一比一；如果没有状态模型，六步建书、五步大纲和六步章节向导只能成为空壳。修正后的顺序为：

> 冻结参考 → 清洁基线 → 领域/API → 分组一比一 UI → MiniMax M3 硬门槛 → 双分辨率 QA → 三本真实写书 → 最终回归

这个顺序既能保持视觉忠实，也能避免再次出现可点击但无行为、演示数据串书和页面状态无法恢复的问题。

### 5.3 主要风险与对应门槛

| 风险 | 对应门槛 |
| --- | --- |
| 参考站更新导致视觉漂移 | 开工前冻结带编号的截图、DOM 和状态证据 |
| 先做 UI 导致后端状态不足 | 领域/API 阶段先于完整 UI 接入 |
| MiniMax M3 输出不足 3000 字 | 字数硬门槛，不足整章重写 |
| 模型加入系统说明或重复凑字 | 正文清洗、重复检查和人工复核 |
| 三本书之间串数据 | 所有查询绑定 novel_id，三书交叉回归 |
| 30 章任务中途丢失进度 | 每章保存正式版本、情报和验收记录 |
| 一比一只停留在截图相似 | 同状态视觉对比加真实 E2E，P0/P1/P2 必须清零 |

## 6. 目标完成判定

以下条件必须同时为真：

- 纳入范围的功能、UI、步骤和行为全部通过一比一验收。
- 所有自动化、数据库集成、E2E 和双分辨率视觉 QA 通过。
- 三本不同题材真实小说全部存在且可重新打开。
- 每本恰有验收用的一卷十章结构，30 章正文全部不少于 3000 字。
- 30 章全部由 MiniMax M3 完成并有可核验记录。
- 版本、情报、故事账本、跨章上下文和导出全部通过。
- `design-qa.md` 最终结果为 `passed`，不存在未解决的 P0/P1/P2。

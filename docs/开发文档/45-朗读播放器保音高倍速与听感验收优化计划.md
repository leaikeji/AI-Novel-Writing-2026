## 0. 结论先行

当前倍速播放的主实现不合格，根因已可由源码和浏览器标准直接证明：

1. `SegmentPlaybackQueue` 正常情况下优先创建 Web Audio 驱动；
2. `WebAudioPlaybackDriver` 直接修改 `AudioBufferSourceNode.playbackRate`；
3. `AudioBufferSourceNode` 只重采样，不做音高校正，因此加速会同时抬高音高；
4. 现有双 `<audio>` 回退驱动反而具备浏览器原生保音高能力，却只在 Web Audio 不可用或解码失败时启用；
5. 现有验收只证明倍速值能传递、控件能切换、偏好能保存，没有证明加速后的音高和听感正确。

首版修复冻结为：

- 把显式启用 `preservesPitch=true` 的双 `HTMLAudioElement` 改为唯一正式播放后端；
- 保留双槽预加载、Manifest 租约、pending gap、跳播、暂停／恢复、进度和音量语义；
- 删除不能保音高的 `AudioBufferSourceNode` 产品播放路径，不再把它作为倍速回退；
- 不重新合成音频，不引入第三方 DSP；
- 用“真实 Chromium 正／负频率探针＋真实章节作者听检”取代“选中了 `1.5×` 就算通过”的口径。

本计划在“倍速音高与听感”范围内取代计划 18／33／35／40 中过宽的倍速 PASS 表述。历史证据原文不改写，其他 TTS 生成、绑定、跳播、恢复和布局结论也不因本缺陷自动失效。

## 1. 当前实现事实与验收漏洞

### 1.1 已核实事实

- 计划制定时当前分支为 `main`，`HEAD=4cb0d47ae01bf1050f0798aa27d734030c44b849`；施工开始时必须重新冻结。
- `frontend/src/narration/segment-playback-queue.ts` 的 `selectInitialDriver()` 优先返回 `createWebAudioPlaybackDriver()`；当前 QwenPaw Chromium 具备 `AudioContext`，所以这是正常产品路径。
- Web Audio 驱动在初始播放和播放中切换倍速时写入 `source.playbackRate`，不含 time-stretch、phase vocoder、WSOLA 或其他保音高处理。

- TypeScript 5.8.3 的 DOM 类型已包含 `HTMLMediaElement.preservesPitch: boolean`；当前目标是 QwenPaw 2.1 现行 Chromium shell，无需引入历史私有前缀。
- `playback_rate` 是播放偏好，范围为 `0.5..3.0`，不进入 Edition 或 render fingerprint；本修复不需要重合成、迁移或更改旧 Edition。

## 2. 目标与非目标

### 2.1 本轮目标

- 所有对用户暴露的 `0.5×..3.0×` 均走浏览器保音高路径，不再出现加速变尖或减速变低沉。
- 倍速切换立即生效，不重合成、不重建 Edition、不回到句首、不覆盖进度或音量。
- 保留 3–5 段媒体预取、双槽预加载、ready window、pending／failed gap、latest-wins、Range／ETag 和播放租约。
- 专项验收播放中 `1×→1.5×→2×→1×`，确保 `currentTime`、句段 ordinal 和保存 offset 不倒退或跳变。
- 增加可区分“重采样变调”和“保音高变速”的真实 Chromium 探针。
- 使用已授权的现有本地章节音频进行作者听检；没有作者结论时保持 `HOLD_AUTHOR_LISTENING`。
- 安全删除已被保音高实现完全取代的 Web Audio 驱动、工厂、切换分支和无独立价值的测试假件。

### 2.2 非目标

- 不修改 MOSS-TTS-Nano、VoiceGenerator、音色绑定、模型采样参数、停顿或发音规则。
- 不增加服务端离线倍速版、多份速率音频、新媒体表或数据库迁移。
- 不引入 SoundTouch、Rubber Band、WASM phase vocoder 或其他新运行时依赖。原生能力若在 `PITCH45-G0` 失败，则停止并重新裁决。
- 不修改 QwenPaw 上游核心、宿主媒体组件或私有内部接口。
- 不修改音量 UI、播放器布局、Edition 选择、字幕跟随或人物声音页。
- 不逆向工程或复制番茄播放器、私有算法、素材、文案或接口；番茄听感只是“加速不应变尖”的产品基准。
- 不借本计划顺带修复其他 TTS、人物、Embedding、关系网或卷章功能。

## 3. 冻结产品与播放契约

### 3.1 用户可见契约

- 倍速是“改变阅读速度、保留原音高”，不是改变音调。
- 现有 11 个速率选项暂时保留，但每个暴露速率都必须通过客观保音高探针。
- 真人听检将“音高／音色身份”和“高倍速可懂度”分开记录。若 `2.25×..3×` 不变尖但仍有不可接受的机械音或漏听，进入 `HOLD_RATE_RANGE_DECISION`，由用户决定缩小上限还是另立 DSP 方案。
- 不增加“保留音高”开关；这是默认质量契约，不应让作者自行修复。

### 3.2 唯一正式媒体后端

将 `DualAudioPlaybackDriver` 收敛为 `MediaElementPlaybackDriver`：

- 仍使用两个 `HTMLAudioElement` 交替预加载；
- 创建后、装载新 `src` 后以及每次播放／切换倍速前均显式保证 `element.preservesPitch === true`；
- `playbackRate`、`volume`、`currentTime`、metadata、ended、error 和对象 URL 生命周期由该驱动唯一管理；
- 音量只使用 `<audio>.volume`，不再存在同一播放链的 `GainNode` 二次增益；
- 内部诊断后端名统一为 `media-element`，不存入 HTTP、数据库或任何权威记录；
- QwenPaw Chromium 若缺少标准 `preservesPitch`，播放就绪门禁返回 `PLAYBACK_UNAVAILABLE`，不静默退回变调 Web Audio。

`WebAudioPlaybackDriver`、`createWebAudioPlaybackDriver()`、Web Audio 优先选择和 decode 失败后切换双 audio 的分支，在 G0 证明媒体元素主路径可用后删除。Web Audio 可继续用于验收端的只读频谱测量，但不再承担产品播放。

### 3.3 倍速、时钟与进度

- `currentTime` 始终是原始媒体时间轴，保存的 `offset_ms` 继续是句段媒体 offset。
- `setRate()` 同时更新正在播放和已预加载的两个元素，不停止、不重建当前句段、不额外触发 `segment-start`。
- `gap_after_ms / rate` 的现有逻辑保留，但必须验证无额外空白、重播或吞字。
- 倍速偏好的即时生效、settings CAS、progress fallback 和 `0.5..3.0` 保持现有公共契约。
- 任何失败都不改写音频、Edition、Manifest、正文、音色绑定或历史进度。

## 4. 客观保音高与听感门禁

### 4.1 真实 Chromium 合成频率探针

新增与小说、模型和媒体库完全隔离的本地探针：

1. 在内存中生成 `220 Hz` 和 `440 Hz` 的短 PCM WAV 正弦波；
2. 在固定 Edge／QwenPaw Chromium 用 `HTMLAudioElement` 播放，用 `MediaElementAudioSourceNode + AnalyserNode` 只读采集实际输出频谱；
3. 先运行 `preservesPitch=false` 负对照，`1.5×`／`2×` 主峰应趋近基频乘以倍速，证明探针真能发现变调；
4. 再运行 `preservesPitch=true` 正向样本，覆盖全部 11 个暴露速率；
5. 记录浏览器版本、属性值、目标频率、实测主峰、墙钟时长、`waiting/stalled/error` 计数和控制台错误；只保存脱敏 JSON，不保存音频。

通过阈值：

- 正向样本实测主峰与 `1×` 基线相对误差不超过 `±3%`；
- 负对照的频率比必须与正向样本明确分离，否则探针无效；
- 播放时长比与 `1 / rate` 的相对误差不超过 `10%`；
- 本地 Blob 就绪后 `waiting`、`stalled`、`error` 均为 0，控制台无 error／warning。

该探针只证明当前浏览器能保音高；产品是否真走该路径，还必须由代码测试和真实听检共同证明。

### 4.2 真实章节作者听检

使用作者自有且已生成的本地 Edition，至少选旁白、一个偏低男声和一个偏高女声的句段。每个样本验收：

- `1× → 1.25× → 1.5× → 1.75× → 2×`；
- `2× → 2.5× → 3×`；
- 播放中 `1× → 1.5× → 2× → 1×`；
- 上一句／下一句、暂停／恢复、跳播和跨角色连续播放。

逐速率记录：是否变尖／变低、是否保持角色声音身份、清晰度、机械音／抖动／回声、漏字／重复、接缝和总体 `PASS/FAIL`。自动化不得代替作者主观结论。

## 5. 公共契约、数据与安全边界

- HTTP API、Manifest v2、Edition、media asset、Range／ETag、进度 CAS、作品 settings 和 `playback_rate` wire 字段不变。
- `SegmentPlaybackBackendKind` 只是前端内部诊断契约；收敛为 `media-element` 不需要迁移。
- 不增加前端或 Python 运行时依赖；频率探针复用现有固定 Node／`playwright-core` 与系统 Edge，不下载新浏览器。
- 不修改任何旧音频、私人声音、生成音色、Edition 或历史证据。
- 合成探针不包含小说文本、人物资料、声纹或真实媒体路径；音频只存内存。
- 真实听检只处理用户自有／已授权内容，不复制音频进入 Git 或证据目录。

## 11. 自查与最终完成口径

### 11.1 已关闭的方案风险

- **不能只加 `preservesPitch=true` 却保留 Web Audio 主路径。** 该属性对 `AudioBufferSourceNode` 无效，所以必须替换正式后端。
- **不能为保音高丢失句段连续性。** 双槽、预取、gap、租约、进度和 latest-wins 全部进入回归。
- **不能用属性值代替实际输出。** 真实 Chromium 同时做 `false` 负对照和 `true` 正向频谱测量。
- **不能用正弦波代替人声听感。** 真实三声线作者听检是独立门禁。
- **不能用缩小倍速选项掩盖失败。** 高倍速听感失败时回到用户裁决。

- **不能与计划 44 互相覆盖。** 已冻结精确文件 Owner 与共享资源锁。

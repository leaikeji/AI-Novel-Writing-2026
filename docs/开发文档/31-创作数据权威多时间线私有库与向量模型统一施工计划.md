## 0. 统一裁决

### 0.1 目标链路

```text
作者规划版本
  -> 正文不可变 revision
  -> 作者确认的类型化事件
  -> 单／多时间线确定性投影
  -> 统一生成上下文
  -> 分层语义索引
  -> AI 生成或分析候选
```

本计划是以下范围的最新统一施工依据：正式大纲与故事设定、人物根与时间线实例、故事事实 V2、关系／故事线／伏笔投影、私有素材版本、上下文组装、阿里云向量模型配置与分层语义索引。历史计划不删除；冲突范围按本文裁决：

1. 计划 05 的私有素材可覆盖行、只引用素材根的预设和缺少小说固定绑定的设计由本文取代。
2. 计划 09 中为人物、故事线、伏笔分别复制独立事件真相的部分由统一 `StoryFact v2` 取代；关系根、关系 revision 和关系图布局继续保留。
3. 计划 24 的阿里云模型、协议、维度、密钥、candidate generation、失败回退和安全边界继续有效；其仅面向正文的 source 结构扩展为本文的全类型 `semantic_sources`，并按 V1/V2 两阶段上线。
4. 计划 27 的短 evidence key、结果后确认、来源绑定、账本 CAS、无 `no_changes` 强制和人物状态四维协议继续有效；“只允许 main、拒绝多时间线”的裁决由本文取代。
5. 计划 28 的两页建书、单页大纲、单页章前卡、一次点击一次模型调用和无自动同步继续有效；“零新表”只在该 UI 减重专项内部成立，不阻止本文的数据权威修复。
6. 计划 29 的正式 outline/character revision、稳定 ID、别名、CAS 和草稿退出正式维护路径继续有效；章纲引用从根人物 ID 提升为人物实例 ID，旧测试小说不再按生产数据建设永久双轨回填。

### 0.2 硬边界

- 不修改、覆盖或 monkey patch QwenPaw 上游核心。
- 不新增 Agent、正文生成模型选择器、向量数据库、推理容器或第二套任务系统。
- AI 结果在作者采用前不得写正式规划、正文、人物卡或故事账本。
- GET/list/context/search 必须只读。
- 向量只是可重建派生数据，不裁决人物、关系、时间、知识、伏笔或故事线真相。
- 单时间线是默认零配置路径；多时间线是作者主动开启的能力上限。

## 2. 权威模型

全系统只保留三种历史机制：

| 数据 | 唯一权威 |
| --- | --- |
| 正文、大纲、故事设定 | 当前 head + 不可变 revision |
| 人物根、人物实例、关系定义、私有素材 | 稳定实体 + 不可变实体 revision |
| 小说世界中的变化 | `StoryFact v2` 追加式事件 |
| 当前人物／关系／故事线／伏笔 | 按时间线、叙事截止点和观察者计算的投影 |
| AI 实际输入 | generation job 不可变 input/context/asset snapshot |
| 向量 | generation 下的可重建派生索引 |

`ChapterBrief` 继续只保存当前 version；每次生成任务冻结其完整输入，不新增章纲 revision 表。

## 3. 冻结数据契约

### 3.1 正式规划与人物版本

新增：

- `novel_outline_heads`、`novel_outline_revisions`；
- `novel_setting_heads`、`novel_setting_revisions`；
- `novel_character_revisions`；
- `novels.character_catalog_version BIGINT NOT NULL DEFAULT 0`。

正式保存、AI 采用和历史恢复创建新 revision；草稿自动保存不创建。`Novel` 现有大纲字段仅作同事务兼容投影，`novel.description` 不再由亮点覆盖。人物变化只推进人物与 catalog version，不推动 outline head；outline revision 只保存轻量人物／时间线版本摘要。

### 3.2 单／多时间线

新增：

- `story_timelines`：小说范围稳定 ID、`timeline_key`、名称、类型、主继承父线、分叉 StoryFact、生命周期、position、CAS version；
- `story_timeline_links`：`travel / memory_transfer / causal / loop_return / merge_reference`；
- `story_event_links`：`causes / reveals / contradicts / supersedes / enables`；
- `revision_timeline_mapping_heads`、不可变 `revision_timeline_mappings` 与 `revision_timeline_mapping_segments`：分别保存当前指针、一次映射版本和精确字符区间；共同绑定 DocumentRevision、内容 hash、时间线与故事时间。

规则：

1. 小说建立正式基线时同事务创建唯一默认主时间线。
2. 只有一条活动时间线时，普通 API 缺省 `timeline_id` 唯一解析为主线；出现第二条后无法唯一解析即返回 `timeline_required`。
3. 主继承父线必须形成 DAG；因果和 loop link 可以成环，但永不自动复制事实。
4. 分支只继承父线分叉锚点之前的有效事实。
5. 汇合新线必须指定唯一主继承线；其他输入线只记录 `merge_reference`，需要生效的变化必须在目标线创建新 StoryFact。
6. 时间循环从历史锚点建立新分支和 `loop_return`，不改写原线。
7. 映射修正创建新 mapping version 及其不可变 segments，不修改正文 revision；同一版本的区间重叠由服务层拒绝。
8. 不可比较或冲突时间返回 `ambiguous/conflicted` 与全部来源，不使用最后写入覆盖。

### 3.3 人物根与人物实例

新增 `character_instances` 与 `character_instance_revisions`：

- `NovelCharacter` 是跨时间线人物根；保存正式姓名、角色层级和公共档案。
- `CharacterInstance` 是具体连续个体；保存 origin timeline、来源实例、continuity kind、显示区分标签、初始状态 revision 和生命周期。
- 创建人物根时在主线同事务创建默认实例。
- 创建分支时为源线有效人物实例建立目标线派生实例，记录 `derived_from_instance_id`，不复制历史事件。
- 穿越者继续使用来源实例，通过目标线 presence/event 表示进入，可与目标线对应实例并存。
- 人物根 revision 保存跨世界资料；人物实例 revision 保存出生、身份、职业、初始性格、目标、秘密和成长方向；故事内变化全部进入 StoryFact。
- TTS 继续绑定人物根，首期不建设实例级音色。

`CharacterAlias` 增加可选 instance/timeline scope、`alias_kind`、故事时间有效范围、identity layer 和 knowledge scope。章纲、关系和故事事件的新结构化引用使用人物实例 ID；目录、TTS 和跨线总览使用人物根 ID。

### 3.4 StoryFact v2

在现表加法增加：`schema_version`、`timeline_id`、`character_id`、`character_instance_id`、`relationship_id`、`storyline_id`、`foreshadow_id`、`dimension`、`event_kind`、`story_sequence`、`story_time_json`、`visibility_json`、`source_start`、`source_end`、`event_fingerprint`。

首期类型：`character_state / relationship_state / storyline_event / foreshadow_event / story_time / knowledge_event / world_state / general_fact`。每类使用版本化 Pydantic schema；AI 只返回短键和逐字证据，服务端解析内部 ID。`no_changes` 合法。作者确认后单事务写事实、来源绑定、事件链接和账本 CAS；更正通过新事实 supersede 旧事实，不原地改写语义。

### 3.5 关系、线路与伏笔

- 关系新写入增加 timeline 与人物实例端点；关系 revision 只保存作者对定义的编辑，故事内发展进入 StoryFact。
- `Storyline`、`Foreshadow` 继续是规划根，不新增独立事件表。
- `progress/latest_progress/status` 降为兼容投影；正式状态由有效事件计算。
- 多线作品查询必须指定 timeline、叙事截止点和观察者；旧无参调用只在单线时自动解析。

### 3.6 私有库

新增 `private_asset_versions` 与 `novel_asset_bindings`：

- `PrivateAsset` 只保存稳定根、当前 version、类型、标签、来源、授权说明和 archive 状态。
- 每次内容修改创建不可变 version，保存标题、内容、结构化元数据、content hash、provenance 与 rights。
- `AssetPresetItem` 固定 `asset_version_id` 并保存 `required / preferred / context_only / prohibited`；预设只维护当前 CAS，不建设完整预设历史。
- 小说绑定固定具体 asset version；素材更新只显示可更新，不自动改变绑定。
- generation snapshot 复制确切 version、内容、hash、使用策略及直接／预设／小说绑定来源。
- 未绑定素材不进入小说云端索引。

### 3.7 语义索引

现有空 `novel_chunks` 保留为弃用兼容表。新增：

- `embedding_configurations`：单行／工作区级配置根，保存 active/candidate/previous generation 指针、Base URL、凭据引用及 CAS；绝不保存或返回明文密钥；
- `embedding_profiles`、`embedding_generations`：不可变模型／renderer/chunker 指纹及一次完整索引代次；
- `embedding_generation_novels`：逐小说的 consent 版本、目标 corpus、状态、来源／分块／失败计数和激活证明；
- `embedding_index_batches`、`embedding_index_batch_items`：可取消、可重试的批次及逐项幂等、请求、token、延迟与脱敏错误证据；
- `novel_embedding_consents`、`semantic_sources`、`semantic_chunks`、`semantic_embeddings`。

现有 `background_jobs` 只在表结构上通用，执行路径仍与 `narration-worker/moss-nano` 耦合。向量任务不得伪装成朗读任务；W6 前先抽出通用执行核心，由调用方显式提供 `executor_key` 与 `resource_classes`，将所有生产 job kind 纳入注册校验，再增加独立 `embedding-worker` epoch 和 `dashscope-embedding` 资源槽。租约、attempt、重试、取消和 `ModelRunRecord` 继续复用，不新建第二套任务系统。

当前首个生产配置：阿里云百炼、`dashscope-native-v1`、`qwen3.7-text-embedding`、正式默认 2048 维 Dense、cosine、document/query 双角色、批次 10、现有 PostgreSQL + pgvector、无新推理容器。候选维度只允许 `256/512/768/1024/1536/2048/2560`，不同维度通过 profile/generation/fingerprint 隔离。

`CDV-VR0-G` 复核记录（2026-08-29）：已只读核验阿里云官方[模型页](https://help.aliyun.com/zh/model-studio/qwen3-7-text-embedding)、[同步接口](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)与[限流页](https://help.aliyun.com/zh/model-studio/rate-limit)，未发模型请求。官方当前确认：模型由百炼提供；DashScope Native HTTP endpoint 为业务空间域名下 `/api/v1/services/embeddings/text-embedding/text-embedding`；支持 `256/512/768/1024/1536/2048/2560`；`output_type=dense`、`text_type=document/query` 与 query-only `instruct` 受支持；响应含 `request_id`、逐条 `text_index`、dense embedding 与 token usage。模型接口最多 20 条，本项目仍保守冻结内部批次 10，以降低失败重试范围；这不是官方最大值。运行时不得把时效限流写成永久常量。文档复核不等于连接成功，candidate 仍须经过 query/document 双角色非敏感哨兵后才能标记 runtime verified。

`VR0-SECRET` 裁决（2026-08-29）：当前项目未发现并验证 QwenPaw 2.1.x 的公开 PawApp Secret API，且禁止探测其私有配置；采用项目自有 AES-256-GCM secret record。数据库只保存 credential reference、末四位和更新时间；GET 最多返回 `********` 加末四位，不返回完整 Key 或末八位。密文 record、nonce 与算法版本位于项目 secret mount，独立 32 字节根密钥也位于该 mount 且与 HMAC digest key/API Key 分离。根密钥优先由部署脚本按固定绝对路径幂等 provision，页面仅保留本机单用户恢复入口。固定新增 `cryptography==48.0.1`：该版本支持 Python 3.11、macOS/Linux ARM64 wheels，许可证为 Apache-2.0 OR BSD-3-Clause，并满足 QwenPaw 2.1.0 现有 `alibabacloud-tea-openapi` 的 `<49` 依赖约束。构建时曾验证 50.0.1 会产生明确解析冲突，因此不得提升到 49+；根密钥丢失只使凭据不可用并要求重新输入，不影响正文、事实或本地向量。

语料类型：`manuscript / planning / private_asset / character / relationship / story_event / storyline / foreshadow / timeline`。每类使用独立、版本化 renderer，禁止把任意 JSON 直接字符串化。

- V1：当前正式正文、正式大纲／设定、小说固定绑定的私有素材。
- V2：当前人物根／实例 revision、关系 revision、有效 StoryFact、故事线、伏笔和时间线摘要。

检索必须先按 owner/workspace/novel、授权、current revision、timeline 可达性、叙事截止点、观察者知识和来源有效性做确定性过滤，再分 corpus 召回并用固定 RRF 融合。结构化状态始终由投影服务裁决。

## 5. 页面冻结

### 5.1 单／多时间线

- 单线作品不显示内部 timeline/instance ID，不增加建书、建章或正文生成步骤。
- 作者创建第二条线后才显示时间线工作区；提供图谱与键盘可操作的树／列表回退。
- 人物页先显示人物根；多实例时才显示实例切换、来源线和当前线状态。
- 关系图、故事线和伏笔页增加 timeline/cutoff/perspective 过滤，不把视图布局当故事事实。

### 5.2 全局向量模型接入页

位于 PawApp 自有设置区，不占用 QwenPaw 全局模型页。显示只读服务商／协议、Base URL、write-only API Key（只显示配置状态或数据库末四位掩码）、active/candidate 模型与实际维度、连接状态、generation 状态、已授权／待重建／失败小说数及脱敏运行摘要。Base URL 首次默认留空，前端允许自由粘贴百炼控制台提供的公网或工作空间地址，官方域名与 SSRF 校验只在测试／保存时由服务端执行。维度使用受支持值选择器，正式默认 2048。提供仅测试连接、验证并保存、为全部授权小说构建、取消、激活、回退、替换／清除密钥。所有授权小说 candidate ready 且检索门禁通过后才可激活；失败时旧 active 继续服务。页面不提供计费、价格、余额、扣费或费用管理。

### 5.3 小说内语义索引卡片

显示授权告知版本、云端发送范围、模型／generation、各 corpus 来源／分块／失败数及索引状态。提供一次授权、撤销、重建、取消、重试、查看未索引原因和独立清理本地向量。授权后新增正式内容和新绑定素材无需重复弹窗，但页面持续披露；撤销立即停止新调用，不自动删本地向量。

## 6. 必须删除的运行时硬编码

1. 删除生产代码内具体样书人物、地点、物件和故事线关键词分支；测试文本可以保留为 fixture，不得驱动生产逻辑。
2. 删除 GET storylines/foreshadows 的写数据库行为。
3. 删除“非空正文必须至少返回一项情报”。

## 9. 验收矩阵

必须覆盖：

- 单线自动主线、零额外步骤、隐藏高级 UI；第二条线创建后才要求明确 timeline/instance。
- 改名后正文、章纲、关系、事件和 TTS 稳定引用不变。
- 平行实例独立年龄／身份／知识／成长；穿越者可与本线对应实例并存。
- 分支不读取兄弟线后续事实；循环不自动传播；汇合冲突由目标事实显式解决。
- 闪回同时遵守故事时间与叙事知识截止点；年龄精度不足返回区间，绝不使用服务器日期。
- revision 替换／恢复正确切换事实和向量来源。
- 私有素材修改不改变旧 generation snapshot 和小说固定绑定。
- GET/list/context/search 零写入；`no_changes` 正常完成。
- 生产样书硬编码命中为 0。
- 无授权云调用为 0；API Key 明文落盘、响应、日志和证据命中为 0。
- API Key 末八位响应命中为 0；掩码只允许数据库末四位。哨兵、CAS 或候选创建失败后旧配置／旧候选／version 不变，临时 secret 已删除。
- 跨 owner/workspace/novel、未来章节、兄弟时间线、未揭露秘密、未采用候选、失效 revision 泄漏为 0。
- 相同 revision/renderer/chunker 重建 hash 完全一致；candidate 失败时旧 active 与词面搜索继续工作。
- V1 固定评测集 Recall@5 >= 0.85、MRR >= 0.70；V2 每个 corpus 单独通过质量和隔离 Gate，否则保持关闭。
- 禁用向量后正文写作、保存、恢复、词面搜索和 QwenPaw 原生能力继续工作。

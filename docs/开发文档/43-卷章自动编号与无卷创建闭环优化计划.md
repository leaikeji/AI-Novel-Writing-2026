## 0. 结论先行

本计划只闭环四个已复核缺口：

1. “没有分卷不能新增章节”目前主要依赖前端入口和章节向导服务；通用 `create_document()` 仍可用 `kind=chapter / volume_id=null` 绕过。
2. 前端已经按顺序计算 `第 N 卷／第 N 章`，但全书导出仍直接使用数据库原始标题；保存纯名称后会丢序号，旧标题重排后还可能导出过期序号。
3. 章节向导以 `creating=false / draft=null` 推导失败态；首次打开到 `useEffect` 启动请求之间可能短暂显示错误。
4. 规格和创建向导允许章节名称为空并显示纯 `第 N 章`，但标题编辑仍禁止空名称保存。

V0.2 修复了 V0.1 复查发现的五个计划缺口；V0.3 继续冻结第三轮复查确认的八项施工条件：自然语言批准有效、旧前缀必须有词边界、卷章创建与草稿 key 必须并发安全、新章预览号按目标卷插入点计算、纯顺序变化只更新语义索引位置元数据且复用向量、Context 片段后缀参与最终限长、每次准备请求使用不复用的 generation，以及只读审计／全量 typecheck 不与源码写入并行。

目标闭环为：

```text
权威卷章树序
  → 唯一卷章序号
  → 语义名称与序号分离
  → 可见标题／上下文／导出统一适配
  → 所有章节创建入口统一要求有效分卷
  → 向导 idle/loading/ready/failure 可证明
```

本计划不以“当前按钮看起来正确”作为完成条件。服务层、导出、前端状态机、旧数据兼容、隔离数据库和真实浏览器必须共同通过门禁。

## 1. 当前实现事实与问题边界

### 1.1 已核实事实

- `frontend/src/workbench-studio.ts` 已在无分卷时禁用主“新建章节”按钮，并在空态说明“请先创建分卷”。

### 1.2 技术判断

- 序号不是名称的一部分，而是 `position` 的派生展示值；不能通过继续保存用户手输序号解决。
- 仅修按钮不足以形成领域规则。HTTP API、章节向导和未来 Agent／工具入口都必须复用同一服务约束。
- 不能批量改写现有标题来“清洗数据”。旧数据应读时兼容、显式编辑时规范化，历史 revision 和正文不受影响。
- Python 后端适配与 TypeScript 页面必须使用同一组示例和规则测试，避免两端正则、树序与空名称行为漂移。

## 2. 目标与非目标

### 2.1 本轮目标

- 所有新章节创建入口都要求当前小说内一个有效分卷；缺失时返回统一中文错误，且零章节、零草稿写入。
- 历史未分卷章节继续可读、可导出、可移动；“移出分卷”继续允许把既有章节设为 `volume_id=null`。
- 卷序号按真实分卷 `position` 升序、从 1 开始计算；未分卷虚拟组不计入卷序号，空卷仍计入。
- 章序号按唯一规范树序计算：真实分卷按 `Volume.position`，每卷章节按 `Document.position`，最后追加未分卷章节并按 `Document.position`；从 1 开始跨卷连续。
- 新增、编辑、列表、章节树、选择器、确认弹窗、朗读目标、删除确认和全书导出统一使用派生展示标题。
- 旧 `第一卷`、`第 1 卷：名称`、`第十二章 · 名称` 等前缀不会重复显示；错误旧序号不会覆盖当前位置。
- 章节向导首次打开直接进入 loading；只有明确失败才进入 failure，已有可用草稿进入 ready。
- 卷名和章节名称可为空；空名称只展示 `第 N 卷／第 N 章`，作者可从有名称状态清空回纯序号。
- 空名称章节仍能进入助手上下文、Context V4、情报提示词、人物工作区和语义索引；任何强制非空契约都不能收到空字符串。
- 失效分卷草稿保留作者已经填写的内容，并能安全恢复到当前有效分卷；不得通过无限重试或静默丢弃解决。
- HTTP 失败使用冻结的状态码与结构化 `detail.type/message`，前端不依赖英文异常文本猜测原因。
- 自动化、隔离 PostgreSQL、隔离 QwenPaw 浏览器和长期环境只读冒烟全部形成证据。

### 2.2 非目标

- 不新增或改写 Alembic revision，不增加 `sequence_number`、`display_title` 等持久化列。
- 不批量清洗现有卷名、章节名、正文、revision 或故事账本。
- 不放宽 Context V4、Embedding 或助手公共契约的非空要求；在边界处传入派生标题或稳定内部标签。
- 不删除“未分卷”能力，不把历史未分卷章节强制搬入某卷。
- 不新增章节排序 UI、第二套搜索系统、第二套 Agent Runtime、模型选择器或任务队列；现有搜索只补当前派生标题的匹配与结果重投影。
- 不修改 QwenPaw 上游核心，不覆盖其路由、组件、数据库或私有配置。
- 不顺带施工 42 号关系网投影计划或其他开发文档中的未完成事项。
- 不因为序号变化单独触发远程向量重嵌入；序号属于位置元数据，不进入稳定 Embedding 标题文本。

## 3. 冻结契约

### 3.1 唯一规范卷章树序

卷与章使用同一份规范树投影，不再让各页面自行选择“全局 position”或“按卷遍历”：

```text
canonical_volume_groups =
  real volumes ordered by Volume.position ascending
  + virtual unassigned group at the end

canonical_chapters = flatten(
  each real volume's chapter documents ordered by Document.position ascending,
  then unassigned chapter documents ordered by Document.position ascending
)

volume_ordinal(volume_id) = real volume index + 1
chapter_ordinal(document_id) = canonical_chapters index + 1
next_chapter_ordinal(volume_id) =
  count(chapters in real volumes before volume_id)
  + count(chapters currently in volume_id)
  + 1
```

约束：

- `Volume.position` 的真实唯一约束是 `(novel_id, position)`；章节位置的真实唯一约束是 `(novel_id, kind, position)`。排序与重复检查必须先过滤 `kind=chapter`，不能把大纲、设定的相同 position 误判为章节冲突。
- 空卷仍进入 `volume_ordinal`，但不向 `canonical_chapters` 添加项目；未分卷虚拟组不占卷号且固定在最后。
- 历史章节即使 `Document.position` 在不同卷之间交错，读取、页面和导出也按规范树序得到单调的 `第 1…N 章`；不为此批量改写数据库。
- 章节向导在完成前显示 `next_chapter_ordinal(draft.volume_id)`，不能使用全书章节总数加一。历史未分卷章节固定在最后，恢复到较早分卷的草稿按该分卷末尾的真实插入点预览；创建成功后以服务端返回文档在最新规范树中的 ordinal 为准。
- `reorder_chapters()` 的 `ordered_document_ids` 冻结为“应用目标分卷映射后的规范树扁平序列”。同一卷的 ID 必须连续、各卷块必须遵循 `Volume.position`、未分卷块必须最后；不一致请求返回结构化 422，不猜测也不部分写入。
- 成功重排使用两阶段临时 position 后按完整规范序列重写章节 position；视图倒序只改变渲染，不改变规范树序。
- 创建卷、创建／完成章节、重排卷章和删除卷必须按 `Novel → Volume/Document/ChapterCreationDraft` 的固定顺序取得同一小说写锁；`max(position)+1000` 只能在该锁内计算。相同 `draft_key` 的首次创建使用 PostgreSQL 原子 upsert 或等价的唯一冲突重读，不把唯一键异常暴露给作者。并发请求必须收敛为唯一草稿／互异 position 或明确可重试的结构化冲突。
- PostgreSQL 导出读取在一个显式 `REPEATABLE READ` 短事务中完成：只读取一次当前卷与章节，先在内存建立不可变的规范树序和 ordinal map，再生成卷块、章节块和 metadata；同一次导出不得在默认 `READ COMMITTED` 下用多次查询混合重排前后结果，事务冲突时整体失败并可安全重试。

### 3.2 名称、展示标题与内部契约标题

数据库 `Volume.title`／章节 `Document.title` 只保存作者名称；序号永远是派生值：

```text
title_name = strip_legacy_ordinal_prefix_at_boundary(trim(raw_title))
display_volume_title = "第{volume_ordinal}卷" + optional(" " + title_name)
display_chapter_title = "第{chapter_ordinal}章" + optional(" " + title_name)
context_chapter_title = bound_contract_title(display_chapter_title, suffix="", max_length=240)
embedding_chapter_title = title_name if title_name else "章节正文"
```

具体决策：

- 卷和章节允许 `title_name=""`；数据库无需迁移，服务与请求校验按文档类型处理空字符串。大纲、设定和其他文档标题继续要求非空。
- 旧序号前缀只在标题恰好等于序号，或序号后存在空白／`:`／`：`／`·`／`—`／`-` 等明确分隔符时剥离；不得把“第一章里的秘密”“第三卷轴之谜”等真实语义名称截短。
- 新建小说的默认首卷、首章存储空名称；页面、导出和模型上下文仍分别显示 `第1卷`、`第1章`。
- Context V4、助手 context、情报／关系／人物模型快照及其他要求非空的运行契约使用当前派生标题，绝不直接传空的存储名称。对 `ContextBlockV2.title` 等现有上限为 240 字符的契约，`bound_contract_title()` 接收最终后缀并为其预留长度，保留完整 ordinal 前缀、只截断语义名称尾部，使“展示标题 + ` · 片段 N`”等最终组合值也不超过 240；不回写数据库，也不截断 UI、导出或作者可见搜索标题。
- Embedding 源标题使用剥离后的语义名称；空名称使用仅限索引内部的稳定标签“章节正文”。该标签不写入数据库，不进入 API、UI、导出或作者可见搜索结果。
- 章节 ordinal 不进入 Embedding 文本。纯卷章顺序变化在权威事务提交后执行本地 metadata-only reprojection：为当前 source/chunk 复用既有 embedding，只更新新的不可变 source 位置投影、authority/published digest 与 index version，不创建远程 embedding batch；不得原地篡改与旧位置绑定的 source fingerprint。若现有 schema／刷新服务无法在不迁移、不复制向量的前提下证明该路径，立即停止并回到本文裁决，不能在“位置过期”和“远程重嵌入”之间静默二选一。
- 名称变化先完成作者名称事务并返回其确定结果，再在独立短事务请求 active-generation 内容刷新。派生刷新失败时 API 仍返回名称保存成功，同时把索引置为可恢复的 `outdated`；不得在已提交后返回会诱发作者盲目重试的通用 500，也不得因刷新异常回滚名称。
- 普通搜索结果标题在返回／展示边界重新结合当前 ordinal，按当前展示标题搜索 `第 N 章` 时应能定位相应章节。现有 `SemanticSearchHit` 公共契约没有 title 字段，本轮不为此扩展第二套标题协议；语义命中的 `source_id` 继续指向权威实体，作者可见 snippet 必须剥离 renderer 头部及内部“章节正文”标签，已有标题表面再按实体 ID 使用当前展示投影。
- 不批量更新旧记录。旧前缀在读取展示、内部契约适配、导出和显式写入时剥离；作者显式保存后只保留语义名称。
- Python 与 TypeScript 共同案例至少覆盖：纯名称、阿拉伯旧前缀、中文旧前缀、错误旧序号、只有旧前缀、空字符串、纯空白、前后空白、中文标点分隔符、多位 ordinal、240 字符边界与超长语义名称、“第一章里的秘密”“第三卷轴之谜”不得被截短，以及不得错误处理非卷章文档。
- 禁止用零宽字符、不可见占位符或作者可见的“未命名章节”维持非空；强制非空只在边界适配为可解释的派生标题或明确限定的内部标签。

### 3.3 无卷创建与失效草稿恢复

统一规则为：

- `kind=chapter` 的新建动作必须显式携带当前小说的有效 `volume_id`；即使小说已有卷，也不再由服务静默选择第一卷。
- `create_document()`、HTTP 创建接口、章节草稿创建和章节草稿完成都在提交前复核该分卷仍属于当前小说。
- 无卷、空 `volume_id`、跨小说分卷或已删除分卷均在任何 Document、working copy、revision 或新 chapter draft 写入前失败。
- `kind=outline|setting` 维持现有非分卷创建能力。
- `reorder_chapters(... volume_by_document={id: null})` 继续允许把既有章节移出分卷；它不是新章节创建入口。

同一个 `draft_key` 的恢复规则冻结为：

1. 已完成且 `completed_document_id` 有效：返回原文档并恢复到该章节，不创建重复 Document。
2. `state=draft` 且原 `volume_id` 仍有效：恢复原草稿及原目标卷；调用方传入不同有效卷时不静默改绑。
3. `state=draft` 且原卷已删除／被置空，但本次请求提供有效卷：原子地把同一草稿重新绑定到请求卷、版本加一、保留全部标题／章纲／角色／线路／伏笔输入，并在原有草稿响应顶层返回 `recovery={"kind":"volume_rebound","from_volume_id":<旧值或 null>,"to_volume_id":<当前值>}`。
4. 失效草稿且当前仍无有效卷：返回 `chapter_volume_required`，草稿本身保持不变。
5. 完成时卷在请求后被删除：返回 `chapter_draft_volume_stale` 409，零章节写入；创建新卷后重试准备流程可按规则 3 恢复。
6. key 属于其他小说或处于不可恢复状态：返回结构化冲突，不覆盖、不复用、不自动删除；前端显式轮换 key 后才可新建。

### 3.4 HTTP 与可选名称契约

领域错误统一映射为 FastAPI `detail={"type": ..., "message": ...}`：

| 场景 | HTTP | `detail.type` | 固定行为 |
| --- | --- | --- | --- |
| 章节创建／草稿缺少或传空 `volume_id` | 422 | `chapter_volume_required` | “请先创建分卷，再新建章节”；零写入 |
| 分卷不存在、已删除或属于其他小说 | 422 | `chapter_volume_invalid` | “所选分卷不存在或不属于当前小说，请刷新后重试”；零写入 |
| 草稿完成前目标卷失效 | 409 | `chapter_draft_volume_stale` | `detail.current` 返回当前完整草稿 payload；零章节写入 |
| `draft_key` 属于其他小说或不可恢复状态 | 409 | `chapter_draft_key_conflict` | 不覆盖旧草稿 |
| 重排列表与目标规范树不一致 | 422 | `chapter_order_inconsistent` | 零 position／归属写入 |
| 新增卷／章节的 `title` 省略、空或纯空白 | 201 | — | 规范化为语义空名称 |
| 更新卷／章节显式提交空或纯空白 `title` | 200 | — | 清空语义名称；version 正常递增 |
| 更新卷／章节省略 `title` | 422 | 请求校验错误 | PUT 不猜测“保持不变”或“清空” |
| 新增／更新 outline、setting 空标题 | 422 | `document_title_required` | 非章节规则不变 |

当同一请求同时缺少分卷与名称时，先返回 `chapter_volume_required`。`CreateVolumeRequest` 与 `kind=chapter` 的 `CreateDocumentRequest` 可把 `title` 默认成空字符串；非章节标题的非空校验由领域服务按 kind 执行。API 路由只做结构化错误映射，不复制业务判断。

所有上表领域错误的 `detail.type` 与 `detail.message` 均必填；不得退回裸字符串。`chapter_draft_volume_stale` 额外携带与成功接口相同字段集合的 `detail.current: ChapterCreationDraftRecord`，用于前端更新 version 并保住全部草稿输入；`chapter_draft_key_conflict` 不返回其他小说的草稿内容。成功重绑仍返回普通 `ChapterCreationDraftRecord`，只额外增加上述可选 `recovery`，不另建第二套草稿 DTO。

### 3.5 章节向导准备状态机

前端显式保存请求阶段，不再由 `creating` 与 `draft` 两个值猜测：

| 状态 | 进入条件 | 可见行为 |
| --- | --- | --- |
| `idle` | 弹窗关闭 | 不显示、不请求 |
| `loading` | 弹窗打开，`requestPhase=not_started|loading` | 只显示准备中，可关闭 |
| `ready` | `requestPhase=succeeded`、`draft.state=draft` 且分卷范围有效 | 显示六步向导；必要时提示已恢复分卷 |
| `failure` | `requestPhase=failed` 或收到结构化范围错误 | 显示具体错误、关闭和重试 |

附加规则：

- 打开动作在同一事件中把状态置为 loading；首帧不得先闪 generic failure。
- 每次真正发起准备请求（首次打开、关闭后重开、Retry、切书后打开）都分配一个单调递增且不复用的 `requestGeneration`，同时把 `requestPhase` 置为 loading；Retry 不能只清空错误后等待一个不会重新执行的 effect。
- `completed_document_id` 按 3.3 规则恢复原章节；`recovery.kind=volume_rebound` 显示一次非阻断提示。
- 切换小说、关闭重开、删除目标分卷、Abort 或网络失败时，以 novel ID、draft key 和 `requestGeneration` 三元组隔离过期响应；每次新 generation 先 Abort 前一请求，只有完整三元组仍匹配时才可提交状态与错误。
- 没有分卷时，按钮、空态、外部 signal 和 API 都阻止创建；向导不得打开，也不得发送草稿请求。

### 3.6 用户可见标题、运行上下文与导出

- 页面组件只调用 TypeScript presenter／规范树投影；不得复制正则、局部计数器或临时拼接。
- 后端集中使用卷章标题适配器；导出、Context V4、助手上下文、情报／关系／人物模型输入和搜索结果分别按 3.2 的边界取值。
- Markdown、纯文本导出的卷标题、章标题和 `metadata.chapters[].title` 使用同一内存快照的派生展示标题；章节标题在文件中严格按第 1…N 章单调出现。
- “未分卷”只作为最后一个虚拟分组标题；其中章节仍使用全书连续章号。
- 重排后页面、搜索结果、上下文和再次导出立刻反映新序号，不依赖作者重命名；既有 Embedding 文本不因纯 ordinal 变化重嵌入。
- 本轮不改变正文、revision 内容哈希或故事事实；标题元数据变更仍沿用现有 CAS/version 规则。

## 5. 数据兼容、恢复与回退

- 本计划预期无 schema 变更，所以不存在数据库 downgrade；若实现中发现必须迁移，立即停止并另行裁决。
- 不运行批量 UPDATE。旧标题原样保留，展示和导出按兼容解析；显式编辑只更新该卷或章自己的 metadata/version。
- 历史未分卷章节不删除、不隐藏；回归必须证明仍可移动回分卷并正常导出。
- 历史跨卷交错 position 不自动写回；读取与导出按规范树序兼容。作者下一次显式重排成功后，服务按冻结序列规范化全部章节 position。
- 空名称不得破坏 Context V4、助手、情报、关系、人物或 Embedding。内部“章节正文”标签只存在于索引输入；若任何 API、UI、导出或截图出现该标签，验收失败。
- 章节名称变化若需要刷新 active semantic source，使用现有可恢复刷新机制且不占用名称事务；纯 ordinal 变化不发起远程重嵌入。
- 自动化和浏览器写入只使用明确命名的隔离 `*_test` PostgreSQL 与隔离 QwenPaw；长期 `18088` 只做安装后只读冒烟，不创建或删除测试小说。
- 长期安装前保存当前插件包、版本和前端资产哈希。回退只重新安装旧插件包，不动 QwenPaw 核心或数据卷。
- 若前端新包失败，禁用/卸载 PawApp 后原生聊天必须恢复；若后端规则失败，退回旧插件后既有小说数据仍可读。

## 8. 验收矩阵

### 8.1 后端领域与 API

- 无卷小说、遗漏／空 `volume_id` 调用通用创建接口或草稿接口：返回 422 `chapter_volume_required`；Document、working copy、initial revision 和新 draft 计数均不变。
- 有效分卷创建 chapter：成功且归属正确；跨小说或已删除 volume 返回 422 `chapter_volume_invalid`，零写入。
- outline/setting 的现有创建路径不回归。
- 新增卷／章的 `title` 省略、空字符串或纯空白均创建语义空名称；更新卷／章显式空 title 可清空，省略字段仍失败；outline/setting 空标题继续返回 `document_title_required`。
- 章节草稿创建后目标卷被删除：完成返回 409 `chapter_draft_volume_stale`，`detail.current` 为同一草稿的完整 payload 且不创建章节；创建新卷后用同一 key 可重新绑定同一草稿，全部已填字段保留、version 增加，并返回精确的 `recovery.from_volume_id/to_volume_id`。
- 有效旧草稿收到另一个有效目标卷时继续恢复原卷；completed key 返回原文档；跨小说／不可恢复 key 返回 `chapter_draft_key_conflict`。
- 既有章节移出分卷后仍可读取、移动回卷、建立 revision 和导出。
- 卷名/章名为空、纯名称或带旧前缀时，服务保存语义名称并维持版本/CAS。
- 重排列表违反分卷块顺序、卷内连续性或未分卷最后规则时返回 `chapter_order_inconsistent`，所有 position 和 volume_id 保持不变。

### 8.2 导出

- 语义名称 `潮汐旧声 / 海边来信` 导出为 `第1卷 潮汐旧声 / 第1章 海边来信`。
- 旧数据 `第五卷：潮汐旧声 / 第十二章 · 海边来信` 位于第一位置时仍导出为第 1 卷／第 1 章，不重复、不保留错误旧号。
- 空名称导出为纯 `第 N 卷／第 N 章`。
- 卷倒序显示不影响导出顺序；执行正式 reorder 后导出序号随 position 更新。
- 反例树包含：卷一章节 position=3000、卷二章节 position=1000、未分卷章节 position=2000。页面和导出仍按卷一 → 卷二 → 未分卷生成第 1、2、3 章，不出现先第 2 章后第 1 章。
- 空卷计入卷号；未分卷虚拟组不计卷号且固定最后，其中章节保持全书连续章号。
- Markdown、text 和 `metadata.chapters[].title` 三处一致。
- 同一导出开始后模拟并发重排，结果必须完全来自重排前或重排后的一份内存快照，不能混合。

### 8.3 前端状态与交互

- 无卷时按钮 disabled，空态和可访问说明明确；点击外部 signal 也不会打开向导或发送草稿请求。
- 有卷首次打开首帧为 loading；成功进入 ready；网络/服务失败进入 failure 并可关闭、重试。
- Retry 产生新的 attempt，旧 Abort／慢响应不能覆盖新状态；切换小说后三元作用域隔离有效。
- 已完成 draft 的幂等恢复不会创建重复章节；`volume_rebound` 恢复原草稿内容并显示一次提示。
- 新增和编辑只输入名称；作者输入旧序号时即时规范化，不会形成双前缀。
- 章节名称可从“海边来信”清空并保存，页面显示纯 `第 N 章`；大纲/设定标题仍不能清空。
- 分卷/章节重排后，列表、章节树、编辑器标题、搜索结果、助手 context、选择器、确认弹窗、朗读目标和删除确认同步更新。
- 用交错 position 与早期未分卷章节构造树时，所有前端表面与导出使用同一规范树号；按 `第2章` 搜索可定位当前第二章。
- 键盘 Tab、Enter、Escape、焦点返回、错误提示朗读正常；桌面与 390×844 窄屏无溢出、遮挡或不可操作按钮。

### 8.4 Context、模型输入与语义索引

- 空名称且有正式正文的章节能成功组装 Context V4；每个 `ContextBlockV2.title` 使用当前 `第 N 章` 展示标题且非空。
- 240 字符语义名称配合多位 chapter ordinal 时，作者可见名称保持完整；传入现有 240 字符运行契约的标题保留完整 ordinal 前缀并稳定截断到上限，不触发 Pydantic 校验失败。
- 助手 context、章节情报、关系快照和人物工作区不接收空标题；旧前缀不重复，chapterNumber 与标题一致。
- 本地词面、Embedding 初建、refresh 和 writing retrieval 可处理空名称；内部标题为稳定“章节正文”，作者可见结果仍显示当前 `第 N 章`。
- 内部“章节正文”不出现在 API、UI、导出、截图或下载内容中。
- 只改变卷／章 ordinal 时，Embedding 输入文本标题和 source content hash 不变，不调用真实向量服务；名称变化只刷新受影响源且失败可恢复。

### 8.5 非回归

- QwenPaw 原生 `/chat`、Agent、模型、Skills、MCP、设置和插件管理不变。
- 正文 working copy、revision、CAS、恢复、Context V4、向量授权与 active generation、情报同步、关系网、朗读和人物卡无回归。
- 不修改真实小说、数据库迁移历史、持久卷或 QwenPaw 上游文件。

## 10. 风险、停止条件与替代方案

| 风险 | 预防 | 停止条件／替代方案 |

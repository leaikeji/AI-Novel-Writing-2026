## 一、立项结论

计划 31、32、34 与 36 已建立创作数据权威、多时间线、人物根／实例、StoryFact v2、私有素材版本、向量写作检索、公开模型证据和统一人物卡。下一步不继续增加账本、向量语料或基础设施，而是通过一部全新的三章合成实验小说，证明以下生产链能够在安装后的真实 PawApp 中连续工作：

```text
建书
→ 生成并采用正式大纲／设定
→ 人物草案正式化
→ 创建章纲
→ 生成并采用正文 revision
→ 确认 StoryFact／人物状态变化
→ active generation 增量索引
→ 下一章召回前文
→ 审稿与选区修改
```

本计划属于中型稳定化与缺陷修复，预计 24–38 个有效工程小时。它不建设第二套人物库、Agent Runtime、向量数据库、任务系统、模型选择器或计费功能。

计划 35 是否完成声音、朗读、高级调音、私人音色或真实 Nano 验收，不影响计划 37 的 PASS／HOLD。

## 三、冻结边界

- 只处理新建合成实验小说，不读取或修改真实用户小说。
- 单时间线是主验收路径，建书、人物、建章和正文生成不得增加时间线操作。
- 多时间线只验证显式选择、来源隔离和结构化错误，不扩展新的分支语义。
- 不启用 `character / relationship / story_event / storyline / foreshadow / timeline` 等 V2 向量 corpus。
- 不新增 Alembic 迁移；若实测发现无法通过代码修复的 schema 缺口，停止施工并单独裁决。
- 不新增账本、人物库、向量数据库、ANN、生成模型选择器或通用队列。
- 结构化人物、关系、时间、知识和伏笔状态继续由 revision、StoryFact 和确定性投影裁决；向量只提供补充语义证据。
- 不调用、测试、验收或裁决 TTS、声音绑定、Nano、VoiceGenerator、播放器和朗读页面。
- 不开发价格、余额、账单、扣费或费用统计功能。
- 未获得当次真实调用授权时，正文模型与百炼全部使用 stub；此时只能裁决自动化链路，不能宣称真实联合 E2E 通过。
- 真实调用获批后只使用本计划的合成小说。正文模型最多三次章节正文生成；其他触发矩阵使用 stub。百炼调用限制为该小说的正式 V1 语料索引和三章写作查询。
- 不修改 QwenPaw 上游，不读取其私有模型状态、私有 usage buffer 或私有数据库结构。

## 四、三章合成实验小说

### 4.1 固定设计

题材使用现代悬疑，确保可以稳定覆盖身份、改名、秘密、私有规则、关系变化、时间线隔离和未来信息泄漏。

固定人物与数据特征：

- 主角具有稳定人物 ID、正式姓名、曾用名、公开身份和真实身份；
- 配角与主角存在明确关系，但关系变化只通过已确认 StoryFact 生效；
- 一份 `required` 私有素材包含案件世界规则；
- 一份 `preferred/context_only` 素材用于语义召回；
- 一份 `prohibited` 素材用于泄漏负例；
- 一条兄弟时间线包含与主线相似但冲突的诱饵事实；
- 第三章事实在前两章生成时必须不可见。

不得使用生产代码中的题材、人物、地点或关键词硬编码驱动结果；所有样本文本只存在于 fixture、隔离实验库和验收证据中。

### 4.2 第一章：身份与线索建立

目标约 2000 个可见中文字符，完成：

- 主角正式姓名和曾用名的叙事引用；
- 公开身份与尚未揭露的真实身份；
- 私有素材中的必要世界规则；
- 第二章必须召回的一项前文线索；
- 第三章才允许揭露的一项秘密。

验证人物根、主线默认实例、alias、正式正文 revision、语义来源和知识可见性。

### 4.3 第二章：前文召回与状态变化

目标约 2000 个可见中文字符，要求：

- 正确召回第一章线索；
- 使用曾用名时仍解析为同一稳定人物；
- 产生位置、目标、知识或关系变化候选；
- 不得知道第三章秘密；
- 不得读取兄弟时间线的诱饵事实。

作者确认后写入 StoryFact，并验证人物工作区投影与 active generation 增量状态。

### 4.4 第三章：身份揭示与连续性

目标约 2000 个可见中文字符，完成：

- 真实身份在明确知识事件后生效；
- 回收第一章线索；
- 使用第二章已经确认的状态变化；
- 验证人物改名后，大纲引用、章纲、关系、StoryFact 和语义来源仍稳定。

## 五、核心验收指标

### 5.1 模型与正文

- 三次正文任务均形成合法、可审阅候选。
- 每章可见正文为 1700–2300 字符，3/3 通过；若未通过，不通过放宽门槛隐藏问题。
- 模型证据为 `verified_from_provider_usage` 或合法 `not_exposed`。
- `not_exposed` 时 actual provider/model 必须为 null，页面不得宣称实际模型已验证。
- usage 畸形、reported actual 错配、调用中模型变化或 postflight 失败时禁止采用。
- 任一失败任务不得修改正式大纲、人物、正文、StoryFact 或向量 current source。

### 5.2 人物与账本

- 正式化创建稳定人物根和主线默认实例，同名角色不自动合并。
- 人物改名后大纲、章纲、关系、StoryFact 和语义来源的稳定引用保持正确。
- 单时间线全程零额外 timeline/instance 步骤。
- 多时间线缺少明确选择时返回结构化错误，不按最近使用值或姓名猜测。
- 年龄资料不足时显示区间或未知，不使用服务器当前日期推断。
- 成长状态只来自已确认 StoryFact，未采用候选不得进入投影。
- GET/workspace/context/search 保持数据库零写入。

### 5.3 向量与私有素材

- 第一、二章正式化后，小说索引从 `updating` 收敛到 `ready`。
- 第二、三章能够召回必要的当前前文 revision。
- 未来章节、兄弟时间线、retired revision、未绑定素材、`prohibited` 素材和未揭露知识泄漏均为 0。
- Dense 不可用、超时、限流或密钥失效时自动降级到本地词面，正文任务仍能继续。
- `required` 素材不得静默丢失；低优先级证据省略必须有 omission 说明。
- 写作快照冻结 generation、index version、来源 revision、chunk、分数、request ID、Token、时延和降级原因。

### 5.4 写作 UI

- 浏览器覆盖 `1920×1080`、`2560×1440`、`390×844`。
- 覆盖建书、大纲人物草案、正式人物卡的基础／本线／成长资料、章纲、正文生成、候选采用、模型证据、向量授权／同步状态、审稿和选区修改。
- 上述写作页面均覆盖空态、错误态、重试、未保存提示、键盘操作与窄屏滚动。
- 人物卡声音页签和朗读页不进入点击、接口、视觉或产品验收矩阵。

## 六、缺陷处理与冗余清理

真实 E2E 暴露的问题按以下顺序处理：

1. 跨小说、未来章节、兄弟线、秘密或私有素材泄漏；
2. 正式数据被失败任务或读取接口意外修改；
3. 正文无法生成、候选无法采用或 revision／索引无法收敛；
4. 人物、StoryFact、关系和向量来源指向不同实体或 revision；
5. 正文长度、上下文预算或 required 素材装配错误；
6. 降级、错误诊断、恢复和 UI 体验问题。

每个缺陷必须先保存可复现证据并增加失败回归，再实施窄修复。不得通过降低隔离、权威性、长度或证据标准让测试通过。

清理候选包括：

- 旧人物简化编辑表单和旧大纲正式人物编辑入口；
- 重复的人物实例档案表单；
- QwenPaw 私有 usage buffer 兼容路径；
- Context V3 新任务生产依赖和重复快照字段；
- semantic-search v1 内部调用者及重复词面/RRF 实现；
- 把 Alembic 当前 head 写死为某个精确值的功能门禁；
- 按人物姓名猜测稳定实体的生产逻辑；
- 生产代码中的样书人物、地点、关系与情节关键词；
- 已证明无调用者的重复写作人物卡适配代码；TTS 专属适配器不在本计划清理。

删除前必须证明无调用者、无独立契约价值、不是迁移／历史证据且不属于用户未提交改动。旧 generation、revision、迁移、恢复记录和原始验收证据不得作为冗余删除。

## 七、施工波次

1. **W0：共享锁释放与写作基线门禁**
   等待其他任务释放共享文件和迁移锁；冻结 Git 提交、迁移 head、包 hash、数据库与长期运行状态，但不运行 TTS 验收。
2. **W1：只读主链审计与 fixture**
   建立入口矩阵、三章样本、查询标签、泄漏负例和恢复说明，不调用真实模型。
3. **W2：自动化纵向链路**
   使用 stub 完成建书、大纲、人物、三章、StoryFact、增量索引、审稿和选区触发矩阵。
4. **W3：最小真实联合 E2E**
   取得当次授权后，只对独立合成小说执行三次正文生成和必要百炼索引／查询。
5. **W4：证据驱动的窄修复**
   按安全、权威、连续性、长度、降级和 UI 顺序修复；默认不改 schema。
6. **W5：旧路径与重复代码清理**
   完成调用者审计、删除和专项回归。
7. **W6：安装、三视口与最终裁决**
   备份后安装长期 PawApp，执行只读运行核验并给出 PASS／HOLD。

# 开发计划 61：语音模型接入入口与多渠道配置页面

状态：**V1.1 已部署至长期 `18088`／`20260908_0044`，页面复核通过，但 W3 完整生命周期验收未关闭。收尾已消除6项 TypeScript 错误、修复并通过11项 Skill 注册检查；继续隔离验证发现新建书籍因旧音色数据库约束返回500，需新增兼容迁移后重验。W4 真实云端 TTS 调用继续等待作者配置完成后的再次授权。**

日期：2026-09-08（Asia/Shanghai）

## 1. 目标与边界

在“创作中心”增加与“向量模型接入”并列的“语音模型接入”入口，集中管理本地 Qwen3-TTS 状态和云端 Qwen TTS 渠道。解决以下问题：

- 不再要求作者通过 `.env` 配置云端 Base URL、模型和 API Key；
- 可保存多个会员渠道，域名不锁定为阿里云官方后缀；
- 同时只激活一个云端渠道，作者主动切换，不建设自动路由；
- 每个渠道可配置“质量优先”和“速度优先”两个模型槽位及真实模型 ID；
- API Key 只写入加密密钥保险箱，页面不回显明文；
- 保存或编辑配置不会自动调用、不会产生费用；连接和模型实测必须由作者显式触发；
- 单本小说继续只负责本地／云端选择、质量／速度选择和作品级云端授权。

本计划是计划 59 的云端配置补全，不改变本地 Qwen3-TTS 模型、分段任务、Edition、缓存、播放器或 QwenPaw 上游。

## 2. 施工前实现事实与缺口

- 创作中心当前只有“私有库”和“向量模型接入”，入口位于 `frontend/src/creative-center.ts`。
- 云端 TTS 施工前由 `QWEN_TTS_ALIYUN_BASE_URL`、私有 API Key 文件和 `QWEN_TTS_ALIYUN_PRODUCT_ENABLED` 构建运行时 Provider，修改后需要重启。
- `AliyunQwenAudioTTSProvider` 施工前只接受 HTTPS 且域名以 `.cn-beijing.maas.aliyuncs.com` 结尾；这能保护官方路径，但无法覆盖使用相同协议的其他会员渠道。
- 作品朗读设置已经支持显式选择本地／云端和 Plus／Flash，但尚未保存“云端渠道配置档案”。
- 本地 Provider 当前健康且已真实生成音频；迁移后的长期环境仍缺一次“真实章节生成到播放”的最终验收。

## 3. 产品裁决

### 3.1 创作中心入口

在现有两个入口后新增第三项：

```text
创作中心
├── 私有库
├── 向量模型接入
└── 语音模型接入
```

- 名称固定为“语音模型接入”，避免把页面误解为单本小说的朗读设置。
- 图标复用宿主 Ant Design 的声音类图标，不增加图片资源。
- 点击后进入 PawApp 自有页面；返回按钮回到创作中心，不占用 QwenPaw 全局设置路由。

### 3.2 页面布局

页面保持桌面优先、窄屏可单列，不复制向量页的候选索引流程：

```text
← 返回创作中心                         语音模型接入

[本地 Qwen3-TTS]
状态 / 当前模型 / revision / 启动提示        只读

[云端渠道]
渠道 A（使用中）   已验证   编辑  停用
渠道 B             未验证   编辑  验证  启用
                                         + 新增渠道

[渠道编辑抽屉或卡片]
渠道名称        [会员渠道 A]
接口协议        [Qwen-Audio 原生 HTTP v1，只读首期]
Base URL        [https://...]
质量模型 ID     [qwen-audio-3.0-tts-plus]
速度模型 ID     [qwen-audio-3.0-tts-flash，可留空]
API Key         [只写；留空保持原 Key]
                保存配置   测试质量模型   测试速度模型
```

状态只使用：`未配置`、`未验证`、`验证中`、`已验证`、`使用中`、`不可用`。测试失败保留原激活渠道和所有历史 Edition。

### 3.3 多渠道最小规则

1. 可以保存多个渠道配置，但一个 workspace 同时只能有一个 `active` 云端渠道。
2. 切换激活渠道只影响以后新建的朗读任务；历史 Edition 继续引用原渠道、模型与生成证据。
3. 不按余额、价格、延迟或失败自动换渠道；失败后由作者重试或手动切换。
4. 首期只支持已经实现的 Qwen-Audio 原生 HTTP 协议。同一协议的代理渠道可以更换域名和路径前缀；如果会员渠道使用另一种请求／响应协议，必须新增窄适配器，不能假设“改域名就兼容”。
5. 渠道只提供一个模型时允许仅填写“质量模型”；未配置的模型槽位不在小说设置中展示。
6. active 渠道不得直接修改域名、Key、协议或模型，必须先停用；激活另一个渠道时在同一事务撤销已有云端 TTS 作品授权，作者必须针对新渠道重新确认，不能把对渠道 A 的授权静默复用于渠道 B。

## 4. 配置与数据契约

新增一张 `tts_cloud_profiles` 表即可，不建设渠道、密钥、模型三套表。建议字段：

- `id`、`owner_id`、`workspace_id`、`name`；
- `protocol`，首期固定 `qwen_audio_native_http/1`；
- `base_url`；
- `credential_ref`、`api_key_last4`、`api_key_updated_at`；
- `quality_model_id`、可空 `speed_model_id`；
- `verification_fingerprint`、`quality_test_state`、`speed_test_state`、`last_tested_at`、脱敏失败码；
- `lifecycle_state`：`draft/verified/active/disabled`；
- `version`、`created_at`、`updated_at`。

约束：同一 workspace 渠道名唯一；使用 PostgreSQL partial unique 保证最多一个 `active`；所有修改使用 CAS `expected_version`。编辑 Base URL、协议、Key 或模型 ID 后立即使旧验证失效，但不修改历史生成证据。

运行时解析冻结为：

```text
小说 TTS 选择
  + 当前 active 云端 profile
  + 质量/速度槽位
  -> 精确 Provider(profile_id, protocol, base_url, actual_model_id, credential_ref)
```

Edition、请求证据与缓存身份必须包含 `profile_id + profile_version + protocol + actual_model_id + base_url_fingerprint`。不同渠道不共享音频缓存，URL 明文和 API Key 不写进生成日志。

为减少迁移，单本小说现有的 `aliyun_model_id=qwen-audio-3.0-tts-plus/flash` 暂时保留为“质量／速度逻辑槽位”，不改已有作品设置 JSON；active profile 在真正调用前把逻辑槽位映射成该渠道填写的真实模型 ID。切换渠道后既有作品无需批量改写，下一次生成会冻结新的 profile 与实际模型证据；历史 Edition 不变。

## 5. API 与交互

PawApp 自有 API 建议为：

- `GET /api/ai-novel-world-2026/tts-cloud-profiles`
- `POST /api/ai-novel-world-2026/tts-cloud-profiles`
- `PATCH /api/ai-novel-world-2026/tts-cloud-profiles/{profile_id}`
- `POST /api/ai-novel-world-2026/tts-cloud-profiles/{profile_id}/test`
- `POST /api/ai-novel-world-2026/tts-cloud-profiles/{profile_id}/activate`
- `POST /api/ai-novel-world-2026/tts-cloud-profiles/{profile_id}/disable`
- `DELETE /api/ai-novel-world-2026/tts-cloud-profiles/{profile_id}`，仅允许删除非 active 且无在途任务引用的配置；先提交权威配置删除，再尽力清理加密记录，清理失败只留下不可引用的加密孤儿记录，不复活配置。

API Key 是 write-only 字段；GET 只返回“已配置”、末四位和更新时间。测试接口必须带测试模型槽位、配置版本、幂等键及显式 `billing_confirmed=true`，使用固定短句或作者输入的非敏感短句生成一次临时 WAV，不自动保存为小说媒体，也不自动激活渠道。

## 6. 域名开放与安全边界

取消 `.cn-beijing.maas.aliyuncs.com` 后缀锁定，但不允许任意危险 URL：

- 只允许 HTTPS；允许规范化的非根路径前缀，以兼容会员网关；
- 禁止 URL userinfo、query、fragment、非法端口、控制字符和超长 URL；
- 禁止 localhost、回环、链路本地、私网、保留地址及解析后落入这些地址的域名；请求前重新校验，禁止自动重定向；
- HTTP 客户端关闭环境代理继承，响应体和音频大小有上限；错误只返回稳定脱敏码；
- 配置页明确提示：第三方会员渠道会接收合成文本及所选参考音频，数据政策和费用由该渠道决定；作品级同意仍是调用前硬门禁。

本地 Provider 继续固定走 `host.docker.internal` 与本机令牌，不复用云端自定义 URL 能力。

## 7. 密钥与迁移

- 复用现有 AES-256-GCM 密钥保险箱机制，抽取为项目级窄组件后由向量和 TTS 使用不同 namespace；不复制一套未审计加密实现，不新增依赖。
- 根密钥继续位于 QwenPaw 私有 secret volume；数据库只保存不透明 `credential_ref` 与末四位。
- 新增 Alembic revision，施工时必须基于唯一 head；当前候选 head 为 `20260908_0043`，暂定下一 revision 为 `20260908_0044`，不得改写历史迁移。
- 旧 `.env` 云端配置不自动导入数据库，避免在迁移日志中接触密钥。新页面激活配置后，移除运行时对旧 Base URL、API Key 文件和发布开关的依赖；配置缺失时云端严格不可用，本地不受影响。

## 9. 验收门禁

施工候选门：

1. 创作中心第三入口、返回路径、桌面与窄屏均可用。
2. 可新增多个渠道，但数据库和服务层始终最多一个 active。
3. Base URL 不锁域名，安全负向测试完整；不同协议不会被误判为可用。
4. Key 不进数据库明文、响应、日志、DOM、Git、`.env` 或错误消息。
5. 保存／编辑不触发云端调用；测试按钮明确提示一次调用可能计费。
6. 渠道切换不修改历史 Edition，不跨渠道命中缓存，不静默回退。
7. 禁用/卸载 PawApp 后不残留路由包装，不影响 QwenPaw 原生功能。

真实模型门（必须等待作者配置）：

1. 作者明确指出要测试的渠道和质量／速度模型。
2. 使用无版权、非小说正文的固定短句分别生成，确认 HTTP 成功、实际模型身份、WAV 元数据和可播放性。
3. 作者听检短样音后，再用测试小说执行本地最小章和云端最小章；检查切换、缓存隔离、失败恢复和作品级授权。
4. 未通过的渠道保持 `verified/active` 之外的状态，不自动切换到本地，也不影响本地朗读。

## 10. 非目标

- 自动选择最便宜、最快或剩余额度最多的渠道；
- 余额、套餐、价格、账单或调用量抓取；
- 同时激活多个云端渠道或失败自动回退；
- 在首期猜测并兼容所有 OpenAI、阿里云或第三方私有协议；
- 把全局密钥放进单本小说设置；
- 修改 QwenPaw 核心或新增第二套任务队列、数据库、前端框架。

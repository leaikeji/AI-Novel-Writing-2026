## 0. 结论先行

本计划以人物卡“声音”标签页为主要对象，对共用官方音色组件做前端减重和可访问性收敛；不重写已经运行的 TTS 领域能力。由于同一组件还出现在朗读音色库及旁白目标中，施工必须同时完成三个既有挂载入口的非回归验收。

最终页面必须保持以下产品能力不变：

- 18 个官方音色可搜索、按语言筛选、试听并零确认直接使用；
- “根据人物卡匹配并使用官方音色”仍是一次点击完成；
- “生成并使用人物专属音色”仍是真正的 VoiceGenerator 新音色链路；
- 私人音色创建、技术验证、人物绑定与删除生命周期不变；
- 任何失败都不得改变原绑定，既有 CAS、幂等和并发保护不变。

本轮只解决七个已经有真实页面证据的问题：

1. 同一官方音色同时由 radio 和“用于人物”按钮执行同一个写动作；
2. 当前音色行同时显示选中 radio、`当前使用`标签和禁用的`当前使用`按钮；
3. “直接使用、试听非前置”的空闲提示重复；
4. 总数、语言数和无搜索条件下的显示数重复；
5. 高级私人音色区三次重复“官方音色请在上方使用”，并存在两层同义标题；
6. 声音标签页已有局部保存，人物卡 footer 仍常驻显示无效的外层撤销和保存；
7. 高级区视觉折叠后，内部控件仍挂载、加载并进入语义树。

计划同时处理前次自查确认的两个伴随问题：移动窄屏音色行过长、radio 可见圆点只有 18×18px，以及根 README／文档索引仍描述旧六音色范围。

## 2. 目标与非目标

### 2.1 本轮目标

- 每个官方音色只有一个“应用此音色”交互控件和一个 `onUse` 调用路径。
- 保留选项式体验：radio 和其文字标签形成至少 44px 高的可点击区域；点击文字或按 Space 直接使用，不增加确认步骤。
- 当前音色只保留 checked radio、非颜色的`当前使用`标签和行背景，不再显示禁用的同义按钮。
- `试听`和`详情`继续是独立操作，绝不触发绑定。
- idle 状态不再常驻显示重复灰条；应用中、成功、失败、冲突和试听状态仍由稳定 live region 播报。
- 无搜索条件时只显示总数和语言标签中的分组数量；有搜索条件时才显示过滤后数量。
- 高级私人音色区只保留一次官方音色去向说明和一个来源步骤标题。
- 高级区首次打开前不发起私人音色 workspace 数据加载；关闭时内部控件不出现在可见布局、Tab 顺序或辅助技术语义树中。
- 声音标签且人物卡草稿未变更时，footer 只保留`关闭`；如果其他标签存在未保存的人物卡修改，则保留外层撤销／保存并明确它们只处理其他人物卡字段。
- 390×844 下官方音色行的选择区单独成行，`试听／详情`并排，减少纵向高度且无横向溢出。
- 更新当前事实摘要：18 个官方音色直用、当前已应用的线性迁移链包含 `0035`、VoiceGenerator 产品链路已运行但作者主观听检仍是独立结论。执行时重新读取实际 Alembic head，不把“必须恰好等于 `0035`”写成运行门禁。

### 2.2 非目标

- 不修改后端 API、DTO、数据库、Alembic、Sidecar、VoiceGenerator、Nano 推理参数、模型 revision 或媒体存储。
- 不改变匹配算法、生成算法、官方目录顺序、语言分组或试听音频。
- 不增加版权、语言、试听、质量或二次确认门禁。
- 不合并“匹配官方音色”和“生成全新专属音色”；两者结果不同，必须继续分别展示。
- 不删除顶部关闭 X 或底部`关闭`；它们是标准弹窗双关闭入口。
- 不删除`试听`、`详情`、搜索字段标签或搜索占位提示；这些承担不同任务。
- 不改写计划 18、T4、计划 35／40 或既有验收原始证据。

## 3. 冻结交互契约

### 3.1 官方音色行

每一行固定为：

```text
[44px+ 选择区：radio + 音色名称 + 性别/语言 + 当前状态]
[试听]
[详情]
```

约束：

- radio 与文字通过原生 `label` 关联；只让选择区触发 `applyVoice()`。
- 所有可选项继续属于同一个原生 radio group；点击 radio、关联 label、Space 或方向键切换到另一可用项时，每次用户动作最多触发一次 `onUse`。
- 删除独立的“用于人物／用于旁白／当前使用／重试使用”按钮和其专用样式，不保留隐藏兼容按钮。
- 当前 radio 保持 checked 且可聚焦；再次点击当前项不发送请求。
- 只有长期不可用的音色使用原生 `disabled`。应用中的短暂忙碌使用 `aria-busy`／`aria-disabled` 和现有处理器守卫阻止第二次写入，不把触发 radio 移出焦点顺序。
- 应用成功、可重试失败或 CAS conflict 后，焦点保留在发起动作的 radio；若用户已主动把焦点移出音色库、scope 已变化或组件已卸载，则不得强行抢回焦点。
- 失败后再次选择同一未应用项仍可重试，并生成新的既有幂等键；一次用户动作最多调用一次 `onUse`。
- `试听`和`详情`位于 label 外，不得因事件冒泡触发选择。
- 现有 `aria-label` 必须继续包含目标人物或旁白和音色名称；语言、跨语言提示和技术来源继续放在详情中。

### 3.2 状态、计数与当前声音

- 音色库标题说明保留：`按语言查看并直接使用；试听可选，技术来源收在详情中。`
- live region 在 idle 时为空且不占用可见灰条；`applying / applied / error / conflict / preview` 才显示并播报消息。
- `18 项`保留为目录总数；语言按钮保留`中文（6）／English（5）／日本語（7）`。
- 搜索字符串 `trim()` 后非空时显示`当前显示 N 项`；未搜索时隐藏视觉计数。另保留一个不占布局的结果状态节点，在搜索或语言筛选变化后向辅助技术播报当前结果数；空结果仍显示现有可恢复空态。
- 当前声音卡删除`当前绑定` eyebrow，保留`当前声音`标题、状态 badge、音色名称和来源／语言。

### 3.3 高级区挂载与折叠

使用“首次打开时激活，之后保持组件状态”的策略：

1. 初始 closed：高级 body 不挂载，不加载 `VoiceSourceWorkspace` 或 `CharacterVoicePanel` 数据。
2. 第一次 open：设置 `advancedActivated=true` 并挂载内容。
3. 再次 close：内容可保持挂载以免中断已开始的生成／保存状态，但必须由明确的关闭态 CSS 从布局、Tab 顺序和辅助技术树隐藏。
4. 再次 open：恢复同一暂态，不重复初始化或丢失进度。
5. 小说／人物 scope 使用 `novelId:characterId` 组成稳定 `scopeKey`；高级区状态放入以该 key 为 React `key` 的 scope-local 子树。scope 变化时同步卸载旧子树并创建新的 closed 子树，不能只依赖提交后执行的 effect 清理。
6. 新 scope 首次渲染不得出现上一人物的 DOM、可访问名称、暂态或请求参数；旧 scope 的异步完成结果也不得写入新 scope。

防御性 CSS 必须显式覆盖关闭态，不能再只依赖浏览器 UA 样式：

```css
.anw-character-voice-advanced:not([open]) > .anw-character-voice-advanced__body {
  display: none;
}
```

验收必须同时证明“首次关闭不加载”和“打开后再关闭不进入可见／可聚焦语义树”，不能只检查截图高度。

### 3.4 私人音色文案层级

- workspace 顶部只保留一次：`这里只管理当前作品的私人音色；官方音色请在上方直接使用。`
- idle 加载状态只写`私人音色档案已加载。`
- 外层步骤标题保留`2. 选择音色来源`。
- 嵌套 `VoiceSourcePanel` 在 embedded 模式下不再渲染第二个`音色来源`标题和重复去向说明；其独立使用场景默认行为不变。
- embedded 模式必须通过判别式 props 强制接收外层步骤标题 ID，例如 `embedded: true` 与 `ariaLabelledBy: string`；外层标题 ID 必须稳定且在当前 scope 内唯一，section 的 `aria-labelledby` 必须指向该真实节点。独立模式继续渲染自己的标题和有效引用，不允许使用指向已删除节点的兼容 ID。
- `文字描述生成`、`选择来源`、`生成试听`、`确认并锁定版本`和`取消`均承担独立状态机动作，继续保留。

### 3.5 人物卡 footer 保存归属

| 当前标签 | 人物卡 dirty | Footer |
| --- | --- | --- |
| 基础／本线档案 | 任意 | 保持现有撤销、关闭、保存人物卡 |
| 成长与状态 | 任意 | 保持现有只读语义 |
| 声音 | `false` | 只显示关闭，不显示禁用的撤销／保存人物卡 |
| 声音 | `true` | 显示提示“其他栏目还有未保存修改”，并保留可用的撤销／保存人物卡和关闭 |

声音组件内的`保存人物声音`继续只保存声音绑定；外层`保存人物卡`继续只保存人物基础／档案草稿。不得让任一按钮偷偷同时提交两套状态。

### 11.1 已修正的方案风险

- **不能无条件隐藏人物卡保存。** 已改为 `activeTab=voice && dirty=false` 才隐藏；其他栏目有未保存修改时继续提供真实保存能力。
- **不能用纯 CSS 假装懒加载。** 已冻结首次展开才挂载；展开后关闭保留暂态，但由显式关闭态 CSS 隔离布局和语义。
- **不能删按钮后缩小可用区域。** radio 与文字 label 组成 44px+ 选择区，移动端同时减少一行操作。
- **不能删除 idle 文案后失去状态播报。** live region 结构保留，只在有实际状态变化时显示和播报。

- **不能越界修复共享工作区。** 全量失败必须区分计划 44 与其他未提交计划，禁止借机修改无关文件。

## 1. 核心决定

**不重建框架：让作者集中做“定方向、写这一章、读改正文、确认变化”，让已有数据与保护机制在后台服务这四件事。**

- 保留：唯一故事账本、人物与规划的权威来源、按需检索、工作稿、不可变版本、来源、CAS和恢复。
- 精简：串行填表、唯一项选择、重复确认、生成后立即催同步、每章检查全部管理页。
- 修复：审稿来源混用、长度自动重写、局部修改阻断、保存和来源显示失真。
- 补足：任务用对资料和方法；结果既要符合事实，也要作为小说可读。
- 不增加：数据库、向量系统、运行时、队列、Agent、模型选择器、逐模型Skill或一套新的质量评分平台。

这四件事是作者任务，不是四个必须逐页点击的新向导。优先合并现有页面、抽屉和折叠区。

首批产品修复仍建议聚焦第4节A—D，不绑定全站重构。设计规划则扩大为第6节的完整写作页面与状态，取消“四视图足够”的限制，先画正常写作工作台再画审改分支；E及扩展F的代码仍是后续候选。恢复／导出先核验现有能力，有缺口再修，不因重新设计而删除。

## 3. 从建书到续章的取舍

| 环节 | 拟议处理 | 对写作的帮助／完成判断 |
| --- | --- | --- |
| 书名、题材、创意、受众 | 合并基本信息；创意原文保留，受众可稍后定；短篇未开放时明确说明，不做假入口 | 有明确书名和方向即可建书；不先强迫市场标签或模型模板 |
| 模板、取名、封面 | 改为可选；文字封面默认；保留现有可用辅助能力，不扩建AI封面 | 手填书名建书0次生成调用，无模板也能继续；没有重复完成屏 |
| 背景、人物、全书走向、简介 | 模块独立手填／生成／采用，可分次补；已有作品编辑正式来源，不重新导入旧草稿人物 | 改一个模块不重做其他模块；未知人物秘密和总章数不强迫编满 |
| 分卷 | 首次建章可同时创建默认卷；多卷管理保留 | 不因0卷阻止首章；沿用幂等和规范章序，不产生重复默认卷 |
| 本章意图、章纲、长度 | 同一章前准备区，意图前置；允许直接手写，章纲可选生成或手填 | 不再走六步；有明确写作要求时不强迫先生成章纲；输入不足只指出缺少什么，不伪造章纲占位 |
| 人物、线路、伏笔 | 相关资料折叠可改；唯一有效主线预选，不调用推荐；空伏笔不占独立步骤 | 常用续章不重复填同一选择；沿用偏好可改，不强制每章同一阵容或推进每条线 |
| 人物新增与退场 | 清楚区分可提及背景人物、可新增关键人物与可决定重要人物退场；不默认授予重大变化 | 不按名字数量判错，不让勾选含义超过作者理解；人物退场不删除其历史 |
| 素材与检索 | 素材成为可选区，当前绑定和采用范围可见；按任务取用已有资料 | 无素材可直接写；不硬塞素材，不把未来计划当已经发生的事实 |
| 生成、阅读、审改 | 一个正文主入口；成功先展示结果；审稿可定位，局部修改可比较与采用／取消 | 作者先读文章；失败保留原文和修改要求，不以整章重写替代局部修改 |
| 保存、同步、下一章 | 自动保存继续；明确工作稿状态；“确认本章变化”为独立显式动作，可稍后处理 | 保存不隐含模型调用、角色删除或事实采用；下一章提示未确认变化但不制造假事实 |
| 账本、人物卡、故事线 | 默认显示事实、人物所知（有依据才显示）、未解决点、来源章节；技术详情折叠；移除误导完整度与无定义百分比 | 来源章号正确；不再提示已有身份“待补”；作者无需为填满表而创作 |
| 关系图、时间线、索引、历史、导出 | 管理能力按需打开；补清楚恢复入口和下载结果 | 普通续写不巡检所有页；能找到手改历史；导出实际内容、编码、章序与落盘可核对 |

偏好继承先复用已有作品／章前数据，不新增偏好表；跨会话尚不能可靠继承的项要明确说明，不靠浏览器缓存假装服务端已保存。规划可选、字段可空所需的后端校验变化必须在施工前冻结，不能只把前端控件藏掉。

已核实的前置限制：`complete_novel_creation_draft`现在要求male/female受众、模板和作者名；`complete_chapter_creation_draft`要求有效分卷和非空章纲。数据表允许部分空字符串，不等于各入口已兼容。E包必须统一创建、修改、恢复、提示与生成入口对“未定／未填”的解释；不得用默认男频、虚构模板或占位章纲伪装可选。作者名本次保留现有要求，不把“书名和方向即可”误解为已经消除全部必填项。短篇、可选总章数与人物政策字段不因画在图上即自动实施。

技术容量限制保留但说明依据，作者目标不是容量上限。一次显式生成只启动一次写作生成尝试；长度不合适、输出格式无效或失败均保留可恢复结果／状态，由作者决定重试。普通HTTP幂等重放不新开模型任务，云端向量查询另行记录，不把应用job数称为Provider计费总数；不启用计划58的辅助语义调用。

A—D不必等高保真设计才能定位，但仍需明确施工批准；E涉及布局，先确认关键视图。删除旧分支前证明无调用者且不覆盖独立合同，旧job／历史revision继续可读，不顺手删历史证据。

### 首批必须冻结的三个端到端合同

1. **长度提醒不是丢弃正文。** 当前`complete_chapter_generation`在候选创建之前将超／欠长任务置failed；`adopt_candidate`又强制`meets_target`和长度范围。B必须覆盖前端、Pydantic、提示、结果保存、列表、采用校验和历史读取，不能仅去掉重试循环。新任务可复用既有ready候选和below/above长度标签，但状态组合及旧失败任务兼容先在W0确认；不凭空恢复从未保存的旧失败输出。空输出、模型不一致、越权、容量溢出、CAS冲突仍不允许采用。历史快照／哈希不变，新旧长度政策显式区分，不把旧验收规则静默改写。
2. **生成不等于采用。** 当前`chapter-workflow.ts`收到候选即调用`/candidates/{id}/adopt`，后者创建`ai_candidate_adopt`正式revision并协调故事事实。目标是先展示候选，由作者明确采用；沿用已有采用事务与CAS，不发明“只进工作稿”却实际改正式版本的中间状态。生成、取消或仅阅读不得更新正式版本和账本；采用后对旧事实的协调应可解释。必要的一次采用操作不是应删除的重复确认。
3. **审稿必须区分定位证据与意见。** 当前review输出的`evidence`是自由文本，没有可靠的逐句锚点。不能只加“跳到原文”按钮。W0需冻结可选的准确引文／来源字段及其服务端校验，保留旧报告只读兼容；唯一匹配才可直接定位，重复匹配让作者选择，无匹配标待核实。整体节奏和人物声音等意见可无单句锚点，但不得冒充硬事实错误。定位结果绑定待审版本，作者已修改正文时旧报告显示过期，不把旧偏移套到新稿。

正文归档、保存、恢复仍保持现有权威模型；本方案没有取消revision或让新草稿直接冒充故事事实。

## 5. 数据与Skill的最小职责

| 本次任务 | 主要资料 | 方法与输出边界 |
| --- | --- | --- |
| 建书／完善设定 | 作者原始创意、当前已确认设定、所改模块 | 任务基础方法给候选，不替作者填写未知真相 |
| 拟章纲 | 本章目标、前章必要承接、相关人物／线路／伏笔 | 章纲方法给可写安排，不固定场景数、字数和反转 |
| 写正文 | 作者要求、已确认事实、必要前文、可用计划与章纲 | 正文方法为主；适用的分类方法补充，不把资料字段写成小说对白 |
| 审稿／局部修改 | 精确正文版本／选区、必要参考及修改要求 | 审阅或编辑方法；事实错误与读感建议分开；引用能回到原文 |
| 同步变化 | 作者选定的章节版本、已有事实及实体 | 仅抽取有证据的候选，不加载鼓励新增情节的方法，不自动采用 |

“使用资料”不等于“全部送入模型”。相关事实走现有确定性来源；长前文与素材可走已有检索；不用向量相似度判断真伪。作者意图优先于通用写法，但与已确认事实冲突时需明确提出修订选择，不静默改旧真相。允许参与、必须出场、背景参考不得混用。

保留通用方法＋分类补充方向；先核实既有五种任务的实际映射和方法内容能否通过公开契约送达，不为证明装载读取宿主私有数据。新增分类继续由现有批准目录管理；本轮不重做自动路由，不开发单书Skill。确需改Skill正文、manifest或安装行为，另列精确切片并通过相关合同与生命周期验证后才实施。

拆书只提供有来源的“方法、适用条件、反例”，不写死原书桥段。没有对照不宣称账本、检索或分类方法独立提高文笔；先修好数据与审改，再对具体问题做小范围验证。

检索保真边界：当前`markdown_to_text`会删除连字符等字符，索引又读取历史revision的`content_text`。仅改snippet拼接无法保证原标点恢复；检索chunk的偏移也不能直接当Markdown原文偏移。A优先把命中当定位线索，按已校验的作品／版本范围回查不可变`content_markdown`核验引文；无法准确还原则降级为参考，不猜标点或宣称精确定位。不得为了这次修复批量改历史`content_text`、哈希、字数或重建全部索引；确需改变全局渲染／坐标契约时另设门禁，不混入局部修复。去重依据来源版本及区间，不删除小说原本就存在的有意重复句。

## 6. 页面重设计：以正常写作为主，不以审改卡片为主

### 6.1 修正依据与范围

V1.1 曾补齐AI入口，但仍把“正文页”画成一小段正文和两句Diff，缺少完整编辑器常态、长文滚动、稳定工具栏、旧章回改与续章路径；其他页面未形成能力去向。上一轮“只补几个状态即可”的判断不足，本次改为重新设计页面结构与交互，不在旧稿上继续堆按钮。

已核实事实：本次在长期18088只读打开创作中心、章节列表、正文、生成历史、大纲、人物列表/卡片、线索、设定和账本，保存10张[新截图与记录](../../audit/写作全流程实用审计-20260908/页面重设计复查/README.md)。当前正常编辑器确有目录搜索/折叠、保存、复制、重新生成、修改章纲、同步和历史入口；不能由新图未画出推断可删除。当前视口1267×713，宿主导航和作品区域共同占用空间；管理页大封面及独立滚动挤压内容。账本首屏主要是统计与筛选，正文事实在下方。

设计目标：保留作者的操作能力与熟悉路径，重做布局和入口层级。没有“按钮越少越好”或“只能四页”的指标；每项功能必须标明保留、合并、移位或删除理由。未覆盖的旧能力先保持原入口。TTS及QwenPaw原生管理界面不重设计、不移除。

### 6.2 正文工作台必须先画的常态

- 主区是连续、可编辑的整章，不是正文节选卡片。正常状态不常驻大块Diff和审稿意见。用《雾宅来信》完整章节验证首、中、尾滚动，另用明确标注的长文布局夹具，不冒充新生成小说。
- 顶部稳定工具区：作品/章名、保存状态、保存版本、上一章/下一章；尾章提供准备下一章。已有章跳转只保证工作稿安全，创建下一章不能暗含生成。删除移入“更多”，复制明确区分正文与AI上下文，不保留含义模糊的单一“复制”。
- 左侧是可搜索、可折叠的卷章目录，能返回章节管理、定位当前章。收起后仍有可发现的展开入口，不要求回首页才能换章。
- AI生成、重新生成、审稿、选区AI修改、章纲/本章要求、故事变化、历史与资料均可发现。高频操作在工具区或选区浮层；详情按需打开，不把按钮都藏到聊天或多级菜单，也不固定占据全文右侧。
- 审稿或资料侧栏打开时仍能读完整正文；空间不足改用可关闭的面板/覆盖层，保留原文定位与返回位置。宽度按PawApp可用容器而非浏览器总宽度决定，不在宿主旁再硬塞固定三栏。不改宿主核心。
- 修改候选按整章/选区明确作用范围，正文与候选切换不丢输入、选区和滚动位置。生成不是采用；采用已有事务创建正式revision后，无额外手改不再逼作者重复“保存”同一内容。自动保存工作稿、保存正式版本、确认故事事实仍是不同动作，用作者可懂的状态说明。
- 无关空面板不占位；默认不弹审稿、不催同步、不自动重写。常用撤销/重做、选择、复制粘贴、输入法与键盘支持沿用现有编辑器能力并补验证；不借重设计更换编辑器或新增富文本框架。

### 6.5 设计顺序和通过标准

1. 先完成旧操作→新位置的清单及正常编辑器设计；由作者评审实际能否持续写作，不先铺全站高保真。

3. 按6.3逐组重设计建书/章前/卷章、大纲/人物/故事记录/素材设置，复用已认可的导航和面板，不重复发明布局。每组补齐正常、空态、编辑和失败/返回，不只交默认截图。
4. 检查宿主存在时的1920×1080、当前约1267×713桌面窗口、390px窄屏；目录收合与面板打开都要看正文可用宽度。实际验证键盘焦点、Escape返回、滚动恢复、中文输入法、未保存切章；静态稿不宣称无障碍通过。

# 开发计划 73：章节生成与朗读连续播放局部刷新优化

状态：**V1.0 已实施并部署至正式 `18088`；自动化与桌面真实播放通过，未触发新的正文或 TTS 模型生成。**

日期：2026-09-12（Asia/Shanghai）

## 1. 目标与边界

本计划只修复章节页两类前端连续性问题：

1. TTS 生成期间，进度轮询不得清空并重建整个朗读会话；生成进度和播放进度只更新各自变化的值。
2. 章节正文 AI 生成期间，既有正文编辑器和朗读会话不得因生成状态被卸载；作者可以继续听已经生成的不可变朗读版本。
3. 已经有合法连续 ready range 时，作者点击一次播放即可边合成边听；到达 pending 缺口时等待同一句段，准备好后自动继续，不跳过缺口。

不修改数据库、Alembic、TTS Provider、本地或云端模型、媒体格式、正文生成协议和 QwenPaw 上游；不新增后台队列、第二套播放器或页面。仅验收桌面 Web，不新增手机或平板范围。

浏览器不允许页面在没有用户手势时擅自开始播放。“边生成边听”冻结为：作者首次明确点击播放后，当前会话可以连续消费随后完成的句段；若浏览器阻止长时间等待后的自动恢复，保留明确的“继续播放”入口。

## 2. 已核实现状与根因

- `frontend/src/workbench-v2.ts` 的 `editorShouldMount` 同时依赖 `!bodyGenerationState.active`。正文生成开始后编辑器被卸载，依赖编辑器 bridge 的朗读 session 随 effect cleanup 执行 `dispose()`，播放器因此停止。
- TTS 生产中的通用轮询每 2.5 秒调用 `session.refresh()`；该方法转入完整 `load()`，先执行 `teardownRuntime()`，再把 `bundle`、`playerState` 和界面 phase 清成 loading，造成生成进度条和播放进度条反复消失、重建。
- `ChapterNarrationSession` 已有同 Edition、同 source、递增 Manifest revision 的 `adoptPolledManifest()`，可以原地更新播放器而不重建会话，但当前只服务于等待某一目标句段的路径，没有用于通用生产轮询。
- 计划 50 和 ADR-0006 已冻结“部分可播”“只在句段边界接纳新 Manifest”“不跨 pending/failed 缺口”的产品语义；本计划修复实现偏差，不重做产品设计。

## 3. 冻结后的用户行为

| 场景 | 目标行为 |
| --- | --- |
| TTS 正在生成、尚无合法 ready range | 只显示稳定的生成进度，播放按钮不可用；进度更新不清空播放器区域 |
| 已出现合法 ready range | 播放按钮立即可用，作者可从合法起点播放 |
| 播放时有新句段完成 | 当前音频和播放位置不变；只原地更新 Manifest 与生成进度 |
| 播放追上 pending 缺口 | 停在该句并显示“等待生成”；就绪后自动从该句继续 |
| 缺口变为 failed/cancelled | 停止等待并显示具体失败；不静默跳到后文 |
| 作者暂停时后台继续生成 | 保持暂停位置；Manifest 可以更新，但不得自动起播 |
| 正文 AI 正在生成 | 既有正文保持可见但暂时不可编辑，朗读控制和音频继续工作 |
| 新正文正式采用 | 旧朗读继续按不可变 Edition 播放，并显示“朗读内容与当前正文不一致”；不得把旧高亮贴到新正文 |
| 切章、关闭编辑器或卸载插件 | 仍按现有规则真正释放播放器、请求和定时器 |

## 4. 最小实现方案

### 4.0 三条实现不变量

施工与验收统一以以下不变量为准，避免把“React 重新执行 render”误判为页面被重建：

1. **实例稳定**：同一章节、同一编辑器 generation、同一 Edition 内，Manifest 进度变化不得改变 editor surface、`ChapterNarrationSession`、player 或当前音频请求的对象身份；React 可以计算新视图，但只能 patch 发生变化的状态区 DOM。
2. **双 revision 角色**：`currentBundle.manifest` 表示客户端最新观察到的 Manifest；`player.lease` 表示当前正在播放请求实际锁定的 Manifest revision。前者可以先推进，后者只在当前 ready window 的句段边界结束旧请求后接纳，二者短暂不同是合法状态。
3. **续播必须有用户意图**：只有作者明确点击播放后建立的连续播放意图，才能在 `PENDING_GAP` 就绪后自动恢复；暂停、停止、切章、重新 seek、Edition 切换或 session dispose 必须撤销或取代旧意图。

### 4.1 Manifest 原地刷新

在现有 `ChapterNarrationSession` 增加唯一窄接口：

```ts
refreshManifestInPlace(): Promise<Readonly<{
  changed: boolean;
  manifestRevision: number;
}>>
```

规则：

- 使用当前 Manifest 强 ETag 请求；`304` 不发布新 snapshot，不触发无意义重绘。
- 只接受同 Edition、同 source revision/hash、严格递增 revision；同 revision 不同 ETag、倒退或跨 scope 继续失败关闭。
- 新 revision 复用现有 `adoptPolledManifest()`，更新 `currentBundle` 和 `player.updateManifest()`，保留 session、播放器实例、播放位置、倍速、音量和暂停状态。
- Manifest 接纳后，播放 fence 必须以 `player.lease` 作为当前活动请求的权威，不得要求其 revision 立即等于已经推进的 `currentBundle.manifest_revision`；否则旧 revision 的合法音频、高亮和跟随会在句段结束前被误判过期。
- 当前播放请求到达 ready window 的句段边界并释放旧租约后，player 才把最新已观察 revision 变成新活动租约；如需继续播放，由同一连续播放意图从该边界目标建立新请求。不得在音频中途更新活动租约，也不得为了保留旧租约而阻止生成进度更新。
- 同一 session 最多一个刷新请求在途；章节切换或 session dispose 必须取消旧请求。
- 轮询网络失败不得清空已有可播放内容；保留当前 Manifest 并显示非破坏性错误。
- 现有完整 `refresh()` 只保留给初次加载、Edition 切换和明确的全量恢复，不再用于周期性生产进度刷新。

页面只消费两个窄投影：Manifest 生成计数和 player 播放状态。原地刷新不得把 `phase`、`bundle` 或 `playerState` 临时写成 loading/null；`304` 时完全不 publish，避免无变化快照触发界面更新。

### 4.2 边生成边听

- 只保留一个 Manifest 刷新调度器，不使用多个 effect 各自轮询，也不使用不会自动退避的 `setInterval`。调度器按一次性 timer 自调度，切章、Edition 变化和 dispose 都必须同步取消。
- 生产仍有 pending/queued/rendering 时：idle、paused 状态最多每 2.5 秒原地刷新一次；playing 状态只在当前 segment 发生边界变化且距上次请求至少 2.5 秒时刷新；preparing 与 `PENDING_GAP` 等待状态只由精确目标句段流程负责。所有路径共用同一个在途请求，不能并发拉取 Manifest。
- 播放请求继续锁定当前完整租约；新 Manifest 只在 ready window 的句段边界通过下一播放请求延长后续窗口，不中途替换正在发声的句段。
- session 显式保存 `continuousPlaybackIntent`、目标 `segment_id` 和意图 generation。普通章节播放器与全书播放器共用同一 `PENDING_GAP` 恢复语义：等待精确目标句段、原地接纳新 Manifest、只从原目标继续一次。
- 作者暂停后可以继续收到生成进度，但不得自动起播；作者重新 seek 时旧等待结果必须被 generation fence 拒绝。浏览器拒绝自动恢复时保留同一目标，并把按钮变为“继续播放”，不从章首重来。
- 不改变 ready range 的三段／8 秒起播门槛，不为了“更快播放”从中间跳过尚未生成的前文。

### 4.3 正文生成时保持朗读会话

- `editorShouldMount` 只由章节、编辑器打开状态和是否存在正文／作者已打开空编辑器决定，不再由 `bodyGenerationState.active` 决定。
- 正文生成状态改为编辑区上方固定高度的轻量状态条；不得用整块 spinner 替换正文。编辑器 DOM、scroll position、selection、narration bridge 和播放器保持同一实例。
- 给现有 editor surface 增加唯一窄接口 `setEditable(editable: boolean)`：CodeMirror 使用可动态重配的 editable 状态，textarea fallback 使用原生 `readOnly`。不对整个编辑区使用 `inert` 或遮罩吞掉事件，因为作者仍需滚动、选择文本和使用独立朗读控制。
- 生成期间只禁止正文写入、粘贴、撤销／重做和助手应用编辑；程序化同步服务端新正文仍允许。播放器继续可点击、暂停、调速和跳转已就绪句段。
- 新正文采用时，先对旧朗读 session 明确调用 working-copy divergence，再把服务端返回正文以 `external` origin 写入同一 editor surface，最后解除只读；移除不再可信的正文高亮，但不中断旧 Edition 音频。失败或取消时不改变正文和 divergence 状态，只解除只读。
- 不修改 `ChapterWorkflowPanel` 的章节单活、重试确认、模型调用或候选采用契约。

### 4.4 状态展示与错误分级

- 正文生成状态条与朗读生成／播放区分开；任何一方更新不得替换另一方根节点。动态提示使用 `aria-live="polite"`，避免高频进度把整段内容反复报读。
- Manifest 临时网络失败属于软错误：保留音频和控制器，按现有节奏重试；`failed/cancelled` 缺口、scope/source/revision 冲突属于硬停止，显示精确原因且不跳段。
- 进度完成后停止调度器；没有 pending 状态时不保留空转 timer。离开章节后到达的旧响应只能被忽略，不能改写新章节状态。

## 7. 验收门禁

自动化至少覆盖：

1. 连续 5 次 `304` 不创建新 player、不调用 pause/dispose、不发布 loading snapshot。
2. 播放旧 revision 时接纳多个递增 Manifest，只更新生成计数；活动 `player.lease` 在句段边界前仍合法，播放器实例、当前 segment、offset、rate、volume 和 paused/playing 状态保持。
3. ready prefix 播放到 pending gap 后等待；目标变 ready 时只从该目标继续一次，不重复播放、不跳段。作者在等待期间暂停后，即使目标 ready 也不能自动起播。
4. 唯一调度器不存在并发请求；playing 只在段落边界且满足节流条件刷新，preparing/gap 只由目标等待流程刷新，完成、切章和 dispose 后没有遗留 timer。
5. failed/cancelled gap 停止等待并提示；cross-Edition、source drift、revision collision 和旧异步响应均不能污染当前会话。
6. `bodyGenerationState.active` 变化前后 editor surface、DOM、scroll、selection 与 narration session 身份不变；CodeMirror 和 textarea 都拒绝用户写入但允许 external 同步，播放器可操作。
7. 新正文采用前先进入 working-copy-diverged；旧音频仍可继续，旧段落高亮不映射到新正文。生成失败／取消不改变正文，只恢复编辑。
8. 切章、关闭编辑器和卸载仍会释放音频、AbortController、object URL、timer 和订阅。
